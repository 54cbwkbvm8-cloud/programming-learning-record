# C 语言 09-30 数组统计：文件简介与学习建议

## 文件简介

- **源码文件：** `05_2026-09-30_数组统计.c`
- **类型：** C 语言一维数组输入与统计练习（原含一个极值比较的 bug，已在 2026-10-15 的提交中修好）
- **功能：** 输入 10 个整数，逐个回显，然后计算最大值、最小值和平均值。
- **主要知识点：** 数组定义 `int arr[10];`、下标从 0 开始、`for` 循环批量读入、数组遍历、最大值与最小值的比较逻辑、用 `10.0` 触发浮点除法。

这份文件是一份很典型的"统计三件套"练习：把 10 个数存进数组，再遍历求最大、最小、平均值。

**注意：这份文件里原来有一个真实的逻辑错误。** 求最大值和最小值时，比较的对象被写成了固定的 `arr[0]`，而不是"当前记录的最大值 / 最小值"，所以最小值会算错。**这个 bug 已经在 2026-10-15 的提交里修好了，现在程序的输出是正确的。**

那为什么还留着这篇文档？因为这个 bug 本身很值得复习：**它不是语法错误**，编译器一句警告都不会给，程序能正常跑完，只是答案悄悄错了。下面把"错在哪、怎么改、修好前后差多少"完整保留下来，当作一份对照案例。以后写极值统计时，先回来读一遍「回顾：这个 bug 当初错在哪」那一节。

## 回顾：这个 bug 当初错在哪（已在 2026-10-15 修好）

先看**修复前**的写法（现在的文件里已经不是这样了）：

```c
max = arr[0];
for (i = 1; i < 10; i++) {
    if (arr[i] > arr[0]) {   // ← 问题在这里
        max = arr[i];
    }
}
```

**为什么错：** 每次比较的对象写成了 `arr[0]`（数组的第一个元素），而不是"当前记录的最大值" `max`。以输入 `5 9 1 7 3 8 2 6 4 10` 为例，`arr[0]` 是 5：

- 求最大值时，程序每次判断的是"这个数是否大于 5"，大于就赋值。大于 5 的数字有 9、7、8、6、10，循环结束时 `max` 等于其中**最后出现**的那个，也就是 10。这次刚好对了，纯属巧合。
- 求最小值时，程序每次判断的是"这个数是否小于 5"，小于就赋值。小于 5 的有 1、3、2、4，最后出现的是 4，于是 `min` 变成 4，而正确答案应该是 1。

**修复方式（最小修改）：** 只把两处比较的对象从 `arr[0]` 换成当前记录的值即可。下面这两段就是**现在文件里的真实写法**。

```c
max = arr[0];
for (i = 1; i < 10; i++) {
    if (arr[i] > max) {      // 只改这一处：和当前最大值比
        max = arr[i];
    }
}
```

```c
min = arr[0];
for (i = 1; i < 10; i++) {
    if (arr[i] < min) {      // 只改这一处：和当前最小值比
        min = arr[i];
    }
}
```

改完之后再运行同一组数据，最小值就变成了 1，也就是本文档开头"建议运行数据"里记录的那份实测输出。

## 零基础学习建议

1. 先理解数组下标：`int arr[10]` 有 10 个格子，编号是 0 到 9，所以提示语里写"第 i + 1 个数字"而数组里用 `arr[i]`，这两个数字永远差 1。
2. `max = arr[0];` 的作用是"先用第一个数占位，再逐个挑战它"。这个写法比 `max = 0` 安全：如果输入全是负数，用 0 占位会得到错误的答案（最大值会一直是 0）。
3. 循环从 `i = 1` 开始而不是 0，是因为 `arr[0]` 已经当过初值了，再从 0 开始相当于让它自己和自己比一次，虽然不影响结果但多了一次无效比较。
4. 平均值那行 `sum / 10.0` 里的 `10.0` 是关键：写 `sum / 10` 是整数除法，小数部分会被丢掉（55 / 10 会得到 5 而不是 5.5）；写成 `10.0` 就会触发浮点除法，得到 5.500000。
5. 用纸跟踪一遍"求和"循环：写下每一轮 `i`、`arr[i]`、`sum` 的值。这是理解数组统计最快的方法，比反复读代码有效得多。
6. 现在文件已经修好了，用"全是负数"和"全部相同"两组数据各跑一次，确认最大值和最小值都正确。这两组数据是检验极值逻辑的标准测试。

## 常见易错点

- 最大值和最小值循环里比较的对象必须是"当前记录值"，不能是固定的 `arr[0]`。这是本次要重点记住的一条。
- `min` 和 `max` 都不应该在循环里重新赋初值。如果 `max = arr[0];` 写在循环内部，每一轮都会重新开始比较，最后只会得到"最后一个数"或"第一个数"。
- 数组下标越界（比如 `arr[10]`）不会报错，但会写到不属于这个数组的内存里，结果不可预测。循环条件写 `i < 10` 而不是 `i <= 10`。
- `scanf("%d", &arr[i])` 里的 `&` 不能少。数组元素不是数组名，必须取地址。
- 提示语 `printf("请输入第%d个数字：", i + 1);` 末尾没有换行，所以 10 条提示会和输入挤在同一行显示，这是本程序保留的写法。
- 如果输入的个数不是 10 个而是其他个数，平均值那里的 `10.0` 就要跟着改。更通用的写法是把个数存进变量 `n`，然后写 `sum / (double)n`。
- `int i = 0;` 在中间重新声明了一次 `i`（前面 `for` 里的 `i` 作用范围已经结束），能正常编译，但两个 `i` 是不同的变量，读代码时要注意。
- 文件开头声明了 `int avg;`，但后面算平均值时是直接 `printf("%f", sum / 10.0)` 打印的，**这个变量从头到尾没有用到**。加上 `-Wall -Wextra` 编译时会出现一条警告：`unused variable 'avg' [-Wunused-variable]`。不影响运行，但这类"声明了却没用上"的变量值得顺手删掉——警告里说的问题，往往就是真正要改的地方。

## 可以继续尝试

1. 复盘一下这个已经修好的极值 bug：先别看「回顾：这个 bug 当初错在哪」那一节，自己用上面那三组数据跑一遍，试着讲清"修复前的最小值为什么总是错的"。能讲明白，说明真的理解了极值比较的写法。
2. 把统计逻辑封装成函数：`int max_of(int a[], int n)`、`int min_of(int a[], int n)`、`double average_of(int a[], int n)`，让 `main` 只负责输入和输出。
3. 增加统计项：正数个数、负数个数、偶数个数、以及"大于平均值的数字有几个"。
4. 让用户先输入数组长度 `n`（用 `scanf`），并把平均值那里的 `10.0` 改成适用任意长度的写法。
5. 增加排序功能：把 10 个数从小到大排序后输出，把前面学过的双重循环排序用上。
6. 增加查找功能：输入一个数字，输出它是否在数组里、出现在第几个位置（练习遍历 + 判断 + 提前结束）。
