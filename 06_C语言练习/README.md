# 06 C 语言练习

本目录按练习日期收录 C 语言入门源码，内容从变量、输入输出、条件判断、循环，逐步走到函数、一维数组、数组统计、字符串、指针，再补上 `switch` 分支、`printf` 输出格式、动态内存和哈希表入门。

**命名约定：** 源码用 `序号_日期_主题.c`（例如 `06_2026-10-01_数组统计与逆序输出.c`），**日期是这个文件第一次上传到仓库的那一天**（格式 `YYYY-MM-DD`，来自 Git 提交记录）。序号是文件的固定编号，方便排序和互相引用，实际阅读顺序见下面的「推荐学习顺序」。每个源码都配有一份同名的「简介与学习建议」文档，说明程序结构、建议输入、预期输出和易错点。

## 推荐学习顺序

按下面的顺序走，每一步都建立在上一步的基础上：

**第一阶段：语法与判断（01、02、14、15）**

1. `01_2026-09-28_基础语法综合练习.c` — 用五道小题把变量、输入输出、格式符过一遍。
2. `02_2026-09-28_正负奇偶与闰年.c` — 判断专题，重点看第五题的闰年条件。
3. `14_2026-09-13_两数比较与成绩等级_教程版.c` + `14_2026-09-13_两数比较与成绩等级_零基础教程.md` — 先读教程再看代码，理解函数是怎么拆出来的。
4. `15_2026-09-13_两数比较与成绩等级_修正版.c` — 对照 14 号，看"两个数相等"这种边界情况为什么要单独处理。

**第二阶段：循环（03、04、18）**

5. `03_2026-09-29_循环与九九乘法表.c` — 先把 `for` 循环和累加器用熟。
6. `04_2026-09-30_循环综合与猜数字.c` — 换成 `while`，体会"循环变量必须自己更新"。
7. `18_2026-10-12_循环求和与奇偶分类.c` — 用四段循环统计 1～10 的偶数和、奇数和与总和，重点看 `i = i + 2` 这种"改步长"的写法和每段开头的 `sum = 0;`。

**第三阶段：数组（05、06）**

8. `05_2026-09-30_数组统计.c` — 一维数组的输入与统计。这个文件原来有一个极值比较的 bug（已经在 2026-10-15 修好），文档里完整保留了"当初错在哪"的回顾，值得顺着读一遍：**程序能跑完、答案却是错的**，这类错误最难发现。
9. `06_2026-10-01_数组统计与逆序输出.c` — 数组遍历的综合运用。

**第四阶段：函数（07、09、17、14 回顾）**

10. `07_2026-10-02_函数基础练习.c` — 函数定义、返回值、函数互相调用。
11. `09_2026-10-05_数组函数统计.c` — 数组作参数时为什么必须同时传长度 `n`。
12. `17_2026-10-12_函数最值平方与奇偶判断.c` — 第一次接触"函数声明（原型）"，体会 `main` 写在前面时为什么需要提前声明；再和 `07` 号对照，看清 `square(a)` 和 `square(max(a, b))` 的区别。

**第五阶段：综合与实战（10、11、12、08、13、16）**

13. `10_2026-10-07_分支循环数组模拟练习.c` — 把前面学的串成一次完整运行。
14. `11_2026-10-07_分支循环数组复习.c` — 用一次综合复习检查掌握情况。
15. `12_2026-10-09_取余与两种循环练习.c` — 对照 `for` 与 `while` 的写法差异。
16. `08_2026-10-05_菜单式计算器.c` — 学会用 `while (1)` 写菜单，这是后面写小程序的常用结构。
17. `13_2026-10-10_数组输入校验与成绩统计.c` — 学会"输入错误后重新输入"的写法。
18. `16_2026-10-11_奇偶组合与数组最值.c` — 综合程度最高的一份。重点看 `if (i == 0 || a > max)` 这个"首元素保护"写法，它和 `05_2026-09-30_数组统计.c` 原来那个 bug 正好是正反两个例子（`05` 现在已修好，可对照它的文档回顾）。

**第六阶段：字符串（19、20）**

19. `19_2026-10-13_字符串输入与常用函数练习.c` — 第一份专门练字符串的程序。重点看 `fgets` 为什么会把行尾的 `\n` 一起读进来、`str[len - 1] = '\0'` 是怎么把它去掉的，以及 `strlen`（实际字节数）和 `sizeof`（数组总容量）为什么不是一回事。汉字在 UTF-8 里占 3 个字节，所以长度不等于字数。
20. `20_2026-10-14_字符串统计与大小写转换练习.c` — 开始逐个字符地处理字符串。重点理解"字符就是数字"（`'a' - 'A'` 等于 32），以及为什么三个 `if` 必须并列而不能写成 `else if`；去换行这一行 `str[strcspn(str, "\n")] = '\0';` 和 19 号的手写版正好可以对照。

**第七阶段：指针（21、22、23、24）**

21. `21_2026-10-15_指针偏移与数组传参练习.c` — 讲清"数组交给函数时到底交给了什么"。核心是那个对比：在 `main` 里 `sizeof(a)` 是 20 字节，在函数里 `sizeof(arr)` 只有 8 字节，因为传过去的其实是指针。也第一次用 `*(p + 1)`、`*(p - 1)` 演示指针的加减。
22. `22_2026-10-15_指针基础读写与switch穿透练习.c` — 指针最基础的用法：`int *p = &value;` 之后，`*p` 既能读也能写，`*p = 20;` 会连着把 `value` 改掉。后半段的 `switch` 演示了漏写 `break` 造成的"穿透"（`choice = 2` 却输出 `BC`），是 `switch` 最需要记住的一条规则。两份一起读，再回头看 `09_2026-10-05_数组函数统计.c` 里"为什么必须传长度 n"，会一下子明白。
23. `23_2026-10-15_指针初始化与数组参数校验练习.c` — 先看清指针的"空"（`int *p = NULL;`）和"有指向"（`p = &number;`）两种状态，再学函数进门的第一件事：**检查参数**。这份文件里的 `print_array` 写了两道检查，但第一道只打印了提示、忘了 `return;`，所以 `print_array(NULL, 3)` 会一路跑到 `arr[i]` 上，程序直接段错误。**先自己补上那句 `return;`，再和文档里的最小修改对照**——这是"写了校验"和"校验真的有效"之间的差别，也是本目录里最值得亲手改一次的一处。改完之后记得再补一次合法调用 `print_array(numbers, 5);`，因为原文件两次调用传的都是非法数据，正常打印数组那段代码其实一次都没跑过。
24. `24_2026-10-15_指针初始化与数组参数校验_教程版.c` + `24_..._零基础教程.md` — 23 号同一道题的**修正 + 逐行注释版**。它做了三件 23 号没做的事：把 `return;` 补上了、补了一次正常的 `print_array(numbers, length)` 调用、把每个代码行都写上了中文注释。配套的《零基础教程》按行号逐行讲解，还专门列了一张表对比 23 和 24 的差别。**建议顺序是：先读 23 踩一次段错误的坑，再读 24 对照着看为什么加一句 `return;` 就不崩了。**

**第八阶段：输入、分支与输出格式（25、26）**

25. `25_2026-10-16_switch分支与scanf输入练习.c` — 用 `scanf` 读一个整数和一个字符，再用 `switch` 分支决定输出。两个重点：**`scanf` 的返回值要检查**（读不到就干净地退出，而不是带着错误的数值继续算），以及 **`scanf(" %c", &ch)` 里那个前导空格**——少了它会读到上一次输入留在缓冲区里的换行符，这也是很多人第一次写菜单程序时踩的坑。可以和 `22_2026-10-15_指针基础读写与switch穿透练习.c` 对着读：22 号看漏写 `break` 的穿透，这一份看每个 `case` 都写 `break` 的规范写法。
26. `26_2026-10-16_强制类型转换与printf格式控制练习.c` — 不需要输入的一份"对照实验"：同一组数字 `7` 和 `2`，`a / b` 得到 3，`(double)a / b` 得到 3.5，看清**整数除法是砍掉小数、不是四舍五入**。另外把 `%.2f`、`%02d`、`%-5d` 三个输出格式放在一起，配合程序末尾的 `END,` 能直接看出空格补在哪一边，最后用 `%%` 输出百分号。**建议先自己猜一遍输出，再跑程序对答案**；`(double)(a / b)` 和 `(double)a / b` 只差一对括号、结果完全不同，是最值得亲手改一次的地方。

**第九阶段：算法与数据结构入门（27、28）**

27. `27_2026-10-18_两数之和_暴力枚举.c`：先用最直观的双层循环写出答案，重点理解内层为什么从 `i + 1` 开始，以及函数如何通过 `result` 数组带回两个下标。
28. `28_2026-10-18_两数之和_哈希表优化.c`：再用哈希表保存已经见过的数字和下标，每轮只查找补数。先分清 `HashEntry`、`hash_index`、`find_slot` 三段代码，再比较它在时间复杂度和额外内存上的取舍。

## 学习方法建议

- 每一份都**先编译、再运行、再改**。用下面这条命令编译（把文件名换成你要练的）：

  ```bash
  cc -std=c17 -Wall -Wextra "06_C语言练习/01_2026-09-28_基础语法综合练习.c" -o /tmp/practice && /tmp/practice
  ```

  加上 `-Wall -Wextra` 会让编译器把可疑写法都提示出来，是非常值得养成的习惯。
- 先用文档里的"建议运行数据"跑一遍，再自己另外准备三组数据：**正常数据、边界数据、特殊数据**（全负数、全部相同、空输入）。这三类数据最容易暴露逻辑错误。
- 出错时的顺序是：先看编译器的报错行号 → 再看是哪一类错误（拼写、分号、类型、下标）→ 做最小修改再编译。不要一次改很多地方。
- `23_2026-10-15_指针初始化与数组参数校验练习.c` 是本目录里**唯一故意留了错误**的文件：空指针检查漏了 `return;`，运行会段错误。先自己补上，再对照文档里的最小修改——找出真实 bug 的经验比多做十道题都有用。改完之后可以接着读 `24` 号的教程版，看同一道题修好之后是什么样子。
- 每一份源码旁边都有对应的「简介与学习建议」，读完源码再看文档，能发现自己漏掉的细节。
