# C 语言 10 月 15 日指针初始化与数组参数校验练习：文件简介与学习建议

## 文件简介

- **源码文件：** `23_2026-10-15_指针初始化与数组参数校验练习.c`
- **类型：** C 语言指针入门 + 数组作参数与参数校验练习
- **功能：** 程序分两段。第一段演示指针的两种状态：先用 `int *p = NULL;` 声明一个"不指向任何东西"的指针，再写 `p = &number;` 让它指向 `number`，最后用 `*p` 把这个值读出来。第二段调用自写的 `print_array(numbers, length)`，把数组和它的长度一起交给函数；然后用 `print_array(numbers, 0)` 和 `print_array(NULL, 3)` 两组非法数据，检查函数里的参数校验到底有没有起作用。

## 建议运行数据

编译运行（这份程序**不需要输入**）：

```bash
cc -std=c17 -Wall -Wextra "06_C语言练习/23_2026-10-15_指针初始化与数组参数校验练习.c" -o /tmp/practice && /tmp/practice
```

**先看这里：按原样运行，程序会在最后一行崩溃**（macOS 上退出码 11，也就是 `Segmentation fault`，段错误）。这不是编译错误，编译器一句警告都不会给。

实测输出（`clang -std=c17 -Wall -Wextra`，macOS）：

```text
===1.指针初始化演示===
指针初始化时为 NULL，此时不解引用。
p现在保存 number 的地址。
number = 42
解引用运算符*访问了p 指向的对象，所以*p = 42

2.数组参数与长度演示
调用函数前计算得到的数组长度：5
错误：数组长度必须大于0,数组长度为 0 或者小于 0，没有可以打印的元素
错误：数组指针为空，不能访问数组。
```

**输出到"错误：数组指针为空"就没有了，后面没有任何内容，程序以段错误结束。** 原因在 `print_array` 开头这四行：

```c
if (arr == NULL) {
    printf("错误：数组指针为空，不能访问数组。\n");
}                       /* ← 这里只打印了提示，没有 return */
if (length <= 0) {
    printf("错误：数组长度必须大于0,...\n");
    return;             /* ← 这一支写了 return，所以真的挡住了 */
}
```

- `print_array(numbers, 0)`：`arr` 不是 `NULL`，走到第二个 `if`，`length <= 0` 成立 → **打印提示并且 `return`**，安全返回。这条校验是有效的。
- `print_array(NULL, 3)`：`arr` 是 `NULL`，第一支**只打印了提示就往下走**；接着 `length <= 0` 不成立（3 > 0），于是继续往下执行到 `arr[i]`——也就是拿 `NULL` 去取数组元素，程序当场崩溃。这条校验是无效的。

**最小修改：在第一个 `if` 里补一句 `return;`。**

```c
if (arr == NULL) {
    printf("错误：数组指针为空，不能访问数组。\n");
    return;   /* 【新增】和下面那一支一样，校验不通过就立刻退出函数 */
}
```

补上之后的实测输出（程序正常结束，退出码 0）：

```text
===1.指针初始化演示===
指针初始化时为 NULL，此时不解引用。
p现在保存 number 的地址。
number = 42
解引用运算符*访问了p 指向的对象，所以*p = 42

2.数组参数与长度演示
调用函数前计算得到的数组长度：5
错误：数组长度必须大于0,数组长度为 0 或者小于 0，没有可以打印的元素
错误：数组指针为空，不能访问数组。
```

**注意：修好之后输出完全一样，唯一的变化是"不再崩溃"。** 这说明本文件两次调用传的都是非法数据，`print_array` 里那段真正打印数组的代码（`printf("数组元素为：")` 和 `for` 循环）**一次都没有被执行过**——正常路径还没有被验证。所以下一个练习应该是补一次合法调用 `print_array(numbers, 5)`，看数组真的被打印出来是什么样子。

两次调用的对照：

| 调用 | `arr == NULL` | `length <= 0` | 原文件的实际结果 | 补上 `return;` 之后 |
| --- | --- | --- | --- | --- |
| `print_array(numbers, 0)` | 否 | 是 | 打印长度提示后正常返回 | 同左（不变） |
| `print_array(NULL, 3)` | 是 | 否 | 打印指针提示后继续执行，**段错误** | 打印提示后正常返回 |
| `print_array(numbers, 5)`（文件里没有） | 否 | 否 | — | 打印 `数组元素为：10 ,20 ,30 ,40 ,50`（末尾还有一个空格） |

## 零基础学习建议

1. **先记住指针有三种状态，本文件演示了前两种。**

   | 写法 | 状态 | 能不能解引用 `*p` |
   | --- | --- | --- |
   | `int *p = NULL;` | 空指针，明确"不指向任何变量" | **不能**，解引用一定崩溃 |
   | `int *p = &number;` | 指向 `number`，可以用 | 能，`*p` 读到的就是 42 |
   | `int *p;`（没初始化） | 野指针，指向一个随机的地址 | **不能**，行为完全不可预测 |

   `int *p = NULL;` 的价值就在于：它把指针明确地设成"什么都没有"，这样后面写 `if (p == NULL)` 才有意义。**声明指针时先给个 `NULL`，是很好的习惯。**

2. **`&` 和 `*` 是一对相反的操作。**

   | 写法 | 读作 | 含义 | 结果类型 |
   | --- | --- | --- | --- |
   | `&number` | 取地址 | "`number` 住在哪" | `int *` |
   | `*p` | 解引用 | "`p` 指的那个格子里的东西" | `int` |

   所以 `p = &number;` 之后，`*p` 和 `number` 就是同一块内存的两个名字。22 号文件演示了通过 `*p = 20;` 改原变量，可以和这份对照着看。

3. **数组交给函数时，必须额外告诉它"有多长"。** 函数里的参数 `const int arr[]` 其实等价于 `const int *arr`，是一个指针，不是数组。指针里只有"从哪里开始"，没有"到哪里结束"，所以 `main` 里要先用 `sizeof(numbers) / sizeof(numbers[0])` 算出 5，再一起传进去。这一点在 21 号文件里讲得更透。

4. **`const int arr[]` 里的 `const` 是"只读约定"。** 意思是"我保证不通过 `arr` 改数组内容"。`print_array` 只负责打印，本来就不该改数据，所以加 `const` 是合适的。写了 `const` 之后如果函数体里出现 `arr[i] = 0;`，编译器会直接报错拦住你。

5. **参数校验必须"检查完就退出"，这是本文件最值得记住的一条。**

   ```c
   if (参数不合法) {
       打印提示;
       return;      /* ← 缺了这句，函数还会继续往下跑 */
   }
   ```

   `return` 的作用是**立刻结束整个函数**，后面所有代码都不再执行。所以校验语句里的 `return` 不是可选项——没有它，"打印错误提示"和"真正拦住错误"是两回事。本文件的第二个 `if` 写对了，第一个 `if` 漏了。

6. **`if` 不写大括号时，只保护紧跟的那一行。** 本文件三个 `if` 都带大括号，所以看着整齐；但如果写成：

   ```c
   if (arr == NULL)
       printf("错误：数组指针为空。\n");
       return;            /* 这一行其实已经不在 if 里了！ */
   ```

   `return;` 会变成"无论如何都执行"，函数永远直接返回。而且缩进会骗人，看起来像是被 `if` 管着。**所以 `if` 一律写大括号**，这是避免这类错误的通用做法。

7. **`NULL` 不需要真的去"访问"。** `arr == NULL` 只是比较两个地址是否相等，完全安全。危险的是 `arr[0]`、`*arr` 这种"顺着这个地址去读内存"的动作。函数里第一件事应该是**比较**，不能是**访问**。

## 常见易错点

- **校验时只打印提示、没有 `return`。** 本文件的核心问题。判断标准很简单：问自己一句"这句话执行完之后，函数还会不会往下走？"如果会，校验就是假的。
- **以为"写了 NULL 检查"就安全了。** 检查了却忘了退出，比不检查更危险，因为读代码的人会以为这里已经处理过了。
- **`print_array(NULL, 3)` 里的 `3` 掩盖了问题。** 如果写成 `print_array(NULL, 0)`，第二个 `if` 会先成立并 `return`，反而看不出第一个 `if` 的漏洞。**这也是为什么测试要一组一组地传不同组合**：一份坏数据掩不住，两份坏数据一起就容易暴露问题。
- **`arr == NULL` 写成 `arr = NULL`。** 一个是比较，一个是赋值。`arr = NULL` 会把传进来的地址直接丢掉，而且多数编译器会警告 `-Wparentheses`，看到警告不要放过。
- **在函数里用 `sizeof(arr)` 求数组长度。** 永远得到指针大小（64 位机器上是 8），不是 20。所以长度必须从外面传进来——这正是本文件第二段要演示的事。
- **用 `NULL` 却只 `#include <stdio.h>`。** 本文件没写 `#include <stddef.h>`，靠 `stdio.h` 间接带进来，实际能编译通过。更严谨的写法是显式加上 `#include <stddef.h>`（21 号文件就是显式写的）。`NULL` 比较特殊的地方在于它是"空指针常量"，不是普通的 0，用 `%d` 打印它也是错的。
- **打印指针要用 `%p`，最好再强制转成 `void *`。** 标准写法是 `printf("%p\n", (void *)p);`。实测在 macOS 的 clang 上，直接写 `printf("%p\n", p);` 不给警告也能正常输出，但把 `p` 转成 `void *` 才是严格符合标准的写法，换编译器或换平台时更稳。
- **段错误不等于"程序有 bug 但结果不对"。** 它意味着程序访问了不允许访问的内存，操作系统直接把进程杀掉了。所以**崩溃前的输出可能不完整**——本文件崩溃前的输出其实是完整的，但很多情况下缓冲区里的内容会一起丢掉，看不到任何提示。
- **函数里的提示信息用 `\n` 结尾，`main` 里的段落标题却漏了。** 本文件第二段标题 `printf("\n2.数组参数与长度演示\n");` 以 `\n` 开头是对的（空一行再打印），这种"排版用 `\n`"的写法每份练习都会出现，值得顺手检查一遍。

## 可以继续尝试

1. **先做这一件：** 在第一个 `if` 里补上 `return;`，重新编译运行，确认不再崩溃、退出码变成 0。这一步做完再往下看。
2. **补一次合法调用。** 在 `main` 的两次非法调用前面加上 `print_array(numbers, 5);`，看正常的数组打印长什么样。实测会多出这一行：

   ```text
   数组元素为：10 ,20 ,30 ,40 ,50
   ```

   （这一行实测在 `50` 后面还跟了一个空格，上面看不出来。）观察其中的标点：元素之间是 `10 ,20`，**逗号前面有一个空格**。因为作者写的是 `printf("%d ", arr[i])` 后面再接逗号——数字后面的 `" "` 先打出来，逗号才跟上，于是逗号前就多了空格。把 `printf("%d ", arr[i])` 改成 `printf("%d", arr[i])`，逗号就贴到数字上了。末尾那个多余的空格来自最后一次的 `printf("%d ", arr[i])`，同理可以去干净。
3. **把 `const int arr[]` 改成 `const int *arr`**，重新编译运行，确认结果完全一样。这能证明"函数参数里的 `int arr[]` 就是一个指针"。反过来把它改成 `const int * const arr`（指针本身也不能改），看编译器是否还接受 `arr[i]`。
4. **给函数加上返回值。** 把 `void print_array(...)` 改成 `int print_array(...)`：参数合法时返回打印的元素个数，`arr` 为空时返回 `-1`，`length <= 0` 时返回 `0`。`main` 里把返回值接住并打印出来。这是 C 语言里最常见的错误上报方式，比"只打印一行提示"更实用。
5. **做一次越界实验，理解"C 语言不检查边界"。** 在本地临时写 `print_array(numbers, 10);`，观察程序会打印出 5 个正常数字加 5 个乱七八糟的数字，甚至可能崩溃。注意：这个实验只在本地做，**不要把它留在上传的文件里**。
6. **把指针的状态打印出来看。** 在 `p = &number;` 前面和后面各加一句 `printf("p = %p\n", (void *)p);`，对比 `NULL` 和真实地址两种状态。`NULL` 打印出来通常是 `0x0`。
7. **写一个 `int *find_max(const int *arr, int length)`**，返回最大元素的**地址**（不是值）。提示：先 `const int *max = &arr[0];`，再遍历比较 `if (arr[i] > *max) max = &arr[i];`，最后 `return (int *)max;`（因为参数是 `const`，返回值要显式去掉 `const`，可以顺便体会一下 `const` 的"传染性"）。
8. **把校验逻辑整理成一个单独的 `int check_args(const int *arr, int length)` 函数**，合法返回 1、非法返回 0，`print_array` 开头只写 `if (!check_args(arr, length)) return;`。这样检查规则只写一遍，以后加新规则也不用改多处。

**学到什么程度算真正理解这份练习：** 能不看代码回答三个问题——(1) 为什么指向 `NULL` 的指针不能解引用；(2) 为什么 `print_array` 必须同时收到 `arr` 和 `length` 两个参数；(3) 为什么参数校验里少了 `return;` 就等于没校验。
