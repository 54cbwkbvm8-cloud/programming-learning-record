# C 语言 10 月 14 日字符串统计练习：文件简介与学习建议

## 文件简介

- **源码文件：** `20_2026-10-14_字符串统计与大小写转换练习.c`
- **类型：** C 语言字符串处理练习（字符分类统计 + 大小写转换）
- **功能：** 读入一行文字，去掉行尾换行符，然后一次性做三件事：数出里面有多少个英文字母、多少个数字，并把所有小写字母改写成大写字母，最后输出三个结果。
- **主要知识点：** `fgets` 读入整行、`strcspn` 去掉换行符、`strlen` 求长度、`for` 遍历字符串、**字符与 ASCII 码的关系**、用 `c >= 'a' && c <= 'z'` 判断范围、用 `c - ('a' - 'A')` 做大小写转换、`int` 与 `size_t` 的强制转换。

这份练习接着 `19_2026-10-13_字符串输入与常用函数练习.c` 往下走：19 号是"读进来、看一看、比一比"，20 号开始**逐个字符地处理**字符串。四段读法：

1. **读入并去掉换行**：`str[strcspn(str, "\n")] = '\0';` 一行搞定。
2. **准备长度**：`len = (int)strlen(str);` 拿到字符个数，顺便做一次类型转换。
3. **遍历一遍，三个 `if` 各管一件事**：数数字、把小写改大写、数字母。
4. **输出**：字母数、数字数、转换后的字符串。

## 零基础学习建议

1. **先把"字符其实也是数字"这件事想通。** 计算机里每个字符都对应一个编号（ASCII 码）：`'A'` 是 65，`'Z'` 是 90，`'a'` 是 97，`'z'` 是 122，`'0'` 是 48。C 语言允许直接把字符当整数运算，所以 `'a' - 'A'` 等于 32——正好是小写字母和大写字母之间的固定差距。
2. **`c - ('a' - 'A')` 就是"把小写字母换成大写字母"。** 展开看：小写 `'c'`（99）减去 32 得到 67，也就是大写 `'C'`。等价写法是 `c - 32`，但 `('a' - 'A')` 更能说明"这是在补上大小写的差值"，也更好记。标准库里的 `toupper(c)` 做的是同一件事。
3. **一行去掉换行符：`str[strcspn(str, "\n")] = '\0';`**

   - `strcspn(str, "\n")` 的意思是"从开头数起，第一次遇到 `\n` 是在第几个位置"。
   - 如果输入 `<回车>` 换行，它就返回换行符的下标，我们直接把那个位置改成 `'\0'`，换行符就没了。
   - 如果这一行本来就没有换行符（例如输入 199 个字符把缓冲区塞满），它返回的是字符串长度，指向的正好是结尾的 `'\0'`，把它重写一遍也无害。所以这一行对两种情况都安全。
   - 对比 `19_2026-10-13_字符串输入与常用函数练习.c` 里手写的 `if (len > 0 && str[len - 1] == '\n')`：功能一样，`strcspn` 更短，但需要清楚它在做什么。
4. **`len = (int)strlen(str);` 为什么要加 `(int)`。** `strlen` 返回的是 `size_t`（无符号整数），而 `len` 是 `int`。显式写 `(int)` 是告诉编译器"我知道这里要做类型转换"。不写往往也能跑，但显式转换能让意图更清楚，也避免了"有符号和无符号比较"这类隐藏问题。
5. **三个 `if` 是并列的，不是 `else if`。** 一个字符可能同时满足多个条件：`'a'` 既"是小写字母"又"是字母"，所以数字计数、转换、字母计数得各判断一次，互不排斥。
6. **注意 `c` 和 `str[i]` 的区别，这是本文件最妙的一处。**

   ```c
   char c = str[i];                 /* 先把原字符存下来 */
   if (c >= 'a' && c <= 'z') {
       str[i] = c - ('a' - 'A');    /* 改的是数组里的格子 */
   }
   if ((c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z')) {
       letter_count++;              /* 这里的 c 还是原字符 */
   }
   ```

   因为始终拿 `c`（原字符）来判断，所以字母计数不受"已经改成大写"的影响：`abc` 三个字符在第一次判断时是小写、被改写，但第三次判断用的是 `c`，仍然算三个字母。如果把这里都换成 `str[i]`，逻辑就跟着改写的顺序变了，很容易数错。
7. **`c >= 'a' && c <= 'z'` 必须写两个条件。** C 语言里 `'a' <= c <= 'z'` 不会报错，但它先算 `('a' <= c)` 得到 `0` 或 `1`，再拿这个结果和 `'z'` 比，结果永远成立——这是初学者最隐蔽的坑之一。
8. **括号里那个"或"不能省：** `(c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z')`，两组条件都要各自带括号，`&&` 的优先级比 `||` 高，写清楚能少一类错误。

## 常见易错点

- **中文为什么不会被当成字母。** 一个汉字在 UTF-8 里占 3 个字节，每个字节的值都大于 `'z'`（122），所以既不落在 `a~z`，也不落在 `A~Z`，两个判断都不成立。另外在 macOS 上 `char` 是**有符号**的，汉字的字节读出来是负数——但它们同样不满足这些范围条件，而且程序也没改它们，所以中文能原样保留、被正确打印。
- **把 `toupper` 的功劳当成自己的。** 这里没有用 `ctype.h`，是手写的字符减法。想用库函数的话要记得 `#include <ctype.h>`，并且注意 `toupper` 的返回类型是 `int`。
- **数字判断不能写 `c >= '0' && c <= '9'` 之外的想当然写法。** 比如用 `c == 0`、用 `c <= '9'`（会把标点也算进去）。数字字符是连续的 `'0'~'9'`，范围判断是最稳的写法。
- **`str[200]` 只装得下 199 个字节。** 超出部分会留在输入缓冲区里，不会自动清空——这一点和 `19` 号文件里演示的"超长第一行会被第二次 `fgets` 读走"是同一个现象。
- **读失败时 `return 1`。** 和 19 号一样，这里用返回值区分"成功 / 失败"。
- **不要让输出的"转换后字符串"替掉原始输入。** 程序直接在 `str` 上改写，所以运行结束后原始的小写形式就看不到了。想同时保留两份，需要在改写前先 `strcpy` 一份副本（19 号里刚练过 `strcpy`）。
- **比较 `'a'` 和 `"a"`。** 单引号是字符（一个整数），双引号是字符串（字符数组常量的地址）。写成 `c >= "a"` 会得到毫无意义的结果甚至编译警告。
- **大小写转换只处理了"小写转大写"。** 如果输入本身就是大写，程序不动它，这是设计如此；但如果你以为输入 `ABC` 会被"规范化"，那就要失望了——它本来就符合要求。

## 可以继续尝试

1. 把统计项目加全：分别数出大写字母、小写字母、空格、数字和其他字符各有多少个，各用一个 `if` 累加。
2. 用 `#include <ctype.h>` 改写成 `toupper(c)` 和 `isdigit(c)` 的版本，和手写版本对比，说说哪个更容易读。
3. 再写一个函数 `void to_lower(char *s)`，把所有大写字母改回小写，练习"传入数组让函数直接修改"。
4. 不用 `strcspn`，改回 19 号文件里手写的去换行写法，自己比较两种写法的优缺点。
5. 把统计逻辑拆成函数：`int count_letters(const char *s)`、`int count_digits(const char *s)`、`void to_upper(char *s)`，让 `main` 只负责输入输出。
6. 结合 19 号的内容：读入两行，分别统计字母数和数字数，再用 `strncmp` 比较转换后的两行是否相同（`abc` 和 `ABC` 转换后就相同了）。
7. 让程序先把原始输入打印出来再打印转换结果，体会"原地修改"和"保留原值"的区别。
