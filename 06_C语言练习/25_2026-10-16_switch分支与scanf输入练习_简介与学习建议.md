# C 语言 10 月 16 日 switch 分支与输入练习：文件简介与学习建议

## 文件简介

- **源码文件：** `25_2026-10-16_switch分支与scanf输入练习.c`
- **类型：** C 语言分支（`switch`）+ 输入（`scanf`）基础练习
- **功能：** 程序先读一个整数，再读一个字符，把读到的东西打印出来，然后用 `switch` 按这个整数决定走哪个分支：是 1、2、3 各有各的输出，其它值一律走 `default`。
- **主要知识点：** `scanf` 的返回值校验（读不到就 `return 1` 退出）、格式符 `%d` 与 `%c` 的区别、`scanf(" %c", &ch)` 里那个**前导空格**的用处、`switch / case / default / break`、用 `printf` 打印字符时要写 `'%c'`。

整个程序就是三段：

1. **读一个整数** —— `scanf("%d", &number)`，并检查返回值是否是 1。
2. **读一个字符** —— `scanf(" %c", &ch)`，同样检查返回值。
3. **`switch` 分支** —— 按 `number` 的值跳到对应的 `case`，都不匹配就走 `default`。

这份练习和 `22_2026-10-15_指针基础读写与switch穿透练习.c` 是互补的：22 号演示的是 `switch` **漏写 `break` 造成的穿透**，这一份里的 `switch` 每个 `case` 都老老实实写了 `break`，正好可以对照着看"正常写法"长什么样。

> **阅读代码时请留意一处：** 程序第一句提示文字写的是"请输入一个字符用于（switch分支演示）："，但紧接着读的其实是**整数**（`scanf("%d", &number)`），第二句才读字符。这是原文件里提示文字和实际读取类型不一致的地方，按约定这次整理**没有改动源码**，只在文档里点出来。想自己动手的话，见下面「可以继续尝试」第 1 条。

两点说明：

- **两句提示会挤在同一行显示。** 第一句 `printf` 的结尾是冒号、没有换行，所以第二句提示紧接着就打印出来了。想看得舒服，可以在第一句末尾加 `\n`。

## 零基础学习建议

1. **先搞懂 `scanf` 的返回值是什么。** `scanf` 返回的是"成功读到并转换了几项"，不是读到的值本身。这份文件里两次都写成 `if (scanf(...) != 1) { ... return 1; }`，意思是"如果连一项都没读成功，就打印错误信息并结束程序"。对比一下不检查的写法：输入 `abc` 时 `number` 会保持初始值 `0`，程序照常往下走，输出一个和输入毫无关系的 `default` 结果——**程序不崩，但结果没有意义**，这就是要做输入校验的原因。
2. **`%d` 和 `%c` 的区别要记牢。** `%d` 读的是"一串数字字符"并转换成整数，它会自动跳过前面的空格和换行；`%c` 读的是"一个字符"，**什么都不跳过**，来什么读什么。
3. **`scanf(" %c", &ch)` 里那个空格，是本文件最值得记住的一处。** 读完 `number` 之后，你按的那个回车（换行符）还留在输入缓冲区里没被取走。如果写成 `scanf("%c", &ch)`，`%c` 会把这个换行符当成你要输入的字符读走，`ch` 就变成 `'\n'`，输出变成 `读取到的字符是 '` 加一个空行。写成 `" %c"`（空格 + `%c`）之后，`scanf` 会**先跳过所有空白字符（空格、制表符、换行）再读一个字符**，于是正好读到 `B` 或 `C`。可以自己把那个空格删掉跑一次，看输出有什么变化。
4. **`switch` 是"跳转到匹配项"，不是"从头逐个判断"。** `number` 是 2，程序就直接跳到 `case 2`，`case 1` 那一段根本不会执行。这和 `if / else if` 从上往下一条条判断的方式不同，速度更快，但只适合"拿一个整数或字符去比对若干个固定值"的场合。
5. **每个 `case` 后面的 `break` 是"到此结束，跳出 `switch`"。** 这一份的四个分支（`case 1`、`case 2`、`case 3`、`default`）都写了 `break`，所以互相独立。少写一个，程序就会从匹配的那一项往下"漏"进下一项，把不该执行的内容也执行掉——那份"反面教材"就是 `22_2026-10-15_指针基础读写与switch穿透练习.c`。
6. **`default` 是"其它所有情况"的总出口。** 这里它负责两种情况：数值是 4、5、-1 这类"有值但没被列举"，也包括输入本身就不合法时的兜底显示。
7. **`char ch = '\0';` 是给字符变量一个干净的初值。** `'\0'` 是空字符，ASCII 码 0。先初始化是个好习惯：万一输入失败，变量的值也是确定的，不会打印出垃圾内容。
8. **两句 `printf` 提示文字和实际读取顺序要对应着读。** 提示是给人看的，`scanf` 才是真正在做事，读代码时以 `scanf` 为准——这就是上面提到"提示文字写错类型"这件事值得留意的原因。

## 常见易错点

- **`scanf` 里忘记写 `&`。** 写成 `scanf("%d", number)` 编译会直接报错或警告，而写成 `scanf("%c", &ch)` 少一个 `&` 甚至可能在运行时崩溃。读整数、字符都要用 `&number`、`&ch` 传地址。
- **`%c` 前面漏掉空格。** 最典型的现象是"我明明输入了 B，程序却说读到的是空字符"。原因就是上一次输入的换行符被 `%c` 读走了。
- **在 `%d` 的位置输入字母。** `scanf("%d", ...)` 读不到整数会返回 0，这份文件的设计是直接打印 `输入错误，程序退出。` 然后 `return 1`。这是**有意**的处理方式：宁可干净地退出，也不要带着错误的数值继续算。
- **`switch` 的 `case` 后面忘了 `break`。** 见上面第 5 条，对照 22 号文件。
- **`case` 后面写了浮点数。** `case 1.5:` 这样的写法无法通过编译。`switch` 只能拿**整数或字符**去比对常量分支，和小数、字符串都不搭。
- **`switch (number);` 多了一个分号。** `switch` 的小括号后面跟的是 `{`，写成 `);` 会让后面那段 `{...}` 变成一个和 `switch` 无关的语句块，所有 `case` 都会变成普通标号，逻辑全乱。
- **以为 `default` 必须写在最后。** 语法上它可以写在任何位置，但写在最后是大家约定俗成的习惯，可读性最好。
- **`printf` 里的单引号被当成格式符。** 例如把 `"读取到的字符是 '%c'\n"` 误写成 `"读取到的字符是 %c\n"`，输出里就没有那对引号了——它们只是普通字符，删不掉也跑不了。

## 可以继续尝试

1. **把第一句提示文字改对。** 把 `printf("请输入一个字符用于（switch分支演示）：");` 改成 `printf("请输入一个整数（switch分支演示）：");`，让提示和实际读取的类型对上。这是本文件最值得亲手改的一处。
2. **把 `switch` 改写成 `if / else if` 版本**，`default` 的部分改成最后的 `else`，然后对照两种写法的可读性：分支少的时候用 `if` 更灵活，分支多且都是固定值的时候 `switch` 更整齐。
3. **故意删掉一个 `break` 再跑一次**，比如删掉 `case 1` 后面的 `break`，输入 `1` 观察输出变成了几行、为什么。再回头读 `22` 号文件，就能把"穿透"这件事彻底理解。
4. **把 `switch` 从"比对整数"改成"比对字符"**：把判断对象换成 `ch`，分支写成 `case 'A':`、`case 'B':`，练习"字符在 `switch` 里可以直接当整数用"。
5. **加一层循环，让它能连续玩。** 用 `while (1)` 把三段包起来，输入 `0` 时用 `break` 退出程序。这是 `08_2026-10-05_菜单式计算器.c` 里已经用过的结构，正好复习一遍。
6. **给 `default` 加一条"重新输入"的路。** 输入不合法时不退出，而是提示"请输入 1、2 或 3"再读一次，可以参照 `13_2026-10-10_数组输入校验与成绩统计.c` 里处理非法输入回退的思路。
7. **两份一起读：** 先跑 `22_2026-10-15_指针基础读写与switch穿透练习.c` 看漏写 `break` 的后果，再跑这一份看规范写法，然后在自己的笔记里写下"什么时候必须写 `break`"。
