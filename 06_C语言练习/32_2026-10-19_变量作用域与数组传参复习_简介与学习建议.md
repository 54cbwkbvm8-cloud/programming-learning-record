# C 语言 10 月 19 日变量作用域与数组传参复习：文件简介与学习建议

## 文件简介

- **源码文件：** `32_2026-10-19_变量作用域与数组传参复习.c`
- **类型：** C 语言变量作用域、指针与数组传参综合复习。
- **功能：** 通过三个函数和 `main` 演示块作用域中的同名变量、指针访问数组中间元素，以及数组传给函数后 `sizeof` 结果发生变化的现象。
- **主要知识点：** 代码块与变量作用域、变量遮蔽、数组名转指针、指针偏移、`sizeof`、函数形参数组退化、`size_t` 与 `%zu`。

程序不需要输入。它没有修改数组内容，重点是观察同名变量和 `sizeof` 在不同位置的含义。

## 三个核心现象

### 1. 内层代码块可以定义同名变量

```c
int x = 1;
{
    int x = 2;
    printf("%d ", x);
}
printf("%d\n", x);
```

内层块里的 `x` 会暂时遮蔽外层的 `x`，所以先输出 `2`。离开花括号后，内层变量结束生命周期，最后输出外层原来的 `1`。

这里不是“修改了外层的 `1`”，而是两个作用域中的两个变量恰好同名。

### 2. `p = a + 2` 指向的是 `a[2]`

```c
int a[5] = {10, 20, 30, 40, 50};
int *p = a + 2;
```

数组中 `a[2]` 的值是 `30`，前一个元素是 `20`，因此：

- `*p` 输出 `30`；
- `*(p - 1)` 输出 `20`；
- `p[0] + *(p - 1)` 等于 `30 + 20 = 50`。

### 3. 数组传给函数后，形参 `a` 已经是指针

函数定义是：

```c
void show_array_parameter_size(int *a, size_t length)
```

虽然参数名叫 `a`，但它的真实类型是 `int *`。因此函数中的 `sizeof(a)` 量到的是一个指针的大小，不是 `main` 里整个数组的大小。

在本机 64 位环境实测：

| 位置或表达式 | 结果 | 含义 |
| --- | --- | --- |
| `main` 中的 `sizeof(a)` | `20` 字节 | 5 个 `int`，每个 4 字节 |
| `main` 中的 `sizeof(a[0])` | `4` 字节 | 一个 `int` 的大小 |
| `main` 中的 `sizeof(a) / sizeof(a[0])` | `5` | 真实元素个数 |
| 函数中的 `sizeof(a)` | `8` 字节 | 一个指针的大小 |
| 函数中的 `sizeof(a[0])` | `4` 字节 | 一个 `int` 的大小 |
| 函数中的 `sizeof(a) / sizeof(a[0])` | `2` | 指针字节数除以元素字节数，不能代表数组长度 |

所以程序把函数中的结果明确标成“错误结果”。函数若要知道真实元素个数，必须像本例一样额外接收 `length` 参数。

指针大小取决于运行环境。当前 64 位环境是 8 字节，32 位环境可能是 4 字节；真正稳定不变的是函数形参已经变成指针，不能用 `sizeof` 还原原数组长度。

## 零基础学习建议

1. **用生命周期理解花括号。** 变量从定义处开始有效，到所在代码块结束时失效。内层同名变量只在内层花括号里生效。
2. **先手算指针题。** 在数组下面画 `p` 的箭头，分别标出 `p - 1`、`p`、`p + 1`，不要先看运行结果。
3. **把“声明类型”当成判断依据。** `int a[5]` 是数组；`int *a` 是指针。函数参数写成 `int *a` 或 `int a[]` 时，进入函数后都不能再靠 `sizeof(a)` 得到原数组字节数。
4. **区分 `sizeof` 有没有看见完整数组。** 在 `main` 里数组定义仍然可见，所以能算出 `20 / 4 = 5`；进入函数后只收到首元素地址，表达式因此变成 `8 / 4 = 2`。
5. **记住“数组 + 长度”这一对参数。** 只要函数需要遍历数组，就同时传入首元素地址和元素个数，不依靠函数里的 `sizeof` 猜测长度。
6. **认识 `size_t` 和 `%zu`。** `sizeof` 的结果类型是 `size_t`，使用同类型的变量和 `%zu` 输出，可以避免类型和格式符不匹配。
7. **达到能讲清错因的程度。** 合上程序后，能解释为什么内层 `x` 不影响外层 `x`、为什么 `*(p - 1)` 是 `20`，以及为什么函数里算出 `2` 不等于数组只有两个元素。

## 常见易错点

- 认为内层 `x = 2` 改写了外层 `x = 1`，忽略了它们是两个作用域中的同名变量。
- 把 `p = a + 2` 误认为让 `p` 指向数组的首地址。它实际指向 `a[2]`。
- 在函数里写 `sizeof(a) / sizeof(a[0])` 求数组长度。这里第一个 `a` 已经是指针。
- 把本机得到的 `8` 当成所有机器都固定不变。64 位平台常见指针大小是 8 字节，但应以实际环境为准。
- 以为加 `const` 后 `sizeof` 就会恢复成数组大小。`const int *` 仍然是指针。
- 用 `%d` 输出 `sizeof` 或 `size_t` 结果。应使用对应的 `%zu`。
- 只把数组地址传进函数，却在函数内声称知道真实长度。没有额外长度信息时，函数无法可靠遍历整个数组。

## 可以继续尝试

1. 把 `main` 中的数组改为 8 个元素，同时修改传入长度，观察 `sizeof` 比值和真实长度怎样变化。
2. 写两个函数版本：一个只接收 `int *a`，一个接收 `int *a, size_t length`；用 `for` 循环证明第二个版本才能安全遍历全部元素。
3. 把 `show_array_parameter_size` 的形参改成 `int a[]`，重新打印 `sizeof(a)`，确认它仍然只是指针大小。
4. 增加一个全局变量和局部变量同名的例子，与代码块遮蔽现象对照，并说明为什么现阶段应尽量避免不必要的全局变量。
