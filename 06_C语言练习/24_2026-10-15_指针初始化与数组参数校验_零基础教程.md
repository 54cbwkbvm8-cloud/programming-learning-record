## 一、最终要完成什么

程序分两部分，**不需要输入任何数据**，运行完就直接结束。

1. **指针初始化演示**：先声明一个不指向任何变量的空指针 `p = NULL`，再让它指向 `number`，最后用 `*p` 把 `number` 里的值读出来。
2. **数组参数与长度演示**：先算出数组里有多少个元素，再分三次调用 `print_array`，分别测试**正常数据**、**长度为 0**、**空指针**这三种情况。

完整运行过程是这样的：

```text
一、指针初始化演示
p 初始化为 NULL，此时不解引用。
p 现在保存 number 的地址。
number = 42
*p = 42

二、数组参数与长度演示
调用函数前计算得到的数组长度：4
数组元素：10, 20, 30, 40
数组长度为 0 或小于 0，没有可打印的元素。
错误：数组指针为空，不能访问数组。
```

`main` 函数的流程：

```text
开始
  |
声明 number = 42
  |
声明空指针 p = NULL
  |
让 p 指向 number（p = &number）
  |
分别用 number 和 *p 把同一个数打印一遍
  |
定义数组 numbers = {10, 20, 30, 40}
  |
算出元素个数 length = 4
  |
print_array(numbers, length)   → 打印 4 个元素
  |
print_array(numbers, 0)        → 提示长度不合法，立即返回
  |
print_array(NULL, 3)           → 提示指针为空，立即返回
  |
结束
```

## 二、开始前要认识的基本符号

| 写法 | 读作 | 含义 |
| --- | --- | --- |
| `int *p` | 声明一个指针 | `p` 专门用来保存"一个 `int` 的地址" |
| `&number` | 取地址 | `number` 住在内存的哪个位置，结果是一个地址 |
| `*p` | 解引用 | `p` 指的那个格子里的值，结果是一个 `int` |
| `NULL` | 空指针 | 明确表示"这个指针现在不指向任何变量" |
| `arr[i]` | 下标访问 | 完全等价于 `*(arr + i)` |
| `sizeof(a)` | 求占用字节数 | `int` 占 4 字节，所以 4 个 `int` 的数组是 16 字节 |

一句话记住 `&` 和 `*` 的关系：**`&` 是"从变量拿到地址"，`*` 是"从地址拿回变量"**，两者方向正好相反。

## 三、完整代码

```c
#include <stdio.h> // 引入标准输入输出库，让程序可以使用 printf() 输出文字和数据。

void print_array(const int arr[],
                 int length) { // 定义数组打印函数：arr 接收首元素地址，length 接收元素个数。
    if (arr == NULL) {         // 先检查传入的指针是否为空；空指针不指向可访问的数组元素。
        printf("错误：数组指针为空，不能访问数组。\n"); // 告诉调用者当前没有可访问的数组地址。
        return; // 立即结束本次函数调用，避免继续读取 arr[i]。
    } // 结束空指针检查分支。

    if (length <= 0) { // 检查长度是否为 0 或负数，防止循环没有意义地执行或使用无效长度。
        printf("数组长度为 0 或小于 0，没有可打印的元素。\n"); // 说明数组当前没有可遍历的元素。
        return;                                                // 结束函数，不进入数组遍历循环。
    } // 结束长度检查分支。

    printf("数组元素：");              // 先输出提示文字，随后输出数组中的各个元素。
    for (int i = 0; i < length; i++) { // 从下标 0 开始，每次加 1，直到 i 等于 length 时停止。
        printf("%d", arr[i]); // 读取下标为 i 的整数元素并输出；arr[i] 等价于通过指针访问对应元素。
        if (i < length - 1) { // 如果当前元素不是最后一个元素，就需要在后面输出分隔符。
            printf(", ");     // 在相邻元素之间输出逗号和空格，使结果更易阅读。
        } // 结束分隔符判断。
    } // 结束数组遍历循环。
    printf("\n"); // 所有元素输出完成后换行，让下一次输出从新的一行开始。
} // 结束 print_array() 函数定义。

int main(void) {     // 主函数是程序运行的入口；void 表示这里不接收命令行参数。
    int number = 42; // 定义整数变量 number，并初始化为 42，后面让指针指向它。
    int *p = NULL;   // 定义指向 int 的指针 p，并初始化为空指针；此时不能使用 *p 读取整数。
    printf("一、指针初始化演示\n");              // 输出第一部分标题。
    printf("p 初始化为 NULL，此时不解引用。\n"); // 强调空指针只是表示当前没有可用目标地址。

    p = &number; // 使用取地址符 & 获取 number 的地址，并把这个有效地址存入 p。
    printf("p 现在保存 number 的地址。\n"); // 说明 p 已经指向一个真实存在的整数变量。
    printf("number = %d\n", number);        // 使用 %d 输出 number 中保存的整数值。
    printf("*p = %d\n", *p); // 使用解引用运算符 * 访问 p 指向的对象，因此这里输出 42。

    int numbers[] = {10, 20, 30, 40}; // 定义含有 4 个整数的数组，并用 10、20、30、40 初始化。
    int length =
        (int)(sizeof(numbers) /
              sizeof(
                  numbers
                      [0])); // 在数组仍是完整数组的这里，用总字节数除以单个元素字节数得到元素个数。
    printf("\n二、数组参数与长度演示\n");                 // 输出第二部分标题。
    printf("调用函数前计算得到的数组长度：%d\n", length); // 展示计算出的元素个数，当前应为 4。
    print_array(numbers, length); // 传入数组首元素地址和元素个数，让函数知道应该读取多少个元素。
    print_array(numbers, 0);      // 测试长度为 0 的边界情况；函数应提示没有可打印元素。
    print_array(NULL, 3);         // 测试空指针防护；函数应报出提示后返回，而不会访问数组元素。

    return 0; // 向操作系统返回 0，通常表示程序正常结束。
} // 结束 main() 函数定义。
```

## 四、逐行讲解

### 第 1 行

```c
#include <stdio.h>
```

把标准输入输出库引进来，后面才能用 `printf`。`#include` 开头带 `#` 的行叫**预处理指令**，结尾**不写分号**，这是初学者最容易多写一个分号的地方。

### 第 3 行和第 4 行

```c
void print_array(const int arr[],
                 int length) {
```

定义一个叫 `print_array` 的函数，作用是"打印一个整数数组"。分成三部分看：

- `void`：函数**没有返回值**，只负责打印，不往调用处送回结果。
- `const int arr[]`：第一个参数。写法像数组，但**实际上它是一个指针**，接收的是数组首元素的地址。前面的 `const` 是一个承诺："我不会通过 `arr` 修改数组里的内容"。
- `int length`：第二个参数，元素个数。**必须由调用者另外传进来**，因为函数里拿到的只是一个地址，地址本身不带"数组有多长"这个信息。

写成两行只是为了让参数不挤在一行里，C 语言对换行不敏感，下面这一行写法和它完全等价：

```c
void print_array(const int arr[], int length) {
```

### 第 5 行

```c
if (arr == NULL) {
```

函数进门做的第一件事：**检查传进来的指针是不是空的**。

`arr == NULL` 只是"比较两个地址是否相等"，不会去访问任何内存，所以这一步是安全的。真正危险的是 `arr[0]`、`*arr` 这种"顺着地址去读内容"的动作——如果地址是 `NULL`，程序会被操作系统直接杀掉（段错误）。

### 第 6 行和第 7 行

```c
printf("错误：数组指针为空，不能访问数组。\n");
return;
```

`printf` 打印一行提示，`return;` 立刻结束整个 `print_array` 函数，后面的代码一行都不会再执行。

**第 7 行的 `return;` 就是这份教程的核心。** 只看第 6 行"打印了错误提示"，很容易以为函数已经处理好了，但如果没有第 7 行，程序会继续往下走：跳过第 10 行的长度检查（因为 `length` 是 3，不小于等于 0），然后执行到第 17 行的 `arr[i]`，拿着 `NULL` 去取数组元素，当场崩溃。`23` 号练习版缺的正是这一行。

### 第 8 行

```c
} // 结束空指针检查分支。
```

第一道检查的右大括号，把第 5 行到第 8 行配成一个完整的 `if` 块。

### 第 10 行

```c
if (length <= 0) {
```

第二道检查：**元素个数是否合法**。长度为 0 时循环一次都不会执行，打印一个空行没有意义；长度为负数时更严重，循环条件 `i < length` 会直接判假，但语义上已经是错误的数据了。所以这两种情况都拦掉。

注意这里写的是 `<=` 而不是 `<`：长度等于 0 **也**要拦。

### 第 11 行和第 12 行

```c
printf("数组长度为 0 或小于 0，没有可打印的元素。\n");
return;
```

和第一道检查完全一样的套路：先提示，再 `return;`。**两道检查的写法必须对称**，这是本程序最值得模仿的地方。

### 第 13 行和第 14 行

```c
} // 结束长度检查分支。
```

第二道检查结束。第 14 行是空行，把"参数检查"和"正式干活"在视觉上隔开，读起来更清楚。

### 第 15 行

```c
printf("数组元素：");
```

走到这里说明两个参数都合法，可以放心打印了。这一行先输出提示文字，**结尾故意没有 `\n`**，因为数组元素要紧跟在冒号后面输出，同一行显示。

### 第 16 行

```c
for (int i = 0; i < length; i++) {
```

标准的 `for` 三段式循环：

- `int i = 0`：从下标 0 开始（数组第一个元素的下标是 0，不是 1）。
- `i < length`：只要下标还没到 `length` 就继续，所以最后一个下标是 `length - 1`。写 `i <= length` 就**越界**了。
- `i++`：每轮结束把 `i` 加 1。

### 第 17 行

```c
printf("%d", arr[i]);
```

读取下标为 `i` 的元素并打印。`arr[i]` 和 `*(arr + i)` 是同一件事的两种写法。

对比一下 `23` 号练习版：那里写的是 `printf("%d ", arr[i])`——**数字后面带了一个空格**，然后第 19 行才输出逗号，于是打出来是 `10 ,20,` 这样逗号前多一个空格。本文件把空格从数字后面挪到了逗号后面，输出就是干净的 `10, 20, 30, 40`。**这是"输出格式由 `printf` 的字符串一字一字决定"的最直观例子。**

### 第 18 行和第 19 行

```c
if (i < length - 1) {
    printf(", ");
}
```

逗号分隔符只加在**相邻两个元素之间**，最后一个元素后面不加。

判断条件是 `i < length - 1`，也就是"只要我还没走到最后一个下标"。如果写成 `i < length`，那么最后一个元素后面也会多出一个逗号（`10, 20, 30, 40,`），虽然不影响程序运行，但不够整洁。

这是一个很常见的"**最后一个元素特殊处理**"套路，后面写输出、写 JSON、写 CSV 都会用到。

### 第 20 行和第 21 行

```c
    }
}
```

两个右大括号：前一个结束第 18 行的 `if`，后一个结束第 16 行的 `for`。**数大括号的时候看缩进**，`for` 的 `}` 应该和 `for` 的缩进位置对齐。

### 第 22 行

```c
printf("\n");
```

所有元素打印完之后补一个换行，让下一次输出从新的一行开始。没有这一行，第二部分的两条提示就会和 `10, 20, 30, 40` 挤在同一行。

### 第 23 行

```c
} // 结束 print_array() 函数定义。
```

函数结束。到这里为止，从第 3 行开始的 `print_array` 全部定义完毕。

### 第 25 行

```c
int main(void) {
```

`main` 是程序的入口，操作系统运行程序时**从 `main` 的第一行开始执行**（前面定义的 `print_array` 只是"备用工具"，没人调用就不会运行）。

`(void)` 表示这个程序不接收命令行参数。

### 第 26 行

```c
int number = 42;
```

定义一个 `int` 变量 `number`，初始值是 42。它会在内存里占据一个 4 字节的格子。

### 第 27 行

```c
int *p = NULL;
```

定义一个**指针** `p`，并把它的初值设成 `NULL`。

指针本身也是一个变量，只不过程它装的不是数字，而是"另一个变量的地址"。为什么要先给它 `NULL`？因为如果写成 `int *p;` 而不初始化，`p` 里就是一段随机残留的垃圾数据，指向哪里完全不知道，这叫**野指针**，非常危险。**先给 `NULL`，等于先明确地告诉程序"它现在什么都没有指向"。**

### 第 28 行和第 29 行

```c
printf("一、指针初始化演示\n");
printf("p 初始化为 NULL，此时不解引用。\n");
```

两行提示文字。重点是第 29 行讲的那条规则：**`p` 是 `NULL` 的时候，不能写 `*p`**。原因在下一行就说清了。

### 第 31 行

```c
p = &number;
```

整份代码里最关键的一行。`&number` 取出 `number` 的地址，然后把这个地址存进 `p`。执行完这一行，`p` 就**指向**了 `number`。

内存里发生的事可以这样画：

```text
        变量 number           指针 p
      +---------------+     +---------------+
      |      42       | <--- |  number 的地址 |
      +---------------+     +---------------+
                ^
                |
          &number 得到的就是这个地址
```

注意 `p` 里装的**不是 42**，而是"42 住的那个格子的门牌号"。

### 第 32 行到第 34 行

```c
printf("p 现在保存 number 的地址。\n");
printf("number = %d\n", number);
printf("*p = %d\n", *p);
```

第 33 行和第 34 行**打印出来的都是 42**，这是本程序想让你亲眼看到的结论：

- `number` 是"直接说出变量名拿值"。
- `*p` 是"通过地址绕一圈拿值"（`*` 就是解引用运算符）。

两条路走的是**同一块内存**，所以值一样。既然指向同一块内存，通过 `*p = 20;` 就能改掉 `number`——这正是 `22_2026-10-15_指针基础读写与switch穿透练习.c` 演示的内容。

### 第 36 行

```c
int numbers[] = {10, 20, 30, 40};
```

定义一个数组，4 个元素。这里**没有写数组长度**，因为初始化列表里给了 4 个数，编译器会自动把长度定成 4。

### 第 37 行到第 41 行

```c
int length =
    (int)(sizeof(numbers) /
          sizeof(numbers[0]));
```

算元素个数，这是 C 语言里最通用的一套写法。它是被格式化工具折成了几行，其实等价于一行：

```c
int length = (int)(sizeof(numbers) / sizeof(numbers[0]));
```

拆开看三段：

- `sizeof(numbers)` = 整个数组占的字节数 = 4 个 `int` × 4 字节 = **16**。
- `sizeof(numbers[0])` = 单个元素占的字节数 = **4**。
- `16 / 4 = 4`，于是 `length` 等于 **4**。

为什么要写成 `sizeof(numbers[0])` 而不是直接写 `sizeof(int)`？因为前者**换了元素类型也照样正确**：把 `int` 改成 `double`，`sizeof(numbers)` 变成 32、`sizeof(numbers[0])` 变成 8，相除仍然是 4。这种"用类型自己算自己"的写法更不容易出错。

外面那层 `(int)` 是**强制类型转换**：`sizeof` 的结果类型是 `size_t`（无符号整数），转成 `int` 之后和下一行的 `%d` 格式符完全匹配。

**关键提醒：这套写法只在数组变量本身看得见的地方有效。** 一旦进了函数，`sizeof(arr)` 就变成指针的大小 8 了，所以长度必须像第 44 行那样，从外面传进去。

### 第 42 行

```c
printf("\n二、数组参数与长度演示\n");
```

输出第二部分标题。开头的 `\n` 是**先空一行**，把第一部分和第二部分在屏幕上隔开。

### 第 43 行

```c
printf("调用函数前计算得到的数组长度：%d\n", length);
```

先把算出来的长度打印出来（应当显示 4），这样后面三次调用的效果才有参照。

### 第 44 行

```c
print_array(numbers, length);
```

**这是唯一一次"正确"的调用**，也是 `23` 号练习版里缺的一次。传进去两个东西：`numbers`（数组名，传到函数里就变成首元素地址）和 `length`（4）。效果是打印出 `数组元素：10, 20, 30, 40`。

要特别注意：数组名 `numbers` 写在这里**不用加 `&`**。数组名本身在大多数场合会自动"退化"成指向首元素的指针，这是数组和普通变量最容易混的一处。

### 第 45 行

```c
print_array(numbers, 0);
```

第二次调用，故意把长度传成 **0**，用来测试第 10 行那道长度检查。预期结果是打印 `数组长度为 0 或小于 0，没有可打印的元素。` 之后正常返回，**不打印任何元素**。

这就是**边界测试**：不只测正常数据，还要专门去试探最边上、最不合理的那几种输入。

### 第 46 行

```c
print_array(NULL, 3);
```

第三次调用，故意把指针传成 **`NULL`**，用来测试第 5 行那道空指针检查。

注意这里的 `3`：它**故意不是 0**。如果写成 `print_array(NULL, 0)`，第 10 行的长度检查会先成立并 `return`，那道漏掉 `return;` 的空指针检查就被掩盖过去了，程序照样不崩。写成 `3`，第二道检查不成立，程序才会真的走到 `arr[i]` 上——`23` 号练习版就是这样暴露问题的。

**这是本程序最值得记住的一条测试经验：用一组组合去测，坏数据的漏洞会被另一组坏数据挡住。**

### 第 48 行和第 49 行

```c
return 0;
}
```

`main` 的 `return 0;` 是向操作系统汇报"程序正常结束"。在终端里可以用 `echo $?` 查看这个返回值：正常结束是 `0`，段错误是 `139`（macOS 上直接显示 `139` 或 `Segmentation fault: 11`）。

## 五、怎样编译和运行

## 八、常见错误

### 1. 校验时只打印提示，忘了 `return;`

最高频的一个。判断方法：盯着校验块问一句"这句话执行完，函数还会不会往下走？"——如果会，校验就是假的。

### 2. 用了 `NULL` 却还去解引用

```c
int *p = NULL;
printf("%d\n", *p);   // 崩溃
```

`NULL` 是"不指向任何东西"的标记，**任何**顺着它去读写的动作都会崩溃。正确顺序永远是"先比较，再访问"。

### 3. 在函数里用 `sizeof(arr)` 求数组长度

实测结果（本机 64 位）：

```text
main 里 sizeof(a)=16          ← 4 个 int，16 字节
函数里 sizeof(arr)=8          ← 只剩指针的大小
```

编译器还会额外给一条警告：`sizeof on array function parameter will return size of 'const int *' instead of 'const int[]'`。这正是**长度必须当参数传**的原因，也是 `23`、`24` 两个文件都带 `length` 参数的原因。

### 4. `p = number;` 少写了 `&`

```
error: incompatible integer to pointer conversion assigning to 'int *' from 'int';
       take the address with &
```

`number` 是 `int`（值是 42），`&number` 才是 `int *`（地址）。类型对不上，编译器会直接报错，并且很贴心地提示你补 `&`。**看到 `take the address with &` 就知道该加 `&` 了。**

### 5. `if` 不加大括号，`return;` 跑到 `if` 外面去了

```c
if (arr == NULL)
    printf("错误：数组指针为空。\n");
    return;          // ← 缩进像在 if 里，其实已经出去了！
```

这样写，`return;` 会**无条件执行**，函数永远在第 3 行就返回。缩进会骗人，所以 `if` 一律加大括号。本文件第 5 行到第 8 行就是标准写法。

### 6. 用 `%d` 打印指针

```c
printf("%d\n", p);   // 警告：format specifies type 'int' but the argument has type 'int *'
```

打印指针要用 `%p`，而且严格来说应该先转成 `void *`：

```c
printf("%p\n", (void *)p);
```

### 7. 循环条件写成 `i <= length`

最后一个合法下标是 `length - 1`，写 `<=` 就越界读了下标 `length` 的位置。C 语言**不会**替你检查边界，也不一定报错，读到的可能是随机内容。第 16 行的 `i < length` 才是对的。

### 8. 用旧的可执行文件测试

改完 `.c` 文件却直接运行之前编译出来的程序，结果当然还是旧的。**每次改完都要重新编译**，这就是第 5 节里把编译和运行用 `&&` 串成一条命令的原因。

## 九、你可以继续做的练习

1. **亲手制造一次崩溃。** 把第 7 行的 `return;` 注释掉，重新编译运行，观察退出码从 `0` 变成 `11`。再把它加回去。这一步做完，这条规则基本就忘不掉了。
2. **再补一组边界测试。** 在 `main` 里加 `print_array(numbers, -1);`，确认长度检查用的是 `<=` 而不是 `<`——负数也能被拦住。
3. **交换两道检查的顺序。** 把空指针检查挪到长度检查后面，用 `print_array(NULL, 0)` 试一次，看看哪一道检查先拦住它。这能让你体会"检查顺序会影响结果"。
4. **让函数报告结果。** 把 `void` 改成 `int`：正常打印返回打印的元素个数，`arr` 为空返回 `-1`，长度不合法返回 `0`。`main` 里把返回值接住并打印出来。这是 C 语言里最常见的错误上报方式。
5. **打印指针的两个状态。** 在第 31 行前后各加一句 `printf("p = %p\n", (void *)p);`，对比 `NULL`（通常显示 `0x0`）和真实地址的差别。
6. **写一个求最大值的函数。** `const int *find_max(const int *arr, int length)`，返回最大元素的**地址**。提示：先让 `max` 指向 `arr[0]`，再遍历比较 `if (arr[i] > *max) max = &arr[i];`。
7. **把长度改大试试越界。** 临时把第 44 行改成 `print_array(numbers, 8);`，观察程序打印出 4 个正常数字加 4 个乱七八糟的数字。这个实验只在本地做，做完记得改回来——它说明**参数校验只能挡住明显的错误，挡不住"长度写大了"这种错误**。
8. **把分隔符去掉。** 删掉第 18 行到第 20 行，重新运行，对比 `10, 20, 30, 40` 和 `10203040` 的差别，再想清楚"最后一个元素不加逗号"这个判断该写在哪里。
