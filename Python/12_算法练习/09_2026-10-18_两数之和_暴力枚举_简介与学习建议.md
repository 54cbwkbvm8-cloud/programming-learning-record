# Python 10 月 18 日两数之和两种解法：文件简介与学习建议

## 文件简介

- **源码文件：**
  - `09_2026-10-18_两数之和_暴力枚举.py`
  - `10_2026-10-18_两数之和_哈希表优化.py`
- **类型：** Python 列表、循环和字典综合练习，同一道“两数之和”题目的两种解法。
- **功能：** 在整数列表 `nums` 中寻找两个不同下标 `i`、`j`，使 `nums[i] + nums[j] == target`，返回 `[i, j]`；没有答案时返回 `None`。
- **示例数据：** `nums = [2, 7, 11, 15]`，`target = 9`。
- **主要知识点：** 函数定义、`for` 循环、嵌套循环、列表下标、字典查找、`if __name__ == '__main__'`。

两份程序解决的是同一个问题，区别在寻找答案的方法：

| 文件 | 方法 | 思路 | 时间复杂度 |
| --- | --- | --- | --- |
| `09_..._暴力枚举.py` | 双层循环 | 把所有下标组合都试一遍 | `O(n²)` |
| `10_..._哈希表优化.py` | 字典查补数 | 记录见过的数字，直接查 `target - current` | `O(n)`（平均情况） |

Python 的 `dict` 使用哈希表保存键值对，所以第二份程序通过空间换时间，把重复遍历列表的过程省掉了。

## 零基础学习建议

1. **先读暴力枚举版。** 外层 `i` 固定一个数，内层 `j` 从 `i + 1` 开始，保证同一对下标不会被重复检查，也保证不会把同一个元素用两次。
2. **用一句人话解释内层循环。** 对每个 `nums[i]`，逐个检查它后面的数字 `nums[j]`，看看两者相加是否为 `target`。
3. **再读哈希表优化版。** 对当前数字 `current`，需要的搭档是 `need = target - current`。如果 `need` 以前出现过，当前数字和它就能组成答案。
4. **看清代码顺序。** 程序先查 `need`，再把 `current` 放进 `seen`。如果先保存再查，当 `need == current` 时可能误用当前下标两次。
5. **把字典想成“数字到下标”的登记表。** `seen[current] = i` 保存的是这个数字最近一次出现的下标；重复值会覆盖旧位置，所以当前算法返回任意一组合法答案，不保证是最早配对。`need in seen` 是在问“搭档以前来过吗”。
6. **亲手比较循环次数。** 给列表加入更多元素，或在两个函数里统计循环执行次数，就能看到 `O(n²)` 和 `O(n)` 的差别。现阶段不必背复杂度符号，但要理解“规模变大后谁增长更快”。

## 常见易错点

- 内层写成 `for j in range(len(nums))`，会检查重复组合，还可能让同一个下标和自己配对。
- 哈希版先执行 `seen[current] = i` 再检查 `need`，两个相同数字可能共用同一个下标。
- 把答案写成数字 `[nums[i], nums[j]]`，而题目要求的是下标 `[i, j]`。
- 没有找到答案时，暴力版执行到函数末尾会自然返回 `None`；虽然不报错，但最好能说出这是 Python 的隐式返回值规则。
- 题目默认只有一组答案。如果列表里可能有多组答案，当前函数只会返回算法遍历中先遇到的一组，不保证是原始下标字典序最小的一组。
- 哈希版用数字作为键，保存的是这个数字最近一次出现的下标。遇到重复值时会覆盖旧下标，因此仍返回合法数对，但不保证返回最早配对。
