## 程序功能说明

### 核心函数

```python
def two_sum(nums,target):
    num_to_index = {}
    for index,num in enumerate(nums):
        complement = target - num
        if complement in num_to_index:
            return [num_to_index[complement],index]
        num_to_index[num] = index
    return[]
```

对每个当前数字：

1. `enumerate` 同时给出下标 `index` 和数字 `num`。
2. 计算还差多少才能凑成目标和：`complement = target - num`。
3. 检查补数以前是否已经出现。
4. 如果出现，返回补数的旧下标和当前下标。
5. 如果没有出现，保存“当前数字 → 当前下标”。
6. 所有数字检查完仍无答案，返回空列表 `[]`。

查找补数必须在保存当前数字之前。否则当补数等于当前数字时，可能把同一个下标使用两次。

### 返回值类型

找到时返回列表：

```python
[i, j]
```

没找到时返回：

```python
[]
```

这和 10、11 号不同，它们没找到时返回 `None`。因此不能直接用旧测试的 `actual == None` 判断本文件。使用方必须先明确接口约定：

- 返回 `None`：明确表示“没有结果对象”。
- 返回 `[]`：属于列表类型，但需要再用 `len(result) == 0` 判断。

两种设计都能工作，但同一项目中的多个版本最好统一，否则调用者容易写错判断。

### `run_test` 的作用

```python
def run_test(nums,target):
    result = two_sum(nums,target)
    ...
```

它负责：

1. 调用 `two_sum`。
2. 返回两个下标时，打印下标和对应数值。
3. 返回空列表时，打印“没有找到”。
4. 输出分隔线，方便多组数据阅读。

`run_test` 目前没有返回结果，只负责打印，因此它属于展示函数，而不是测试断言函数。与 11 号的 `run_tests` 不同，它不会自动判断预期答案是否正确。

### 主流程必须接入展示函数

当前 `main` 中写的是：

```python
for nums,target in test_case:
    run_test(nums,target)
```

因此每组数据都会进入展示函数并产生输出。

同类代码的常见错误是只写：

```python
two_sum(nums,target)
```

这样做虽然会计算答案，却把返回值丢掉，程序不会报错，也不会显示结果。当前版本已经正确调用了 `run_test`，不存在这个调用错误。学习时应把“算法能够返回正确答案”和“主流程把答案交给展示函数”当作两个独立检查点。

## 学习重点

1. **理解 `enumerate`。** 它同时提供下标和值，省去 `current = nums[index]`。
2. **理解补数。** 当前数字需要的搭档是 `target - num`。
3. **理解先查后存。** 先检查补数是否出现，再记录当前数字。
4. **理解返回接口。** 找到返回两个位置，没找到返回空列表。
5. **理解函数和调用。** 函数写得正确，还必须由主流程调用，并正确使用返回值。
6. **理解打印函数与测试函数。** `run_test` 只打印结果；11 号的测试函数还会比较预期并抛错。
7. **理解输出来自调用链。** 当前可见结果来自 `main → run_test → two_sum → print` 的完整调用链。
8. **理解版本差异。** `None` 与 `[]` 都是“无答案”的表示，但接口类型不同。

## 学习难点

- 把 `index` 和 `num` 的先后顺序写反。`enumerate` 默认先给下标，再给值。
- 先保存当前数字，再检查补数，导致同一个下标可能被重复使用。
- 以为 `return []` 和 `return None` 完全一样。它们在条件判断中表现相近，但类型和比较结果不同。
- 把 `run_test(nums, target)` 错写成只调用 `two_sum(nums, target)`，导致返回值被丢弃。
- 忘记 Python 只有调用函数才会执行函数体。
- 把展示函数的 `print` 当成断言；打印“没有找到”不会自动让程序失败。
- 只看函数定义，不检查 `main` 是否真正把输入交给展示函数。

## 零基础学习流程

1. **先手算 `[3, 3]`。** 第一轮保存 `3:0`，第二轮发现补数 3 已存在，返回 `[0,1]`。
2. **再手算 `[3,2,4]`。** 记录每轮字典内容和补数。
3. **单独调用 `two_sum`。** 不经过 `main`，确认五组函数结果正确。
4. **阅读 `run_test`。** 标出它先调用算法，再按返回列表长度选择输出分支。
5. **运行原文件。** 确认五组展示结果全部出现。
6. **检查调用链。** 从 `main` 追到 `run_test`，再追到 `two_sum`。
7. **制造一个小错误。** 在临时副本把 `run_test(nums,target)` 改成 `two_sum(nums,target)`，观察程序为何静默无输出。
8. **恢复调用。** 改回 `run_test(nums,target)`，确认输出恢复。
9. **比较版本。** 与 10 号比较 `enumerate` 写法，与 11 号比较测试和返回类型。
