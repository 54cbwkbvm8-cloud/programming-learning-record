## 程序功能说明

### 核心函数

```python
def two_sum(nums, target):
    seen = {}
    for current_index in range(len(nums)):
        current_num = nums[current_index]
        needed_num = target - current_num
        if needed_num in seen:
            return (seen[needed_num], current_index)
        seen[current_num] = current_index
    return None
```

对每个当前数字：

1. 计算还差多少才能得到目标和：`needed_num = target - current_num`。
2. 检查补数以前是否出现过：`needed_num in seen`。
3. 如果出现过，返回补数的旧下标和当前下标。
4. 如果没有出现，保存当前数字和它在列表中的位置。

查找补数必须发生在保存当前数字之前。这样不会把同一个下标同时当作两个答案。

### 字典保存了什么

`seen` 的键是已经见过的数字，值是这个数字最近一次出现的下标：

```python
[2, 7, 11, 15], target = 9
```

手工跟踪：

| 下标 | 当前值 | 补数 | 查找结果 | 保存后 `seen` |
| --- | --- | --- | --- | --- |
| 0 | 2 | 7 | 7 未出现 | `{2: 0}` |
| 1 | 7 | 2 | 2 已在下标 0 | 找到，返回 `(0, 1)` |

时间复杂度是平均 `O(n)`，因为每个元素大致只经历一次字典查找和一次字典写入；额外空间复杂度是 `O(n)`，因为最坏情况下要把所有数字存进字典。

### 为什么返回元组

Python 的 `(i, j)` 是元组，`[i, j]` 是列表。两者都可以按下标读取，但类型不同：

```python
answer = (0, 1)
print(answer[0])  # 0
```

元组适合表示“固定两个位置的结果”，也不会被误以为后续还需要频繁增删。若下游接口明确要求列表，可以写 `return [seen[needed_num], current_index]`，或调用后统一执行 `list(answer)`。

### 测试是怎样组织的

`test_cases` 中每一项都是：

```python
(测试名称, nums, target, expected)
```

`run_tests` 会逐项调用 `two_sum`，比较 `actual == expected`，再输出状态。任意一项失败时，`all_passed` 会变成 `False`，最后抛出：

```python
raise AssertionError("存在失败用例，请检查！⚠️⚠️⚠️")
```

这比只看一次 `[2, 7, 11, 15]` 的结果更完整，因为测试主动覆盖了空列表、无答案和重复元素等边界。

## 已验证的边界行为

本文件内置 6 组测试全部通过。此外，本次整理还对长度 `0～4`、元素取值 `-2～2` 的小数组做了穷举，检查返回值是否满足：

- 没找到时必须返回 `None`。
- 找到时两个下标必须不同。
- 两个下标对应的数字之和必须等于 `target`。

穷举中所有返回值都满足这三个条件。

但额外对比发现一个需要理解的细节：如果同一个数字重复出现，`seen[current_num] = current_index` 会覆盖旧下标，所以程序仍返回合法数对，却不保证返回“最早出现的那一对”。

例如：

```python
nums = [-2, -2, -1]
target = -3
```

程序返回：

```python
(1, 2)
```

最早配对其实是 `(0, 2)`，但两组下标的和都等于 `-3`，因此当前函数符合“返回任意一组有效答案”的常见题意。

如果需求是“返回最早出现的一对”，应先暂时保存当前数，检查完补数后再写入初始位置，即 `seen.setdefault(current_num, current_index)`；或者只在 `current_num not in seen` 时保存。修复选择必须在明确题目要求后决定，本次保留原逻辑。

## 学习重点

1. **理解补数。** 当前数字是 `current_num`，搭档必须是 `target - current_num`。
2. **理解先查后存。** 只有先查旧数字、再保存当前下标，才能保证两个答案来自不同位置。
3. **把字典看成登记表。** 键是数字，值是下标；`in` 只检查键是否存在。
4. **理解早返回。** 找到第一组合法答案就 `return`，后面的数字不再检查。
5. **理解 `None`。** 所有元素都检查完仍没有答案时，明确表示“没有结果”。
6. **理解元组和列表的区别。** 两者都能保存两个下标，但类型、表达意图和下游兼容方式不同。
7. **理解测试用例结构。** 一个列表可以同时保存输入、目标和预期结果，循环即可批量验证。
8. **理解测试通过的真正含义。** 6 个固定用例全部通过，说明这些情况正确，不等同于穷举所有输入都正确。
9. **理解重复值边界。** 当前字典会覆盖重复数字的旧下标，因此返回任意合法答案，而不是保证最早答案。

## 学习难点

- 把“下标”和“元素值”混淆。函数返回的是位置，不是 `nums[i]` 本身。
- 先保存当前数字再查补数，可能让同一个下标参与两次。
- 把 `needed_num in seen` 写成检查列表或数字，忘记字典成员检查的是键。
- 以为 `seen[current_num] = current_index` 永远保留第一次出现的下标。实际上它会覆盖。
- 以为所有测试通过就证明程序等价于“最早配对”。当前程序没有保证这一点。
- 比较结果时忽略元组和列表的类型差异，导致下游断言 `actual == expected` 失败。
- 修改 `test_cases` 时字段顺序写错，或忘记更新预期值。
- 任意一个失败用例后没有把 `all_passed` 设为 `False`，测试会错误地打印全部通过。
- 把 `AssertionError` 当成程序崩溃。这里的异常是主动报告测试失败，便于命令行或持续集成发现错误。

## 零基础学习流程

1. **先手算基础案例。** 对 `[2, 7, 11, 15]` 和 `target = 9` 写出每一轮 `current_num`、`needed_num`、`seen`。
2. **把自己当成字典。** 每读一个数字，先问“补数以前来过吗”，再登记“当前数字在哪里”。
3. **单独运行程序。** 先只看 6 行测试结果，确认每行“期望”和“实际”相等。
4. **改变一个期望值。** 在临时副本中把某个预期下标改错，观察 `AssertionError`，理解断言的作用。
5. **只改一组数据。** 把基础配对中的 `target` 改成 `18`，预测新的结果，再运行验证。
6. **专门测试重复值。** 增加 `[-2, -2, -1]`、`target = -3`，确认返回 `(1, 2)`，并解释为什么不是 `(0, 2)`。
7. **对比旧版。** 同时阅读 10 号文件，确认算法相同，差异集中在命名、返回类型和测试框架。
8. **关闭源码重写。** 先写核心函数，再加测试列表和失败断言。
9. **口头复盘。** 能说明为什么时间复杂度是平均 `O(n)`，为什么需要额外字典空间，以及当前版本不保证什么。

## 可以继续尝试

1. 明确题目是否要求“最早配对”。如果需要，使用 `seen.setdefault(current_num, current_index)` 并补充 `(0, 2)` 的测试。
2. 增加空列表、单元素、全部相同、两个相同元素、正负混合等更多测试数据。
3. 加入 `try / except AssertionError`，让测试失败时先打印汇总再退出，比较它与直接抛出异常的差别。
4. 引入 `unittest` 或 `pytest`，把 `run_tests` 改写成标准测试函数。
5. 比较元组和列表返回值的类型差异，并增加 `isinstance(answer, tuple)` 测试。
6. 对于合法答案，增加自动检查 `left != right` 和 `nums[left] + nums[right] == target`，不要只比较一个固定答案。
7. 阅读 [Python 学习指南](../../docs/Python学习指南.md#阶段八算法练习)，把时间复杂度、空间复杂度和测试覆盖连起来复习。

完成本练习后，应能独立解释字典记录的是什么、为什么要先查后存、测试框架怎样发现失败，以及“任意合法答案”和“最早答案”是两种不同需求。下一步适合把 6 个手工用例升级为 `unittest`/`pytest`，再练习多组答案和输入校验。
