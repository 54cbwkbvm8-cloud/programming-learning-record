# C 语言 10 月 16 日强制类型转换与输出格式练习：文件简介与学习建议

## 文件简介

- **源码文件：** `26_2026-10-16_强制类型转换与printf格式控制练习.c`
- **类型：** C 语言类型转换 + `printf` 格式控制基础练习
- **功能：** 用同一组很简单的数字 `a = 7`、`b = 2`，把三件事摆在一起对照：① **整数除法**和**强制类型转换**差在哪（`7 / 2` 是 3，`(double)a / b` 是 3.5）；② 想输出一个百分号，格式串里要写 `%%`；③ 三个格式控制补练，演示 `%.2f` 保留两位小数、`%02d` 不足补零、`%-5d` 左对齐。程序**不需要任何输入**，跑起来直接出结果。
- **主要知识点：** 整数相除会**截断**（丢掉小数）而不是四舍五入、`(double)` 强制类型转换、`int` 和 `double` 一起运算时的类型提升、`printf` 的格式符 `%d` / `%f` / `%%`、格式串里的宽度与精度（`.2`、`02`、`-5`）、多条 `printf` 的输出会按顺序拼在一起。

这份练习和 `20_2026-10-14_字符串统计与大小写转换练习_简介与学习建议.md` 里提到的 `(int)` 转换是一对：那边把 `size_t` 转成 `int`，这边把 `int` 转成 `double`，方向相反，但都是"我要亲手控制这个值的类型"。

## 建议运行数据

编译运行（这份程序**不需要输入**，编译完直接跑就行）：

```bash
cc -std=c17 -Wall -Wextra "C/02_变量与数据类型/26_2026-10-16_强制类型转换与printf格式控制练习.c" -o /tmp/practice && /tmp/practice
```

实测输出：

```text
第一条输出：3
第二条输出：3.500000
第三条输出：80%
补充练习 1（保留两位小数）:3.50
补充练习 2（宽度为两个空格，不足补零）：07
补充练习 3（宽度为五个空格，左对齐）：7    END,
```

逐行对着源码看：

| 输出的行 | 对应的源码 | 说明 |
| --- | --- | --- |
| `第一条输出：3` | `printf("%d", a / b);` | `a`、`b` 都是 `int`，整数相除得 3，小数部分直接被丢掉 |
| `第二条输出：3.500000` | `printf("%f", (double)a / b);` | 先把 `a` 转成 `double` 再除，得到真正的 3.5；`%f` 默认打印 **6 位小数** |
| `第三条输出：80%` | `printf("%d%%", 80);` | 格式串里写 `%%`，输出的才是**一个**百分号 |
| `补充练习 1（保留两位小数）:3.50` | `printf("%.2f", (double)a / b);` | `.2` 表示"保留两位小数"，所以 `3.500000` 变成 `3.50` |
| `补充练习 2（宽度为两个空格，不足补零）：07` | `printf("%02d", 7);` | 宽度 2、不足前面补 `0`，所以 `7` 打印成 `07` |
| `补充练习 3（宽度为五个空格，左对齐）：7    END,` | `printf("%-5d", 7);` | 宽度 5、`-` 表示左对齐，所以 `7` 后面补了 4 个空格，`END,` 才跟在后面 |

想看清宽度到底补了几个空格，把 `a`、`b` 换几组数再跑，实测结果如下：

| `a` | `b` | `a / b` | `(double)a / b` | `%.2f` 的输出 |
| --- | --- | --- | --- | --- |
| 7 | 2 | 3 | 3.5 | `3.50` |
| 9 | 4 | 2 | 2.25 | `2.25` |
| 10 | 4 | 2 | 2.5 | `2.50` |
| 1 | 3 | 0 | 0.333333… | `0.33` |
| 8 | 3 | 2 | 2.666666… | `2.67` |

最后一行特别值得记住：`1 / 3` 在整数除法里结果是 **0**，而 `8 / 3` 得到的是 2 而不是 2.67——**整数除法是"砍掉尾巴"，不是"四舍五入"**。

## 零基础学习建议

1. **先接受一个反直觉的规则：在 C 语言里 `7 / 2` 等于 3。** 因为 `7` 和 `2` 都是整数，C 语言做的就是**整数除法**：能整除多少算多少，剩下的小数部分直接扔掉。想让结果是小数，必须让参与运算的数里**至少有一个是小数类型**。
2. **`(double)a / b` 拆开读。** `(double)a` 的意思是"把 `a` 的值临时看成 `double` 类型"，于是 `a` 变成 7.0；接下来 `7.0 / b` 里出现了一个小数，`b` 会被自动提升成 2.0，除法按小数规则做，结果就是 3.5。整个过程**没有改变 `a` 本身**，`a` 仍然是 `int` 类型的 7，只是这一行计算时用了一下它的"小数版本"。
3. **括号的位置决定了结果，这是本文件最容易写错的地方。**

   | 写法 | 结果 | 原因 |
   | --- | --- | --- |
   | `(double)a / b` | 3.5 | 先转换，再除以 2 |
   | `(double)(a / b)` | 3.0 | **先**按整数除法算出 3，**再**把它转成 `double`，小数早就丢了 |

   两写法只差一对括号，结果完全不同。判断哪边需要转换的口诀是：**转换要发生在除法之前**。
4. **`%d` 配整数，`%f` 配小数，不能混。** `%f` 只认小数类型，如果写成 `printf("%f", a / b);`（传进去的是 `int`），程序会打印出一串乱七八糟的数字甚至崩溃。所以第二条输出里那个 `(double)` 不只是为了算得对，**也是为了 `printf` 能正确读这个值**。
5. **`%f` 默认打印 6 位小数。** 所以 3.5 输出的是 `3.500000`，不是 `3.5`。小数位数由格式串控制：`%.2f` 两位、`%.3f` 三位、`%.0f` 不要小数。小数点后面的数字叫**精度**。
6. **宽度和精度是不同的东西，别混。** `%.2f` 里的 `.2` 是精度（小数点后几位）；`%02d` 里的 `2` 是**宽度**（至少要占几格）。`%02d` 表示"至少占 2 格，不够的用 0 补在左边"，所以 7 变成 `07`，而 70 仍然是 `70`（本来就够宽）。宽度和精度也可以一起用，例如 `%07.2f` 表示"总宽 7 格、保留两位小数"。
7. **`%-5d` 里的 `-` 是"左对齐"。** 不加 `-` 时是右对齐（数字靠右、空格补在左边），加上 `-` 就变成数字靠左、空格补在右边。程序里故意在格式串末尾加了 `END,`，就是为了让你**看见**那几个补出来的空格：`7    END,` 里 `7` 和 `END,` 之间正好 4 个空格。
8. **想打印百分号，格式串里必须写 `%%`。** 因为 `%` 在 `printf` 里是"后面要跟格式符"的信号，想让 `%` 老老实实当一个字符输出，就要写两个。这是 `printf` 的固定规则，和转义字符 `\n` 是一类"特殊写法的字符"。
9. **一条输出可以拆成好几次 `printf` 拼出来。** 看源码的前三行输出，每一行都是"先 `printf("第一条输出：")`、再 `printf("%d", a / b)`、再 `printf("\n")`"拼成的，输出效果和写成一整句 `printf("第一条输出：%d\n", a / b);` 完全一样。平时写代码推荐后者（更短、更清楚），但拆开写能帮你看清"格式串里的普通文字会原样打印，`%` 开头的才会被替换"。

## 常见易错点

- **忘了转换就直接除。** `printf("%f", a / b);` 想打印 3.5，实际拿到的是整数 3 转成的小数 3.0，而且 `%f` 收到 `int` 是**未定义行为**，输出可能是 `0.000000` 或别的乱码。正确写法必须是 `(double)a / b`。
- **转换写晚了：`(double)(a / b)`。** 已经算完的整数除法再转换，小数回不来了。括号必须包在**分子**上。
- **只转换了除号另一边的括号。** 例如 `(double)(a) / (b)` 是对的，但 `(double)(a / b)` 是错的。判断标准只有一个：**转换写在除法之前**。
- **想当然地以为 `1 / 3 * 3` 等于 1。** 整数除法的世界里 `1 / 3` 是 0，`0 * 3` 还是 0。涉及小数运算时，先转类型再算。
- **`%d` 里传了 `double`。** 和反面情况一样会出乱码，例如 `printf("%d", (double)a / b);`。格式符和值的类型必须一一对应。
- **百分号只写了一个。** 实测 `printf("%d%", 80);` 编译时得到警告 `incomplete format specifier [-Wformat]`，运行后只打印出 `80`，那个孤零零的 `%` 被吞掉了——**既没有百分号，也没有报错提示你**。要输出百分号就写 `%%`。
- **把 `%02d` 当成"前两位数字"或"保留两位小数"。** `0` 只是"空位补 0"的标记，宽度是那个 `2`；它有宽度、没有精度。想保留小数位要用 `%.2f`。
- **以为 `%-5d` 是在数字前面加个减号。** `-` 出现在**格式串的格式符里**表示左对齐；要打印负号，直接把负数传进去就行，例如 `printf("%-5d", -7);` 输出 `-7   `。
- **忘了写 `\n` 导致输出挤成一行。** 这份文件里每个信息后面都补了一句 `printf("\n")`，删掉其中任意一句，后面的内容就会挤在同一行。多条 `printf` 只是"顺序追加"，换行得自己写。
- **`a = 7; ... a = (double)a / 2;` 这类"直接改原变量"的写法。** `a` 是 `int`，把 3.5 存回 `a` 会又变回 3 并丢掉小数。想保留小数结果，得另外定义一个 `double` 变量来接。

## 可以继续尝试

1. **把 `a`、`b` 改成从键盘输入。** 用两次 `scanf("%d%d", &a, &b)`（记得校验返回值），再输出三种除法结果，比较"整数版"和"小数版"的差别。
2. **做一个"平均分计算器"。** 让用户输入总分和人数两个整数，输出 `%.2f` 格式的平均分——这正是 `(double)sum / n` 最常用的场合，`10_2026-10-07_分支循环数组模拟练习.c` 里用过同样的技巧。
3. **把 `%.2f` 依次改成 `%.1f`、`%.3f`、`%.0f`** 各跑一次，观察四舍五入发生在哪一位，尤其是 `2.666666…` 在 `%.2f` 下变成 `2.67`。
4. **把 `%02d`、`%5d`、`%-5d` 三个放一起对照。** 每次都在格式串末尾加 `|` 标记，例如 `printf("[%5d]\n", 7);`，一眼就能看出空格补在左边还是右边。
5. **用这套格式控制打印一个日期。** 例如用 `printf("%04d-%02d-%02d\n", 2026, 10, 16);` 输出 `2026-10-16`，体会"补零"在实际项目里最常见的用法。
6. **把 `double` 换成 `float` 对比。** 把 `(double)a` 改成 `(float)a`，`%f` 不用改（`printf` 里 `float` 会自动提升成 `double`），但把结果存进 `float` 变量时能观察到精度差别——顺便记住 `scanf` 读 `float` 要用 `%f`、读 `double` 要用 `%lf`，这一点和 `printf` 不同。
7. **回看 `20_2026-10-14_字符串统计与大小写转换练习.c` 里的 `(int)strlen(str);`**，把两个方向的强制转换放在一起记：`(int)` 是把大的类型收窄，`(double)` 是把整数"升级"成小数，两者都写着"我知道这里在换类型"。
