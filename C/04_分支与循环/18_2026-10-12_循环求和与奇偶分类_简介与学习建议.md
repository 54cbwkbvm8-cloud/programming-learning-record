# C 语言 10 月 12 日循环练习：文件简介与学习建议

## 文件简介

- **源码文件：** `18_2026-10-12_循环求和与奇偶分类.c`
- **类型：** C 语言循环与累加综合练习
- **功能：** 一段程序里连做四段统计，全部围绕 1～10：先用 `if (i % 2 == 0)` 求偶数和，再用 `if (i % 2 != 0)` 求奇数和，接着改用步长 `i = i + 2` 再求一次奇数和做对拍，最后求总和，并用"总和 − 奇数和"反推出偶数和。
- **主要知识点：** 全局变量、`for` 三段式、**循环步长**（`i = i + 2`）、累加器 `sum += i`、累加器清零、取余筛选、用已知结果反推。

程序可以分成四段阅读，每段的开头都有一句 `sum = 0;`，这四行是整份代码的骨架：

1. **偶数和**：`for (i = 1; i <= 10; i++)` 每步都用 `if (i % 2 == 0)` 筛一次，命中就 `sum += i`，得到 `30`。
2. **奇数和（筛选写法）**：把条件换成 `i % 2 != 0`，得到 `25`。
3. **奇数和（步长写法）**：不用 `if`，直接 `for (i = 1; i <= 10; i = i + 2)`，只走 1、3、5、7、9，结果同样是 `25`。这一段和第 2 段互为验证。
4. **总和与反推**：先 `j = sum;` 把上一步的 `25` 存起来，再清零累加 1～10 得到 `55`，最后用 `sum - j`（也就是 `55 - 25`）输出偶数和 `30`。

## 建议运行数据

这份程序**不需要输入**，编译后直接运行即可：

```bash
cc -std=c17 -Wall -Wextra "C/04_分支与循环/18_2026-10-12_循环求和与奇偶分类.c" -o /tmp/practice && /tmp/practice
```

实测输出：

```text
1到 10 之间的偶数和为：30
1到 10 之间的奇数和为：25
1到 10 之间的奇数和为：25
1到 10 之间的和为：55
1到 10 之间的偶数和为：30
```

五个结果都能手工验算：

| 检查点 | 计算 | 结果 |
| --- | --- | --- |
| 1～10 偶数和 | 2 + 4 + 6 + 8 + 10 | 30 |
| 1～10 奇数和 | 1 + 3 + 5 + 7 + 9 | 25 |
| 1～10 总和 | (1 + 10) × 10 ÷ 2 | 55 |
| 总和 − 奇数和 | 55 − 25 | 30 |

第 2 行和第 3 行输出完全一样，这不是重复打印，而是**两种写法算同一件事**的对拍结果。看到两个相同数字，说明"筛选写法"和"步长写法"都对上了。

## 零基础学习建议

1. **累加器的三条纪律，本文件各用了一遍：**
   - 用之前先清零：`sum = 0;`
   - 循环体里累加：`sum += i;`（它是 `sum = sum + i` 的简写）
   - 换一段统计前再清零，否则上一段的结果会被带进来。

   第 2、3、4 段之前各写了一次 `sum = 0;`。试着把其中任意一行注释掉再跑一遍，你会立刻看到数字变大——这是理解"累加器为什么要清零"最快的办法。
2. **同一个目标可以有两种循环写法。** 第 2 段是"每个数都看一遍，用 `if` 挑出奇数"；第 3 段是"把步长改成 2，只走奇数这条路"。两种都能得到 `25`，但第 3 段的循环次数少一半。以后做题时，能一次划掉一半范围的写法往往更省时间，这叫**优化循环步长**。
3. **`j = sum;` 是"先记住一个中间结果"。** 此时 `sum` 还是第 3 段算出的奇数 `25`，把它拷进 `j`，等第 4 段把 `sum` 算成 `55` 之后，用 `sum - j` 就能反推偶数部分。这种"先存下某一步的结果，最后用加减法反推另一个量"的思路，在后面前缀和、差分等算法里会反复出现，值得现在就有个印象。
4. **读懂 `for (i = 1; i <= 10; i = i + 2)` 的执行过程。** 三段式分别管"起点、条件、每步怎么走"：从 1 开始，不超过 10 就执行，每轮加 2。所以循环变量依次取 1、3、5、7、9，正好是全部奇数。
5. **`i` 和 `sum` 是全局变量。** 它们写在 `main` 外面，四段循环共用同一个 `i`、同一个 `sum`。能正常工作，但读代码时要一直盯住"`i` 现在是几"。更清楚的做法是把它们写进 `main`，或用 `for (int i = 1; ...)` 声明成临时变量。
6. **循环结束时循环变量会多走一步。** 第 4 段结束后 `i` 是 `11`，不是 `10`——因为 `i++` 先执行、条件后判断。这个细节在"循环结束后还想用 `i`"的场景里很关键。

## 常见易错点

- **忘记清零，结果连锁出错。** 这是本文件最需要警惕的一处。只要漏掉任意一行 `sum = 0;`，后面的奇数和、总和、反推的偶数和都会偏大。写完累加代码后，先检查"每段开始有没有清零"。
- **`j = sum;` 和 `sum = 0;` 的顺序不能颠倒。** 必须先 `j = sum;` 再 `sum = 0;`；反过来写，`j` 里存的就变成 `0`，最后一行的 `sum - j` 会直接等于总和 `55`。
- **最后一行的提示语和实际算法要分清。** 它打印的是 `sum - j`，也就是"用总和减奇数和反推的偶数和"，而不是重新循环算一遍。结果 `30` 是对的，但要能把这个推理链条讲清楚，否则属于"答案对、思路没掌握"。
- **两行奇数和的提示文字一模一样。** 都是"1到 10 之间的奇数和为"，区别只在于上一行用了步长 `i = i + 2`。读输出时容易误以为是重复打印，其实是两组不同写法的结果。
- **全局变量的初始值。** 全局的 `sum` 不写 `= 0` 也会自动是 `0`，所以本文件把 `int sum = 0;` 写成 `int sum;` 也照样能跑；但在函数内部，局部变量不初始化就是不确定的值。显式清零既安全又清楚，别图省事。
- **`i % 2` 与负数。** 本文件只用到正数，所以不必纠结；但如果范围改成从负数开始，要记得 C 里 `-3 % 2` 是 `-1` 而不是 `1`，判断奇偶仍可用"是否等于 0"，但不要用"是否等于 1"。
- **别把 `i = i + 2` 误写成 `i + 2`。** 少了赋值号，循环变量永远不变，程序会一直循环下去（死循环），需要用 `Ctrl+C` 强行停止。

## 可以继续尝试

1. 加一段 `for (i = 2; i <= 10; i = i + 2)`，用步长直接算偶数和，和第一段对拍，看两个结果是否一致。
2. 把范围从 1～10 改成 1～100：偶数和 `2550`、奇数和 `2500`、总和 `5050`，看看规律是不是"总和的一半上下相差 50"。
3. 用 `while` 把这四段各重写一遍，对比 `for` 和 `while` 在"起点、条件、更新"上各自负责什么。
4. 把 `i`、`sum` 改成 `main` 里的局部变量（`int i; int sum = 0;`），重新编译运行，感受作用范围变小之后代码是不是更好读。
5. 在统计和的同时加"个数"统计：1～10 中偶数、奇数各有几个，再输出平均值，练习"和 + 个数"的组合。
6. 让程序先读入一个上限 `n`（`scanf("%d", &n)`），把四段循环里的 `10` 换成 `n`，然后用 `3`、`10`、`100` 三组数据测试边界。
