# 单链表尾插、遍历、删除与测试：零基础教程

## 1. 这份程序要解决什么问题

前面 43 号程序手动创建了三个节点：

```text
10 → 20 → 30 → NULL
```

本程序进一步完成一条可以反复操作的链表：

1. 创建节点。
2. 把头插和尾插封装成函数。
3. 从头遍历并打印。
4. 删除指定值。
5. 统计节点数量。
6. 释放整条链表。
7. 用固定数据自动判断每一步是否符合预期。

## 2. 开始前必须理解的概念

### 2.1 节点

```c
typedef struct Node {
    int data;
    struct Node *next;
} Node;
```

一个节点可以画成：

```text
[data | next]
```

- `data` 放数据。
- `next` 放下一个节点的地址。
- 最后一个节点的 `next = NULL`。

### 2.2 头指针

```c
Node *head = NULL;
```

`head` 不是第一个节点本身，而是保存第一个节点的地址。

```text
head ──> [20|next] ──> [30|next] ──> NULL
```

空链表就是：

```text
head ──> NULL
```

### 2.3 为什么修改头指针要返回新值

普通参数按值复制。调用：

```c
head = insert_tail(head, 20);
```

时，函数得到的是 `head` 当前地址的副本。函数可以把新节点地址作为返回值交回来，再由调用者写回 `head`。

头节点变化时，这种写法尤其重要：

```c
head = delete_by_value(head, 20, &deleted);
```

### 2.4 为什么删除要用两个指针

如果删除第一个节点，直接移动 `head` 即可。

如果删除中间节点：

```text
prev ──> current ──> next_node
```

必须让前驱跳过当前节点：

```text
prev ─────────────> next_node
```

所以需要：

- `prev`：当前节点的前一个节点。
- `current`：正在检查的节点。

## 4. 节点创建与释放

### 4.1 创建节点

核心语句：

```c
Node *new_node = (Node *)malloc(sizeof(Node));
```

过程：

```text
申请一个 Node 大小的内存
→ 如果失败，打印错误并退出
→ 写入 data
→ next 设为 NULL
→ 创建计数加 1
→ 返回地址
```

为什么必须立刻设置：

```c
new_node->next = NULL;
```

因为动态内存刚申请时不会自动得到“链尾”的意思，用户必须主动初始化所有必要字段。

当前程序在申请失败时调用：

```c
exit(EXIT_FAILURE);
```

它会结束整个进程。对入门固定程序来说容易理解；更成熟的设计通常把失败返回给调用者，以便保存错误状态并释放已有节点。

### 4.2 释放单个节点

```c
if (node == NULL) {
    return;
}
free(node);
freed_count++;
```

`free(NULL)` 本身不会出错，但这里仍先检查空指针，目的是明确“空地址不视为一次实际释放”，避免释放计数增加。

### 4.3 释放整条链

正确顺序：

```c
Node *next_node = head->next;
destroy_node(head);
head = next_node;
```

如果反过来：

```c
free(head);
head = head->next;
```

第二行访问的是已经释放的内存，属于未定义行为，可能崩溃，也可能看起来暂时正常。

## 5. 头插与尾插

### 5.1 头插

原链表：

```text
head ──> 20 ──> 30 ──> NULL
```

执行头插 `10`：

```c
new_node->next = head;
return new_node;
```

结果：

```text
head ──> 10 ──> 20 ──> 30 ──> NULL
```

注意：新节点的 `next` 必须先接旧链表，再让新的头指针指向新节点。

### 5.2 空链表尾插

空表：

```text
head ──> NULL
```

尾插 `20`：

```c
if (head == NULL) {
    return new_node;
}
```

新节点自己成为第一个节点：

```text
head ──> 20 ──> NULL
```

### 5.3 非空链表尾插

原链表：

```text
head ──> 20 ──> 30 ──> NULL
```

寻找尾节点：

```c
Node *current = head;
while (current->next != NULL) {
    current = current->next;
}
```

变量变化：

| 轮次 | `current->data` | `current->next` | 是否继续 |
| --- | --- | --- | --- |
| 开始 | 20 | 节点 30 | 是 |
| 第 1 次移动后 | 30 | `NULL` | 否 |

然后把新节点接上：

```c
current->next = new_node;
```

结果：

```text
head ──> 20 ──> 30 ──> 40 ──> NULL
```

### 5.4 尾插的时间代价

每插入一个节点都从头找尾：

```text
插入第 1 个：走 0 步
插入第 2 个：走 1 步
插入第 3 个：走 2 步
插入第 n 个：走 n-1 步
```

总代价会接近 `O(n²)`。如果保存一个尾指针，就可以直接得到尾节点，把每次尾插降为 `O(1)`。当前程序先优先保证指针关系容易理解。

## 6. 遍历和打印

```c
Node *current = head;
while (current != NULL) {
    printf(" -> %d", current->data);
    current = current->next;
}
```

三件事必须发生：

1. `current` 从 `head` 开始。
2. 每次访问当前节点的 `data`。
3. 每轮把 `current` 移到 `next`。

输出示例：

```text
head -> 20 -> 30 -> 40 -> 50 -> NULL
```

### 常见错误：死循环

漏写：

```c
current = current->next;
```

`current` 永远指向同一个节点，`current != NULL` 一直成立。

### 常见错误：访问空指针

循环条件应先用 `current != NULL` 判断，再访问：

```c
current->data
```

如果先访问再判断，空链表会解引用 `NULL`。

## 7. 按值删除

这是本程序最值得慢慢读的函数。

### 7.1 函数接口

```c
Node *delete_by_value(Node *head, int target, int *is_deleted);
```

三个参数：

- `head`：当前链表头指针。
- `target`：要删除的数据。
- `is_deleted`：指向调用者整数的指针，用来返回是否实际删除。

返回新头指针，因为删除头节点会改变头。

### 7.2 先默认删除失败

```c
*is_deleted = 0;
```

只有找到节点并真正释放后才改成 `1`。

当前实现假设 `is_deleted` 一定不是 `NULL`。如果调用者写：

```c
delete_by_value(head, 20, NULL);
```

第一行就会解引用空指针。通用版本应先检查这个参数。本教程记录风险，但不要求直接修改原始学习代码。

### 7.3 情况一：空链表

```text
head -> NULL
```

没有可删除节点，直接返回 `NULL`，删除标志保持 `0`。

### 7.4 情况二：删除头节点

原链表：

```text
head -> 20 -> 30 -> 40 -> NULL
```

步骤：

```c
Node *to_delete = head;
head = head->next;
destroy_node(to_delete);
*is_deleted = 1;
return head;
```

图示：

```text
删除前：head ──> [20] ──> [30] ──> [40]
移动后：head ───────────> [30] ──> [40]
释放：            [20]
```

不能只写：

```c
free(head);
head = head->next;
```

因为第二行会访问已释放节点。

### 7.5 情况三：删除中间节点

原链表：

```text
head -> 30 -> 40 -> 50 -> NULL
```

目标为 `40`。循环开始：

```text
prev = 30
current = 40
```

找到后：

```c
prev->next = current->next;
```

图示：

```text
原来：prev -> current -> next_node
之后：prev -----------> next_node
```

然后释放 `current`：

```text
30 -> 50 -> NULL
```

### 7.6 情况四：删除尾节点

原链表：

```text
30 -> 40 -> 50 -> NULL
```

删除 `50` 时，`current->next` 是 `NULL`，所以：

```c
prev->next = current->next;
```

等价于：

```text
40->next = NULL
```

新的尾节点变成 `40`。

### 7.7 情况五：找不到目标

循环结束后没有任何释放，`head` 不变，删除标志仍为 `0`。

### 7.8 情况六：重复值

找到第一个匹配节点后立即返回，因此只删除第一个：

```text
5 -> 7 -> 5 -> NULL
```

删除 `5` 后：

```text
7 -> 5 -> NULL
```

## 8. 测试函数怎样工作

### 8.1 `check`

```c
void check(int condition, const char *description) {
    total_checks++;
    if (condition) {
        printf("[通过] %s\n", description);
    } else {
        printf("[失败] %s\n", description);
        failed_checks++;
    }
}
```

它把“条件是否为真”和“这次检查的名称”分开。

例如：

```c
check(is_deleted == 1, "删除头节点 20 应成功");
```

把条件写进函数调用后，`main` 不必重复写“测试总数加一”和失败分支。

### 8.2 `list_equals`

两个条件都必须成立：

1. 数组中的每个值都与链表当前节点相同。
2. 数组比较完后，链表也恰好结束。

如果只检查数组中要求的值，链表末尾多一个节点也可能被误判为相同。

### 8.3 `memory_ok`

```c
created_count - freed_count == count_nodes(head);
```

含义：

```text
已创建但尚未释放的节点数 = 当前仍在链表中的节点数
```

如果修改了指针却丢失某一整段节点，这个等式可能不成立。

注意这不是操作系统级泄漏检测。更可靠的方法是用 AddressSanitizer、LeakSanitizer 或专门的工具。

## 11. 常见错误与定位方法

### 错误 1：尾插后链表缺少新节点

检查是否在寻找尾节点前就修改了错误的指针，以及是否忘了：

```c
current->next = new_node;
```

### 错误 2：尾插后出现环

可能把新节点的 `next` 指回了旧节点。新节点创建时应保持：

```c
new_node->next = NULL;
```

### 错误 3：删除头节点后崩溃

检查是否先保存旧头、再移动 `head`、最后释放旧头。

### 错误 4：删除中间节点后链表断开

检查是否写了：

```c
prev->next = current->next;
```

而不是把 `prev` 也修改成别的节点。

### 错误 5：删除尾节点后仍能打印旧尾

检查前驱的 `next` 是否已改成 `NULL`，并确认释放后没有继续使用旧节点地址。

### 错误 6：遍历死循环

每轮必须执行：

```c
current = current->next;
```

### 错误 7：释放后访问

不要写：

```c
free(current);
current = current->next;
```

应先保存 `next_node`。

### 推荐调试顺序

1. 先用空链表测试。
2. 再测试单节点。
3. 再测试两个节点。
4. 分别删除头、中间和尾节点。
5. 最后测试重复值。
6. 每次只改变一个条件或数据。
7. 出现错误时，打印当前指针、当前数据或插入临时检查，不要一次改多处。
