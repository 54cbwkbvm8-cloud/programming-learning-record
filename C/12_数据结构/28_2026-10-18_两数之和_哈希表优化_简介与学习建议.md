# C 语言 10 月 18 日两数之和哈希表优化：文件简介与学习建议

## 文件简介

- **源码文件：** `28_2026-10-18_两数之和_哈希表优化.c`
- **类型：** C 语言结构体、动态内存、哈希表和算法优化综合练习。
- **功能：** 从左到右扫描整数数组，用哈希表保存已经遇到的数字及其下标；对当前数字寻找补数 `target - nums[i]`，找到后返回两个不同下标。
- **当前示例：** `nums = {2, 7, 11, 15}`，`target = 9`，答案下标为 `0` 和 `1`。
- **主要知识点：** `typedef struct`、`calloc` 与 `free`、哈希函数、线性探测处理冲突、`size_t`、溢出检查、数组参数校验、返回状态码。

这份程序用“空间换时间”把暴力枚举的双层循环改成一次数组扫描。平均情况下，查表和插入接近常数时间，整体时间复杂度从 `O(n²)` 降到 `O(n)`，代价是需要额外申请哈希表内存。

## 程序结构

1. `HashEntry` 表示一个槽位，保存数字 `key`、原数组下标 `index` 和是否已使用 `used`。
2. `hash_index` 把整数映射到哈希表位置。它先转成无符号整数，避免负数取余产生负下标。
3. `find_slot` 从初始位置开始查找；如果槽位被别的数字占用，就沿线性探测继续找下一个位置。
4. `two_sum_hash` 检查参数和容量计算，申请 `2 * n + 1` 个槽位，再遍历数组。
5. 每个元素先查补数，再把自己的数字和下标写入表中；找到答案或扫描结束后都会释放动态内存。
6. `main` 使用固定数组演示一次调用，并根据返回值区分“找到了”“没找到”和“参数或内存错误”。

## 零基础学习建议

1. **先理解“补数”。** 当前数字是 `current`，目标和是 `target`，搭档必须是 `target - current`。如果这个搭档以前出现过，当前下标和它的旧下标就是答案。
2. **必须“先查后存”。** 如果先把当前数字保存进表里，再查找补数，那么当补数恰好等于当前数字时，程序可能把同一个下标使用两次。源码在查完 `need` 后才记录 `current`，顺序不能交换。
3. **把哈希表看成很多编号的格子。** `hash_index` 决定从哪一格开始找，`find_slot` 负责处理两个数字抢同一个位置的情况。
4. **理解线性探测。** 如果目标位置已经被别的数字占用，就检查下一格；到最后一格后回到第 0 格。表里必须至少留下一个空槽，程序用 `2 * n + 1` 的容量满足这一点。
5. **逐项读安全检查。** 函数先检查 `result` 和输入数组，再检查容量乘法是否溢出，然后才调用 `calloc`。这些检查不是装饰，而是防止空指针访问、负长度和内存尺寸溢出的必要步骤。
6. **关注内存配对。** 每次成功调用 `calloc` 后，所有返回路径都必须执行 `free(table)`。以后改代码或增加提前返回分支时，最容易漏掉的也是释放内存。
7. **用对比理解优化价值。** 对同样长度的数组，暴力版比较次数按平方增长，哈希版大体只增长一倍；但哈希表也有额外内存，并且极端情况下冲突很多，查找会变慢。

## 常见易错点

- 忘记处理负数哈希。直接把负数拿去做 `% capacity` 可能得到负下标，源码先转成 `unsigned long long`。
- 容量为 `0` 时调用取余或申请空表。`n = 0` 时源码仍使用 `capacity = 1`，循环不会执行，最后返回没找到。
- 表里没有空槽时，线性探测可能一直循环。源码让容量大于元素总数，保证能停下。
- 重复数字覆盖旧下标。源码只在槽位尚未使用时插入，因此保留第一次出现的下标，正好能让 `{3, 3}` 配成 `[0, 1]`。
- 补数计算直接使用 `target - nums[i]`。两个 `int` 相减可能溢出，源码先转成 `long long`。
- 找到答案后忘记 `free(table)`。程序虽然可能马上结束，但函数级代码仍应遵守“申请一次、释放一次”的约定。
- 把 `calloc` 返回的 `NULL` 当成有效指针。内存申请失败时必须返回错误，不能继续写表。
- 只看编译是否通过。哈希冲突、重复数字、空数组和内存释放都属于运行问题，必须用实际数据测试。

## 可以继续尝试

3. 把线性探测改成链地址法，每个槽位保存一条链表，观察实现复杂度和查找速度的变化。

5. 学完结构体和文件后，把数组和目标值保存到文件中，让程序读取文件后输出全部答案。
