```c
typedef struct Node {
    int data;

} Node;
```

这是单链表节点，因此新文件名按真实内容命名。旧文件内容没有修改。

## 单链表是什么

普通数组的元素在内存中连续排列：

```text
[10][20][30]
```

链表节点不保证连续，每个节点保存数据和“下一个节点的地址”：

```text
node1               node2               node3
[data=10|next] ──> [data=20|next] ──> [data=30|next=NULL]
```

链表的起点叫头指针。本程序用 `node1` 作为起点：

```c
Node *current = node1;
```

链尾节点的 `next` 为 `NULL`，表示没有下一个节点。

## 程序流程

### 创建节点

```c
Node *create_node(int value)
```

函数负责：

1. 用 `malloc(sizeof(Node))` 申请一个节点。
2. 检查是否返回 `NULL`。
3. 写入 `data`。
4. 把 `next` 初始化为 `NULL`。
5. 返回新节点地址。

节点刚创建时还没有连接：

```text
[10|NULL]  [20|NULL]  [30|NULL]
```

### 检查创建失败

`main` 连续创建三个节点，再检查：

```c
if (node1 == NULL || node2 == NULL || node3 == NULL)
```

如果任意一个失败：

- 打印错误。
- `free(node1)`、`free(node2)`、`free(node3)`。
- 返回 1。

`free(NULL)` 是安全的，所以即使某次申请失败，也不需要为每个空指针单独写一个 `if`。

### 连接节点

```c
node1->next = node2;
node2->next = node3;
```

连接后：

```text
node1 -> node2 -> node3 -> NULL
```

`node1` 仍保存第一个节点地址，`node2` 和 `node3` 是额外保存的指针变量。遍历链表时只需要 `node1`，后面的节点可以依次通过 `next` 找到。

### 连续访问第三个节点

```c
node1->next->next->data
```

每一步都沿一个 `next`：

1. `node1` 指向第 1 个节点。
2. `node1->next` 是 `node2`。
3. `node2->next` 是 `node3`。
4. 再取 `.data`，得到 30。

这种写法只适合已经知道连接层数且确定所有指针非空的情况。普遍遍历应使用 `while`。

### 遍历

```c
Node *current = node1;
while (current != NULL) {
    printf("%d\n", current->data);
    current = current->next;
}
```

变量变化：

| 轮次 | `current` 指向 | 输出 | 下一轮 |
| --- | --- | --- | --- |
| 1 | node1 | 10 | node2 |
| 2 | node2 | 20 | node3 |
| 3 | node3 | 30 | NULL |
| 结束 | NULL | 无 | 退出循环 |

### 释放

```c
Node *next_node = current->next;
free(current);
current = next_node;
```

必须先保存 `current->next`，再释放 `current`。释放后的节点不能继续访问，所以不能先 `free` 再读取 `current->next`。

## 学习重点

1. **理解自引用结构体。** `struct Node *next` 保存同类型节点的地址。
2. **理解节点不是数组元素。** 节点由多次 `malloc` 分配，地址不一定连续。
3. **理解头指针。** `node1` 是访问整条链表的入口。
4. **理解 `NULL`。** 它表示没有后继，也是遍历和连接的终止条件。
5. **理解 `->`。** `current->data` 和 `current->next` 都通过指针访问成员。
6. **理解连续 `next`。** `node1->next->next` 的每一段都必须有有效节点。
7. **理解释放顺序。** 先保存后继，再释放当前节点。
8. **理解失败清理。** 部分节点申请成功、部分失败时，已成功的节点也要释放。

## 学习难点

- 把链表节点误认为连续数组元素。它们通常由三次独立 `malloc` 分配。
- 忘记初始化 `next`，导致链尾变成随机地址。
- 把 `node1->next = node2;` 理解成复制了 node2；实际只复制了地址。
- 释放节点时先 `free(current)`，再读 `current->next`，产生释放后访问。
- 只释放头节点，忘记沿链释放后续节点。
- 以为 `node2` 和 `node3` 变量可以删除。当前程序保留它们用于创建和输出；实际链表操作可以只保留头指针，但获取新节点时仍需函数返回地址。
- 链表成环时，遍历和释放可能永不结束。当前代码明确连接为三个节点后结束，没有成环。
- 对不确定是否为 `NULL` 的指针连续使用多次 `->`。

## 零基础学习流程

1. **先画三个独立节点。** 每个都写 `data` 和值为 `NULL` 的 `next`。
2. **读 `create_node`。** 确认 `malloc` 只分配一个节点，`next` 初始为空。
3. **手工连接。** 把 `node1.next` 改成 node2 地址，再把 node2 指向 node3。
4. **用箭头跟踪访问。** 从 `node1` 出发写 `next`、`next`、`data` 对应什么。
5. **手工遍历。** 模拟 `current` 依次移动三次，最后变成 `NULL`。
6. **重点读释放顺序。** 比较“先保存 next 再 free”和“先 free 再访问 next”。
7. **运行程序。** 地址会变，但连接顺序和输出数据不变。
8. **关闭源码重写。** 先写一个节点，再写三个节点和两条连接，最后补遍历和释放。

## 常见测试与检查

| 检查 | 预期结果 | 目的 |
| --- | --- | --- |
| `node3->next == NULL` | 为真 | 链尾正确 |
| `node1->next == node2` | 为真 | 第一、二节点连接 |
| `node2->next == node3` | 为真 | 第二、三节点连接 |
| 从 node1 遍历 | 10、20、30 | 遍历顺序 |
| 遍历结束后 `current` | `NULL` | 终止条件 |
| 释放顺序 | 每个节点一次 | 无泄漏、无重复释放 |
| 三个地址是否连续 | 不保证 | 链表不要求连续内存 |
