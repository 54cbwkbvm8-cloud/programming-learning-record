## 程序结构

源码可分为三部分。

### 1. 节点与内存工具

- `Node`：保存 `data` 和指向下一个节点的 `next`。
- `create_node()`：申请一个节点；失败时打印错误并退出程序。
- `destroy_node()`：释放一个非空节点，并累计释放数量。
- `free_list()`：遍历整条链，先保存后继，再释放当前节点。

### 2. 链表操作

- `insert_head()`：把新节点放到链首。
- `insert_tail()`：把新节点追加到链尾。
- `delete_by_value()`：删除第一个值等于目标的节点。
- `print_list()`：从头打印链表。
- `count_nodes()`：统计节点数量。

### 3. 测试与检查

- `list_equals()`：逐项比较链表和期望数组。
- `check()`：统计测试总数和失败数。
- `memory_ok()`：比较“已创建未释放节点数”和“当前链表节点数”。
- `report_memory()`：打印创建、释放和未释放计数。
- `main()`：依次运行空链表删除、尾插、删除头节点、删除尾节点、删除不存在值、删除唯一节点和重复值等场景。

## 删除操作最关键

### 删除头节点

原链表：

```text
head -> 20 -> 30 -> 40 -> NULL
```

删除 `20` 时：

1. 用 `to_delete` 保存原头节点。
2. 让 `head = head->next`。
3. 释放 `to_delete`。
4. 返回新的 `head`。

必须先移动 `head` 再释放旧节点，否则会丢失后续链表的入口。

### 删除中间或尾节点

非头节点需要两个指针：

```text
prev -> current -> current->next
```

找到目标后：

```c
prev->next = current->next;
destroy_node(current);
```

让前驱直接跳到后继，再释放当前节点。删除尾节点时，`current->next` 正好是 `NULL`，所以前驱会变成新的尾节点。

### 只删除第一个匹配值

删除成功后函数立即返回，因此重复值 `5 -> 7 -> 5` 在删除 `5` 后会变成 `7 -> 5`，第二个 `5` 仍然保留。

## 学习重点

1. **头插与尾插的顺序不同。** 头插先让新节点指向旧头，再更新头指针；尾插先找到最后一个节点，再修改它的 `next`。
2. **空链表是特殊路径。** 头插和尾插在 `head == NULL` 时都应让新节点成为头节点。
3. **删除是否成功需要单独反馈。** `is_deleted` 是输出参数，调用者通过它区分“链表没变”是因为没找到，还是删除后内容恰好相同。
4. **头节点删除必须返回新头。** 普通参数按值传递，函数内修改 `head` 不会自动修改调用者的变量。
5. **删除中间节点必须维护前驱。** 只保存当前节点无法把前驱重新接向后继。
6. **释放整表必须先保存后继。** `free` 后不能继续读取原节点的 `next`。
7. **测试要覆盖分支。** 当前测试包含空表、头节点、尾节点、唯一节点、不存在值和重复值。
8. **内存计数不等于完整泄漏检测。** `created_count - freed_count` 只统计本程序封装的创建和释放函数。

## 学习难点

### 难点 1：区分“删除失败”和“链表为空”

空链表删除和值不存在都会让链表保持空或不变，但两者都属于删除失败。函数在开始时把：

```c
*is_deleted = 0;
```

设为失败，只有真正找到并释放节点后才改为 `1`。

### 难点 2：`is_deleted` 是 `int *`

调用时必须传地址：

```c
delete_by_value(head, 20, &is_deleted);
```

函数内部通过：

```c
*is_deleted = 1;
```

修改 `main` 中的变量。

当前函数没有检查 `is_deleted` 本身是否为 `NULL`。仓库内所有调用都传入有效地址，所以当前测试安全；如果作为通用库函数复用，应先增加：

```c
if (is_deleted == NULL) {
    return head;
}
```

本次不修改原始源码，这个最小修复建议只用于后续独立练习。

### 难点 3：头节点为什么不能只写 `head = head->next`

如果不保存旧头：

```c
head = head->next;
free(head);
```

会错误释放新的头节点，同时泄漏原来的头节点。正确顺序是：

```c
Node *to_delete = head;
head = head->next;
destroy_node(to_delete);
```

### 难点 4：连续 `->` 不能代替遍历

源码在特定位置使用 `head->next`，但链表长度是动态的，不能写死 `head->next->next->next` 来删除任意位置。通用操作必须用循环沿 `next` 前进。

### 难点 5：测试通过为什么仍不能证明全部正确

当前 29 项测试只覆盖源码预先设计的场景。至少还有以下路径未覆盖：

- 删除输出参数传入 `NULL`。
- 节点分配失败。
- 包含 `INT_MIN`、`INT_MAX` 等极限整数。
- 大量节点的性能。
- 链表意外成环。

因此结论应表述为“当前 29 项固定测试通过”，不能表述为“所有输入都已验证”。
