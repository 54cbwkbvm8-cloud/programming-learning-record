## 程序功能说明

### 创建节点

```c
Node *create_node(int value) {
    Node *node = malloc(sizeof(Node));
    if (node == NULL) {
        exit(1);
    }
    node->data = value;
    node->next = NULL;
    return node;
}
```

`malloc` 只在运行时申请内存。新节点的 `next` 必须主动设为 `NULL`，否则它可能保存未定义的旧内容，遍历时会把随机值误当作下一个地址。

当前程序在申请失败时直接打印错误并 `exit(1)`。对固定教学程序来说状态明确，但大型程序更常见的设计是返回失败状态，让上层释放已有节点并决定怎样退出。

### 尾插

空链表时：

```text
head = NULL
new_node
```

直接返回新节点，让它成为头节点。

非空链表时，`cur` 从 `head` 出发：

```c
while (cur->next != NULL) {
    cur = cur->next;
}
cur->next = new_node;
```

循环结束时，`cur` 是尾节点；`cur->next` 原为 `NULL`，把它改成新节点的地址即可接上。

### 删除值

`delete_value` 按四种情况处理：

1. 空链表：提示无法删除，返回 `NULL`。
2. 头节点匹配：先保存旧头，移动 `head`，再释放旧头。
3. 中间或尾部匹配：用 `prev` 和 `cur` 找到节点，执行 `prev->next = cur->next`，再释放 `cur`。
4. 没找到：打印提示，返回原 `head`，链表不变。

删除头节点时不能先执行：

```c
free(head);
head = head->next;
```

因为 `head->next` 会读取已经释放的内存。正确顺序是先保存旧头、移动头指针、释放旧头。

### 只删除第一个匹配值

找到第一个匹配节点后，函数立即 `free` 并返回。测试数据：

```text
10 -> 20 -> 30 -> 20 -> NULL
```

删除 20 后变成：

```text
10 -> 30 -> 20 -> NULL
```

后面的 20 仍然保留。如果题目要求删除全部匹配值，需要让循环继续寻找，而不能提前返回。

### 整表释放

正确顺序：

```c
Node *temp = cur;
cur = cur->next;
free(temp);
```

必须在释放当前节点前保存下一个节点地址。释放后继续读取 `temp->next` 属于 use-after-free。

`free_list` 收到的是 `head` 的副本，不能自动修改 `main` 中的头指针。因此每次调用后都写：

```c
head = NULL;
```

避免留下指向已释放内存的悬空指针。

## 学习重点

1. `head` 是进入整条链表的唯一入口，丢失后通常无法再访问或释放后续节点。
2. 空链表访问 `head->data` 前必须先判断 `head == NULL`。
3. 尾插循环应在 `cur->next == NULL` 时停下，而不是在 `cur == NULL` 后才停。
4. 删除头节点会改变头指针，所以函数必须把新头返回给调用者。
5. 删除中间或尾节点必须保存前驱，才能把前驱直接接到后继。
6. 删除目标节点前先改接指针，再 `free`，这样不会丢失后继。
7. 整表释放必须每轮先保存 `next`，再释放当前节点。
8. 每次成功 `malloc` 都必须最终对应一次 `free`。
9. 连续尾插每次都从头找尾，构建长度为 `n` 的链表代价接近 `O(n²)`。
10. 固定测试覆盖空表、头、中、尾、唯一节点、不存在值和重复值，不能只看程序能否运行。

## 学习难点

### 为什么函数要返回 `Node *`

C 普通参数按值传递。`delete_value(head, value)` 中的形参 `head` 是调用者指针的副本。删除头节点后，如果函数只修改副本而不返回，调用者仍保存旧头地址。因此当前采用：

```c
head = delete_value(head, value);
```

### 尾插和删除的循环条件不同

- 尾插找“最后一个节点”：`while (cur->next != NULL)`。
- 从第二个节点开始找待删除节点：`while (cur != NULL)`。

前者结束时 `cur` 必须仍是非空尾节点；后者允许越过尾节点，因为删除尾节点时前驱和当前节点都已经保存。

### 重复值只删一个

当前函数成功删除后立即 `return head`。这个行为与“删除一个指定值”的题目定义一致。若需求是“删除全部指定值”，需要特别控制头节点连续匹配、中间连续匹配和尾部删除的循环。

### `free_list` 后为什么还要手动置空

函数收到的 `head` 是副本。即使函数内部遍历到 `NULL`，调用者变量本身没有变化。若不设置：

```c
head = NULL;
```

它仍保存已经释放的旧地址，后续误用会造成悬空指针问题。

## 易错点与测试用例

| 场景 | 输入或操作 | 实际结果 | 检查目标 |
| --- | --- | --- | --- |
| 空链表删除 | `head = NULL`，删除 5 | 提示无法删除，仍为 `NULL` | 不访问空指针 |
| 删除头节点 | `10 -> 20 -> 30`，删除 10 | `20 -> 30` | 保存旧头、更新新头 |
| 删除尾节点 | `10 -> 20 -> 30`，删除 30 | `10 -> 20` | 前驱成为新尾节点 |
| 删除不存在值 | `10 -> 20 -> 30`，删除 99 | 链表不变 | 遍历失败后返回原头 |
| 删除唯一节点 | `10`，删除 10 | `NULL` | 新头为空并释放旧节点 |
| 重复值只删一个 | `10 -> 20 -> 30 -> 20`，删除 20 | `10 -> 30 -> 20` | 删除后立即返回 |
| 整表释放 | 任意非空链表 | 所有节点释放，输出提示 | 先保存后继再 free |
| 释放后置空 | `free_list(head); head = NULL;` | 头指针不再指向旧地址 | 避免悬空指针 |

常见错误：

- `insert_tail` 空表分支忽略返回值，导致新节点地址丢失。
- 打印循环或删除循环忘记执行 `cur = cur->next`。
- 删除头节点时先 `free`，再访问旧头 `next`。
- 中间节点删除只释放 `cur`，忘记让 `prev->next` 接上后继。
- 整表释放先 `free` 当前节点，再读取 `cur->next`。
- 删除后没有用返回值更新调用者的 `head`。
- 把“只删第一个匹配值”误解成“删除所有重复值”。

## 当前边界与改进方向

- 当前固定测试不读取用户输入，适合稳定复现，但没有验证非法数组长度或空数组指针。
- `build_list` 假定 `arr` 在 `n > 0` 时有效，没有检查 `arr == NULL` 或负长度。
- 每次尾插都从头找尾，批量构建是 `O(n²)`；保存尾指针可以降到摊还 `O(1)`。
- `create_node` 申请失败时直接结束进程，不能由调用者恢复。
- `delete_value` 只删除第一个匹配值，也没有返回“是否实际删除”的状态。
- `free_list` 不会自动把调用者头指针置空，调用者必须主动赋 `NULL`。
- 第 131 行以后是历史长注释，其中有些换行和注释代码的排版不整齐，但都在注释内，不影响编译。

这些边界不影响当前 6 组固定测试，但通用库函数需要更完整的参数检查和错误返回。
