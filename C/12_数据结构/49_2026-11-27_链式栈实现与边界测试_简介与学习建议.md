## 学习重点

- **头插就是入栈**：`node->next = s->top; s->top = node;` 两行的顺序不能反——先改 `top` 会丢掉旧链表。
- **`pop` 的三步顺序**：取数据 → 移动 `top` → `free`。颠倒 `free` 与取值会读到已释放内存。
- **空栈保护用返回值而非异常**：C 没有 Java 的异常，`bool` 返回 + `int *value` 输出参数是标准做法；调用方必须检查返回值。
- **`stack_free` 必须暂存后继**：`free(node)` 之后 `node->next` 不可再访问，所以先 `s->top = node->next` 再释放。
- **`size_t` 与 `%zu`**：元素个数用无符号类型更贴合语义；用 `%d` 打印 `size_t` 是未定义行为。
- **测试可自动化**：`check` 返回 0/1 并累计，`main` 用 `passed == total` 决定退出码——这是从"看输出"走向"可脚本验证"的第一步（对照 48 号单链表测试）。

## 学习难点

- **指针与释放的时序**：初学者常写 `free(node); node = node->next;`，此时 `node->next` 已是非法访问。正确写法是先保存后继。
- **`top` 与 `size` 的一致性**：每次成功 `push` / `pop` 都要同步维护；漏改会导致 `size` 与实际结点数不符，判空失真。
- **分配失败的处理**：本文件选择 `exit(EXIT_FAILURE)`（教学简化）；真实项目应把失败传给调用方决定，不应在库函数里直接终止进程——这一点与 Java 抛异常的思路对照理解。
- **`const Stack *s` 的含义**：函数内不能通过 `s` 修改栈；`peek` / `print` / `is_empty` 都应是只读操作。
- **输出参数的可写性**：`stack_pop(&s, &value)` 要求 `value` 可写；传 `NULL` 会在解引用时崩溃，本示例未做该防护（属教学简化）。
