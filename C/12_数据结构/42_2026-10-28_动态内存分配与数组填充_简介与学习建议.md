## 动态内存是什么

普通局部数组：

```c
int a[10];
```

编译时就能确定容量，通常位于栈上。

动态数组：

```c
int *a = malloc(n * sizeof(int));
```

程序运行到这一行时，才向堆申请 `n * sizeof(int)` 字节，并返回首地址。

可以把它想成：

```text
a ──> [int][int][int] ... [int]
       a[0] a[1] a[2] ... a[n-1]
```

申请成功后，`a` 像数组名一样可以使用 `a[i]`，但 `a` 本身是一个保存首地址的指针变量。

## 程序执行流程

1. 读取 `n`。
2. 拒绝 `n == 0` 或读取失败。
3. 检查 `n > SIZE_MAX / sizeof(int)`，防止乘法溢出。
4. 调用 `malloc` 申请内存。
5. 检查返回地址是否为 `NULL`。
6. 用循环给每个元素写入平方数。
7. 输出全部元素。
8. `free` 释放内存。
9. 把 `a = NULL`，避免继续保留失效地址。

这里的检查顺序不能随意交换。不能在容量乘法可能溢出时直接调用 `malloc(n * sizeof(int))`，因为乘法可能先溢出，得到一个错误的小尺寸。

## 为什么使用 `size_t`

`n` 表示元素个数，不能是负数，因此使用无符号的 `size_t`：

```c
size_t n;
```

输出格式使用：

```c
printf("%zu", n);
scanf("%zu", &n);
```

循环变量也使用 `size_t`，与数组下标和容量类型保持一致。

即使使用无符号类型，仍然必须检查乘法：

```c
if (n > SIZE_MAX / sizeof(int)) {
    ...
}
```

若 `n * sizeof(int)` 超过 `SIZE_MAX`，`malloc` 不会得到真实需要的大小。

## `malloc` 和 `free` 的配对

```c
int *a = malloc(n * sizeof(int));
...
free(a);
```

规则：

- `malloc` 返回的内存由程序负责释放。
- `free(a)` 释放的是 `a` 指向的整块内存，不是只释放一个 `int`。
- 未初始化内容是未定义的；本程序在读取每个元素前先写入平方数，所以安全。
- 释放后不能继续访问 `a[0]`。
- `free(NULL)` 是安全的，但重复释放同一块已释放内存会产生未定义行为。

`a = NULL` 不是释放内存，而是在 `free` 后明确标记“当前不再指向有效数组”。

## 已发现的数值边界

程序能防止“申请字节数乘法溢出”，但不能防止“元素值平方后超出 `int` 范围”。

当前赋值：

```c
a[i] = (int)((i + 1) * (i + 1));
```

`(i + 1)` 是 `size_t`，平方运算也在无符号范围进行；最后转换成 `int`。当平方值超过 `INT_MAX` 时，转换结果不再能按普通整数安全理解。

本次用 `n = 50000` 做了受控运行，观察到：

```text
a[46339] = 2147395600
a[46340] = -2147479015
a[46341] = -2147386332
```

`46340²` 仍在 `int` 范围内，而 `46341²` 已经超过 `INT_MAX`。程序没有崩溃，分配和释放也正常，但输出值发生了整数转换问题。

最小修复思路：

1. 把数组元素类型改成 `long long` 或 `uint64_t`，并同步打印格式。
2. 或者在赋值前检查 `(i + 1) > INT_MAX / (i + 1)`，超过时停止或报告。
3. 如果题目只要求小规模平方数，应明确限制 `n`，例如 `n <= 46340`。

源码本次保持原样，问题记录在说明和教程中。

## 学习重点

1. **理解指针指向一块动态内存。** `a` 保存首地址，`a[i]` 访问第 `i` 个整数。
2. **理解容量和字节数。** 元素个数是 `n`，总字节数是 `n * sizeof(int)`。
3. **理解溢出检查。** 先检查乘法，再申请内存。
4. **理解 `malloc` 可能失败。** `NULL` 必须检查。
5. **理解 `free` 的配对关系。** 成功申请后，正常路径必须释放。
6. **理解未初始化。** `malloc` 不清零，不能直接依赖旧内容。
7. **理解释放后的指针。** `free(a)` 后不能再解引用；置 `NULL` 是防御性习惯。
8. **区分内存大小溢出和元素值溢出。** 前者已检查，后者仍可能发生。

## 学习难点

- 把“分配了 `n` 个元素”误写成“分配 `n` 字节”。
- 用 `int` 保存很大的元素数量，导致负数或不匹配。
- 只检查 `malloc == NULL`，却忽略乘法可能先溢出。
- 忘记 `free`，造成内存泄漏。
- `free` 后继续使用 `a[i]`，产生悬空指针访问。
- 把 `a = NULL` 当成已经释放内存；它只是修改指针值。
- 认为语法检查能发现所有整数溢出。上面的平方值问题在编译阶段不会报错。
- 使用 `%d` 输出 `size_t`，格式符与类型不匹配。
