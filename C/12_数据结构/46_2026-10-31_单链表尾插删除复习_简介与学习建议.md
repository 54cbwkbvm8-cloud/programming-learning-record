## 程序在做什么

程序从空链表出发：

```text
NULL
```

连续尾插 `10、20、30`：

```text
10 -> 20 -> 30 -> NULL
```

然后依次：

1. 删除中间值 `20`。
2. 删除尾节点 `30`。
3. 尝试删除不存在的 `99`。
4. 删除头节点 `10`。
5. 在空链表上再次尾插 `1、2`。
6. 释放整条链表。

这段顺序有意覆盖了链表删除的主要情况。

## 五个核心函数

### `creat_node`

向系统申请一个 `Node` 大小的内存，保存数据并把 `next` 初始化为 `NULL`。申请失败时打印错误并返回 `NULL`。

函数名中的 `creat` 少了字母 `e`，但它目前只是一个命名问题。本次任务不擅自修改你的源码；如果要重写自己的版本，建议使用 `create_node`。

### `append_node`

分两种情况：

- 空链表：新节点直接成为新的头指针。
- 非空链表：从头走到 `cur->next == NULL` 的最后一个节点，再把新节点接到后面。

函数返回更新后的 `head`。调用时必须写：

```c
head = append_node(head, value);
```

如果空链表时忽略返回值，新节点虽然创建成功，调用者的 `head` 仍然是 `NULL`，整条链表就找不到了。

### `print_list`

`cur` 从 `head` 出发，每轮打印当前数据，再执行：

```c
cur = cur->next;
```

没有这一步就会永远停在同一节点。`const Node *` 表示函数只读，不修改节点内容。

### `delete_value`

删除时分别处理：

1. 空链表：没有节点可删，打印提示并返回 `NULL`。
2. 头节点就是目标：先保存旧头，把 `head` 移到下一节点，再释放旧头。
3. 中间或尾节点：用 `prev` 找到目标节点的前一个节点，把 `prev->next` 接到 `target->next`，然后释放 `target`。
4. 没找到：链表不变，返回原 `head`。

当前实现只删除**第一个**匹配值。若链表中有多个相同值，后面的节点仍会保留。

### `free_list`

释放前必须先保存：

```c
Node *next = head->next;
```

再：

```c
free(head);
```

如果先 `free(head)`，再用 `head->next`，就是在访问已经失效的内存。释放完成后把 `head` 移到保存的 `next`，直到整条链表结束。

函数参数是按值传递的，所以 `free_list(head)` 不会自动把调用者的 `head` 改成 `NULL`。`main` 中主动写了：

```c
head = NULL;
```

这是好的收尾习惯。

## 学习重点

1. **链表只有一个入口。** 只要 `head` 丢失，后续节点通常就无法再访问，也无法正确释放。
2. **空链表要先判断。** 访问 `head->data` 前必须确认 `head != NULL`。
3. **尾插要停在尾节点。** 条件应是 `cur->next != NULL`，不是 `cur != NULL`。
4. **删除要保存前驱。** 单链表不能倒着走，想删除当前节点，通常要拿到它前一个节点。
5. **删除头节点与删除其他节点不同。** 头节点会改变整条链表的入口，必须返回新的 `head`。
6. **释放顺序必须正确。** 先取得后继地址，再释放当前节点。
7. **创建和释放要配对。** 每个成功 `malloc` 的节点都必须在某条路径上 `free`。

## 学习难点

### 为什么函数返回 `Node *`

普通参数按值传递。函数内部改 `head` 不会自动修改 `main` 的 `head`。因此空链表尾插、删除头节点等操作需要把新头返回，由调用者接收。

### 为什么 `prev->next` 的两层判断顺序不能反

```c
while (prev->next != NULL && prev->next->data != value) {
```

先检查 `prev->next != NULL`，才能安全访问 `prev->next->data`。如果调换两边，`prev` 已经是尾节点时，左边还没判断就先解引用 `NULL`。

### 为什么只删除一次

当前函数在找到第一个匹配节点后立即 `free` 并返回。重复值场景下，这符合“删除一个指定值”的当前实现，不等价于“删除所有指定值”。

### 为什么没有断言内存计数

46 号主要用打印结果观察操作，没有像 45 号那样统计 `malloc/free` 次数。因此“输出看起来正确”不代表内存管理已经被自动证明。需要更严格验证时，应使用 45 号的测试思路或 sanitizer。

## 易错点与测试用例

| 场景 | 操作 | 预期结果 | 检查目标 |
| --- | --- | --- | --- |
| 空链表 | 打印 | `NULL` | 不解引用空指针 |
| 空链表 | 尾插 | 新节点成为头 | 接收返回的新 `head` |
| 非空链表 | 尾插 | 接到最后一个节点 | 循环停在 `cur->next == NULL` |
| 删除中间 | 删除 `20` | `10 -> 30 -> NULL` | 前驱的 `next` 改接 |
| 删除尾部 | 删除 `30` | `10 -> NULL` | 尾节点成为新的尾 |
| 删除头部 | 删除 `10` | `NULL` | 先移头再释放 |
| 删除不存在 | 删除 `99` | 链表不变 | 找不到时返回原头 |
| 清空后再尾插 | 插入 `1、2` | `1 -> 2 -> NULL` | 空链表分支可复用 |

以上场景在本次维护中已实际运行并符合当前输出。新增修改后的预期结果需要重新运行，不能直接宣称已通过。

常见错误：

- 把 `head = append_node(head, value);` 写成只调用不接收返回值。
- 在 `print_list` 中忘记 `cur = cur->next;`。
- 尾插走到 `NULL` 后访问 `cur->next`。
- 删除头节点时先 `free`，再访问旧头的 `next`。
- 删除节点后忘记把前驱与后继重新连接。
- 只 `free(node)` 但忘记更新链表头。
- 重复调用 `free`，或释放后继续访问节点数据。
- 以为 `free_list(head)` 会自动把外部 `head` 变成 `NULL`。

## 当前实现的边界与改进方向

本次不修改原始源码，但学习时应明确：

- `creat_node` 拼写建议改为 `create_node`。
- `append_node` 在申请内存失败时只返回原链表，调用者无法直接知道追加失败。更完整的接口可增加状态返回值。
- `delete_value` 只删除第一个匹配值。
- 通用版本可增加“删除全部匹配值”和“返回实际删除数量”。
- `free_list` 可使用 `Node **head` 让调用者的头指针在释放后自动置空。
- 若链表可能成环，普通遍历和释放会无限进行，需要先用快慢指针检测环。
