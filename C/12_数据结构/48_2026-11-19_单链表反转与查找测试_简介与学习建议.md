## 程序功能说明

### 创建节点与尾插

`create_node` 用 `malloc(sizeof(Node))` 申请一块刚好能放下一个节点的内存。申请失败时打印提示并 `exit(1)`，因此它要么返回有效地址，要么直接结束程序，不会把 `NULL` 交给调用者。

`push_back` 分两种情况：

- 空链表：新节点直接成为头节点，返回 `new_node`。
- 非空链表：用 `tail` 从头走到最后一个节点，执行 `tail->next = new_node`，再返回原来的 `head`。

因为参数 `head` 是调用者指针的副本，空表分支必须把新头返回出去，调用者再用 `head = push_back(head, value);` 接住。

### 构建、打印、长度与查找

`build_list` 从 `head = NULL` 开始，循环调用 `push_back`。当 `count == 0` 时循环一次也不执行，返回空链表；此时即使 `value` 是 `NULL` 也不会解引用数组。

`print_list` 用 `current` 游标遍历，条件是非空；空链表只打印一个换行。`list_length` 的计数从 0 开始，每经过一个节点加 1。

`find_value` 返回的是“链表内部某个节点的地址”，不是新节点：

- 找到了：调用者可以通过返回指针读取 `found->data`。
- 没找到：返回 `NULL`。

这个返回指针与链表共享同一块内存，因此不能对它单独调用 `free`；整条链表只能通过 `free_list` 统一释放。

### 原地反转

`reverse_list` 保存三个指针：

```c
Node *prev = NULL;
Node *current = head;
Node *next = NULL;
```

每一轮固定做四步：

```c
next = current->next;   // ① 先记住后继
current->next = prev;   // ② 当前节点掉头
prev = current;         // ③ prev 前进
current = next;         // ④ current 前进
```

以 `10 -> 20 -> 30 -> NULL` 为例：

| 阶段 | `prev` | `current` | 操作后的连接方向 |
| --- | --- | --- | --- |
| 开始 | `NULL` | 10 | `10 -> 20 -> 30 -> NULL` |
| 第 1 轮 | 10 | 20 | `NULL <- 10`，`20 -> 30` |
| 第 2 轮 | 20 | 30 | `NULL <- 10 <- 20`，`30` |
| 第 3 轮 | 30 | `NULL` | `NULL <- 10 <- 20 <- 30` |
| 结束 | 30 | `NULL` | 返回 `prev`，即 `30 -> 20 -> 10 -> NULL` |

第 ① 步必须在第 ② 步之前。因为一旦执行 `current->next = prev`，原来的后继地址就被覆盖了，不提前保存就再也找不到后面的链表。

循环结束时 `current == NULL`，`prev` 正好停在原来的尾节点，也就是反转后的新头，所以返回 `prev`。

### 释放与测试

`free_list` 同样必须先保存 `next`，再 `free(current)`，最后移动到下一个：

```c
Node *next = current->next;
free(current);
current = next;
```

顺序反过来就是读取已经归还的内存，属于 use-after-free。

`test_case` 把一次完整流程固定下来：构建、打印原始链表、求长度、查找目标、反转、打印反转后的链表、释放，最后把 `head` 置为 `NULL`，避免留下悬空指针。四组测试分别覆盖：

1. 空链表（`NULL`，长度 0）。
2. 单节点（反转后仍是自己）。
3. 两节点（验证交换）。
4. 三节点（查找中间节点，反转成逆序）。

## 学习重点

1. 反转只修改 `next` 的指向，不申请新节点，也不交换 `data`。
2. 三个游标的分工：`prev` 是已反转部分的头，`current` 是正在处理的节点，`next` 是尚未处理部分的开头。
3. 必须先保存 `next`，再修改 `current->next`，否则后半条链表会丢失。
4. 循环结束时返回 `prev`，因为原来的头节点已经变成尾节点，`current` 已经是 `NULL`。
5. 空链表反转后仍为空，单节点反转后仍是自己，这两个边界不需要额外分支。
6. `push_back` 每次从头找尾，连续构建长度为 `n` 的链表总代价接近 `O(n²)`。
7. `find_value` 返回的是链表内部节点地址，不能单独释放。
8. `print_list`、`list_length`、`find_value`、`reverse_list` 都用 `current` 或 `tail` 游标，不直接移动 `head`。
9. `free_list` 必须先保存后继再释放当前节点。
10. 固定测试只打印结果、不自动判定通过失败，因此仍要人工核对每组输出。

## 学习难点

### 为什么不能直接改 `head`

如果只把 `head` 移到第二个节点，第一个节点的 `next` 仍然指向第二个节点，链表方向没有改变，而且第一个节点失去了入口，无法再访问或释放。反转必须逐个修改每个节点的 `next`。

### 为什么需要三个指针

反转一个节点时，需要知道它原来指向谁（后继），以及它应该改为指向谁（前驱）。当前节点本身由 `current` 保存。三个信息缺一不可：

```text
prev <- current -> next
```

如果只有 `prev` 和 `current`，执行 `current->next = prev` 后就找不到后继；如果只有 `current` 和 `next`，就不知道应该把 `next` 改成哪个地址。

### 循环结束时谁是新头

每一轮结束后，`prev` 都指向“已经完成反转的部分”的第一个节点。最后一轮处理完原来的尾节点后，`prev` 就是它，因此新头是 `prev`。此时 `current` 是 `NULL`，不能再返回 `current`。

### 反转和释放都要先保存后继

两处的共同点是：一旦修改或释放当前节点，就必须先保存它的 `next`。反转时保存到 `next` 变量，释放时保存到局部 `next` 变量。这是链表操作最容易被忽略的顺序问题。

### `test_case` 为什么最后要置空

`free_list(head)` 收到的是指针副本，函数内部把局部变量走到 `NULL`，并不会改变 `test_case` 里的 `head`。释放后立刻写 `head = NULL;`，可以防止后续误用悬空指针。

## 易错点与测试用例

| 场景 | 输入或操作 | 实际结果 | 检查目标 |
| --- | --- | --- | --- |
| 空链表 | `NULL`，长度 0 | 原始和反转后都为空，长度 0 | 不访问空指针 |
| 空表查找 | 在空表中查找 1 | 没找到 | `find_value` 返回 `NULL` |
| 单节点 | `5` | 长度 1，反转后仍为 `5` | 边界不特殊处理也正确 |
| 两节点 | `1 -> 2` | 反转后 `2 -> 1` | 一次掉头 |
| 三节点 | `10 -> 20 -> 30` | 反转后 `30 -> 20 -> 10` | 多轮游标移动 |
| 查找中间节点 | 在三节点中查找 20 | 找到了，节点值 20 | 返回内部节点地址 |
| 查找不存在值 | 查找 99 | 没找到 | 遍历到 `NULL` 后返回 |
| 重复值查找 | `10 -> 20 -> 20` 查找 20 | 返回第一个 20 | 找到后立即返回 |
| 反转两次 | 连续调用两次 `reverse_list` | 恢复原顺序 | 验证可逆性 |
| 整表释放 | 任意非空链表 | 全部节点释放 | 先保存后继再 `free` |

常见错误：

- 先执行 `current->next = prev;` 再保存 `next`，导致后半条链表丢失。
- 循环结束后返回 `head` 或 `current`，而不是 `prev`。
- 在循环里忘记推进 `prev` 或 `current`，造成死循环。
- 空链表时直接访问 `head->next`。
- 把 `find_value` 返回的节点单独 `free`，造成重复释放或破坏链表。
- `free_list` 先 `free(current)` 再读 `current->next`。
- 释放后没有把 `head` 置为 `NULL`，留下悬空指针。
- 误以为反转需要新建节点或交换 `data`。

## 当前边界与改进方向

- 第 112 行以后的历史注释把文件名写为 `linked_list_reverse.c`，并记录了 `find_node` → `find_value`、`creat_node` → `create_node` 等修复过程；当前可执行代码已经使用修正后的名字，历史注释保留原样，未修改源码。
- `build_list` 假定 `count > 0` 时 `value` 有效，没有检查 `value == NULL` 或负的 `count`。
- `push_back` 每次都从头找尾，批量构建是 `O(n²)`；增加尾指针可以优化到摊还 `O(1)`。
- `create_node` 申请失败时直接结束进程，调用者无法回收已经创建的节点。
- `find_value` 只返回第一个匹配节点，没有返回“第几个”或“全部匹配”。
- `reverse_list` 只处理单向链表，不能直接用于双向链表。
- `test_case` 只打印结果，没有把期望值写成断言；即使输出错了，退出码仍然是 0。
- 程序没有删除、插入到指定位置、合并链表等操作，也没有递归版本。
- 第 112 行以后是历史长注释，排版不完全整齐，但都在注释内，不影响编译和运行。
