# C 语言 10 月 19 日巴什博弈函数与测试用例：文件简介与学习建议

## 文件简介

- **源码文件：** `33_2026-10-19_巴什博弈函数与测试用例.c`
- **类型：** C 语言函数封装、布尔返回值和固定测试用例练习。
- **功能：** `canWin(int n, int m)` 判断石子数为 `n`、每轮最多取 `m` 颗时，先手是否有必胜策略；`testCase` 输出余数、判断结果和第一步建议；`main` 依次运行三组固定数据。
- **主要知识点：** `#include <stdbool.h>`、`bool` 返回值、函数参数、`return`、取余 `%`、`printf` 的三元表达式、无输入自动测试。

这份程序与 `29_2026-10-18_巴什博弈.c` 不同。29 号是完整的交互游戏演示，本文件把核心判断抽成纯函数，并用固定测试用例检查结果，更适合考试、单元测试和函数复用。

## 核心逻辑

```c
bool canWin(int n, int m) {
    if (n <= 0 || m <= 0) {
        return false;
    }
    return n % (m + 1) != 0;
}
```

- `n <= 0` 或 `m <= 0` 时，输入参数没有实际意义，函数返回 `false`。
- 合法输入下，`n % (m + 1) != 0` 表示当前先手存在必胜策略。
- 余数为 `0` 时，先手没有必胜策略。
- 余数不为 `0` 时，第一步取走这个余数，就能把局面交给对手。

`testCase` 负责打印每个测试编号、参数、余数和判断结果，因此把“计算”与“输出”分开在两个函数里。

## 零基础学习建议

1. **先分清两个函数。** `canWin` 只负责计算“能不能赢”，用 `bool` 返回 `true` 或 `false`；`testCase` 负责打印测试信息。这样核心逻辑可以被其他程序重复调用。
2. **理解函数参数 `n` 和 `m`。** 它们只在函数内部使用，调用 `canWin(10, 3)` 时，`n` 得到 `10`，`m` 得到 `3`。
3. **把 `%` 和 `+ 1` 联系起来。** 每轮最多取 `m` 颗，双方一轮最多可以合计控制 `m + 1` 颗；因此余数是否为 `0` 决定先手有没有必胜策略。
4. **理解 `return` 会立即结束函数。** `canWin` 在参数无效时直接返回 `false`，后面的取余语句不会再执行。
5. **把三组测试当成小型“考试检查表”。** 一组测试正常必胜局面，一组测试余数为 0 的必败局面，一组测试最小边界 `n = 1`。
6. **自己推演后再运行。** 先手算三组余数并预测输出，再运行程序核对，这比直接看结果更能检查是否真正理解。
7. **达到独立迁移的程度。** 能把 `canWin` 改造成 `canWin(long long n, long long m)`，并能写出一个函数返回第一步应该取多少颗，而不是只打印一句话。

## 常见易错点

- 忘记包含 `<stdbool.h>`，却直接使用 `bool`、`true` 和 `false`。
- 把 `canWin` 写成 `void`，导致函数不能把判断结果返回给调用者。
- 忘记处理 `n <= 0` 或 `m <= 0`；当前 `main` 没有调用这些非法参数，但函数本身已经提供了保护和独立测试入口。
- 把 `n % (m + 1) != 0` 写成 `n % (m + 1) == 0`，胜负判断会完全反过来。
- 认为 `testCase` 没有 `return` 就有错误。它返回类型是 `void`，打印完成后自然结束；只有 `canWin` 需要返回 `bool`。
- 固定测试只覆盖三组数据，不能代表所有输入。边界值、负数和大数需要另外补充测试。
- 当 `m == INT_MAX` 时，`m + 1` 可能溢出。更健壮的版本应限制输入范围或先转换为更宽的类型。
- 直接把 `printf` 当成验证工具，只看输出的文字。真正可靠的测试应检查返回值，或者在输出之外建立独立断言。
