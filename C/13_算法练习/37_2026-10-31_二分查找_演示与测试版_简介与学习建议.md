## 程序在做什么

假设有一个已经从小到大排好的数组：

```text
下标：   0   1   2   3   4   5   6   7
数组：   2   5   8  12  16  23  38  56
```

要查找 `16`，程序先看中间位置：

```text
left = 0，right = 7
mid = 3，arr[3] = 12
```

因为 `12 < 16`，目标只可能在右边，所以 `0～3` 这一段可以整体排除，下一次把 `left` 改成 `4`。每轮比较后，至少丢掉当前区间的一半。

程序分为三部分：

1. **过程演示：** 分别查找中间值、首元素和不存在值。
2. **自动测试：** 用空数组、单元素、两元素、首尾元素等 13 个用例检查函数。
3. **有序性演示：** 用无序数组查找一个明明存在的值，观察二分查找为什么返回 `-1`。

## 核心代码怎么连接

### 1. 搜索区间

```c
int left = 0;
int right = n - 1;
```

`left` 和 `right` 表示当前仍然可能需要搜索的闭区间 `[left, right]`。区间两端都包括在搜索范围内。

### 2. 循环什么时候继续

```c
while (left <= right) {
```

只要 `left <= right`，区间里至少还有一个下标。若 `left > right`，区间已经空了，循环结束。

### 3. 中点怎样计算

```c
int mid = left + (right - left) / 2;
```

这里不是随便写的一种等价形式。`left + right` 在特别大的数组上可能超出 `int` 范围，而 `left + (right - left) / 2` 可以避免这个中间加法溢出。

### 4. 三个分支

```text
arr[mid] == target  -> 找到，返回 mid
arr[mid] < target   -> 目标在右半边，left = mid + 1
arr[mid] > target   -> 目标在左半边，right = mid - 1
```

已经检查过的 `mid` 不可能是答案，因此新区间要从 `mid + 1` 或 `mid - 1` 开始。如果忘记 `+1` 或 `-1`，循环可能无法推进。

### 5. 找不到

```c
return -1;
```

下标不可能为负数，所以本程序用 `-1` 表示“没有找到”。调用者必须先区分返回值和合法下标。

### 6. 自动测试

`run_test` 接收数组、长度、目标值和预期下标，再调用 `binary_search(..., 0)` 关闭过程输出。实际结果与预期相同就返回 `1`，否则返回 `0`，最后统计通过数量。

## 学习重点

1. **先判断前提。** 二分查找要求待搜索数据按与比较方向一致的顺序排列。本程序要求升序。
2. **维持区间含义。** 写循环时始终问自己：`left` 和 `right` 到底表示闭区间、左闭右开区间，还是别的含义？本程序使用闭区间 `[left, right]`。
3. **跟踪中点。** 对 `16`、`2` 和 `20` 各写出至少一轮 `left / right / mid` 的变化。
4. **理解每次排除一半。** 长度从 `n` 逐轮缩小为约 `n/2`、`n/4`，因此最多比较约 `log2(n) + 1` 次。
5. **区分过程输出与算法结果。** `show` 只控制打印，不控制比较逻辑；`run_test` 使用 `show = 0` 避免测试输出被过程日志淹没。
6. **用小测试验证函数。** 只测试“中间能找到”远远不够，还要看首元素、尾元素、空数组和不存在值。

## 学习难点

### 难点一：为什么必须有序

有序时，如果 `arr[mid] < target`，可以断定左半边及 `mid` 都不可能包含目标。无序时这个推断不成立。第三部分正是这个反例。

### 难点二：为什么是 `left <= right`

闭区间只剩下一个元素时，`left == right`，仍然必须检查这个元素。如果写成 `left < right`，某些单元素或最后一步会被漏掉。

### 难点三：为什么更新要跳过 `mid`

`arr[mid]` 已经比较过。下一轮若仍保留 `mid`，不仅多做一次无用比较，稍不注意还可能让区间不再缩小。

### 难点四：返回 `-1` 和返回合法下标是两类结果

调用后必须判断：

```c
if (result == -1) {
    /* 没找到 */
} else {
    /* result 是合法下标 */
}
```

不要直接拿 `result` 访问数组，除非已经确认它不是 `-1`。

### 难点五：当前函数的输入边界

本程序只在自己的固定数组上调用，因此没有在函数开头检查空指针。若以后把它做成通用函数，至少应约定：

- `n <= 0` 时直接返回 `-1`。
- `n > 0` 时必须保证 `arr != NULL`。
- 数组必须按升序排列。

## 适合零基础的学习流程

1. 先读“程序在做什么”，用猜数字游戏理解“每次排除一半”。
2. 不运行源码，手算查找 `16` 时的三轮变化。
3. 编译运行，对照源码打印结果。
4. 在纸上跟踪查找 `2` 和 `20`，重点记录最后一次 `left > right`。
5. 把目标 `56` 改成 `38`，先预测过程，再运行核对。
6. 读完自动测试，选出你原来最容易漏掉的三个边界。
7. 关闭源码，独立写出 `binary_search` 的核心循环。
8. 再用无序数组测试一遍，解释为什么这个测试是“前提被破坏”，而不是“算法随机出错”。

## 易错点与测试用例

| 用例 | 数据 | 目标 | 预期结果 | 重点 |
| --- | --- | --- | --- | --- |
| 普通中间命中 | `{2,5,8,12,16,23,38,56}` | `16` | 下标 `4` | 至少两次缩小 |
| 首元素 | 同上 | `2` | 下标 `0` | 检查左边界 |
| 尾元素 | 同上 | `56` | 下标 `7` | 检查右边界 |
| 不存在且居中空隙 | 同上 | `20` | `-1` | 最后区间为空 |
| 单元素命中 | `{7}` | `7` | 下标 `0` | `left == right` |
| 空数组 | 长度 `0` | `5` | `-1` | 不访问 `arr[0]` |
| 无序反例 | `{5,2,8,1,9}` | `2` | 本实现返回 `-1` | 前提不成立时结论不保证 |

以上 13 个源码内固定测试在本次维护中已实际运行，均通过。新增修改后的预期结果需要重新运行，不能沿用旧结论。

常见错误：

- 把数组当成有序，却没有先排序或验证前提。
- 中点写成 `mid = (left + right) / 2`，忽略极端大小下的加法溢出风险。
- 更新 `left` 或 `right` 时没有跳过 `mid`。
- 循环结束条件写错，导致漏查最后一个元素。
- 找到后忘记 `return`，程序继续执行下一轮。
- 测试只覆盖一个能找到的目标。
- 把 `show` 打印逻辑和搜索结果混在一起。

## 拓展练习与后续学习

由易到难：

1. 把数组和目标值改成通过 `scanf` 输入，同时保持升序检查。
2. 给函数增加参数检查，并证明 `n = 0`、`n = 1`、`n < 0` 都不会越界。
3. 在数组中有重复值时，分别求“任意一个匹配下标”“第一个匹配下标”“最后一个匹配下标”。
4. 比较线性查找和二分查找，在 `n = 10`、`1000`、`1000000` 时的最坏比较次数。
5. 写出左闭右开区间版本 `[left, right)`，比较两种边界写法。
6. 用二分答案解决一个简单题，例如在单调函数中寻找最小可行值。

下一步建议：先复习数组和固定测试，再学习二分查找的“任意命中版”，最后再进入“第一个/最后一个位置”等变体。不要同时开始复杂二分答案题。
