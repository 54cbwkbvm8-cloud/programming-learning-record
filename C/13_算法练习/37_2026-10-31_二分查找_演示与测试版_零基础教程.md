# 二分查找零基础教程

这份教程配合 [37_2026-10-31_二分查找_演示与测试版.c](37_2026-10-31_二分查找_演示与测试版.c) 使用。重点不是把每一行重新抄一次，而是建立四个直觉：为什么能排除一半、区间怎样缩小、循环何时结束、怎样证明实现没有漏掉边界。

## 1. 先把它想成猜数字

如果答案在 `1～100` 之间，你每次可以问“它比中间值大还是小”。

第一次猜 `50`：

- 如果答案更大，下一次只需要考虑 `51～100`。
- 如果答案更小，下一次只需要考虑 `1～49`。

每问一次，候选范围大约减半。100 个数通常最多 7 次，100 万个数通常最多约 20 次。这就是二分查找的核心。

## 2. 本题需要什么前置知识

开始阅读代码前，确认自己会下面几件事：

1. 数组长度是 `n` 时，合法下标是 `0～n-1`。
2. `while` 会在条件为真时反复执行。
3. `return` 会立即结束函数。
4. 函数中的数组参数还要额外传入长度，因为函数内不能靠 `sizeof` 得到原数组长度。
5. `arr[mid]` 表示“数组第 `mid` 个元素”，不是第 `mid` 个从 1 开始编号的元素。

如果这五项里有任何一项不熟，先回到数组和函数练习，不需要急着背二分模板。

## 3. 最重要的前提：数组必须有序

本程序要求数组从小到大排列：

```text
下标：   0   1   2   3   4   5   6   7
数组：   2   5   8  12  16  23  38  56
```

为什么有序如此重要？

程序看到中间元素 `arr[3] = 12`，目标 `16` 比 `12` 大。因为数组有序，所以从下标 `0` 到 `3` 的所有数都不可能比 `12` 大，也就不可能等于 `16`。于是可以放心丢掉整个左半边。

如果数组是：

```text
{5, 2, 8, 1, 9}
```

中间是 `8`，目标 `2` 比 `8` 小。程序会去左半边寻找，但 `2` 实际位于右边部分。局部比较无法再代表整个数组的顺序关系。

所以正确说法是：

> 二分查找的前提被破坏后，结果不再有保证。

不能说“二分查找偶尔会随机出错”。它严格依赖输入顺序。

## 4. 先固定区间的含义

源码使用：

```c
int left = 0;
int right = n - 1;
```

这表示搜索区间是：

```text
[left, right]
```

方括号表示两端都包含。例如：

```text
left = 2，right = 5
```

可能的下标是 `2、3、4、5`，共 `right - left + 1 = 4` 个。

不要把 `right` 理解成“当前元素个数”。它是最后一个可能位置的下标。

## 5. 中点怎样算

源码：

```c
int mid = left + (right - left) / 2;
```

先看一个普通例子：

```text
left = 0，right = 7
right - left = 7
7 / 2 = 3
mid = 0 + 3 = 3
```

当区间长度是偶数时，中点偏向左边。这样做没有问题，只要每轮都能缩小范围。

为什么不写：

```c
int mid = (left + right) / 2;
```

在两个数都很小时，两者结果相同。但当 `left` 和 `right` 很大时，`left + right` 可能先超过 `int` 上限，发生整数溢出。源码写法先算差值，可以避免这个中间加法溢出。

## 6. 跟着 `16` 走一遍

初始：

```text
left = 0
right = 7
target = 16
```

### 第 1 轮

```text
mid = 0 + (7 - 0) / 2 = 3
arr[3] = 12
12 < 16
```

目标在右边，排除 `mid` 及左半边：

```text
left = mid + 1 = 4
right = 7
```

### 第 2 轮

```text
mid = 4 + (7 - 4) / 2 = 5
arr[5] = 23
23 > 16
```

目标在左边，排除 `mid` 及右半边：

```text
left = 4
right = mid - 1 = 4
```

### 第 3 轮

```text
mid = 4 + (4 - 4) / 2 = 4
arr[4] = 16
```

相等，返回：

```c
return 4;
```

三轮后访问到 `16`。注意第 2 轮后 `left == right`，区间仍然有最后一个元素，因此必须继续检查一次。

## 7. 为什么循环条件必须是 `left <= right`

在闭区间 `[left, right]` 中，`left == right` 表示还剩一个元素。

例如：

```text
left = 4
right = 4
```

下标 `4` 仍需检查。如果写成：

```c
while (left < right)
```

那么 `left == right` 时循环会提前停止，可能漏掉答案。

当：

```text
left = right + 1
```

闭区间里已经没有元素，继续检查只会越界，所以循环结束。

可以记成：

```text
left <= right  区间非空
left > right   区间为空
```

## 8. 三个分支分别做什么

### 找到

```c
if (arr[mid] == target) {
    return mid;
}
```

一旦找到就立即返回，不再继续搜索。

### 目标更大

```c
left = mid + 1;
```

由于 `arr[mid] < target`，目标可能在右边。`mid` 本身已经检查过，所以新区间从 `mid + 1` 开始。

### 目标更小

```c
right = mid - 1;
```

由于 `arr[mid] > target`，目标可能在左边。`mid` 本身已经检查过，所以新区间到 `mid - 1` 为止。

`+1` 和 `-1` 有两个作用：

1. 不重复检查已经比较过的位置。
2. 保证搜索区间每轮严格缩小，避免死循环。

## 9. `show` 参数怎样工作

函数中的：

```c
if (show) {
    printf(...);
}
```

只决定要不要打印过程。搜索逻辑没有变化。

调用：

```c
binary_search(arr, n, 16, 1);
```

会打印每一轮。调用：

```c
binary_search(arr, n, target, 0);
```

只返回结果，不打印过程，适合自动测试。

这样把“算法”和“展示”分开，比把 `printf` 到处都是更清楚。

## 10. 空数组为什么安全

当 `n = 0`：

```text
left = 0
right = -1
```

循环条件：

```text
0 <= -1
```

结果为假，循环体一次也不执行，最后返回 `-1`。因此不会访问 `arr[0]`。

但这只说明“当前固定测试中的空长度调用安全”，不等价于函数能接受任意非法指针。如果 `n > 0` 却传入了 `NULL`，访问 `arr[mid]` 仍是未定义行为。通用函数应明确规定输入契约或增加检查。

## 11. 自动测试是怎样组织的

测试函数：

```c
int run_test(const char name[], const int arr[], int n, int target, int expected)
```

参数含义：

| 参数 | 含义 |
| --- | --- |
| `name` | 测试名称，失败时便于定位 |
| `arr` | 要搜索的数组 |
| `n` | 数组长度 |
| `target` | 目标值 |
| `expected` | 期望返回的下标或 `-1` |

调用示例：

```c
run_test("目标在中间（16）", arr, n, 16, 4);
```

函数内部实际调用：

```c
int result = binary_search(arr, n, target, 0);
```

如果 `result == expected`，返回 `1`；否则返回 `0`。`main` 用：

```c
passed += run_test(...);
```

累计通过数量。

这种“固定输入 + 预期值”的写法就是自动测试的入门形式。它比只用眼睛看输出更可靠，因为每个结果都有明确判断标准。

## 12. 13 个测试覆盖了什么

源码实际覆盖：

- 中间元素。
- 第一个元素。
- 最后一个元素。
- 位于两个元素之间的不存在值。
- 比最小值还小的目标。
- 比最大值还大的目标。
- 单元素数组找到与找不到。
- 两元素数组找左边和右边。
- 空数组。
- 两元素之间落空。

这些测试都不需要键盘输入，所以每次运行结果稳定，适合重复验证。

测试通过说明“函数在这些固定用例上符合预期”，并不自动证明它对所有可能输入都正确。更严格的正确性还要结合算法推理、边界分析和更多随机测试。

## 13. 无序数组的反例

程序第三部分使用：

```c
int messy[5] = {5, 2, 8, 1, 9};
```

查找 `2`：

```text
第 1 轮：mid = 2，arr[2] = 8，8 > 2，去左半边
第 2 轮：mid = 0，arr[0] = 5，5 > 2，区间变空
结果：-1
```

`2` 明明在下标 `1`，但算法没有检查右边，因为前面的比较错误地假定左边所有数都小于 `8`。

学习这道反例时，要能明确说出：

1. `binary_search` 的循环实现本身没有突然改变。
2. 出错的是调用者违反了“升序数组”前提。
3. 若要支持无序输入，应先排序，或者改用线性查找等方法。

## 14. 常见错误与定位方法

### 错误 1：死循环

现象：程序反复打印同一个 `left / right / mid`。

优先检查：

- `left = mid` 是否误写成没有 `+1`。
- `right = mid` 是否误写成没有 `-1`。
- 是否还有一个分支完全没有更新边界。

### 错误 2：首元素或尾元素找不到

优先检查：

- 初始 `right` 是否写成 `n`。
- 合法区间是不是 `0～n-1`。
- 循环条件是否漏掉 `left == right`。

### 错误 3：数组越界

常见原因：

- `right` 初始为 `n`。
- 访问了 `arr[mid]`，但 `mid` 已经落在合法范围外。
- 函数约定不明确，长度与数组真实大小不一致。

### 错误 4：找到后继续循环

若找到分支只给变量赋值而忘记 `return`，程序可能继续运行并改写结果。先检查找到分支的终止路径。

### 错误 5：输入无序却怪模板

先验证前提。二分查找不能自动识别数组是否有序，调用者有责任保证数据满足要求。
