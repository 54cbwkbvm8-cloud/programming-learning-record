# C 语言 10 月 18 日巴什博弈：文件简介与学习建议

## 文件简介

- **源码文件：** `29_2026-10-18_巴什博弈.c`
- **类型：** C 语言循环、输入校验与博弈论入门练习。
- **功能：** 程序接收石子总数 `stones` 和每次最多可取数 `maxTake`，计算最优首取数量，并在后续回合中根据对手取走的数量给出补数回应。
- **主要知识点：** `scanf` 返回值检查、取余运算 `%`、`while` 循环、`if / else`、局面变量更新、取法合法性检查、巴什博弈的余数策略。

巴什博弈的常见规则是：共有 `n` 颗石子，每轮至少取 1 颗、最多取 `m` 颗，取走最后一颗的人获胜。令

```text
r = n % (m + 1)
```

当 `r != 0` 时，先手先取 `r` 颗，之后对手取 `x` 颗，先手就取 `m + 1 - x` 颗。这样每一轮两人合计取走 `m + 1` 颗，最后一定由先手取到最后一颗。当 `r == 0` 时，当前先手没有必胜策略。

## 程序流程

1. 读入石子总数，要求它是正整数。
2. 读入每次最多可取数，要求它也是正整数。
3. 计算 `stones % (maxTake + 1)`，输出建议首取数量或“先手没有必胜策略”的提示。
4. 读入一个合法的首取数量，并减少剩余石子数。
5. 循环读取对手每轮取几颗，程序再取 `maxTake + 1 - opponentTake` 颗。
6. 如果剩余石子不够完成这个补数回应，程序只取走剩余数量，避免一次取走超过当前剩余数。
7. 任一方取到最后一颗后结束循环，并打印胜负结果。

这份程序是一份“策略演示”，不是完整的双人轮流输入程序。首取之后，用户持续输入“对手”的取法，程序演示自己应该如何回应。

## 建议运行数据

在仓库根目录编译并运行：

```bash
clang -std=c17 -Wall -Wextra -Wpedantic -Werror \
  "06_C语言练习/29_2026-10-18_巴什博弈.c" \
  -o /tmp/bash_game
/tmp/bash_game
```

建议输入：

```text
10
3
2
1
1
```

这组数据的含义是：

| 输入 | 含义 |
| --- | --- |
| `10` | 一共有 10 颗石子 |
| `3` | 每轮最多取 3 颗 |
| `2` | 先手按照提示取 2 颗，留下 8 颗 |
| `1` | 对手第一轮取 1 颗 |
| `1` | 对手第二轮取 1 颗 |

实测关键输出：

```text
提示：按照必胜策略，你应该先取 2 颗石子。
你先取 2 颗，剩余 8 颗。
程序回应取走 3 颗，还剩 4 颗。
程序回应取走 3 颗，还剩 0 颗。
程序取到了最后一颗石子，程序获胜。
```

如果先手故意不按提示，例如输入 `10`、`3`、`1`，再让对手连续取 1 颗，实际运行会出现：

```text
你先取 1 颗，剩余 9 颗。
程序回应取走 3 颗，还剩 1 颗。
对手取走 1 颗后，还剩 0 颗。
对手取到了最后一颗石子，对手获胜。
```

这说明程序允许玩家输入任意合法首取，但“必胜”建立在先取数量确实等于余数的前提上。它不是在判定每个中间局面后重新计算最优策略。

程序还检查了非法初始输入。输入石子总数 `0`，或把最多可取数输入为 `0`，都会打印错误信息并返回状态码 `1`。文档中的正常路线、故意偏离策略路线和非法输入路线都经过了实际运行验证。

## 零基础学习建议

1. **先把 `%` 读成“求余数”。** `10 % 4` 等于 2，因为 `10` 可以放满 2 组 `4`，还剩 `2`。这里把每组的固定数量设成 `maxTake + 1`，所以余数就是先手应当先取走的数量。
2. **把目标局面想成“成组取走”。** 先手取走余数后，剩余石子数可以全部按 `maxTake + 1` 分组。对手拿 `x` 颗，程序就补到这一组正好取完。
3. **盯住三行核心逻辑。** `remainder = stones % (maxTake + 1);` 负责判断首取策略，`myTake = maxTake + 1 - opponentTake;` 负责补数，`stones -= myTake;` 负责更新局面。
4. **理解最后一段保护。** 当 `myTake > stones` 时，程序把它改成 `stones`，因为不能取走比剩余数量还多的石子。
5. **先画表格再写代码。** 对 `stones = 10`、`maxTake = 3` 手动列出剩余 `10、8、7、4、3、0` 的变化，比直接背公式更容易理解。
6. **自己走一遍两条路线。** 先按提示首取，确认程序每次都能把局面补成固定余数；再把首取改成别的数字，观察策略失配后的结果。
7. **达到独立解释的程度。** 合上代码后，应该能说清为什么余数不为 0 时先手能掌控局面，余数为 0 时为什么不能保证先手获胜。

## 常见易错点

- 把“巴什博弈”写成“巴士博弈”。“巴什”是 Bash Game 的中文常见译名，源码中的提示也是“巴什博弈”。
- 只判断石子是否大于 0，却不检查 `scanf` 是否真的读到整数。输入字母时，必须检查返回值。
- 在后续循环里只检查 `opponentTake <= maxTake`，忘记检查它不能超过当前剩余石子数。
- 对手输入非法时直接退出。源码会打印提示并 `continue`，重新读取这一轮。
- 误以为程序会始终获胜。程序是在演示固定补数策略；如果首取没有留下 `maxTake + 1` 的整数倍，局面可能已经被破坏。
- 忘记更新 `stones`。取走石子后不更新剩余数，循环条件和胜负判断都会出错。
- 直接计算 `maxTake + 1` 时忽略整数上限。如果用户输入 `INT_MAX`，加法可能溢出；做更健壮的版本时可以先用 `long long`，或显式限制 `maxTake` 的最大值。
- 把“先手没有必胜策略”理解成“先手一定输”。它表示在双方都采用最优策略时，先手没有保证获胜的办法，不代表每一步都会输。
