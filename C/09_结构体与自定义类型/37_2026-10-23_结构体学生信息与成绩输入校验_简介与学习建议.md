## 程序功能说明

### 用结构体把相关数据放在一起

程序先定义：

```c
struct Student {
    char name[50];
    int age;
    float score;
};
```

`Student` 不是变量，而是“学生记录长什么样”的类型说明。每个 `struct Student` 变量都包含三个成员：

- `name`：长度为 50 的字符数组，用来保存姓名文本。
- `age`：整数，用来保存年龄。
- `score`：单精度浮点数，用来保存成绩。

这种组织方式比分别声明 `name1`、`age1`、`score1`、`name2`、`age2`、`score2` 更清楚，因为“同一个学生的数据”被放在了一起。

### 初始化并访问成员

```c
struct Student student1 = {"张三", 18, 90.5f};
struct Student student2 = {"李四", 19, 85.0f};
```

初始化列表按照成员声明顺序，依次给 `name`、`age`、`score` 赋值。`90.5f` 末尾的 `f` 表示这个字面量按 `float` 使用。

访问成员时使用点运算符：

```c
student1.name
student1.age
student1.score
```

输出时，`name` 用 `%s`，`age` 用 `%d`，`score` 用 `%.2f`。成员类型、传入数据和格式符必须互相对应。

### 读取并检查一次成绩

学生 1 的输入循环可以分成四步：

1. `scanf("%f", &a) != 1`：检查是否成功读到一个浮点数。失败时说明输入开头不是数字。
2. 第一个 `while ((ch = getchar())...)`：读取失败后清掉这一行剩余字符，防止它们影响下一次输入。
3. 读取成功后，再用 `getchar()` 检查数字后面是否还有空格之外的字符。因此 `90abc` 不会被当成合法的 `90`。
4. `!(a >= 0 && a <= 100)`：检查成绩是否在闭区间 `0～100` 内；不合格就重新提示输入。

允许的输入是数字以及数字后的空格、制表符、回车符，最后以换行结束。若数字后直接遇到 `EOF`，这一个字段的尾部检查会放行；但程序还需要读取另一个成绩时，下一次读取会失败并返回 `1`。因此在完整的交互流程中，仍应提供两行有效输入。

验证成功后：

```c
student1.score = a;
```

程序只修改成绩成员，姓名和年龄保持不变。学生 2 使用同样的流程，最后再次输出两名学生的信息。

### 为什么需要临时变量 `a` 和 `b`

程序先把输入读到临时变量，确认格式和范围都合格后，才写入 `student1.score` 或 `student2.score`。这样无效输入不会提前覆盖原来的成绩。当前两个流程分开写成 `a` 和 `b`，便于初学阶段逐步阅读，但后期可以把重复逻辑提取成函数。

## 学习重点

1. **分清类型和变量。** `struct Student` 是类型，`student1` 和 `student2` 才是实际变量。
2. **理解成员的整体关系。** `student1.name`、`student1.age` 和 `student1.score` 描述同一个人，不要把它们当成三份互不相关的数据。
3. **掌握点运算符。** 读取和修改普通结构体变量的成员都使用 `.`。
4. **理解字符数组容量。** `name[50]` 表示最多保存 49 个普通 ASCII 字符再加结尾的 `'\0'`；中文按 UTF-8 编码会占多个字节。
5. **理解 `scanf` 的返回值。** 它返回成功读取的项数，不能只看变量里有没有内容。
6. **理解为什么检查数字后的字符。** `%f` 读到 `90` 后会停在 `a`，如果不清掉并拒绝，程序可能把 `90abc` 误当成正确成绩。
7. **理解范围检查。** 成绩是否合法不仅取决于是否“能读成数字”，还要检查业务范围。
8. **保留输入校验的价值。** 先验证、再写回字段，可以让错误输入不破坏原来的数据。

## 学习难点

- 把结构体定义和结构体变量混为一谈。
- 初始化时成员顺序与结构体声明顺序不一致，导致成绩或年龄写错位置。
- 输出 `float` 时误用 `%d`，或输入时漏写 `&a`。
- `scanf` 失败后不清理输入缓冲区，导致程序反复读取同一个错误字符。
- 只检查 `scanf` 是否成功，却不检查后面是否跟着多余字符。
- 只接受数字，却忘记检查 `0～100` 的业务范围。
- 看到 `while` 里有多个 `continue` 就失去执行线索。阅读时应先判断本轮是“读取失败”“格式不完整”还是“范围不合法”，再找对应的重新开始位置。
- 认为 `char name[50]` 一定能容纳 50 个中文姓名。实际容量取决于每个字符占多少字节。
- 忽略 `EOF`。交互输入通常以换行结束，但重定向文件或关闭输入时可能直接遇到文件结束。

## 零基础学习流程

1. **先画一条学生记录。** 写出 `Student` 的三个字段，再在字段旁边分别标注类型。
2. **手动展开 initialization。** 对照声明顺序，确认 `"张三"`、`18`、`90.5f` 分别进入哪个成员。
3. **只看输出部分。** 说明为什么 `name` 使用 `%s`、`age` 使用 `%d`、`score` 使用 `%.2f`。
4. **只跟踪学生 1 的正常输入。** 输入 `95` 后，依次记录 `scanf` 返回 `1`、`a` 变成 `95.0`、最后写入 `student1.score`。
5. **分别制造三类错误。** 先输入一个字母，再输入 `101`，最后输入 `90abc`；每类错误都要说出程序走了哪个分支。
6. **用边界值检查条件。** 输入 `-0.01`、`0`、`100`、`100.01`，判断哪些数据会被接受。
7. **观察重复代码。** 对比学生 1 和学生 2 的两段 `while`，找出只有变量名和输出对象不同的部分。
8. **关闭源码复写。** 先完成一个学生的结构体和成绩修改，确认无误后再复制思路处理第二个学生。

## 常见易错点与测试用例

| 测试输入或操作 | 预期行为 | 检查目的 |
| --- | --- | --- |
| 学生 1 输入 `95`，学生 2 输入 `88.5` | 分别保存为 `95.00`、`88.50` | 正常小数输入 |
| 学生 1 输入 `0`，学生 2 输入 `100` | 两个值都接受 | 闭区间边界 |
| 学生 1 输入 `-0.01` 后输入 `60` | 第一次被拒绝，第二次接受 | 小于下限 |
| 学生 2 输入 `100.01` 后输入 `70` | 第一次被拒绝，第二次接受 | 大于上限 |
| 输入 `abc` 后输入合法数字 | 提示格式错误，再读一次 | `scanf` 失败与缓冲区清理 |
| 输入 `90abc` 后输入合法数字 | 提示数字不完整，再读一次 | 数字后的多余字符 |
| 输入 `nan` | 被范围检查拒绝 | 比较运算对非普通数值的结果 |

常见错误及原因：

- **错误：** `scanf("%f", a)`。**原因：** `a` 是普通浮点变量，`scanf` 需要写入它的地址。**修改：** 使用 `&a`。
- **错误：** 用 `%d` 输出 `student1.score`。**原因：** 类型和格式符不匹配，输出结果不可靠。**修改：** 使用 `%.2f`。
- **错误：** `scanf` 失败后立刻再次调用，却不清理输入。**原因：** 错误字符仍在缓冲区。**修改：** 用 `getchar()` 读到行尾。
- **错误：** 数字读取成功后直接赋值，不检查 `0～100`。**原因：** `999` 也是合法数字，但不是合法成绩。**修改：** 增加范围判断后再写回成员。
- **错误：** 只测试一次正常输入就认定程序完整。**原因：** 输入校验的价值主要体现在错误和边界输入。**修改：** 至少覆盖上表中的正常、边界和非法情况。
