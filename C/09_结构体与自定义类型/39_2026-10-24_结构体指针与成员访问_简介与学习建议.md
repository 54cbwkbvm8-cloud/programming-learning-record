## 程序功能说明

### 结构体变量和结构体指针

```c
typedef struct {
    int id;
    char name[NAME_LENGTH];
    float score;
} Student;
```

`Student s` 是一块真实的学生记录，包含 `id`、`name`、`score` 三个成员。

```c
Student *p = &s;
```

这里有两层含义：

1. `&s` 取得结构体变量 `s` 的地址。
2. `Student *p` 声明一个“指向 `Student` 类型对象的指针”，并用 `s` 的地址初始化。

因此：

- `p` 本身保存的是地址。
- `*p` 表示“p 指向的那条 `Student` 记录”。
- `&p` 表示“指针变量 p 自己的地址”，它与 `&s` 不是同一个对象。

程序比较 `p == &s`，结果为真，因为两者保存的地址相同。

### 三种成员访问写法

| 写法 | 前面是什么 | 怎样理解 |
| --- | --- | --- |
| `s.score` | 结构体变量 | 直接访问 `s` 的成员 |
| `p->score` | 结构体指针 | 沿着 `p` 找到记录，再访问 `score` |
| `(*p).score` | 解引用后的结构体 | 先用 `*p` 得到记录，再用 `.score` 访问成员 |

`p->score` 是 `(*p).score` 的常用简写。圆括号不能省，因为成员访问运算符 `.` 的优先级高于解引用运算符 `*`。写成 `*p.score` 会被理解成 `*(p.score)`，但 `p` 没有名为 `score` 的成员，属于错误写法。

三种写法输出相同的 `80.00`，因为它们最终访问的是同一条学生记录中的同一个 `score` 成员。

### 地址输出

```c
printf("%p\n", (void *)&s);
printf("%p\n", (void *)p);
```

`%p` 用于输出指针地址，实参转换为 `void *` 是常见的规范写法。

本次运行中两个地址相同，但具体地址会随进程、系统和每次运行变化，不能把某个十六进制地址当成程序结果的一部分。真正稳定可验证的是：

- `p` 保存的地址等于 `&s`。
- `p == &s` 的判断为真。

### 通过指针修改结构体

```c
void change_score(Student *p, float new_score) {
    p->score = new_score;
}
```

调用：

```c
change_score(p, new_score);
```

函数收到的是地址副本，但地址仍指向 `main` 中的 `s`。因此 `p->score = new_score` 修改的是原结构体，而不是另一个独立副本。

调用前后：

- `s.score` 从 `80.00` 变为 `95.50`。
- `p->score` 也显示 `95.50`，因为 `p` 指向同一个 `s`。

如果函数参数写成 `Student p`，函数只会收到整条记录的副本，修改 `p.score` 不会改变 `main` 中的 `s`。

## 指针安全边界

当前 `change_score` 没有检查 `p == NULL`。本文件只传入 `&s`，地址一定有效，所以现有调用路径是安全的。

如果把该函数扩展成可重复使用的公共函数，直接执行 `p->score` 前必须先检查空指针。例如：

```c
if (p == NULL) {
    return;
}
```

或者在设计成返回状态的版本中返回错误码。空指针是合法指针值，但不能被解引用；解引用空指针会产生未定义行为，而不是普通的可恢复错误。

## 学习重点

1. **分清 `s` 和 `p`。** `s` 是整条学生记录，`p` 是保存 `s` 地址的指针变量。
2. **分清 `p` 和 `*p`。** `p` 的值是地址，`*p` 才是地址指向的结构体记录。
3. **理解 `&` 和 `*` 的配对关系。** `p = &s` 建立指向关系，`*p` 沿着这个关系取回 `s`。
4. **掌握 `p->score`。** 它是“指针指向结构体并访问成员”的常用语法。
5. **理解三种写法的等价性。** `s.score`、`p->score`、`(*p).score` 在当前指向关系下访问同一成员。
6. **理解函数为什么能修改原变量。** 指针参数让函数得到原对象地址，解引用或 `->` 后写入的是原对象。
7. **理解地址输出不能做固定值比较。** 地址会变化，应该比较 `p == &s`，而不是比较某次打印的十六进制文本。
8. **理解空指针边界。** 指针变量可以保存 `NULL`，而 `NULL` 不能用于成员访问。

## 学习难点

- 把 `p` 保存的地址和 `*p` 指向的结构体数据混为一谈。
- 误以为 `p` 是结构体本身，尝试写 `p.score`。
- 忘记用括号，写成错误的 `*p.score`。
- 把 `&p` 当成 `p` 保存的地址。`p` 指向 `s`，而 `&p` 是“指针变量 p 自己”的地址。
- 以为函数形参 `Student *p` 是原指针变量本身。传入的是地址副本，但地址指向的对象没有复制。
- 认为打印地址不同就代表指向不同。编译器、调试器和运行时布局都可能改变具体地址；关键是地址值是否相等。
- 直接对未初始化的指针或空指针使用 `->`，造成未定义行为。
- 把 `Student *p = s;` 当成合法初始化，混淆结构体值和结构体地址。

## 零基础学习流程

1. **先不运行，画出两个对象。** 画一个结构体格子 `s`，再画一个指针格子 `p`，箭头从 `p` 指向 `s`。
2. **跟踪初始化。** 说明 `p` 保存的是 `&s`，不是整条结构体记录的副本。
3. **手工读三种写法。** 依次把 `s.score`、`p->score`、`(*p).score` 翻译成“s 的成绩”“p 指向的学生成绩”“解引用 p 后取成绩”。
4. **先预测再运行。** 预测三种写法的输出，并观察地址是否相同。
5. **只改一个值。** 把 `new_score` 改为 `88.0f`，确认 `s.score` 和 `p->score` 同时变化。
6. **对照值传递。** 临时写一个接收 `Student` 值的函数，观察修改只会作用于副本；不要覆盖仓库原文件。
7. **制造编译错误。** 在临时副本中故意写 `p.score` 和 `*p.score`，阅读编译器错误，再恢复正确写法。
8. **独立重写。** 关闭源码，自己写结构体、指针初始化、三种访问写法和一个通过指针修改成员的函数。
9. **口头复盘。** 能解释“p 存了什么、*p 是什么、-> 省掉了哪一步、函数为什么改到原结构体”。

## 常见易错点与测试用例

| 检查操作 | 预期结果 | 检查目的 |
| --- | --- | --- |
| 比较 `p == &s` | 为真 | 指针是否指向同一个对象 |
| 比较 `p` 与 `&p` | 不相等 | 区分指向对象的地址和指针变量自身地址 |
| 输出 `s.score`、`p->score`、`(*p).score` | 三者都是 `80.00` | 三种成员访问等价 |
| 调用 `change_score(p, 95.5f)` | `s.score` 变为 `95.50` | 指针参数修改原对象 |
| 把 `new_score` 改为 `0.0f` | 原结构体成绩变为 `0.00` | 修改效果不依赖具体数值 |
| 调用 `change_score(NULL, 90.0f)` | 当前代码会解引用空指针 | 不能安全执行，只用于说明扩展前的风险 |

最后一组空指针调用没有在仓库源码中执行。当前函数只有在调用者保证地址有效时才安全。
