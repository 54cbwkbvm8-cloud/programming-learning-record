## 原始版与修正版

原始版第五题代码块在 `}` 后没有及时写块注释结束符 `*/`。下一段“详细中文注释版”开头的 `/*` 因此嵌在当前块注释中，直到详细说明的结束 `*/` 才把外层注释关掉。

这种结构在不加 `-Werror` 时通常仍能编译，因为后面的 `*/` 最终结束了外层注释，但详细说明开头会被吞掉，而且 Clang 会给出 `'/*' within block comment` 警告。按仓库的严格检查方式加上 `-Werror` 后，编译会失败。

修正版只做了最小修复：在原来的第五题代码块后补上一个 `*/`。原始版继续保留，方便观察“块注释结束位置错误会改变后续文本的编译含义”这一真实问题。

阅读顺序：

1. 先看原卷，独立写下五道题的输入、输出和思路。
2. 打开原始版，找到第 78～121 行附近，解释为什么详细说明开头的 `/*` 会产生嵌套注释警告，以及后面的 `*/` 实际关闭了哪一段。
3. 对比修正版，确认只增加了一个注释结束符。
4. 分别用 `RUN_Q1` 到 `RUN_Q5` 编译五道题。
5. 最后再读源码中的详细注释和本说明，不先照抄答案。

## 五道题总览

| 题目 | 主要任务 | 关键知识 | 当前固定结果 |
| --- | --- | --- | --- |
| 第一题 | 从 100 到 1 倒序输出 4 的倍数并计数 | `for`、自减、取余、计数器 | 100、96、……、4，共 25 个数 |
| 第二题 | 在价格数组 `{4, 9, 6, 13}` 中找和为 19 的两个下标 | 数组、双层循环、去重遍历 | `[2,3]` |
| 第三题 | 直接枚举三位和积数 | 整数除法、取余、复合条件 | `135`、`144` |
| 第四题 | 把和积数判断封装成函数 | 函数参数、返回值、局部变量、范围校验 | `135`、`144` |
| 第五题 | 判断取石子游戏先手是否必胜 | 巴什博弈、模运算、`scanf`、`bool` | 输入 `19 5` 时输出 `true` |

“和积数”的规则是：

```text
(百位 + 十位 + 个位) × (百位 × 十位 × 个位) = 原三位数
```

例如 `135`：

```text
(1 + 3 + 5) × (1 × 3 × 5) = 9 × 15 = 135
```

所以 `135` 是和积数。三位数的百位、十位、个位可以分别用 `n / 100`、`n / 10 % 10`、`n % 10` 提取。

## 条件编译的运行方式

一个普通 C 程序只能有一个 `main` 函数。本文件把五道完整程序的 `main` 放在不同的预处理分支中，编译时通过 `-DRUN_Q1` 到 `-DRUN_Q5` 只选择一道。

在仓库根目录编译第一题：

```bash
clang -std=c17 -Wall -Wextra -Wpedantic -Werror -DRUN_Q1 \
  "C/14_综合项目/44_2026-10-30_软件协会入门考试五题综合练习_修正版.c" \
  -o /tmp/c_exam_q1
/tmp/c_exam_q1
```

把宏和输出文件替换成对应题目即可：

| 题目 | 编译宏 | 临时程序 |
| --- | --- | --- |
| 第一题 | `-DRUN_Q1` | `/tmp/c_exam_q1` |
| 第二题 | `-DRUN_Q2` | `/tmp/c_exam_q2` |
| 第三题 | `-DRUN_Q3` | `/tmp/c_exam_q3` |
| 第四题 | `-DRUN_Q4` | `/tmp/c_exam_q4` |
| 第五题 | `-DRUN_Q5` | `/tmp/c_exam_q5` |

如果不加任何 `RUN_Q*` 宏，文件会通过 `#error` 提醒“请选择一道题”。这是有意的保护，不是漏写代码。

## 建议测试数据

### 第一题

程序不需要输入。正常输出应从 `100` 开始，每次减少 4，最后到 `4`，末尾统计为：

```text
一共有25个数
```

```text
prices[0] = 4
prices[1] = 9
```

`prices[2] + prices[3] = 6 + 13 = 19`，正常输出：

```text
[2,3]
```

第四题还可以手工跟踪一次 `is_sum_product(135)`：

| 表达式 | 结果 |
| --- | --- |
| `135 / 100` | `1` |
| `135 / 10 % 10` | `3` |
| `135 % 10` | `5` |
| `(1 + 3 + 5) * (1 * 3 * 5)` | `135` |

### 第五题

先手必胜条件是：

```text
n % (m + 1) != 0
```

先手第一步应取：

```text
n % (m + 1)
```

代表性测试：

```text
19 5
```

`19 % (5 + 1) = 1`，先手第一步取 1 颗，输出：

```text

```

```text

```


## 学习重点

1. **条件编译不是普通 `if`。** `#if`、`#elif`、`#else` 在真正编译前完成选择，每次只留下一个 `main`。`#error` 适合阻止错误构建。
2. **循环边界要包含题目范围。** 第一题 `i > 0` 会检查 100 到 1；第三、四题 `num <= 999` 才会包含 999。
3. **数组遍历要防止重复和自配对。** 第二题内层从 `i + 1` 开始，既避免同一商品使用两次，也避免把 `[2,3]`、`[3,2]` 重复检查。
4. **`int` 加法可能溢出。** 修正版先把价格转换为 `long long` 再相加，比直接计算 `prices[i] + prices[j]` 更安全。
5. **函数内部的局部变量更容易推理。** 第四题把百位、十位、个位放在函数内部，避免不同函数误用同一组全局变量。
6. **输入成功与数值合法要分别检查。** 第五题先检查 `scanf` 是否读到两个数，再检查 `n`、`m` 是否为正数。
7. **大数运算要处理边界。** `m == LLONG_MAX` 时不能直接计算 `m + 1`；修正版专门处理了这个情况。
8. **格式字符串不能直接放用户数据。** 原作答中有把判断结果直接当 `printf` 格式字符串的写法。修正版使用固定格式字符串：

```c
printf(first_win(n, m) ? "true\n" : "false\n");
```

这里两个格式串都写在代码中，没有 `%`，所以安全；更直观的写法也可以拆成普通 `if / else`。

## 原卷与解析中需要核对的地方

两份 Word 资料保留了当时的作答与讲解，但其中存在几处互相冲突或计算不完整的内容，复习时以代码实际运行和自己的推导为准：

- 选择题第 1 题原卷标记为 B，解析给出的正确答案是 A。`%c` 输出字符 `A`，所以 A 正确。
- 填空题第 1 题原卷写 `10 12 13 5`，解析写 `10 12 5`，两处都不准确。按实际循环，`i = 0` 时输出 `10`，`i = 1` 时输出 `11`，`i = 2` 时执行 `continue`，`i = 3` 时输出 `13`，`i = 4` 时执行 `break`，最后输出外层 `x = 5`；正确答案是 `10 11 13 5`。
- 填空题第 2 题解析给出的 `1 15` 正确。函数按值接收 `a[0]` 不会修改数组首元素；`p` 指向 `a[2]`，所以 `p[-1]` 是 2，指针值加 10 后 `p[0]` 是 13。
- 填空题第 5 题原卷写 `2F`，解析写 `2D`。二进制 `101101 = 32 + 8 + 4 + 1 = 45`，十六进制是 `2D`，所以 `2D` 正确。
- Word 中的作答代码存在拼写、大小写和语法错误，例如 `mian`、`Int`、`Return`、下标拼写以及未声明的变量。它们适合作为“找出并修复错误”的材料，但不要直接复制运行。

原卷中的题目本身仍可用来练习；上述提醒只用于防止把解析中的笔误当成标准答案。

## 适合初学者的学习流程

1. **先按题目练，不按源码顺序死背。** 每道题先写一句输入、处理、输出说明。
2. **先读原稿的错误。** 在原始版中定位错位的块注释边界，比较加与不加 `-Werror` 时的编译结果。
3. **对比最小修复。** 找出修正版新增的唯一注释结束符，不把修复扩大到无授权的算法改写。
4. **逐题编译。** 每次只定义一道题的宏，观察没有宏时 `#error` 的保护效果。
5. **手工跟踪变量。** 第一题跟踪 `i` 和 `count`，第二题跟踪 `i`、`j`，第四题跟踪 `a`、`b`、`c`。
6. **修改一个条件。** 例如只改第一题起点，或只改第二题 `money`，记录输出变化。
7. **补边界测试。** 第五题至少测试余数为 0、余数不为 0、非法输入和极大 `m`。
8. **独立重写。** 先分别写五个小文件，再把其中三题合成一个带菜单的程序。

## 易错点

- 把 `#if` 当成运行时分支，忘记它决定的是“哪段代码参与编译”。
- 没有定义 `RUN_Q*` 就直接编译，把有意的 `#error` 误认为文件损坏。
- 第一题写成 `i >= 0` 后输出 0；0 是 4 的倍数，但题目范围是 1～100。
- 第二题内层从 0 开始，导致重复组合或同一商品使用两次。
- 用 `sizeof(prices)` 得到的是数组总字节数，不是元素个数；除法后类型是 `size_t`，不能随便用 `%d`。
- 和积数拆位混淆为 `n / 10`、`n % 100` 等不完整表达式。
- `bool` 函数需要包含 `<stdbool.h>`，并用 `true`、`false` 表达结果。
- 第五题只检查输入范围而忘记检查 `scanf` 是否成功，输入字母后可能继续使用未赋值数据。
- 计算 `n % (m + 1)` 前不处理 `m + 1` 的溢出边界。
