# C 语言 10 月 18 日考试四题综合练习：文件简介与学习建议

## 文件简介

- **源码文件：** `30_2026-10-18_考试四题综合练习.c`
- **类型：** C 语言阶段考试综合练习，四道题放在同一个 `main` 函数中顺序执行。
- **功能：**
  1. 输出 1 到 100 之间的全部奇数。
  2. 在固定数组 `{2, 7, 11, 15}` 中查找和等于 `9` 的两个下标。
  3. 输出 100 到 999 之间的全部水仙花数。
  4. 演示巴什博弈的余数策略和补数回应。
- **主要知识点：** `for`、嵌套循环、`if`、取余 `%`、数组下标、整数除法拆位、水仙花数判断、`scanf` 返回值检查、`while` 循环和巴什博弈。

前三个题目不需要输入，程序运行后会依次输出结果；第四题会等待输入。因此运行时需要把巴什博弈的测试数据一起传给程序。

## 四道题的核心

### 第一题：1 到 100 的奇数

```c
for (i = 1; i <= 100; i++) {
    if (i % 2 != 0) {
        printf("%d\n", i);
    }
}
```

`i % 2` 的余数不为 `0` 时，`i` 就是奇数。列表一共有 50 个奇数，从 `1` 到 `99`。

### 第二题：两数之和

外层下标 `m1` 从 `0` 到 `3`，内层下标 `n1` 从 `m1 + 1` 到 `3`。这样每一对不同的下标只会检查一次：

```c
if (nums[m1] + nums[n1] == target) {
    printf("[%d,%d]\n", m1, n1);
}
```

当前数组的答案下标是 `[0,1]`，对应数字 `2 + 7 = 9`。

### 第三题：水仙花数

水仙花数是一个三位数，它的百位、十位、个位数字的立方和等于原数。程序用整数除法和取余拆位：

```c
a = numbers / 100;
b = numbers / 10 % 10;
c = numbers % 10;
```

例如 `153` 的数字是 `1`、`5`、`3`，而 `1³ + 5³ + 3³ = 153`，所以它是水仙花数。100 到 999 之间共有 `153`、`370`、`371`、`407` 四个。

### 第四题：巴什博弈

令石子总数为 `n`，每轮最多取 `m` 颗，则先手应取：

```text
n % (m + 1)
```

取走这个余数后，后续每轮对手取 `x` 颗，程序就取 `m + 1 - x` 颗，使两人一轮合计取走固定的 `m + 1` 颗。如果余数为 `0`，当前先手没有必胜策略。

## 零基础学习建议

1. **先说清每道题的输入和输出。** 前三个题没有输入，第四题要求先输入石子总数和上限，再输入每轮取法。先确定输入格式，再运行程序。
2. **把 `for` 分成三段读。** 初始化、继续条件、每轮更新。第一题遍历 1 到 100，第三题遍历 100 到 999，第二题则用两个下标的组合遍历数组。
3. **重点理解整数除法和取余。** `/` 取商的整数部分，`%` 取余数。拆三位数和判断奇偶都依赖这两个运算。
4. **理解两数之和的双层循环。** 内层从 `m1 + 1` 开始，保证两个下标不同，也避免把同一对元素重复检查。
5. **记住巴什博弈的两个动作。** 首取余数，之后补到 `m + 1`。如果 `n % (m + 1) == 0`，则先手没有必胜策略。
6. **先手不要只看提示。** 程序允许输入任意合法首取；只有首取等于余数时，后续固定补数策略才能保证同一套必胜演示成立。
7. **达到独立复现的程度。** 合上文件后，能分别写出奇数筛选、水仙花数判断和两数之和的核心循环，并能用水位数和每轮取数解释巴什博弈的步骤。

## 常见易错点

- 第二题把内层写成 `n1 = 0`，会重复检查组合，也可能让一个元素和自己相加。
- 第二题把循环上界写死为 `4`。当前数组固定为 4 个元素时能运行，但修改数组后必须同步修改上界；更稳妥的写法是用 `sizeof(nums) / sizeof(nums[0])`。
- 第二题直接写 `nums[m1] + nums[n1]`。普通测试数据没有问题，但如果元素接近 `int` 上限，和可能溢出，可以先转成 `long long`。
- 水仙花数拆位时把 `a`、`b`、`c` 的含义弄反，或把十位写成 `numbers % 10`。
- 用 `pow()` 计算立方时忘记包含 `math.h`，或者把浮点结果直接与整数比较。本题直接用整数乘法，避免这个问题。
- 巴什博弈中忘记检查 `scanf` 的返回值，输入字母时程序会带着未定义或旧的值继续运行。
- 巴什博弈的每轮取法没有检查“不能超过当前剩余石子数”，可能出现负数。
- `m + 1` 在 `m == INT_MAX` 时可能溢出；做更健壮的版本时要限制输入范围或使用更宽的类型。
- 以为程序会重新计算每一步的最优策略。它只是按“首取余数、后续补数”的固定策略演示，首取偏离后不一定还能获胜。
