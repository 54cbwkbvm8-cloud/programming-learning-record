## 程序整体结构

### 数据模型

```c
typedef struct {
    int id;
    char name[NAME_LENGTH];
    float score;
} Student;
```

程序使用固定数组：

```c
Student students[MAX_STUDENTS];
int count;
```

- `MAX_STUDENTS` 是 100，表示最多保存 100 条记录。
- `count` 表示当前实际保存了多少条。
- 数组容量始终是 100，但只有 `students[0]` 到 `students[count - 1]` 是有效数据。

### 函数职责

| 函数 | 职责 |
| --- | --- |
| `read_line` | 读取一整行，处理超长输入和输入结束 |
| `read_int_range` | 读取并校验指定范围内的整数 |
| `read_score` | 读取 `0～100` 的有限浮点数 |
| `read_name` | 读取姓名，去掉首尾空白并拒绝空姓名 |
| `find_student_by_id` | 按学号查找数组下标 |
| `display_students` | 输出全部学生 |
| `calculate_average` | 计算平均成绩 |
| `find_highest_score` | 返回最高分学生下标 |
| `show_highest_score` | 输出最高分学生 |
| `modify_student_score` | 按学号修改成绩 |
| `add_student` | 检查容量并添加一名学生 |
| `input_student` | 检查重复学号，再输入姓名和成绩 |
| `show_menu` | 输出菜单 |
| `main` | 组织初始录入和菜单循环 |

阅读程序时不要从 `main` 第一行开始硬背到底。先看 `Student` 保存什么，再看输入函数如何保证数据合法，最后看菜单怎样调用业务函数。

## 输入层为什么要单独拆出来

早期使用 `scanf("%d", &id)` 时，如果输入 `12abc`，可能只读到 12，把 `abc` 留在缓冲区，后面的输入就会错位。本程序改用整行读取：

1. `fgets` 一次读入一整行。
2. 去掉末尾换行。
3. 如果一行过长，清掉剩余字符并提示重新输入。
4. `strtol` 或 `strtof` 解析完整字符串。
5. 跳过尾部空白后，必须真的到达 `'\0'`，拒绝 `12abc` 和 `80分` 这类残留字符。
6. 再检查最小、最大范围和 `errno`。

这比直接使用 `scanf` 更复杂，但错误恢复更可靠，是综合项目值得学习的地方。

## 各功能怎样连接

### 初始录入

`main` 先读取学生人数，要求 `3～100`。最小人数为 3 是当前业务规则，不是数组本身的限制。

然后逐条调用 `input_student`。每添加一名学生：

1. 读取学号并检查范围。
2. 在已有记录中检查学号是否重复。
3. 读取姓名并去掉首尾空白。
4. 读取 `0～100` 的成绩。
5. 写入 `students[i]`。

### 显示全部

`display_students` 从下标 0 遍历到 `count - 1`。`count` 不能超过 100，否则会越界。

### 平均成绩

`calculate_average` 累加所有成绩后除以 `count`。有效调用时 `count >= 3`；函数也处理了 `count <= 0`，返回 0，避免除零。

### 最高分

`find_highest_score` 先假设下标 0 是最高分，再从下标 1 开始比较。使用 `>` 而不是 `>=`，所以并列最高分保留最先出现的学生。

### 修改成绩

`modify_student_score` 先按学号查找。找到后读取新成绩，只有输入合法才写入原记录。没有找到时保持数据不变。

### 添加学生

`add_student` 先检查 `*count >= MAX_STUDENTS`。如果已满，函数打印提示后返回，不写入数组。否则把新记录写到 `students[*count]`，再把人数加一。

这里必须传入 `int *count`，因为函数需要修改调用者中的人数。如果只传 `int count`，函数内部增加的值会在返回后丢失。

## 学习重点

1. **先理解 `count`。** 数组有 100 个格子，不等于当前有 100 名学生。
2. **理解结构体数组。** `students[i]` 是一条记录，`students[i].score` 是成绩字段。
3. **理解函数职责。** 输入函数负责合法性，业务函数负责查找、统计和修改，`main` 负责流程。
4. **理解整行解析。** `fgets + strtol/strtof` 比只检查 `scanf` 返回值更完整。
5. **理解重复检查。** 学号在插入前通过 `find_student_by_id` 检查，保证当前记录中唯一。
6. **理解指针输出参数。** `add_student` 用 `int *count` 修改真实人数。
7. **理解最大值下标。** 保存 `max_index` 可以同时取得学号、姓名和成绩。
8. **理解菜单循环。** 每次操作后回到菜单，直到选择 0 才 `return 0`。
9. **理解数据生命周期。** 当前记录只在内存中，退出程序后全部丢失。

## 学习难点

- 把数组容量 100 和实际人数 `count` 混为一谈。
- 循环误写成 `i <= count`，访问未使用或越界元素。
- `read_line` 的 `size` 是缓冲区总容量，最多只能保存 `size - 1` 个字符加 `'\0'`。
- 读到换行后忘记去掉，导致姓名比较和显示带隐藏换行。
- 只检查字符串开头能解析成数字，没有检查尾部残留字符。
- 重复学号检查时只比较已录入人数，而不是整张 100 格数组，这是正确做法。
- `add_student(students, &count)` 中漏掉 `&`，参数类型不匹配。
- 修改成绩前没有先按学号确认学生存在。
- 最高分并列时强行要求只有一个答案，但程序当前保留第一个。
- 认为程序有“管理系统”名称就一定会自动保存数据。当前版本没有文件持久化。
- `read_line` 遇到 `EOF` 会直接 `exit(EXIT_FAILURE)`。这在当前单文件程序中可工作，但大型程序通常会把失败状态返回给调用者。

## 零基础学习流程

1. **先画 100 格数组。** 只把前 `count` 格标成有效记录。
2. **录入第一名学生。** 跟踪学号、姓名、成绩分别写进 `students[0]` 的哪个字段。
3. **只读菜单分发。** 看 `choice` 如何进入 `switch`，每个 `case` 调用哪个函数。
4. **按功能读函数。** 一次只看显示、平均分、最高分、修改或添加中的一项。
5. **单独跟踪输入失败。** 输入 `abc`、`101` 和重复学号，确认错误在哪一层被发现。
6. **跟踪修改。** 查找 1002，记录旧成绩、新成绩和数组字段变化。
7. **跟踪添加。** 给当前 `count` 加一前，先确认数组没有满。
8. **关闭源码重写。** 先完成单条录入、显示和菜单，再逐个增加统计与修改。
9. **验证掌握。** 能画出一次从菜单到函数再回到菜单的完整路径。

## 当前版本没有完成的功能

- 没有删除学生。
- 没有按学号单独查询并展示，只会在修改时查找。
- 没有排序。
- 没有把数据保存到文件，关闭程序后记录丢失。
- 没有编辑姓名或学号，只支持修改成绩。
- 姓名缓冲区 `NAME_LENGTH` 按字节限制；中文在 UTF-8 中占多个字节。
- 输入结束会直接退出，尚未设计可恢复的返回状态。

这些不是源码错误，而是项目当前边界。后续扩展时应保留这个可运行版本作为对照，不要让一次改动同时加入文件、排序和删除。
