# C 语言 10 月 13 日字符串练习：文件简介与学习建议

## 文件简介

- **源码文件：** `19_2026-10-13_字符串输入与常用函数练习.c`
- **类型：** C 语言字符串基础练习（`06_C语言练习` 里第一份专门练字符串的程序）
- **功能：** 读入两行文字，先删掉行尾的换行符，然后依次演示四件事：用 `strlen` 求字符串的实际字节长度、用 `sizeof` 看数组的总容量、用 `strcpy` 复制一份、用 `strncmp` 比较两行文字并给出"相同 / 小于 / 大于"的结论。
- **主要知识点：** `char` 字符数组、`fgets` 读入整行、字符串结束符 `'\0'`、`strlen` 与 `sizeof` 的区别、`strcpy` 复制、`strncmp` 比较、`%zu` 格式符、行尾 `\n` 的处理、`#include <string.h>`。

这份代码的注释写得很完整，可以直接当作"字符串入门"的第一份阅读材料，按三段读：

1. **读入与去换行**：`fgets` 把整行（连同换行符）读进 `str`，再用 `str[len - 1] = '\0'` 把行尾的 `\n` 换成字符串结束符。
2. **长度与复制**：`strlen(str)` 得到实际内容长度，`sizeof(str)` 得到数组总容量 100，两者对照着看；`strcpy(copied, str)` 复制一份到 `copied`。
3. **比较**：读取第二行并做同样的去换行处理，然后用 `strncmp` 比较，最后用 `if / else if / else` 三分支把返回值翻译成中文结论。


换几组数据核对 `strncmp` 的三种情况和中文字节数：

| 第一行 | 第二行 | 第一行长度 | 比较结果 | 结论 |
| --- | --- | --- | --- | --- |
| `Hello` | `Hello` | 5 | 0 | 两个字符串相同 |
| `abc` | `abd` | 3 | -1 | 第一个字符串小于第二个字符串 |
| `abd` | `abc` | 3 | 1 | 第一个字符串大于第二个字符串 |
| `苹果` | `香蕉` | 6 | -1 | 第一个字符串小于第二个字符串 |
| `你好世界` | `你好` | 12 | 228 | 第一个字符串大于第二个字符串 |

两点提醒：

- **长度按字节算。** 一个汉字在 UTF-8 里占 3 个字节，所以"苹果"（2 个汉字）长度是 `6`，"你好世界"（4 个汉字）长度是 `12`，都远大于汉字个数。
- **比较结果的具体数值不用背。** `strncmp` 返回的是两个字符的差值（如 `'c' - 'd' = -1`），数字大小和字符编码有关，换个字符就变。真正要看的是**符号**：等于 0 表示相同，小于 0 表示第一行小，大于 0 表示第一行大。程序最后的三分支判断用的也正是符号。

## 零基础学习建议

1. **字符数组为什么要写 `= {0}`。** `char str[100] = {0};` 会把这 100 个格子全部清零。字符串靠 `'\0'` 标记结束，如果数组里恰好没有 `'\0'`，用 `%s` 打印就会一直往后读，出现乱码。清零是最省事的保险。
2. **`fgets` 的三个参数要按"存哪、多长、从哪读"来记：**

   ```c
   fgets(str, sizeof(str), stdin);
   ```

   第一个是"存到哪个数组"，第二个是"最多读多少字节"（包含结尾的 `'\0'`，所以 `sizeof(str)` 正好够用），第三个是"从哪读"，`stdin` 表示键盘。它的返回值是"读到的字符串地址"，读失败（比如遇到文件结束）才返回 `NULL`，所以本文件用 `== NULL` 来判断失败。
3. **`fgets` 会连换行符一起读进来。** 这是它和 `scanf("%s")` 最不一样的地方：你按的那个回车也在字符串里。所以才有下面这段"去换行"：

   ```c
   len = strlen(str);
   if (len > 0 && str[len - 1] == '\n') {
       str[len - 1] = '\0';   /* 把换行符换成结束符 */
       len--;
   }
   ```

   `len > 0` 是为了防止空输入时访问 `str[-1]`。处理完以后再 `strlen` 一次，长度才是"纯内容"的长度。
4. **`strlen` 和 `sizeof` 是这道题的重点对比：**

   | | `strlen(str)` | `sizeof(str)` |
   | --- | --- | --- |
   | 含义 | 实际内容有几个字节 | 数组一共占多少字节 |
   | 会不会变 | 会，内容变了它就变 | 不会，声明成 100 就永远是 100 |
   | 算不算 `'\0'` | 不算 | 算 |

   输入 `Hello` 时是 `5` 和 `100`；就算删掉换行，`sizeof` 依然是 100。
5. **`strcpy(copied, str)` 的方向是"目标在前、来源在后"，** 读作"把 str 复制到 copied"。写反了编译器不一定报错，但结果会错得很离谱。
6. **`strncmp(str, other, sizeof(other))` 是"最多比较这么多个字节"。** 第三个参数是上限，比较过程中一遇到 `'\0'` 就会停下。这里传 `sizeof(other)`（等于 100）是安全的，因为两个数组都是 100；`strncmp` 不会越过数组边界。
7. **`%zu` 是 `size_t` 类型（`strlen`、`sizeof` 的返回类型）的格式符。** 如果写成 `%d`，在部分平台上会打错数字或报警告。
8. **中文为什么算 3 个字节。** C 语言的 `char` 只管一个字节，汉字在 UTF-8 里通常占 3 个字节。这不是程序算错，而是"字节数"和"字符个数"本来就是两个概念——程序里那句提示说的就是这件事。

## 常见易错点

- **忘了删换行符。** 结果会是"长度多 1"（`Hello` 显示成 `6`），而且比较时也多带了一个 `\n`。本文件连着调用了两次 `strlen`，就是为了先量出"带换行的长度"、再量出"去掉换行后的长度"，这个顺序不能省。
- **原字符串和副本一起错了却看不出来。** `strcpy` 是在去换行**之后**做的，所以 `copied` 里也没有换行。如果把 `strcpy` 提到去换行之前，两个字符串都会多一个 `\n`。
- **`strlen`、`sizeof` 混用。** 把 `sizeof(str)` 当成"输入了几个字节"是最常见的误解；反过来，`strlen(copied)` 也永远不会是 100。
- **把 `sizeof` 当成"元素个数"。** 对 `char` 数组恰好等价，但对 `int arr[10]`，`sizeof(arr)` 是 40 而不是 10。通用的写法是 `sizeof(arr) / sizeof(arr[0])`。
- **`sizeof` 只在数组变量可见的地方有效。** 一旦把数组当参数传给函数，函数里的 `sizeof(参数)` 得到的是指针大小（8 字节），不是数组容量 100。这是后面学"数组作函数参数必须另传长度"时最容易踩的坑，`09_2026-10-05_数组函数统计.c` 里就是按这个思路写的。
- **第一行超过 99 字节时，剩下的字符会留给第二次 `fgets`。** 实测输入 120 个 `A` 再接一行 `xyz`：`str` 只装得下 99 个 `A`，剩下的 21 个 `A` 还留在输入缓冲区里，被第二次 `fgets` 当成"第二行文字"读走，所以那一行显示的是 21 个 `A`，而不是 `xyz`。`fgets` 只保证"不会写越界"，不会替你清空多余的输入。
- **空输入（第一次就按回车）。** `str` 变成空字符串，长度是 `0`，比较时 `'\0'` 和 `'x'` 相减得到负数，程序输出"第一个字符串小于第二个字符串"。逻辑上说得通，但要能解释清楚，这正是"比较是从第一个字节开始"的体现。
- **读取失败时 `return 1`。** 这份程序把"读不到内容"当作错误，返回 1；正常结束返回 0。以后在脚本或自动化里，这两个返回值就代表"成功 / 失败"。
- **`string.h` 不能少。** `strlen`、`strcpy`、`strncmp` 都在里面。少了这个头文件，老编译器可能只是警告，新编译器（C99 之后）会直接报"隐式声明"错误。

## 可以继续尝试

1. 打印数组的**元素个数**：`printf("%zu\n", sizeof(str) / sizeof(str[0]));`，对这个程序来说结果是 100，但它对 `int` 数组同样成立。
2. 加上 `strcat(copied, other)`，把两行文字拼成一个新字符串再打印，注意目标数组要有足够空间。
3. 自己实现一遍 `strlen`：`size_t my_strlen(const char *s) { size_t n = 0; while (s[n] != '\0') n++; return n; }`，和库函数的输出对比。
4. 用 `strcmp(str, other)` 替换 `strncmp`，比较整个字符串；想清楚"比较前 100 字节"和"比较到结束符"这两种上限有什么差别。
5. 在输出里加上"第一个不同的位置是第几个字节"，把比较结果从"谁大谁小"细化到"哪里不一样"。
6. 把两段输入改成循环，反复读入并比较，直到输入 `quit` 为止——正好复习 `04`、`12` 号文件里的循环写法。
7. 把 `char str[100]` 改成 `char str[10]`，再输入 `HelloWorld` 试试截断；然后给第二行的提示语加上"检测到第一行被截断"的提示，练习判断"读到的内容有没有换行结尾"。
8. 换一份英文单词表做测试（例如 `apple` / `apply`），体会 `strncmp` 是按字节逐个比、一旦分出大小就停止。
