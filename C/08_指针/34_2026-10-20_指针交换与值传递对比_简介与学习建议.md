# C 语言 10 月 20 日指针交换与值传递对比：文件简介与学习建议

## 文件简介

- **源码文件：** `34_2026-10-20_指针交换与值传递对比.c`
- **所属分类：** `C/08_指针`
- **程序用途：** 用两个函数对比“普通值传递”和“指针传递”修改外部变量的效果。
- **核心问题：** 为什么 `swapByValue(x, y)` 只在函数内部交换了形参，而 `swap(&x, &y)` 能真正改变 `main` 中的两个变量？
- **主要知识点：** 函数参数按值传递、取地址运算符 `&`、指针形参、解引用 `*`、通过指针修改外部变量、交换两个值时的临时变量、`void` 函数。
- **前置知识：** 变量、函数调用、形参和实参、变量的地址、`*p` 与 `&x` 的基本含义。
- **相关练习：** [指针基础读写与 switch 穿透](22_2026-10-15_指针基础读写与switch穿透练习.c) 讲指针怎样读写一个变量；本练习把同一机制用于两个变量，完成经典交换。

程序不需要输入，使用固定数据演示两种情况：

1. `swap(&x, &y)` 接收两个地址，通过解引用交换 `main` 中的 `x`、`y`。
2. `swapByValue(m, n)` 只收到 `m`、`n` 的副本，函数内部交换副本，调用结束后原变量不变。

## 两个函数的区别

| 函数 | 参数形式 | 函数拿到的是什么 | 能否改变调用者变量 |
| --- | --- | --- | --- |
| `swap` | `int *a, int *b` | `x`、`y` 的地址 | 能，`*a`、`*b` 指向原变量 |
| `swapByValue` | `int a, int b` | `m`、`n` 的值副本 | 不能，函数只交换自己的局部变量 |

指针交换的核心三句是：

```c
int temp = *a;
*a = *b;
*b = temp;
```

可以先把 `*a` 理解成“`a` 指向的那个变量”。于是这三句就是：先保存第一个数，再把第二个数写进第一个位置，最后把保存的值写进第二个位置。临时变量 `temp` 不可缺少，否则第一次赋值会覆盖原来的值。

普通值传递则不同。调用 `swapByValue(m, n)` 时，`a` 和 `b` 只是两个新变量，初始值分别复制自 `m`、`n`。函数内部无论怎样交换 `a`、`b`，都不会改到 `m`、`n`。

## 学习重点

1. **先理解实参到形参的复制过程。** `swapByValue(m, n)` 中的 `m`、`n` 是实参，`a`、`b` 是形参。调用时发生的是值复制，不是给 `m`、`n` 改名字。
2. **理解指针参数为什么能修改外部变量。** `swap(&x, &y)` 把地址传进去，`a` 指向 `x`，`b` 指向 `y`。`*a = *b` 修改的是 `x` 所在的内存。
3. **分清 `a`、`*a`、`&a`。** 在 `swap` 中，`a` 自己保存地址，`*a` 访问该地址里的整数；在 `main` 中，`&x` 才取得 `x` 的地址。
4. **掌握交换三步。** 临时变量保存一份旧值，是避免数据被覆盖的必要步骤。
5. **知道 `void` 函数也可以产生效果。** `swap` 没有返回交换结果，但它通过指针参数修改了外部变量。函数的“输出”不只可以是 `return`。
6. **理解形参名与实参名不需要相同。** `main` 中叫 `x`、`y`，`swap` 中叫 `a`、`b`，它们只是通过地址发生联系。

## 学习难点

- 普通值传递时，函数内部的交换只改变局部副本。看到函数内部输出 `a = 20, b = 10`，不代表 `main` 中的 `m`、`n` 被交换。
- 调用指针版本时必须传地址：`swap(&x, &y)`。传成 `swap(x, y)` 时，参数类型不匹配，编译器会报错或给出严重警告。
- 如果写成 `int *temp = a; a = b; b = temp;`，交换的是两个指针变量自己保存的地址，不是调用者变量的值。想改变指向的数据，必须使用 `*a`、`*b`。
- 解引用空指针会产生未定义行为。本程序的实参都是有效变量地址，所以安全；把 `swap` 扩展成公共函数时，应先检查 `a != NULL` 和 `b != NULL`。
- 交换不能写成“直接相加再相减”来省临时变量，因为大整数相加可能溢出。当前使用临时变量的三步写法适用于普通整数，也不需要算术运算。

## 零基础学习流程

1. **先猜输出。** 不运行程序，分别写出 `x,y`、`m,n` 在两次调用后的值。
2. **给变量画图。** 给 `x`、`y` 各画一个格子，写入 10、20；再画两个箭头 `a`、`b` 分别指向它们。
3. **逐句跟踪 `swap`。** 写出 `temp`、`*a`、`*b` 每一步的值，确认旧值没有丢失。
4. **对照值传递版本。** 在 `swapByValue` 里给 `a`、`b` 画另外两个独立格子，观察交换只发生在这两个副本中。
5. **编译并运行。** 先对照实际输出，再修改 `x`、`y`、`m`、`n` 的初值重跑。
6. **故意制造错误。** 在临时副本中把 `swap(&x, &y)` 改成 `swap(x, y)`，阅读编译器错误；不要修改仓库中的原文件。
7. **独立重写。** 关闭源码，自己写出 `swap`、`main` 和一组测试数据，再与仓库版本比较。
8. **口头复盘。** 能不看代码说清“值传递复制了什么，指针传递让函数知道了什么，`temp` 为什么不能省”。

## 常见易错点与测试思路

- 认为函数参数名相同就会共享变量。C 的普通参数始终会创建独立的形参副本，名字相同也不共享存储。
- 在 `main` 中通过指针函数交换时漏掉 `&`，导致类型不匹配。
- 在 `swap` 中只写 `*a = *b; *b = *a;`，第二句拿到的是已经被覆盖的新值，结果两个变量会变成同一个数。
- 忘记临时变量会破坏原始值，这是交换逻辑最常见的数据覆盖错误。
- 认为 `swapByValue` 的局部输出能证明外部变量也改变了。判断修改效果的依据是调用返回后打印原变量。
- 只测试 `10` 和 `20`。还应测试负数、整数边界、两个相同的值，以及 `swap(&same, &same)` 这种特殊调用。
- 把 `swap` 的参数改为 `int **` 但调用方式仍是 `swap(&x, &y)`，会造成类型不匹配；类型必须和“想修改什么”一起设计。
