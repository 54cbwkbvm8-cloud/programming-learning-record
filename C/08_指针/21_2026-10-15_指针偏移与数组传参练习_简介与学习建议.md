# C 语言 10 月 15 日指针与数组练习：文件简介与学习建议

## 文件简介

- **源码文件：** `21_2026-10-15_指针偏移与数组传参练习.c`
- **类型：** C 语言指针入门练习（指针和数组的关系）
- **功能：** 先打印数组的长度、总占用空间和单个元素的占用空间；调用 `print_array` 函数遍历打印整个数组，并在函数内部打印一次 `sizeof(arr)`；最后用一个指向数组中间元素的指针 `p`，演示 `*p`、`*(p + 1)`、`*(p - 1)` 三种取值。
- **主要知识点：** `sizeof(数组) / sizeof(数组[0])` 求元素个数、**数组名作参数时会退化成指针**、函数内部 `sizeof(指针)` 和 `sizeof(数组)` 的差别、指针的加减偏移、`*` 解引用、`const int *` 只读约定、`size_t` 与 `%zu`。

这份练习是接在 `09_2026-10-05_数组函数统计.c` 之后最重要的一步：以前只是"用数组"，这份开始看清"数组交给函数时到底交给了什么"。程序可以分三段读：

1. **在 `main` 里量数组**：`sizeof(a) / sizeof(a[0])` 算出 5 个元素，`sizeof(a)` 是 20 字节。
2. **把数组交给函数**：`print_array(a, length)` 传进去的是"数组名 + 长度"。
3. **用指针走位**：`int *p = &a[3];` 让 `p` 指向 40，再分别读它的下一个、上一个元素。

## 零基础学习建议

1. **先把"数组名是什么"想清楚。** `int a[5]` 里的 `a` 在大多数场合会**自动变成"指向第一个元素的指针"**，也就是 `&a[0]`。所以 `print_array(a, length)` 里的 `a` 传过去的其实是地址，不是"整份数组的拷贝"。
2. **`sizeof(arr)` 在函数里为什么是 8？** 看函数签名：

   ```c
   void print_array(const int *arr, size_t length)
   ```

   参数 `arr` 的类型是"指向 `int` 的指针"，**它本身就是一个指针变量**，不是数组。`sizeof` 一个指针得到的就是指针自己占几个字节，所以是 8。C 语言没有办法在函数里用 `sizeof` 反推出数组有多长，这正是必须**额外传一个 `length` 参数**的原因。
3. **`sizeof(a) / sizeof(a[0])` 才是"元素个数"的通用写法。** 在 `main` 里（数组变量本身就看得见的地方）它等于 5。写成 `sizeof(a) / sizeof(int)` 也可以，但前者换了类型仍然正确，更稳妥。
4. **`size_t` 和 `%zu` 是一对。** `sizeof` 的结果类型是 `size_t`（无符号整数），循环变量 `size_t i` 和格式符 `%zu` 都和它对应。混用 `int` 和 `%d` 常常不会报错，但语义上不严谨。
5. **`const int *arr` 里的 `const` 是"只读约定"。** 它的意思是"我承诺不通过 `arr` 修改数组内容"，函数体里写 `arr[i] = 0;` 会直接编译报错。这是写函数时保护数据的常用方法——`print_array` 只是打印，本来就不该改。
6. **`arr[i]` 和 `*(arr + i)` 完全等价。** 记住这一条，指针的加减就不再神秘：`arr[i]` 只是 `*(arr + i)` 的好看写法。
7. **指针的加减是"按元素走"，不是"按字节走"。**

   ```c
   int *p = &a[3];      /* p 指向 40 */
   *p         /* 40，当前格子 */
   *(p + 1)   /* 50，往后走一个 int（4 字节），不是 1 个字节 */
   *(p - 1)   /* 30，往前走一个 int */
   ```

   因为 `p` 的类型是 `int *`，编译器知道一个"格子"是 4 字节，所以 `p + 1` 自动跳到下一个 `int`。如果把 `p` 换成 `char *`，`p + 1` 就只前进 1 个字节了。
8. **`*(p + 1)` 不会改变 `p` 本身。** 它只是"临时算出下一个位置再取值"，`p` 还是指着 40。想让 `p` 真的移动，要写 `p = p + 1;` 或 `p++`。

## 常见易错点

- **在函数里用 `sizeof(参数)` 求数组长度。** 这是本文件的核心考点：得到的永远是指针大小（64 位机器上是 8），不是数组总字节数。`05_2026-09-30_数组统计.c` 和 `09_2026-10-05_数组函数统计.c` 里之所以要传 `n`，根源就在这里。
- **把 `sizeof` 用在指针上却以为在用数组。** `int *q = a; sizeof(q)` 是 8，不是 20。判断标准很简单：**看这个变量声明的类型**——`int a[5]` 是数组，`int *q` 是指针。
- **越界取值。** 本文件里 `p` 指向 `a[3]`，`*(p + 1)` 正好是 `a[4]`，还在数组范围内；但如果写 `*(p + 2)` 或 `*(p - 4)`，就已经跑到数组外面了。C 语言**不会**替你检查边界，读出来的是别的内存内容，程序可能不报错但结果完全是随机的。
- **把 `&a[3]` 写成 `a[3]`。** `a[3]` 是 40 这个**值**（`int`），`&a[3]` 才是它的**地址**（`int *`）。用错类型编译器会警告，但值得自己先看出来。
- **`*(p + 1)` 写成 `*p + 1`。** 这两者完全不同：前者是"下一个元素的值"（50），后者是"当前元素的值加 1"（41）。括号的优先级问题，在这一类表达式里几乎天天出现。
- **打印一行忘了 `\n`。** 本文件第 3 行输出就是活例子，两段文字挤在一起了。
- **`const` 保护只在编译期有效。** 它拦得住"通过 `arr` 修改"，拦不住别的指针从别的地方改同一份内存。它是一份约定，不是运行时锁。
- **数组作参数时"传的是地址"。** 这意味着在函数里改 `arr[i]`，`main` 里的数组也会跟着变——这既是函数能"就地改数组"的原因，也是不小心改坏数据的原因。想只读就加 `const`。

## 可以继续尝试

1. 给那句提示补上 `\n`，让输出不再挤在一起，然后对比修改前后的排版。
2. 在 `print_array` 里故意写一句 `arr[0] = 0;`，看编译器报什么错，理解 `const int *` 的作用；再改成 `int *arr` 编译一次，对比两种写法。
3. 写一个 `int sum_array(const int *arr, size_t n)`，用 `arr[i]` 的方式求和；再写一个版本改用 `*(arr + i)`，确认结果完全一样。
4. 把 `int *p = &a[3];` 改成 `int *p = a;`，然后用一个 `for` 循环配合 `p++` 依次打印 5 个元素，体会"用指针遍历数组"和"用下标遍历数组"是同一件事。
5. 打印地址验证"按元素走"：`printf("%p %p\n", (void *)p, (void *)(p + 1));`，把两个地址相减，看看差值是不是 4 个字节。
6. 用 `sizeof` 写一个"陷阱实验"：把数组声明成 `int b[10]`，在 `main` 里打印 `sizeof(b)` 和 `sizeof(b) / sizeof(b[0])`，再把它传进函数打印一次 `sizeof(参数)`，把三个数字摆在一起看。
7. 把元素类型从 `int` 改成 `double`，重新观察 `sizeof(a)`、`sizeof(a[0])` 和 `p + 1` 的地址差值，确认"加减按元素走"这件事。
8. 用指针找最大值：`int *max = a;` 然后遍历比较 `if (a[i] > *max) max = &a[i];`，最后打印 `*max`。
