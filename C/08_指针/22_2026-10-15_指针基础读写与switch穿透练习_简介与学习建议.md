# C 语言 10 月 15 日指针基础与 switch 练习：文件简介与学习建议

## 文件简介

- **源码文件：** `22_2026-10-15_指针基础读写与switch穿透练习.c`
- **类型：** C 语言指针入门 + `switch` 分支练习（一份文件里两个小专题）
- **功能：** 程序分两部分。第一部分用 `int *p = &value;` 演示读指针、写指针：先读出 `value` 是 10，再通过 `*p = 20;` 把 `value` 改成 20，证明"改指针指向的内存就等于改那个变量"。第二部分用 `choice = 2` 演示 `switch` 的执行顺序：因为 `case 1`、`case 2` 后面都没有写 `break`，程序从 `case 2` 进入后会**一路往下穿透**，把 `case 3` 的内容也执行掉，最后输出 `BC`。
- **主要知识点：** 取地址运算符 `&`、解引用 `*`、用指针读和写、指针的"别名"作用、`switch / case / default / break`、**case 穿透（fall-through）**、`switch` 是"跳转到匹配项"而不是"从头逐个判断"。

这份练习是 10 月 15 日两份指针练习里的"基础款"，和 `21_2026-10-15_指针偏移与数组传参练习.c` 搭配着看：21 号讲指针怎么在数组里走位，22 号讲指针最原始的用法——**通过地址去读写另一个变量的值**。

编译运行（这份程序**不需要输入**）：

```bash
cc -std=c17 -Wall -Wextra "C/08_指针/22_2026-10-15_指针基础读写与switch穿透练习.c" -o /tmp/practice && /tmp/practice
```

实测输出：

```text
===安全使用指针===
value 当前的值是：10
*p当前读到的值是：10
通过*p 修改后 value 的值是：20

===switch的执行顺序===
choice 当前的值是：2
 switch输出的值是：
BC
```

三点说明：

- **最后一行是 `BC` 而不是 `B`，也不是 `BC` 两行。** `B` 来自 `case 2`，`C\n` 来自 `case 3`——中间没有 `break`，所以执行完 `case 2` 就直接"漏"进了 `case 3`，直到遇到 `case 3` 结尾的 `break` 才停下。这就是 `switch` 的**穿透（fall-through）**。
- **`case 1` 里的 `A` 一直没打印。** 因为 `switch` 不从头逐个判断，而是**直接跳到 `choice` 匹配的那一项**。`choice` 是 2，所以 `case 1` 根本不会被执行。
- **第 7 行行首多了一个空格**（` switch输出的值是：`）。原因是上一句 `printf("choice 当前的值是：%d\n ", choice);` 的 `\n` 后面还留了一个空格。不影响的运行，但能说明"格式字符串里多一个字符都会被打印出来"。

| `choice` 的值 | 匹配的 `case` | 实际输出 |
| --- | --- | --- |
| 1 | `case 1` → 穿透到 `case 2`、`case 3` | `ABC` |
| 2（原文件） | `case 2` → 穿透到 `case 3` | `BC` |
| 3 | `case 3`（自带 `break`） | `C` |
| 4 或 5 | 都不匹配 → `default` | `我真牛逼` |

## 零基础学习建议

1. **`&` 和 `*` 是一对相反的操作，先把这两个符号读顺：**

   | 写法 | 读作 | 含义 |
   | --- | --- | --- |
   | `&value` | 取地址 | "`value` 住在哪"，结果是一个地址（`int *`） |
   | `*p` | 解引用 | "`p` 指的那个格子里的东西"，结果是一个 `int` |

   所以 `int *p = &value;` 读作：**让 `p` 保存 `value` 的地址**，也就是让 `p` 指向 `value`。
2. **`*p` 在等号左边是"写"，在右边是"读"。**

   ```c
   printf("%d\n", *p);   /* 右边：读出 value 的值，打印 10 */
   *p = 20;              /* 左边：把 value 那一格改成 20 */
   ```

   改完之后再打印 `value`，就是 20——因为 `p` 和 `value` 指的是**同一块内存**。可以把它想成：`value` 是房间，`p` 是写着房间号的纸条，`*p` 就是"按纸条去房间看/改"。
3. **该写 `*p = 20;` 而不是 `p = 20;`。** `p` 自己存的是地址，`p = 20;` 等于"把纸条改成 20 号房间"，那不是我们要做的事（而且会当场丢掉原来的地址）。**要用指针改数据，等号左边必须有 `*`。**
4. **文件里那句标题"安全使用指针"值得记住三条守则：**
   - 定义的时候就让它指向一个**真实存在的变量**（本文件是 `int *p = &value;`）；
   - 解引用之前，心里要清楚它指向的东西是**有效的、还没被释放的**；
   - 想清楚这次 `*p` 是**读**还是**写**，写的时候会连带改掉原变量。
5. **`switch` 的执行方式是"跳着走"。** 流程是：算出 `choice` 的值 → **直接跳到值相等的那个 `case`** → 从那里开始**一路往下执行**，直到遇到 `break` 或整个 `switch` 结束。理解这两步（先跳、再往下走），穿透现象就完全是自然结果。
6. **`break` 在 `switch` 里的作用就是"到此为止"。** 本文件里只有 `case 3` 写了 `break`，所以它挡住了一路向下的执行。想让"选 2 只输出 B"，就要在 `case 2` 的末尾补一个 `break`。
7. **`default` 是"都不匹配时的兜底"。** 它不要求写在最后，但写在最后最符合阅读习惯。本文件里 `choice` 是 2，所以 `default` 不会执行。
8. **`switch` 和 `if` 的分工。** 判断一个值等于几种固定情况中的哪一种，用 `switch` 更整齐；判断范围（比如"分数是否大于 60"）或复合条件（`&&`、`||`）就只能用 `if`。仓库里 `02_2026-09-28_正负奇偶与闰年.c` 用的是 `if / else if`，本文件用的是 `switch`，正好可以对比。

## 常见易错点

- **漏写 `break` 造成穿透，是最常见的 `switch` 错误。** 编译器**不会**报错（有些编译器和工具会给出提示），程序也能跑，只是多执行了后面的分支。真实项目里这类问题常常表现为"选了 A 却把 B 也做了"。本文件是**故意**留的演示，但自己写程序时要主动检查每个 `case` 末尾。
- **`case` 后面必须是常量。** `case 1:`、`case 'a':` 可以，`case choice:` 或 `case n:`（变量）不行。`switch` 的表达式也必须是整型（`int`、`char`、枚举等），不能用浮点数或字符串。
- **以为 `switch` 会从 `case 1` 开始挨个判断。** 它是直接跳转到匹配项，所以本文件里 `A` 从来没有被打印过。反过来说，`case` 的书写顺序不影响匹配，只影响穿透时"往下经过哪些"。
- **忘记 `default`。** 没有 `default` 时，一个都不匹配就什么都不做，程序照样跑，但你可能完全看不出"输入不合法"。
- **以为 `*p = 20;` 只是改了 `p`。** 它改的是 `p` 指向的变量，也就是 `value`。这是指针最有用、也最容易失控的地方。
- **在指针没初始化时就解引用。** `int *q; *q = 5;` 里的 `q` 存着一个不确定的地址（俗称野指针），这一句会写到随机内存上，轻则结果错乱，重则程序崩溃。必须先 `q = &value;` 之类的初始化。本文件做对了：声明时就写 `int *p = &value;`。
- **打印地址用错格式符。** 打印指针本身要用 `%p` 并转换成 `void *`，例如 `printf("%p\n", (void *)p);`；用 `%d` 打印地址在不同平台上结果不一样。
- **把 `%p` 打印出来的地址当成"数字"去运算。** 地址的具体数值每次运行都可能不同（这跟操作系统有关），要看的是**两个地址之间的关系**，比如 `p + 1` 比 `p` 大多少。
- **`case 3:` 后面那句 `break;` 写在 `printf` 的同一行还是下一行，都不影响结果。** 但要保证它在正确的位置——本文件里它属于 `case 3`，所以挡住了继续往下。
