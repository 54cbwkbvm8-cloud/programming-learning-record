# C 语言 10-11 奇偶组合与数组最值：文件简介与学习建议

## 文件简介

- **源码文件：** `16_2026-10-11_奇偶组合与数组最值.c`
- **类型：** C 语言综合练习，一段程序里串起分支、循环和数组
- **功能：** 程序依次完成四段任务：

  1. **两数相加与奇偶组合判断**：输入两个整数，输出它们的和，并说明两者分别是奇数还是偶数（共四种组合）。
  2. **三数最大值**：再输入一个整数，和前面两个一起比较出最大值。
  3. **1～100 求和**：用 `while` 循环累加，输出 5050。
  4. **两轮 10 个整数的统计**：第一轮边读边求最大值和平均值；第二轮先存进数组，再求平均值、最大值和最小值。

- **主要知识点：** 全局变量、用 `if / else if` 覆盖 2×2 种奇偶组合、逐步比较求最大值、`while` 与 `for` 混用、用 `if (i == 0 || a > max)` 保护首个元素、数组、`double` 与 `%.2f`。

这份练习和之前 `05_2026-09-30_数组统计.c` 是同题材，但**最大值和最小值的写法是正确的**。把两份放在一起对比，能一次看清"错在哪、该怎么写"。

## 建议运行数据

程序要连续输入 23 个数字，按这个顺序：

1. 两个整数（第 1 段）

## 零基础学习建议

1. 文件开头有六个变量写在 `main` 外面（`a`、`b`、`c`、`max`、`sum`、`i`），它们是**全局变量**，程序任何位置都能改。好处是不用到处传参数，坏处是"谁改了它"很难追踪。现在已经能写了，但建议养成习惯：**只在本文件用到的变量，放进 `main` 里**。
2. 第一段的奇偶判断用 `else if` 链把两个数字的奇偶组合穷举完整：偶偶、偶奇、奇偶、奇奇，正好四种，一个不漏。这种"两两组合穷举"是判断语句的经典练习。
3. 第二段的三数最大值用的是"先假设第一个最大，再逐个挑战"：

   ```c
   max = a;
   if (b > max) { max = b; }
   if (c > max) { max = c; }
   ```

   注意两个 `if` 之间没有 `else`：不管 `b` 有没有取代 `max`，都要再和 `c` 比一次。
4. 第三段用的是全局变量 `i`，它在声明时就被赋成 1（`int i = 1;`）。`while (i <= 100)` 把 1 到 100 累加到 `sum`，循环结束时 `i` 变成 101。
5. 第四段第一轮的写法值得专门记住：

   ```c
   max = 0;
   for (i = 0; i < 10; i++) {
       scanf("%d", &a);
       if (i == 0 || a > max) { max = a; }   // 第一个数无条件成为当前最大值
       sum = sum + a;
   }
   ```

   `i == 0 ||` 的作用是"第一个数字不管多大都先当最大值"，从第二个数字开始才真正比较。这样 `max` 的初值是 0 也不会出错，因为它会在第一轮就被覆盖。
6. 第二轮把 10 个数先存进数组 `arr[10]`，再用同样的技巧求最大值和最小值：

   ```c
   if (m == 0 || arr[m] > max2) { max2 = arr[m]; }
   if (m == 0 || arr[m] < min2) { min2 = arr[m]; }
   ```

   对比一下 `05_2026-09-30_数组统计.c`：那份文件写成了和固定的 `arr[0]` 比较，所以最小值算错；这里用 `max2`、`min2` 这两个"当前记录值"比较，才是正确写法。两处放在一起看，印象会特别深。
7. 平均值输出用的是 `sum / 10.0`。写成 `10.0` 而不是 `10` 是为了触发浮点除法，否则小数部分会被丢掉。

## 常见易错点

- **平均值被打印了两次**：数组段结尾既有 `printf("平均值是：%.2f\n", sum2 / 10.0);`，又有一句 `printf("这十个整数的平均值为 %.2f\n", sum2 / 10.0);`。两句内容一样，删掉一句即可。
- **第二轮的提示语和第一轮一模一样**，都写着"请输入 10 个整数求最大值"，但第二轮实际还统计了平均值和最小值。提示改了会更准确，例如改成"请输入 10 个整数（先存数组再统计）"。
- 全局变量 `sum` 被用在了两个地方：先算 1～100 的和，后面又算 10 个数的和。中间靠 `sum = 0;` 重新清零。**如果忘了清零，1～100 的 5050 会被带进后面的计算**，结果全部偏大。这就是复用变量的风险，换成两个不同名字的变量更安全。
- `int max2; int min2;` 声明时没有赋初值，靠 `m == 0 ||` 保证第一次一定赋值。如果去掉 `m == 0 ||`，第一次比较就会用到不确定的值——这正是 `05_2026-09-30_数组统计.c` 那类错误的源头。
- 第一轮的 `max = 0;` 单独看是危险的（全是负数时会得到 0），但因为后面有 `i == 0 ||` 保护，实际不会出错。读代码时要把这两行连起来理解。
- 程序要连续输入 23 个数字，中间没有提示"还剩几组"。输入顺序错了，后面所有结果都会跟着错，而且程序不会报错。输入前先按顺序把数据准备好。
- 循环变量 `i` 是全局的，`while` 用完变成 101，后面的 `for (i = 0; ...)` 又把它重新赋值为 0。能正常工作，但同一个变量承担多个循环，容易看错。局部变量的写法（`for (int i = 0; ...)`）更清楚。
- `scanf("%d", &a)` 把读到的数字存进了全局变量 `a`，而 `a` 原本存的是第一段的第一个输入。**同一个变量被反复复用**，读代码时要注意它此刻代表什么。

## 可以继续尝试

1. 删掉重复的平均值输出，并把第二轮的提示语改成准确的文字。
2. 把 `sum` 拆成 `sum1`（1～100 求和）和 `sum10`（10 个数求和）两个变量，消除"忘记清零"的隐患。
3. 把六个全局变量全部移进 `main`，重新编译运行，对比改前改后哪种写法更好读。
4. 给 10 个整数的统计加上"奇数个数""负数个数""大于平均值的数字个数"。
5. 把第二轮改造成函数版：`int max_of(int a[], int n)`、`int min_of(int a[], int n)`、`double average_of(int a[], int n)`。
6. 把 23 个输入压缩一点：第一轮的 10 个数直接存进数组，第二轮复用同一组数据，看看能不能用一个数组完成两轮的统计。
