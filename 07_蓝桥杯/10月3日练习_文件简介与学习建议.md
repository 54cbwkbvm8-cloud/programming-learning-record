# 10 月 3 日练习：文件简介与学习建议

## 文件简介

- **源码文件：** `10 月 3 日练习.c`
- **类型：** C 语言基础与算法入门综合练习
- **功能：** 完成 1～100 求和、统计 1～100 中 3 的倍数个数、输入 10 个整数求最大值和最小值、打印九九乘法表、打印星号三角形。
- **主要知识点：** `for` 循环、累加器、取模判断 `%`、一维数组、嵌套循环、`printf` 格式控制。

这个文件把几道常见基础题集中在一起。求和使用 `sum = sum + i2` 逐项累加，倍数统计用 `i % 3 == 0` 判断，数组部分先读入 10 个数再逐个比较，最后用两层 `for` 打印九九乘法表和三角形，外层 `i` 控制行、内层 `j` 控制每行的列数。

## 建议运行数据

运行后先经过前几段输出，在输入数组时输入：

```text
5 3 9 1 7 2 8 4 6 10
```

主要预期结果：

```text
1到 100的和是 5050
1～100 中 3 的倍数有 33 个
max = 10
```

九九乘法表和三角形部分应各打印 9 行。

## 零基础学习建议

1. 逐段运行、逐段理解：先只看 1～100 求和，再往下加一段，不要一次试图看懂整份文件。
2. 重点跟踪 `i` 和 `j` 的变化。九九乘法表里 `j <= i` 决定了第几行打印几列，把条件改成 `j <= 9` 再运行，形状会立刻变成矩形。
3. 数组部分先用 `5 3 9 1 7 2 8 4 6 10` 跑一遍，确认最大值是不是 `10`，然后注意最小值的输出是否合理。
4. 把 1～100 求和改写成 `while` 版本，比较 `for` 和 `while` 在写法上的差别。
5. 每次只改一处条件就运行一次，先预测结果再和实际输出核对。

## 常见易错点

- **本文件的最小值部分目前是错的。** `min` 只声明了类型，没有赋初值，却直接参与 `arr[i] < min` 比较；而且循环从下标 `0` 开始，第一轮会拿 `min` 和它自己比较。因为用的是未初始化的变量，输出会随编译器和编译选项变化：实测输入 `100 200 300 400 500 600 700 800 900 1000` 时，期望最小值是 `100`，`-O0` 编译却输出 `1`；换成 `-O2` 编译还会输出 `-2147483648`。最小改动是把初值改成第一个元素，并让循环从下标 `1` 开始：

    ```c
    min = arr[0];
    for (int i = 1; i < 10; i++) {
        if (arr[i] < min) {
            min = arr[i];
        }
    }
    ```

    先自己按这个思路改一遍、跑一遍，再回头看这段说明，会比直接看答案记得牢。
- `scanf("%d", &arr[i])` 里的取地址符 `&` 不能漏，数组元素同样需要取地址。
- 同一个程序里先用了 `int i2`，后面又用 `int i`，命名不统一容易看混，建议统一成同一套命名。
- 输出中文提示时如果终端出现乱码，多数是终端编码问题，不是程序逻辑错误。
- 所有小题都挤在 `main` 里，后期建议把每道小题拆成独立函数，方便单独调试。
