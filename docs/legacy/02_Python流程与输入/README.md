# 02 Python 流程与输入

> **历史归档：** 本文件保留迁移前的阶段说明，不作为当前导航。当前入口见 [仓库首页](../../../README.md)，历史归档索引见 [legacy](../README.md)。

本目录收录"接收用户输入、根据输入改变程序执行路径"的练习脚本，重点是 **`input` 输入、条件判断、`while` 循环、随机数、输入校验和异常处理**。

和 `01_Python基础练习` 相比，这里的程序开始**等待用户输入**，所以要用交互式终端运行，一行一行地回答问题。

## 每个文件在学什么

**`01_2026-08-23_登录验证.py`** 是第一份"双分支套双分支"的练习：先判断用户名是否为空，再判断用户名和密码是否正确。它会让你第一次体会到"如果里面还有如果"的写法虽然能跑，但很快就会变得不好读——这正是优化版要解决的问题。

**`02_2026-08-23_登录验证_循环重试版.py`** 用 `while True` 包住整个流程，用户名照旧校验，但登录失败后不再让用户重新运行程序，而是自动回到开头。对比 01 号可以直观看到 `continue` 和 `break` 如何控制流程走向。

**`03_2026-08-24_学生信息登记表.py`** 一次性收集姓名、专业、学校和年龄，再和预设信息逐项比较。重点是四个条件要用 `and` 连起来，只有全部匹配才算通过。

**`04_2026-08-24_奖学金资格判断.py`** 和 **`05_2026-08-24_大学奖金资格判定.py`** 是同一类题目的两个版本：前者用较简单的条件表达式收集"是否挂科"的回答，后者用布尔值和 `not` 表达"没有挂科"。两个文件放在一起看，能理解同一件事可以有多种表达方式。

**`06_2026-08-17_猜数字_固定答案版.py`** 到 **`08_2026-08-25_猜数字_固定数字37.py`** 是三个难度递进的猜数字程序：先是固定答案加次数限制，再是随机答案，最后是不限次数的循环猜法。三个版本对比着看，能看清"次数限制"是怎么用计数器实现的。

**`09_2026-08-23_九九乘法表与学习打卡.py`** 把循环用在两个场景上：先用嵌套 `while` 打印乘法表，再用七天循环模拟每天打卡一次，`break` 用来保证每天只输出一条记录。

**`10_2026-09-09_随机数与输入异常处理.py`** 是本目录唯一涉及异常处理的文件。用户输入的不是数字时，`int()` 会抛出 `ValueError`，程序用 `try / except` 拦住它并提示重新输入，这样程序就不会因为一次错误输入直接崩溃。

## 推荐学习顺序

1. `01_2026-08-23_登录验证.py` → `02_2026-08-23_登录验证_循环重试版.py`：看同一件事如何从"能跑"改到"好用"。
2. `03_2026-08-24_学生信息登记表.py` → `04_2026-08-24_奖学金资格判断.py` → `05_2026-08-24_大学奖金资格判定.py`：逐步增加判断条件。
3. `08_2026-08-25_猜数字_固定数字37.py`：先把循环和计数器用熟。
4. `06_2026-08-17_猜数字_固定答案版.py` → `07_2026-08-23_猜数字_随机答案版.py`：加入次数限制和随机数。
5. `09_2026-08-23_九九乘法表与学习打卡.py`：练习嵌套循环。
6. `10_2026-09-09_随机数与输入异常处理.py`：最后学异常处理，让程序不怕输错。

## 学习方法建议

- 这些程序都需要输入，建议在终端里运行，**故意输错几次**（空用户名、字母、负数、超范围的分数），看看程序怎么反应。这是检查自己是否真的理解输入校验的最好方式。
- 遇到"程序卡住不动"，先看是不是进了 `while True` 而没有 `break` 或退出条件。
- 三个猜数字程序都玩一遍，记录每个版本各用了几行代码，体会"功能相近但写法不同"的区别。
- 学完这一目录，你应该能自己写出"输入 + 判断 + 循环 + 错误处理"的完整小程序，这是后面综合项目的基本功。

运行方式：

```bash
python3 "Python/03_分支与循环/02_2026-08-23_登录验证_循环重试版.py"
python3 "Python/03_分支与循环/07_2026-08-23_猜数字_随机答案版.py"
```
