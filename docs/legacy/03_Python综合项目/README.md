# 03 Python 综合项目

> **历史归档：** 本文件保留迁移前的阶段说明，不作为当前导航。当前入口见 [仓库首页](../../../README.md)，历史归档索引见 [legacy](../README.md)。

本目录收录**完整的小程序**：它们由多个函数组成，能连续处理一批数据，或者用菜单反复操作直到用户主动退出。这是从"写一个练习"走向"写一个小项目"的过渡阶段，重点是 **函数拆分、字典、输入校验、循环控制、异常处理和文件持久化**。

目录内的 8 个文件其实记录了三条成长线：

- **计算器线**：`02` → `03`，从函数版升级到带异常处理的健壮版。
- **成绩管理线**：`01` → `07` → `08` → `05` → `06`，从两个列表，到函数版，到带输入校验的版本，再到字典菜单版，最后到能存盘的 JSON 持久化版。
- **通讯录线**：`04`，字典 + 菜单的综合应用。

## 每个文件在学什么

**`01_2026-08-23_学生成绩管理_列表雏形.py`** 是这条线最早的样子：用一个列表存姓名，另一个列表存成绩，靠下标对应关系把两者配对。它能用，但一旦删掉一个学生，两个列表的对应关系就容易错乱——这个"不方便"正是后面改字典版的原因。

**`02_2026-09-09_简易计算器_函数版.py`** 第一次把运算逻辑写成独立函数（`add`、`subtract` 等）。它的好处是 `main` 只需要读输入、选菜单、调用函数，逻辑清楚。除法里有一句"除数不能为 0"的检查，这是计算器类程序的必备判断。

**`03_2026-08-30_简易计算器_异常处理版.py`** 补齐了上一个版本的短板：用 `try / except` 拦住"输入的不是数字"这种情况，只要输入非法就提示重新输入，程序不会崩。它支持小数连续计算，是"能真正用起来"的版本。

**`04_2026-09-09_通讯录_字典版.py`** 用字典把姓名和手机号绑在一起，实现了添加、修改、删除、查看，以及"按姓名查手机号""按手机号查姓名"的**双向查询**。双向查询需要遍历字典的值，是字典专题里很有代表性的练习。

**`05_2026-10-05_学生成绩管理_字典菜单版.py`** 用字典套字典的结构（`students[姓名] = 成绩`）保存数据，功能包括添加（检查重名）、删除、修改、查询、显示全部、计算平均分，并把成绩换算成 A～E 等级。140 行左右的代码，是本目录里最适合精读的主程序。详细讲解见同目录的 `05_2026-10-05_学生成绩管理_字典菜单版_简介与学习建议.md`。

**`06_2026-08-31_学生成绩管理系统_JSON持久化版.py`** 是整条线的终点：程序启动时从 `students.json` 读入之前的数据，操作结束后再写回文件，所以关掉程序数据也不会丢。这里用到 `json.dump` / `json.load`、`pathlib` 定位文件路径，以及 `ensure_ascii=False` 让中文不被转成乱码。程序运行时生成的 `students.json` 已被 `.gitignore` 排除，不会污染仓库。

**`07_2026-10-11_学生成绩管理_函数版.py`** 是成绩管理线的第二站，特点是**把功能拆成函数**：`get_level` 负责等级、`show_students` 负责输出列表、`show_summary` 负责统计、`main` 只负责录入流程。数据用列表套字典保存（`[{"name": ..., "score": ...}, ...]`），录入靠输入 `exit` 结束。它还专门处理了"一个学生都没录"的情况，提示"没有录入学生，无法统计成绩。"。注意它的成绩用 `float()` 转换，所以能录 88.5 这样的小数；`float(score)` 没有做输入校验，输字母会直接报错——这正是 `08` 号要解决的问题。

**`08_2026-10-11_学生成绩管理_输入校验版.py`** 是成绩管理线里**输入校验做得最完整**的一版：先用 `count.isdigit() and int(count) > 0` 校验人数，再逐个用 `score.isdigit() and 0 <= 分数 <= 100` 校验成绩，任何一步输入不合法都会提示重新输入。它把等级也存进了字典（`{"name", "score", "level"}`），并用 `max(students, key=lambda x: x["score"])` 一次性找出成绩最好的学生。和 `07` 号对比着看很有意思：`07` 用 `float` 能收小数但不校验，`08` 校验很严但 `isdigit()` 只接受整数，88.5 会被拒绝——两种取舍都值得理解。

## 推荐学习顺序

1. `02_2026-09-09_简易计算器_函数版.py`：先用最短的代码理解"菜单 + 函数"的结构。
2. `03_2026-08-30_简易计算器_异常处理版.py`：看同一个程序如何变得不怕输错。
3. `01_2026-08-23_学生成绩管理_列表雏形.py`：感受列表版成绩管理的局限。
4. `07_2026-10-11_学生成绩管理_函数版.py`：学会把功能拆成函数、用列表套字典存数据。
5. `08_2026-10-11_学生成绩管理_输入校验版.py`：学会把用户输入校验做完整。
6. `04_2026-09-09_通讯录_字典版.py`：练习字典的增删改查。
7. `05_2026-10-05_学生成绩管理_字典菜单版.py`：读完整版菜单程序，配合讲解文档。
8. `06_2026-08-31_学生成绩管理系统_JSON持久化版.py`：最后学数据持久化，让程序有"记忆"。

## 学习方法建议

- 读这些文件时的重点是**结构**而不是语法：先看程序是怎么循环的，再看每个功能是怎么拆成函数的，最后看数据存在哪里。
- 把两个计算器对比着读：`03` 只比 `02` 多了异常处理和小数支持，其余结构几乎一样。这种"增量改造"是今后工作里最常见的改动方式。
- 成绩管理这条线有五个版本（`01` → `07` → `08` → `05` → `06`），最好按顺序读，边读边问自己："如果是列表版，这一步要怎么实现？换成字典呢？"这样能真正理解不同数据结构和不同校验策略的取舍。
- 把 `07` 和 `08` 放在一起对比输入处理：一个用 `float()` 收小数但不校验，一个用 `isdigit()` 校验严格但只收整数。想清楚"哪种更适合真实场景"，比记住语法更有价值。
- 运行 `06` 时，操作几个学生后关掉程序再重新打开，就能亲眼看到数据被保存了下来。

运行方式：

```bash
python3 "Python/13_综合项目/02_2026-09-09_简易计算器_函数版.py"
python3 "Python/13_综合项目/04_2026-09-09_通讯录_字典版.py"
python3 "Python/13_综合项目/06_2026-08-31_学生成绩管理系统_JSON持久化版.py"
```
