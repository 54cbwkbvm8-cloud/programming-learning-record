# 仓库结构说明

本文件说明仓库的分类方法、命名规范和维护约定，方便以后继续往仓库里加练习时保持一致。

## 整理目标

1. **按语言分区**：Python 和 C 语言各自成组，不会混在一起。
2. **按学习阶段排序**：目录和文件都带序号，从基础到综合依次排列。
3. **文件位置可预测**：看到文件名就能知道它属于哪个阶段、对应哪份说明文档。
4. **每个文件都有简介**：源码本身带中文注释，另配一份「简介与学习建议」文档。
5. **保留历史**：被取代的旧版本不删除，集中归档，便于对比进步。

## 分类依据

整理时按四条规则判断文件归属：

1. **语言**：Python 放 `01`～`05`，C 语言放 `06`～`07`。
2. **学习阶段**：Python 按"基础语法 → 流程与输入 → 综合项目 → 可视化 → 文件读写"排列，靠后的阶段会用到前面的知识。
3. **程序复杂度**：单个功能的短脚本放基础目录，带菜单、多函数、能存数据的放综合项目目录。
4. **是否被取代**：内容和写法被更新版本替代的文件，进 `99_早期版本归档`，不占用正式目录的位置。

配套的说明文档一律**与源码放在同一个目录**，不单独集中到一个 `docs` 里。原因是：读代码时想查说明，抬头就在旁边；如果集中存放，就要在两个目录之间来回跳。

## 命名规范

| 对象 | 规范 | 示例 |
| --- | --- | --- |
| 顶层目录 | `序号_主题`，序号决定推荐顺序 | `01_Python基础练习`、`06_C语言练习` |
| Python 源文件 | `NN_日期_主题.py`，`NN` 是本目录内的文件编号 | `05_2026-08-30_成绩统计与及格人数.py` |
| C 语言 / 蓝桥杯源文件 | `NN_日期_主题.c`，`NN` 是本目录内的文件编号 | `13_2026-10-10_数组输入校验与成绩统计.c` |
| 配套说明文档 | 与源码同名，加 `_简介与学习建议` | `05_2026-10-10_数组统计_简介与学习建议.md` |
| 逐行教程 | 与源码同名，加 `_零基础教程` | `14_2026-09-13_两数比较与成绩等级_零基础教程.md` |
| 归档文件、教程、`docs` 下的说明 | 没有编号的文件，日期放在最前面，并按需加 `_早期版` 或 `_旧版` 后缀 | `2026-08-23_密码_早期版.py`、`docs/2026-10-10_学习顺序.md` |

**日期是"这个文件第一次上传到仓库的那一天"**，格式为 `YYYY-MM-DD`，来源是 Git 提交记录（会跨改名向前追溯，所以文件后来被改名、移动都不会改变这个日期）。它的作用是让人一眼看出每个文件的创建时间。

同一天上传的源码和它的说明文档，日期通常相同；如果说明文档是后来补写的，日期就会比源码晚一些——这也是真实情况，不需要刻意对齐。

下面这些文件的文件名**不带日期**，因为名字本身有固定用途：

- `README.md`（仓库主页和各目录首页，GitHub 靠这个确切的名字把内容显示成目录说明）；
- `学生信息.json`、`学生成绩示例.txt`（被 Python 程序按文件名读取，改名程序就会找不到文件）；
- `requirements.txt`、`.gitignore`（工具和 Git 约定的标准文件名）；
- `gamebox2.3.2.exe`（Windows 安装包，不是学习文件）。

命名规则的三条原则：

1. **保留中文。** 中文名一看就懂，比拼音和英文缩写更适合现阶段复习。
2. **序号和日期在前。** 打开目录就能看到"编号 + 日期"两列，既能按编号找文件，也能一眼看到创建时间。
3. **不带多余后缀。** 原来表示"修改过程"的后缀（如 `_你贴代码的修正版`）统一改成能说明版本关系的写法（如 `15_..._修正版`）。

## 各目录说明

**`01_Python基础练习`** 适合刚学 Python 时反复运行。文件都很短（20～45 行），每个文件只练一两个语法点，改一行就能看到结果变化。

**`02_Python流程与输入`** 的程序会等待用户输入，需要在终端里交互运行。重点是"输入合法/非法时程序分别怎么反应"。

**`03_Python综合项目`** 收录带菜单的完整小程序，每个都在 50～140 行之间。这一目录的三个主题（计算器、成绩管理、通讯录）各自有多个版本，按版本看能体会到"程序是怎么一步步变好的"。

**`04_Python可视化项目`** 需要 NumPy 和 Matplotlib，依赖统一写在根目录的 `requirements.txt`。现阶段不要求全看懂，先跑起来、再改几个参数即可。

**`05_Python文件读写练习`** 里的 5 个 `.py` 是同一组四道题的四个版本，命名中的"逐行注释""修正版""输入版"就代表版本关系。配套的 `2026-09-13_四道基础题_零基础教程.md` 适合零基础第一次读较长代码。

**`06_C语言练习`** 按练习日期排列，序号即学习顺序。每份源码都配有同名说明文档，写明建议输入、预期输出和易错点。其中 `05_2026-09-30_数组统计.c` 保留了一个真实的逻辑错误，需要自己按文档修正。

**`07_蓝桥杯练习`** 是整题训练，题目比 `06` 更完整：一道题里往往包含循环、数组和多个统计任务。建议先自己写，再对照仓库里的实现。

**`99_早期版本归档`** 保存整理前的旧文件。它们的特点是没有文件说明和逐行注释，功能也偏简单。想对比"加注释前后"的差别时再看。

**`docs`** 存放仓库级说明：学习顺序、文件清单、本文件。这三个文件不参与代码运行。

## 后续维护约定

**新增练习时：**

1. Python 基础练习放 `01`～`02`，带菜单的完整程序放 `03`，文件和 JSON 相关放 `05`，绘图放 `04`。
2. C 语言练习放 `06`，整题训练和算法题放 `07`。
3. 文件名按命名规范办理：Python 用 `NN_日期_主题.py`，C 语言用 `NN_日期_主题.c`，`NN` 接在目录内已有编号之后，日期填这个文件第一次上传的日期（用 `git log --follow --date=short --format=%ad -- <文件>` 取最早的那条）。
4. 同时补一份同名的 `_简介与学习建议.md`，内容包含：文件简介、建议运行数据、零基础学习建议、常见易错点、可以继续尝试。

**更新已有文件时：**

1. 不要直接删掉旧版本，需要保留的话移入 `99_早期版本归档`。
2. 改动后同步更新 `docs/2026-09-12_文件清单.md` 里对应的说明。
3. 新增或移动文件后，检查 `README.md`、目录 `README.md` 和 `docs/2026-09-12_文件清单.md` 里的引用是否还有效。

**每次提交前：**

1. 用 `cc -std=c17 -Wall -Wextra` 编译改过的 C 文件，用 `python3 -m py_compile` 检查改过的 Python 文件。
2. 至少用一组真实数据运行一次，确认输出和文档里写的一致。
3. 确认没有把临时文件、编译产物（如 `a.out`）、`__pycache__` 提交上去。
