# 仓库结构说明

本文件定义当前仓库的分类、命名、文档职责和维护方式。首页入口见 [README](../README.md)，学习顺序见 [综合学习路线](2026-10-10_学习顺序.md)。

## 设计目标

1. 第一层按语言区分：`C/` 与 `Python/`。
2. 第二层按知识点、算法类型或项目性质区分。
3. 每个练习的源码与学习说明放在同一目录。
4. 综合项目保留整体，不为迁就单个语法点而拆散。
5. 仓库可以持续新增练习，而不需要反复重写整套结构。

## 命名规范

### 源码

- C：`NN_YYYY-MM-DD_主题.c`
- Python：`NN_YYYY-MM-DD_主题.py`

`NN` 是文件首次整理时分配的稳定编号，日期是首次进入仓库的日期。编号在同一目录中用于排序和互相引用，不表示整个仓库的唯一 ID。

保留原文件名中的版本信息，例如：

- `_教程版`
- `_修正版`
- `_暴力枚举`
- `_哈希表优化`
- `_早期版`
- `_旧版`

这些后缀用于区别学习过程和算法版本，不随意精简。

### 文档

- 练习说明：与源码同主题名，加 `_简介与学习建议.md`。
- 逐行教程：与源码同主题名，加 `_零基础教程.md`。
- 仓库级主文档：放在 `docs/`，通过 README 和语言导航进入。
- 历史目录说明：放在 `docs/legacy/原目录名/README.md`，不作为当前导航。

## 新增练习流程

1. **确定语言**：C 或 Python。
2. **确定主要目标**：只看这道题最想训练什么，不按偶然使用的语法分类。
3. **选择现有目录**：没有必要时不新建目录。
4. **文件名**：使用序号、首次上传日期和主题。
5. **源码旁边补说明**：至少写文件简介、建议运行数据、学习建议和常见易错点。
6. **更新导航**：如果新增类别、改变入口或增加重要项目，更新对应 README/指南。
7. **验证**：
   - Python 运行 `python3 -m py_compile`。
   - C 运行 `clang -std=c17 -Wall -Wextra -Wpedantic -fsyntax-only`。
   - 至少运行一组真实数据。
8. **提交前检查**：`git status`、`git diff --check`，确认没有缓存、可执行文件和敏感信息。

## 多知识点练习

- 函数 + 数组：根据“主要训练函数拆分还是数组操作”决定。
- 数组 + 指针：如果重点是数组传参后为什么变指针，放 `08_指针`。
- 算法 + 哈希表：如果是数据结构实现，放 `12_数据结构`；如果是算法思路比较，放 `13_算法练习`。
- 完整菜单程序：即使使用了数组、字典或文件，也保留在综合项目目录。
- 同一题多个版本：保持同一主题命名，放在同一目录，方便递进阅读。

## 保护原始学习代码

- 文档优化不得修改源码、数据文件、运行配置或依赖清单。
- 发现代码错误时，在学习说明中记录现象、原因和最小修复思路。
- 需要练习修复时，优先复制到自己的新文件，不覆盖原始版本。
- 旧版本不删除，文件名保留 `_早期版` 或 `_旧版`。
