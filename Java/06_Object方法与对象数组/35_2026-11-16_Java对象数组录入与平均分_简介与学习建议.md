## 程序功能说明

```java
Student[] students = new Student[2];
System.out.println("刚创建数组时 students[0] = " + students[0]);
for (int i = 0; i < students.length; i++) {
    String name = sc.next();
    while (!sc.hasNextInt()) {
        System.out.println("成绩必须是整数，请重新输入...");
        sc.next();
    }
    int score = sc.nextInt();
    students[i] = new Student(name, score);
}
```

程序先创建长度为 2 的对象数组，此时两个格子都是 `null`，所以第一行输出 `students[0] = null`。循环中每次读取一个姓名（`next()` 读取一个不含空格的“单词”），再检查下一个输入是否为整数；不是整数就提示重读并丢弃错误内容，直到读到整数。然后 `new Student(name, score)` 创建对象，把引用存进 `students[i]`。

录入完成后，用增强 `for` 遍历数组，`System.out.println(stu)` 自动调用 `Student.toString()` 输出学生信息，同时累加 `getScore()`。最后计算平均分：

```java
double average = (double) sum / students.length;
System.out.printf("平均成绩：%.2f%n", average);
```

`(double) sum` 先把整数转成小数，避免 `175 / 2` 被截断成 `87`。`%.2f` 保留两位小数，`%n` 换行。

## 学习重点

- `new Student[2]` 只创建数组，两个元素是 `null`；必须逐个 `new Student(...)` 才有对象。
- `students.length` 是数组容量，不是“已经录入的人数”。本题恰好每个格子都录入，所以两者相同；更一般的程序要用单独的 `count` 记录有效数量。
- `sc.next()` 读取一个单词，遇到空格或换行停止，所以姓名不能含空格。若姓名可能含空格，应改用 `nextLine()` 并额外处理换行残留。
- `sc.hasNextInt()` 只检查下一个输入能否当作整数，不读取；确认后再 `nextInt()`。检查失败时用 `sc.next()` 把错误内容读走，否则会反复检查同一个位置，形成无限循环。
- 增强 `for` 的 `stu` 是元素引用的副本，但通过它调用 `getScore()` 读取的是同一个对象的数据。
- `(double) sum / students.length` 与 `sum / students.length` 的结果可能不同，后者先做整数除法。
- `printf` 的 `%.2f` 会自动四舍五入到两位小数。

## 学习难点

### 对象数组的“空格子”

```text
students[0] → null
students[1] → null
```

创建数组时并没有调用 `Student` 的构造方法。只有执行 `students[i] = new Student(...)` 后，对应格子才指向一个对象。如果循环次数少于数组长度，剩下的格子保持 `null`，遍历时直接调用 `getScore()` 会抛出 `NullPointerException`。

### 输入校验为什么不会死循环

假设输入是 `abc`：

1. `hasNextInt()` 返回 `false`。
2. 打印提示。
3. `sc.next()` 读走 `abc`。
4. 下一次 `hasNextInt()` 检查的是后面的内容。

如果第 3 步漏掉，输入位置不动，第 4 步仍然看到 `abc`，循环就会无限打印提示。

### 整数除法的陷阱

```java
int sum = 175;
int n = 2;
double wrong = sum / n;          // 87.0
double right = (double) sum / n; // 87.5
```

`sum / n` 的两个操作数都是 `int`，先按整数除法得到 `87`，再赋值给 `double` 变成 `87.0`。强制转换必须发生在除法之前，或者把 `n` 改成 `double`。

### 成绩只校验了“是整数”

`hasNextInt()` 只保证输入是整数，不保证在 0～100 之间。输入 `-5` 或 `200` 都会被接受。如果题目要求成绩范围，需要在读取后再加一层判断，并把“类型错误”和“范围错误”分开提示。

### EOF 没有处理

如果输入提前结束，`hasNextInt()` 会一直返回 `false`，`sc.next()` 在无内容可读时抛出 `NoSuchElementException`。本题假设输入足够；完整程序应先检查 `hasNext()`，或在 EOF 时结束录入。

## 建议学习流程

1. 先画出长度为 2 的对象数组，标出创建时两个格子的值。
2. 手工跟踪 `Tom 90` 的读取过程：`next()` 得到什么，`hasNextInt()` 检查什么，`nextInt()` 得到什么。
3. 运行正常输入，核对 6 行输出和平均分 87.50。
4. 运行 `Tom abc 90`，观察重试提示和最终成绩。
5. 把 `(double)` 删除，运行 90 和 85，观察平均分变成 87.00，再改回。
6. 把数组长度改成 3，但只输入两组数据，观察程序在等待第三组输入时的行为，思考怎样处理“提前结束”。
7. 关闭源码，自己写一个录入 3 名学生并输出最高分的版本。

## 易错点与测试用例

| 输入 | 真实输出 | 检查目标 |
| --- | --- | --- |
| `Tom 90 / Amy 85` | 两名学生，平均 87.50 | 正常录入与小数除法 |
| `Tom abc 90 / Amy 85` | 多一行重试提示，平均 87.50 | 非整数成绩 |
| `Tom 90 / Amy 85`，数组长度改为 3 | 等待第三组输入 | 容量与有效数量混淆 |

| 输入提前结束 | `NoSuchElementException` | 未处理 EOF |
| 姓名含空格 | 只读到空格前 | `next()` 的限制 |

前两行已于 2026-11-16 实际运行验证；其余为按代码逻辑推导的预期结果，未单独运行。

常见错误包括：以为 `new Student[2]` 会自动创建学生；忘记 `new` 直接给字段赋值；`hasNextInt()` 失败后不读走错误输入；用 `nextLine()` 读姓名但前一次 `nextInt()` 留下换行，导致读到空字符串；整数除法丢小数；遍历时对 `null` 调用方法；把数组容量当作实际人数。
