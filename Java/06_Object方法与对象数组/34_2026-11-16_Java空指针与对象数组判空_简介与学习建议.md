## 程序功能说明

```java
Student[] students = new Student[2];
students[0] = new Student("Tom", 90);

System.out.println("students[0] = " + students[0]);
System.out.println("students[1] = " + students[1]);

if (students[1] != null) {
    System.out.println("students[1].getName() = " + students[1].getName());
} else {
    System.out.println("students[1] is null，已经跳过访问，所以没有出错");
}

System.out.println("下面故意不判断 null，直接访问 students[1]");
System.out.println("students[1].getName() = " + students[1].getName());
System.out.println("这一行不会被输出");
```

`new Student[2]` 只创建了“两个能放 `Student` 引用的格子”，并没有创建任何 `Student` 对象。对象数组的每个格子默认值是 `null`。程序只往下标 0 放了学生，下标 1 仍是 `null`。

第一次访问下标 1 前有 `!= null` 判断，所以走 `else` 分支，安全输出提示。第二次故意不判断，直接调用 `students[1].getName()`，Java 找不到对象，抛出 `NullPointerException`，程序立即终止，最后一行不会执行。

## 运行方式

需要和 `Student.java` 一起编译：

```bash
java_dir=$(mktemp -d /tmp/java-null.XXXXXX)
javac -encoding UTF-8 -Xlint:all -Werror -d "$java_dir" \
  "Java/06_Object方法与对象数组/Student.java" \
  "Java/06_Object方法与对象数组/NullPointerDemo.java"
java -cp "$java_dir" NullPointerDemo
```

预期输出（以 Java 11 为例）：

```text
students[0] = Student{name='Tom', score=90}
students[1] = null
students[1] is null，已经跳过访问，所以没有出错
下面故意不判断 null，直接访问 students[1]
Exception in thread "main" java.lang.NullPointerException
	at NullPointerDemo.main(NullPointerDemo.java:13)
```

命令的退出码是 1，不是 0。这不是运行失败，而是程序按设计在最后抛出异常。不同 Java 版本的异常提示可能多一行“Cannot invoke ... because ... is null”，但类型和终止位置相同。

## 学习重点

- `new Student[2]` 创建的是数组对象，两个元素都是 `null`，不会自动 `new Student()`。
- `null` 表示“不指向任何对象”，不是空字符串 `""`，也不是 0。
- 打印 `null` 本身是安全的，`System.out.println(null)` 会输出 `null`；危险的是对 `null` 调用方法或访问字段。
- `students[1] != null` 为 `false` 时，`if` 块被跳过，程序走 `else`，因此不会崩溃。
- 异常一旦抛出且没有捕获，`main` 立即结束，后续语句不会执行。
- 栈轨迹 `at NullPointerDemo.main(NullPointerDemo.java:13)` 指出出错的文件和行号，是调试的第一线索。

## 学习难点

### 数组创建与对象创建是两件事

```java
Student[] students = new Student[2];   // 只创建数组，两个格子是 null
students[0] = new Student("Tom", 90);  // 这时才创建一个学生对象
```

如果以为 `new Student[2]` 会顺便创建两个学生，就会在访问 `students[1].getName()` 时崩溃。基本类型数组（如 `int[]`）的默认值是 0，对象数组的默认值是 `null`，这是重要区别。

### 打印 null 与调用方法的区别

```java
System.out.println(students[1]);          // 输出 null，安全
System.out.println(students[1].getName()); // 崩溃
```

第一行只是把引用交给打印方法，打印方法能处理 `null`。第二行要先找到对象再调用 `getName()`，对象不存在，无法调用。

### 为什么最后一行不输出

异常会沿着调用栈向上传播。`main` 没有 `try-catch` 捕获它，JVM 打印异常信息后终止程序。`System.out.println("这一行不会被输出")` 位于抛出异常的语句之后，永远到不了。

### 判空不是万能

`if (students[1] != null)` 只能保证“这个格子里有对象”，不能保证对象内部字段都合法。例如 `name` 仍可能是 `null`。完整程序需要对每个可能为 `null` 的引用分别判断，或者从源头保证对象创建时字段不为 `null`。

## 建议学习流程

1. 先阅读代码，标出哪一行会崩溃。
2. 运行程序，确认异常类型、行号和最后一行没有输出。
3. 把最后一行移到异常语句之前，观察它这次会输出，理解“异常之后不执行”。
4. 删除 `if` 判断，直接访问 `students[1]`，确认崩溃位置前移。
5. 用 `students[1] = new Student("Amy", 85);` 补上对象，重新运行，确认程序完整结束。
6. 关闭源码，自己写一个长度为 3 的对象数组，只填两个元素，遍历时先判空再打印姓名。

## 易错点与测试用例

| 操作 | 结果 | 说明 |
| --- | --- | --- |
| 打印未赋值格子 | `null` | 打印引用本身安全 |
| 判空后访问 | 走 `else`，不崩溃 | 正确做法 |
| 不判空直接调用方法 | `NullPointerException`，退出码 1 | 本程序的预期教学结果 |
| 异常后的语句 | 不执行 | 程序已终止 |
| 补上 `students[1]` 对象 | 正常输出姓名 | 有对象才能调用方法 |

以上结果已于 2026-11-16 实际运行验证（Java 11.0.32.1）。

常见错误包括：把 `null` 当成空字符串；用 `students[1].getName() != null` 判断，结果在判断前就崩溃；以为捕获异常后还能继续执行原语句；数组长度和有效元素个数混淆；只判断数组变量本身不为 `null`，却忽略元素为 `null`。
