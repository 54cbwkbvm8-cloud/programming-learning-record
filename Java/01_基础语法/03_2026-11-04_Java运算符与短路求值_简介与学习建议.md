# Java 运算符与短路求值：简介与学习建议

## 文件基本信息

- 源码：`OperatorsDemo.java`
- 所属分类：`Java/01_基础语法`
- 首次整理日期：2026-11-04
- 程序用途：用固定数据集中演示算术、比较、逻辑、自增和三元运算符
- 核心知识点：整数除法、取余、字符串拼接、关系运算、短路求值、前缀与后缀自增、三元表达式
- 前置知识：变量、基本类型、赋值、`System.out.println`
- 相关练习：`BasicTypes.java`、`SwitchBreakDemo.java`、`GradeLevel.java`

源码与上传附件保持字节一致，没有修改代码。这个程序不读取输入，适合先观察固定输出，再逐个改变量做实验。

## 程序功能

程序按以下顺序演示运算符：

1. 用 `a = 17`、`b = 5` 计算加、减、乘、除和取余。
2. 比较整数除法 `17 / 5` 与小数除法 `17.0 / 5`。
3. 观察负数取余、数字与字符串混合拼接的顺序。
4. 使用 `>`、`>=`、`<=`、`==`、`!=` 生成布尔结果。
5. 比较短路 `&&`、`||` 与非短路 `&`、`|` 对自增次数的影响。
6. 演示 `i++`、`++i` 以及容易误解的 `t = t++`。
7. 用三元运算符求及格结果、两数最大值和奇偶性。

几种代表性输出已经实际运行验证：

```text
a / b = 3
a % b = 2
-17 % 5 = -2
1 + 2 + "3" = 33
"1" + 2 + 3 = 123
&& : r1 = false, n1 = 5
& : r2 = false, n2 = 6
|| : r3 = true, n3 = 5
| : r4 = true, n4 = 6
t = t++ : t = 5
s++ + ++s : r = 8, s = 5
```

## 学习重点

### 整数运算与浮点运算

`17 / 5` 的两个操作数都是 `int`，所以小数部分被截断，结果是 `3`。`17.0 / 5` 中有一个 `double`，整个计算提升为小数运算，结果是 `3.4`。

Java 的 `%` 是求余。`-17 % 5` 的结果是 `-2`，负号跟随被除数一侧，不要把它和数学里的“总是非负余数”混为一谈。

### 字符串拼接的顺序

```java
1 + 2 + "3"    // 先算 1 + 2，再拼成 "33"
"1" + 2 + 3   // 先得到 "12"，再得到 "123"
```

`+` 既可能表示数值加法，也可能表示字符串拼接。计算按从左到右结合，一旦某一步已经变成字符串，后面的 `+` 通常就是拼接。

### 短路与非短路逻辑

`&&` 和 `||` 会尽量少计算右侧：

- `false && 右侧`：结果已经确定为 `false`，右侧不执行。
- `true || 右侧`：结果已经确定为 `true`，右侧不执行。

`&` 和 `|` 用于两个 `boolean` 时仍会计算两边。源码因此得到：

```text
&& : r1 = false, n1 = 5
&  : r2 = false, n2 = 6
```

安全检查 `d != 0 && 10 / d > 1` 依赖短路。先把 `d != 0` 放在左边，`d` 为 0 时右侧的除法不会执行，避免除零。

### 自增与赋值

`i++` 先交出旧值，再让 `i` 加一；`++i` 先加一，再交出新的值。源程序里的 `t = t++` 最终仍是 `5`：

1. 右侧 `t++` 交出旧值 `5`。
2. `t` 自增为 `6`。
3. 赋值又把旧值 `5` 写回 `t`。

这种写法容易让程序难读，学习时可以用它理解求值顺序，但实际代码不应依赖这种风格。

### 三元运算符

```java
condition ? valueWhenTrue : valueWhenFalse
```

源码用它在“及格/不及格”“较大值/较小值”“偶数/奇数”两种结果之间选择。三元表达式适合很短的选择；分支包含多条语句时仍应使用 `if`。

## 学习难点

1. 看字符串拼接时，要按从左到右的顺序，不能只看最后有没有字符串。
2. `&&` 与 `&` 都能得到布尔值，但副作用是否发生不同。
3. `i++` 和 `++i` 的区别不只在符号位置，而在“返回旧值还是新值”。
4. `s++ + ++s` 在 Java 中按操作数从左到右求值，结果是 `r = 8, s = 5`；但可读性很差，不建议写进正式程序。
5. 三元运算符只负责选出值，不等同于完整的多分支流程。

## 建议学习流程

1. 先运行程序，只圈出算术和比较输出。
2. 在纸上写出 `17 / 5`、`17.0 / 5`、`-17 % 5` 的预期值，再核对输出。
3. 分别解释两种字符串拼接为什么得到 `33` 和 `123`。
4. 给 `n1` 到 `n4` 做变量表，记录每一行执行前后的值。
5. 单独研究安全检查为什么不会发生除以零。
6. 用变量表跟踪 `t = t++`，不要只背结果。
7. 合上源码，重写“最大数、是否及格、奇偶判断”三条三元表达式。
