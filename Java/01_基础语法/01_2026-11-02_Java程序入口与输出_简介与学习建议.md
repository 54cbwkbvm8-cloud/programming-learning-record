## 程序功能

程序声明一个名为 `hellojava` 的类，并在 `main` 方法中调用：

```java
System.out.println("Hello, World!");
```

`System.out` 表示标准输出，`println` 会打印括号里的文本并在末尾换行。程序运行后只输出：

```text
Hello, World!
```

这个程序看起来简单，但它同时验证了源文件能被编译器读取、类能生成字节码、虚拟机找到 `main` 方法并执行。

## 运行方式

本机环境是 OpenJDK 21。在仓库根目录运行：

```bash
java_dir=$(mktemp -d /tmp/java-practice.XXXXXX)
javac -encoding UTF-8 -Xlint:all -d "$java_dir" "Java/01_基础语法/hellojava.java"
java -cp "$java_dir" hellojava
```

预期输出：

```text
Hello, World!
```

上面的运行结果已在当前环境实际验证。`-d` 和 `-cp` 都是临时目录，因此不会在仓库里留下 `hellojava.class`。

## 学习重点

### 类与文件

Java 代码通常写在类中。`class hellojava` 声明类；当前这个类没有 `public` 修饰符，所以文件名不要求与类名大小写完全一致。

如果把声明改成 `public class HelloJava`，源文件就必须叫 `HelloJava.java`。类名使用大驼峰（例如 `HelloJava`）是常见可读写法，但当前附件使用 `hellojava`，本次保留原始学习记录。

### main 方法

```java
public static void main(String[] args)
```

这是 Java 应用常见的启动入口。`args` 用来接收命令行参数，本程序没有使用。暂时可以先把它理解为运行时准备好的参数字符串数组。

### 输出语句

- `System` 是标准库中的入口类之一。
- `out` 是标准输出流。
- `println` 打印后换行；`print` 打印后不自动换行。
- 双引号中的文字是字符串字面量，分号结束一条语句。

## 学习难点

1. 文件名、类名和运行命令中的类名不是同一个概念。当前程序运行时写 `java hellojava`，因为启动的是类，不是文件。
2. Java 区分大小写，`hellojava`、`HelloJava` 和 `Hellojava` 是不同名字。
3. `main` 写错一个修饰符或参数形式，都可能让程序无法按预期启动。初学时应先对照标准形式，理解后再变式。
4. 源码后半段的注释没有参与编译。只看终端输出不能证明那些注释中的文字完全正确。

## 原附件中的静态检查结果

可执行部分可以通过编译并正确运行。阅读源码后半段注释时，发现两处说明与当前有效代码不一致：

- 注释示例写成 `public class hellojava`，随后又要求文件叫 `Hellojava.java`；一旦类名是 `hellojava`，文件名必须是 `hellojava.java`。
- 最后一条注释写成“HelloWorld 类”，实际类名是 `hellojava`。

这两处是注释文字问题，不影响当前非 `public` 类的编译和运行。为保护原始学习记录，未直接修改附件。

## 建议学习流程

1. 先运行程序，确认输出。
2. 圈出类声明、`main` 方法和输出语句。
3. 解释 `javac` 生成了什么，`java` 又加载了什么。
4. 把字符串改成自己的姓名或一句话，先预测结果再运行。
5. 新建自己的 `HelloJava.java`，使用 `public class HelloJava`，遵守文件名规则。
6. 故意漏写一个分号，阅读第一条编译错误，再恢复。
