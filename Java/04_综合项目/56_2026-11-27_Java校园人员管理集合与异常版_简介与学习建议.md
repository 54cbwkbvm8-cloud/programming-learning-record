# Java 校园人员管理（集合与异常版）：简介与学习建议

## 1. 文件基本信息

- **源码**：`CampusPersonManager.java`
- **分类**：`Java/04_综合项目`
- **程序用途**：菜单式校园人员管理系统第二版——用 `List<Person>`（实际是 `ArrayList`）保存人员，录入/查询/排序/显示四个功能；所有输入校验改为"抛异常 + 菜单层统一捕获"，`main` 用 `try-catch-finally` 处理输入结束与资源关闭。
- **核心知识点**：`List` 接口与 `ArrayList` 实现、集合的增删查改（`add` / `size` / `get` / `set` / `isEmpty`）、集合版冒泡排序、异常驱动的校验分层（`throw IllegalArgumentException` + 统一 `catch`）、`finally` 释放 `Scanner`、`NoSuchElementException` 处理 EOF、私有静态内部类。
- **前置知识**：48 号数组版校园管理、52 号异常处理、50 号 `Integer.parseInt`、25/26 号类与封装。
- **相关练习**：与 48 号 `CampusManager` 同题材不同实现——48 号用固定数组 + 继承多态，本题用集合 + 异常；两题对照是"数组 → 集合"演进的最佳案例。

## 2. 程序功能说明

结构与 48 号相似：菜单循环、四条业务分支、退出。但三处关键变化：

1. **存储从数组换成集合**：`private static final List<Person> persons = new ArrayList<>()`。不再需要 `MAX` 容量和 `count` 计数——`size()` 就是有效人数，加入用 `add`，不再有"容量已满"分支。
2. **校验从"返回提示"换成"抛异常"**：`addPerson` 里姓名空、年龄非整数、年龄越界都 `throw new IllegalArgumentException("原因")`；`findByName` 空姓名同样抛。菜单层 `catch (IllegalArgumentException e)` 统一打印 `输入错误：原因`。
3. **资源与输入结束由 `main` 兜底**：`try { runMenu(); } catch (NoSuchElementException e) { 输入结束 } finally { scanner.close(); 程序结束 }`。

排序改为集合版冒泡：`persons.get(j)` 比较年龄、`persons.set(j, ...)` 交换引用。`Person` 是 `private static` 内部类，只有姓名、年龄与 `toString`。

源码后半段保留附件注释教程（逐行讲解）。

## 4. 学习重点与难点

- **接口类型声明、实现类创建**：`List<Person> persons = new ArrayList<>()`——左边是接口（只暴露 `List` 规定的能力），右边是实现。以后想换 `LinkedList` 只改右边。这是 08 号"抽象/接口"思想在 JDK 里的落地。
- **`final` 引用不等于不可变**：`final List` 只禁止 `persons = 另一个列表`，`add` / `set` / 排序都照常。初学者常误以为 `final` 让集合只读。
- **集合与数组的职责差异**：没有容量上限、没有 `count`、`size()` 随时可用；但 `get` / `set` 的越界检查在运行时（`IndexOutOfBoundsException`）。
- **异常作为控制流的分层**：底层方法只负责"发现并说明问题"（`throw ...("姓名不能为空！")`），菜单层负责"怎么呈现"。新增校验只需改一处 `throw`，不必在每个分支重复打印。
- **`throw` 在 `try` 内的传播**：`addPerson` 抛出的异常会穿透 `switch` 被同一 `try` 的 `catch (IllegalArgumentException)` 接住，循环继续——这是"业务校验不中断菜单"的实现机制。
- **两条异常通道**：`NumberFormatException`（菜单数字解析，就地 `catch` 后 `continue`）与 `IllegalArgumentException`（业务校验，外层统一 `catch`）。两者的捕获位置刻意不同，需分清。
- **`finally` 收尾**：无论正常退出还是 EOF 异常，`scanner.close()` 与"程序结束"都会执行；52 号学的 `finally` 语义在此落地。
- **内部类不产生类名冲突**：`private static class Person` 的二进制名是 `CampusPersonManager$Person`，与 04/05/06/08 各目录的顶层 `Person` **不冲突**，编译本文件不会触发 `duplicate class`。

## 5. 推荐学习流程

1. 运行综合脚本，先看输出再读代码；特别留意"每条错误提示由谁打印"。
2. 与 48 号并排对照：容量/计数、添加、校验、排序、退出五处逐一比较实现差异。
3. 手工跟踪一次非法年龄：异常在哪一行抛出、被哪一层 `catch` 接住、循环如何继续。
4. 读懂 `main` 的 `try-catch-finally`：分别用正常 `0` 退出与中途 EOF 两条路径验证。
5. 合上源码重写一个"通讯录"小项目，要求使用 `List` + 异常校验。
