# Java 校园人员管理系统：简介与学习建议

## 1. 文件基本信息

- **源码**：`CampusManager.java`
- **分类**：`Java/04_综合项目`
- **程序用途**：菜单式校园人员管理系统——录入（学生/教师/其他）、按姓名查找、按年龄冒泡排序、显示全部、退出，容量 5 人。
- **核心知识点**：继承 + 多态落地到项目（`Person` 数组混装三类对象、`toString` 多态显示）、`static` 全局状态、`final` 常量、`Integer.parseInt` 与 `try-catch` 输入校验、`hasNextLine` 防输入枯竭、包级多类文件。
- **前置知识**：24 号（菜单项目骨架）、36 号（对象数组管理器）、38–41 号（继承与多态）、40/41 号（多文件父子类）。
- **相关练习**：24 号过程式版、36 号重构版管理"成绩"，本题管理"人员"并把继承多态放进菜单循环；是 08 分类的综合应用。

## 2. 程序功能说明

一个文件里有四个类：`Person`（姓名、年龄，私有 + getter + `toString`）、`Student`/`Teacher` 继承 `Person` 并各自追加学号/工号、`CampusManager` 是入口（`public`）。核心设计：`static Person[] people` 这个**父类数组**同时存普通人员、学生、教师；录入时按类型选择 `new` 哪个子类；显示、查找时 `"…" + people[i]` 自动调用**各自真实类型**的 `toString`——学生带学号、教师带工号。这就是"录入时分化、使用时统一"的多态项目模式。

输入防护贯穿全程序：非数字菜单项经 `toInt`（`parseInt` + `catch`）返回 -1 落入 `default`；姓名空、年龄超 0~150（`MAX_AGE` 常量）、类型非法、容量已满都各自拦截；`ask`/主循环用 `hasNextLine()` 先查后读，输入枯竭时优雅退出。

附件注释教程记录了原始版本的 5 处问题（`Student`/`Teacher` 从未被创建、重名只显示第一个、年龄无上限、输入枯竭崩溃、`printmenu` 命名），当前源码已是修复后的版本。注释不影响编译执行。

## 3. 编译与运行

在仓库根目录执行：

```bash
java_dir=$(mktemp -d /tmp/java-campus.XXXXXX)
javac -encoding UTF-8 -Xlint:all -Werror -d "$java_dir" \
  "Java/04_综合项目/CampusManager.java"
printf '1\n张三\n20\n1\n2026001\n1\n李四\n35\n2\nT001\n1\n王五\n28\n3\n2\n张三\n3\n4\n0\n' |
  java -cp "$java_dir" CampusManager
```

已使用 OpenJDK 21.0.13 严格编译并实际运行。以上脚本依次：录入学生张三 → 录入教师李四 → 录入其他王五 → 查找"张三" → 按年龄排序 → 显示全部 → 退出。关键输出：

```text
找到：张三（20 岁），学号：2026001
1. 张三（20 岁），学号：2026001
2. 王五（28 岁）
3. 李四（35 岁），工号：T001
```

⚠️ **必须单独编译**：本文件内含包级 `Person`、`Student`、`Teacher`，与 `04`（`StudentManagementSystem` 内部类）、`05`、`06`、`08` 各分组的同名类冲突；放进同一次 `javac` 调用会报重复类错误。

另已实测：菜单输 `x` → 无效选择；年龄 `999` → 拦截；容量满 5 人后第 6 次录入 → `容量已满`；`n=0` 式空输入 → 正常退出。

## 4. 学习重点与难点

- **多态的"一存一取"**：存——`Person` 变量接收 `new Student(...)`（向上转型，自动）；取——`+ people[i]` 按真实类型调 `toString`。36 号用接口/类分层管理器，本题用继承达到同样效果，两相对照。
- **`static` 全局状态的取舍**：`people/count/sc/running` 都是 `static`，全部方法直接共享。规模小时代价最小；规模大时（36 号的做法）应封装进对象。能说清两种写法的适用边界，比背"static 不好"重要。
- **`people[count++] = person` 的语义**：先用 `count` 当下标存入、再自增。`++count` 会错位。数组后半段是 `null`，所以一切遍历用 `i < count` 而不是 `i < MAX`。
- **排序只动前 `count` 个**：冒泡外层 `count - 1`、内层 `count - 1 - i`，`null` 格子绝不参与比较（否则 NPE）。
- **三道输入防线**：`hasNextLine`（防枯竭）→ `toInt`（防非数字）→ 范围/非空校验（防越界值）。24 号学过的"校验分层"在这里全部复用。
- **重名查找**：遍历全程、计数器 `found` 记录命中数，而不是找到第一个就 `return`——边界语义由题意决定。

## 5. 推荐学习流程

1. 运行上面的脚本，对照输出理解"录入分化、显示统一"。
2. 画出内存图：`people` 的 5 个格子、`count` 的位置、三个对象各自的字段（含父类部分）。
3. 遮住 `addPerson`，自己写出"类型选择 + 三分支创建 + 入库"，再对照。
4. 追踪 `sortByAge` 一轮：`people[j]` 与 `people[j+1]` 交换时，交换的是引用还是对象本体？（引用——对象在内存里不动。）
5. 边界实验：容量满继续录入、两次同名查找、排序后重复运行排序（已有序仍跑满趟数，本题无 `swapped` 优化）。
6. 与 36 号对比总结：两题的"实体/管理/界面"职责分别放在哪里，各自的代价是什么。

| 场景 | 预期结果 | 状态 |
| --- | --- | --- |
| 上述综合脚本 | 录入 3 人、重名查找 2 条、按年龄排序、多态显示 | 已运行验证 |

| 标准输入提前结束（EOF） | 主循环 `break`，正常退出 | 已运行验证（空输入） |
| 姓名输入空白行 | `姓名不能为空。` | 预期结果，未运行验证 |
| 学生学号输入空白行 | `学号不能为空。` | 预期结果，未运行验证 |
| 把遍历条件写成 `i < MAX` | 访问 `null` 格子抛 `NullPointerException` | 预期结果，未修改源码测试 |

一个值得注意的实测现象：容量已满时 `addPerson` 在读姓名**之前**就返回，因此用脚本连续喂数据时，原计划给第 6 人的"姓名/年龄/类型"三个字段会被后续菜单循环当作选项消费掉（例如年龄 `60` 会触发一次无效选择、`3` 会触发一次排序）。交互式逐行输入不会遇到；写自动测试脚本时要按实际读取顺序供数。

## 7. 拓展与后续学习

- 加"删除人员"功能：找到下标后 `people[i] = people[i+1]` 逐个前移、`count--`（练数组搬移与 `null` 收尾）。
- 用 `47` 号思路把 `Person` 改成抽象类、加抽象方法 `getRole()`，让显示逻辑完全交给子类。
- 把容量上限改成"满时自动扩容"（`Arrays.copyOf`，14 号学过），体会固定数组与动态扩容的取舍。
- 数据仍只在内存：学完文件操作后加持久化，即可形成"录入→保存→重启加载"的完整闭环。
