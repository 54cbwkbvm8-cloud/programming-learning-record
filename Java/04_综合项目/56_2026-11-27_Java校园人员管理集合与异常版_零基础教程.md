# Java 校园人员管理（集合与异常版）：零基础教程

> 配合 [CampusPersonManager.java](CampusPersonManager.java) 与 [56 号简介](56_2026-11-27_Java校园人员管理集合与异常版_简介与学习建议.md) 使用。本教程假设你已经学过 48 号（数组版）与 52 号（异常处理）。

## 0. 这一版改了什么

先看两版的关键差异，再逐块理解：

| 对比项 | 48 号 `CampusManager` | 56 号 `CampusPersonManager` |
| --- | --- | --- |
| 存储 | `Person[]` + `MAX` + `count` | `List<Person>` + `ArrayList` |
| 容量 | 固定 5 人，满了提示 | 自动扩容，无上限 |
| 校验 | 布尔判断 + `return` + 打印提示 | `throw new IllegalArgumentException(原因)` |
| 提示 | 每个分支各自打印 | 菜单层统一 `catch` 打印 |
| 输入结束 | `hasNextLine()` 主动检查 | `catch (NoSuchElementException)` 兜底 |
| 资源关闭 | 无（程序直接结束） | `finally { scanner.close(); }` |
| 人员类型 | 父类 + 学生/教师子类（多态） | 单一 `Person`（内部类） |

一句话：**48 号教"继承多态怎么组织数据"，56 号教"集合与异常怎么组织流程"**。

## 1. 集合：从"自己数格子"到"交给容器"

48 号需要自己维护两样东西：

```java
static Person[] people = new Person[MAX];   // 格子数固定
static int count = 0;                        // 手动记录存了几个
```

56 号只留一行：

```java
private static final List<Person> persons = new ArrayList<>();
```

三个变化：

1. **不用数了**：`persons.size()` 随时返回人数；遍历用 `for (Person p : persons)`，不用 `i < count`。
2. **不用管容量**：`add` 自动扩容；也就不存在"容量已满"分支。
3. **换实现只改一处**：声明用 `List`（接口），创建用 `ArrayList`（实现）。以后想换 `LinkedList`，只改 `new` 那一处，其余代码不动。

⚠️ 常见误解：`final` 修饰 `persons` **不是**让集合不可变。`final` 只禁止"重新指向另一个列表"，`add` / `set` / 排序都正常。真正不可变要 `List.of(...)` 之类的工厂。

## 2. 集合版冒泡排序

```java
for (int i = 0; i < persons.size() - 1; i++) {
    for (int j = 0; j < persons.size() - 1 - i; j++) {
        if (persons.get(j).getAge() > persons.get(j + 1).getAge()) {
            Person temp = persons.get(j);
            persons.set(j, persons.get(j + 1));
            persons.set(j + 1, temp);
        }
    }
}
```

和 48 号的结构一模一样，只是三处替换：

- `persons[j]` → `persons.get(j)`
- `persons[j] = x` → `persons.set(j, x)`
- `count` → `persons.size()`

**仍要注意**：`size()` 在循环条件里每次都会求值，所以外层上界用的是当下的实际人数；排序过程中人数不变，结果正确。

## 3. 异常驱动的校验：把"提示"从业务里抽走

48 号的写法（每个分支自己打印）：

```java
if (name.isEmpty()) {
    System.out.println("姓名不能为空。");
    return;
}
```

56 号的写法（业务只抛，界面统一接）：

```java
if (name.isEmpty()) {
    throw new IllegalArgumentException("姓名不能为空！");
}
```

菜单层：

```java
try {
    switch (choice) { ... case 1: addPerson(); ... }
} catch (IllegalArgumentException e) {
    System.out.println("输入错误：" + e.getMessage());
}
```

好处有三个：

1. **校验逻辑集中**：所有规则都在 `addPerson` / `findByName` 里，一眼看完。
2. **提示格式统一**：`输入错误：` 前缀只写一次，改文案只改一处。
3. **不易漏 `return`**：抛异常天然中断当前方法，不需要在每个失败分支记得 `return`。

执行路径（非法年龄）：

```text
菜单 → switch case 1 → addPerson → parseInt 失败 → throw IllegalArgumentException
   ↑                                                        │
   └────────── catch 捕获，打印“输入错误：年龄必须是整数！” ←──┘
```

**异常不会退出程序**：`catch` 接住后循环继续，菜单重新显示。这正是 52 号"异常是控制流"的实战用法。

## 4. 两条异常通道，别混淆

| 异常 | 在哪抛出 | 在哪捕获 | 捕获后 |
| --- | --- | --- | --- |
| `NumberFormatException` | 菜单数字解析 `parseInt(line)` | 紧邻的 `catch`（同一循环内） | 打印"输入有误"，`continue` 重显菜单 |
| `IllegalArgumentException` | `addPerson` / `findByName` 的业务校验 | 外层 `try` 的 `catch` | 打印"输入错误：原因"，循环继续 |
| `NoSuchElementException` | `scanner.nextLine()` 遇到输入结束 | `main` 的 `catch` | 打印"输入结束"，进入 `finally` 后结束 |

为什么不把菜单解析也交给外层？因为它的提示语不同（要回显用户原文），而且解析失败后 `choice` 没有值，必须先 `continue` 跳过 `switch`。

## 5. finally 与输入结束

```java
public static void main(String[] args) {
    System.out.println("===== 校园人员管理系统 （带异常校验）=====");
    try {
        runMenu();
    } catch (NoSuchElementException e) {
        System.out.println("输入结束，程序退出。");
    } finally {
        scanner.close();
        System.out.println("程序结束");
    }
}
```

- 正常选 `0` 退出：`runMenu` 里 `return` → `try` 正常结束 → `finally` 执行 → 打印"程序结束"。
- 输入中途断了：`nextLine()` 抛 `NoSuchElementException` → `catch` 打印"输入结束" → `finally` 执行。

两条路都以"程序结束"收尾——这就是 52 号学的 `finally` 在实际项目里的用途：**收尾代码只写一次，不管怎么离开都执行**。

## 6. 内部类：为什么不冲突

```java
private static class Person {
    private final String name;
    private final int age;
    ...
}
```

`Person` 定义在 `CampusPersonManager` 内部，编译后的类名是 `CampusPersonManager$Person`，与 `08_继承与多态` 各目录的顶层 `Person` **不是同一个类名**，所以本题可以和别的文件一起编译（尽管实践中仍建议单独编译以免混淆）。

`private static` 的含义：只在本类内部可见；`static` 表示不需要外部类实例就能创建——对"纯数据载体"足够。

## 7. 常见错误与排查

| 现象 | 原因 | 修复 |
| --- | --- | --- |
| `cannot find symbol: method add` | 变量声明成数组类型 | 声明为 `List<Person>` |
| `persons.get(j)` 越界 | 混用了 `MAX` 与 `size()` | 循环上界统一用 `size()` |
| 校验失败后菜单没重显 | 用了 `return` 而非 `throw`，或 `catch` 包住了整个循环 | 确认 `catch` 在 `while` 内、`throw` 在业务方法内 |
| 输入结束后程序崩溃并打印栈 | 没有 `catch (NoSuchElementException)` | 按第 5 节加兜底 |
| 认为 `final List` 不能 `add` | 混淆"引用不可变"与"内容不可变" | 见第 1 节说明 |
| 排序后列表没变 | 只读 `get` 忘了 `set` | 交换必须 `get` + `set` 成对使用 |

## 8. 动手练习

1. 运行第 3 节脚本，标出每条提示分别由哪一层打印（菜单层 / 业务层 / main）。
2. 加"按姓名删除"功能：遍历找到下标后 `persons.remove(index)`，注意删除后下标变化。

5. 对比 48 号：把本题的 `Person` 改回"父类 + 学生/教师子类"，同时保留集合与异常——得到两版优点的合并版。
