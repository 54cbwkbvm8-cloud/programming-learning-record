# Java 成绩管理系统零基础教程

本教程配合 [GradeManager.java](GradeManager.java) 使用。目标不是背完 205 行可执行代码，而是能回答以下问题：

1. 一条学生记录由哪些数组位置共同组成？
2. 菜单选一个编号后，程序按什么顺序调用方法？
3. 输入错误在哪一层被拦截？
4. 排序时为什么不能只交换成绩？
5. 空名单、重复学号、并列最高分和 EOF 应该怎样测试？

## 一、先看程序全貌

程序的核心结构可以画成：

```text
main
├── printMenu
├── readInt
└── switch(choice)
    ├── 1 addStudent
    │   ├── findIndexById
    │   ├── readToken
    │   └── readScore
    ├── 2 queryStudent
    │   └── findIndexById
    ├── 3 showAll
    ├── 4 showStats
    ├── 5 bubbleSortDesc
    │   └── showAll
    ├── 0 退出
    └── default 提示无效选项
```

这个结构先不要逐行看。先理解 `main` 只负责循环和分发，具体功能由不同方法完成。

## 二、数据放在哪里

程序没有定义 `Student` 类，而是使用三个平行数组：

```java
static String[] ids = new String[MAX];
static String[] names = new String[MAX];
static double[] scores = new double[MAX];
```

假定已经录入两名学生：

```text
下标        0        1        2 ... 49
ids       1001     1002     null    null
names     张三     李四     null    null
scores     88.5     95.0     0.0     0.0
```

`count` 是 2，说明只有下标 0 和 1 有效。数组还有 48 个格子，但里面不是学生记录。

这条关系必须牢记：

```text
同一条学生记录 = ids[i] + names[i] + scores[i]
```

### 为什么不能用 `count` 表示数组容量

容量永远是 `MAX = 50`。实际人数会从 0 增加到 50。循环处理学生时使用：

```java
for (int i = 0; i < count; i++)
```

如果写成 `i < MAX`，程序会访问未录入的 `null` 和默认成绩 0.0。

## 三、菜单循环怎样持续运行

```java
boolean running = true;
while (running) {
    printMenu();
    int choice = readInt("请选择功能编号：");
    switch (choice) {
        // 调用不同功能
    }
}
```

执行顺序：

1. `running` 初始为 `true`。
2. 每轮先打印菜单。
3. 读取一个整数 `choice`。
4. `switch` 跳到匹配功能。
5. 功能结束后回到 `while` 顶部。
6. 只有选择 0 时把 `running` 改成 `false`。
7. 下一轮条件为假，循环结束。

菜单功能结束后不需要额外“返回菜单”语句，因为方法返回后会自然回到 `main` 的循环中。

## 四、读取输入为什么要拆成三个方法

### `readToken`：读取一个不含空格的词

```java
static String readToken(String prompt) {
    System.out.print(prompt);
    exitIfNoInput();
    return sc.next();
}
```

`next()` 读取到空格或换行就停止。所以：

- 学号 `1001` 可以。
- 姓名 `张三` 可以。
- 姓名 `张 三` 只会读入“张”，后面的“三”可能被下一项误读。

### `readInt`：确保得到整数

如果下一个输入不是整数，`hasNextInt()` 为假。程序把这个非法词读走，避免它永远挡在输入缓冲区最前面，然后提示重新输入。

### `readDouble`：确保得到数字

`readDouble` 先保证输入能被解析成 `double`，但它不保证成绩范围合法。范围和类型是两个不同问题。

### `readScore`：再检查 0～100

```java
double score = readDouble("请输入成绩（0~100）：");
while (!(score >= 0 && score <= 100)) {
    // 提示并重新读取
}
```

`abc` 在 `readDouble` 层被拒绝；`-1` 和 `101` 已经能解析成数字，在 `readScore` 层被拒绝。

## 五、EOF 为什么单独处理

`exitIfNoInput()` 使用：

```java
if (!sc.hasNext()) {
    System.out.println("输入已结束，程序退出。");
    System.exit(0);
}
```

当固定测试数据提前结束时，`hasNext()` 为假。如果不先检查，后续 `nextInt()` 或 `nextDouble()` 可能抛出 `NoSuchElementException`。

当前使用 `System.exit(0)` 立即结束整个进程：

- 优点是单文件菜单不会卡住。
- 缺点是方法不会正常返回上层，也不方便单元测试。

更完整的工程通常让输入方法返回“成功/失败”状态，再让 `main` 决定退出。

## 六、录入一名学生

`addStudent` 按顺序做四件事：

1. 检查 `count >= MAX`。
2. 读取学号。
3. 用 `findIndexById` 检查学号是否已经存在。
4. 读取姓名和合法成绩，再写入 `count` 下标。

### 学号为什么必须用 `equals`

```java
if (ids[i].equals(id)) {
    return i;
}
```

`String` 是引用类型。`==` 比较“是否引用同一个对象”，`equals` 比较字符串内容。学号来自多次输入，可能创建不同对象，因此必须使用 `equals`。

### 为什么先查重再写入

如果先写数组再查重复，发现重复时旧记录已经被覆盖一部分，需要额外回滚。当前代码先完成所有检查，最后才写三个数组，失败时不会污染已有数据。

### `count++` 后发生了什么

录入前 `count = 0`：

```text
ids[0] = "1001"
names[0] = "张三"
scores[0] = 88.5
count = 1
```

下一次录入写入下标 1。`count` 同时表示人数和下一个空位。

## 七、查询一个学生

`findIndexById` 从 0 遍历到 `count - 1`：

- 找到时返回当前下标。
- 循环结束仍未找到时返回 `-1`。

`queryStudent` 根据返回值分两路：

```text
index == -1  -> 没找到
index != -1  -> 用同一 index 输出三个数组
```

用下标把三个数组重新关联起来，是平行数组设计最重要的步骤。

## 八、显示全部和统计

`showAll` 用普通 `for` 和下标输出，因为需要同时取得学号、姓名、成绩。

`showStats` 先检查 `count == 0`，避免访问 `scores[0]` 和除以 0。

第一次遍历维护：

```java
sum += scores[i];
if (scores[i] > max) {
    max = scores[i];
}
```

结束后：

```java
double average = sum / count;
```

第二次遍历打印所有与 `max` 相同的姓名和学号。

### 并列最高分示例

成绩为 95、95、80：

| 轮次 | 成绩 | `sum` | `max` |
| ---: | ---: | ---: | ---: |
| 1 | 95 | 95 | 95 |
| 2 | 95 | 190 | 95 |
| 3 | 80 | 270 | 95 |

平均分是 `270 / 3 = 90.00`。第二次遍历找到前两名 95 分学生，所以两人都输出。

## 九、为什么排序最危险

假设排序前：

```text
下标 0: 1001 张三 70
下标 1: 1002 李四 90
```

降序排序后应该变成：

```text
下标 0: 1002 李四 90
下标 1: 1001 张三 70
```

如果只交换成绩：

```text
下标 0: 1001 张三 90  ← 错误
下标 1: 1002 李四 70
```

成绩顺序对了，但学号、姓名和成绩已经错配。因此当前源码在每次交换时同时处理三个数组：

```java
double tempScore = scores[j];
String tempId = ids[j];
String tempName = names[j];
```

然后分别交换三组元素。

### 三元素交换的检查方法

只需检查交换后每个下标：

```text
ids[i] 仍对应 names[i] 和 scores[i]
```

如果三组都整体移动，对应关系保持不变；只移动一两组，数据就会错位。

### 为什么相同成绩不需要交换

条件是 `scores[j] < scores[j+1]`。相等时不交换，因此相同成绩的原有录入顺序会保留。

## 十、一个完整执行轨迹

输入：

```text
1
1001
张三
88.5
5
0
```

程序路径：

```text
main
-> printMenu
-> readInt 得到 1
-> addStudent
   -> readToken 得到 1001
   -> findIndexById 返回 -1
   -> readToken 得到 张三
   -> readScore 得到 88.5
   -> 写入下标 0
   -> count 变为 1
-> 回到菜单
-> readInt 得到 5
-> bubbleSortDesc
   -> 单元素无需交换
   -> showAll
-> 回到菜单
-> readInt 得到 0
-> running = false
-> 退出
```

## 十一、测试要覆盖哪些边界

| 场景 | 输入或操作 | 预期 |
| --- | --- | --- |
| 空名单显示 | 菜单 3 | 暂无学生数据 |
| 空名单统计 | 菜单 4 | 无法统计，不除零 |
| 空名单排序 | 菜单 5 | 无法排序 |
| 正常录入 | 1001、张三、88.5 | 添加成功 |
| 重复学号 | 再输入 1001 | 拒绝添加 |
| 非数字成绩 | `abc` 后输入 88 | 重试后成功 |
| 超范围成绩 | `-1`、`101` 后输入 88 | 两次重试后成功 |
| 并列最高分 | 95、95、80 | 列出两名最高分学生 |
| 容量上限 | 第 51 人 | 名单已满 |
| 查询不存在 | 9999 | 未找到 |
| 非法菜单词 | `abc` 后输入 0 | 提示整数无效 |
| 超出菜单范围 | 9 | 提示 0～5 |
| 输入提前结束 | 无输入或数据耗尽 | 输出退出提示，退出码 0 |

## 十二、怎样判断自己真正理解了

尝试不看答案完成：

1. 画出两位学生时三个数组和 `count` 的状态。
2. 说明 `findIndexById` 为什么只遍历到 `count`。
3. 写出 `readDouble` 与 `readScore` 分别拦截哪一种错误。
4. 解释 `ids[i].equals(id)` 不能改成 `ids[i] == id`。
5. 手工推演 95、80、95 的降序冒泡排序，写出每轮三个数组。
6. 解释删除学生时为什么要把后面的平行数组元素向前移动。
7. 把三个平行数组改成一个 `Student[]`，说明哪些同步问题会消失。
8. 给出至少三组能暴露容量、重复和空名单错误的测试数据。

## 十三、由易到难的改造练习

### 练习一：最小菜单

先只保留录入、显示和退出三个功能。理解 `main`、`addStudent` 和 `showAll` 的最小闭环。

### 练习二：修改成绩

先按学号查找，确认存在后读取合法成绩，再更新 `scores[index]`。不要改动另外两个数组。

### 练习三：删除学生

找到下标后，把该下标之后的三个数组元素全部向前移动一格，再执行 `count--`。

### 练习四：保存文件

说明学号、姓名和成绩用什么格式写入文件，读取时怎样恢复 `count`，以及文件不存在或某一行损坏时怎样处理。

### 练习五：对象化

定义：

```java
static class Student {
    String id;
    String name;
    double score;
}
```

再把三个平行数组改成一个 `Student[]`。重点比较代码是否更安全、排序交换是否更简单。

### 练习六：集合与测试

用 `ArrayList<Student>` 替代固定容量数组，并把查找、统计、排序拆成独立方法。学会 JUnit 后，为这些方法增加真正的自动断言。
