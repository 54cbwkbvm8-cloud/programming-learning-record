## 分类理由

本文件虽然大量使用类和封装，但它的主要目标不是单独讲某一个 OOP 语法，而是把录入、查询、显示、统计、排序和菜单组合成一个完整项目。仓库结构说明规定：完整的成绩管理系统等多知识点程序，按项目性质放入 `04_综合项目`。因此本文件与 24 号并列，而不是放进 `05_面向对象`。

## 与 24 号的关系

本文件不是 24 号的复制，也不是简单改名。两版的数据模型和职责划分不同：

| 对比项 | 24 号 `GradeManager.java` | 36 号 `StudentManagementSystem.java` |
| --- | --- | --- |
| 数据组织 | 三个平行数组 `ids`、`names`、`scores` | 一个 `Student[]` 对象数组 |
| 成绩类型 | `double`，支持小数 | `int`，只接受整数 |
| 容量 | 50 | 100 |
| 方法组织 | 全部是 `static` 方法 | `StudentManager` 的实例方法 |
| 校验位置 | 菜单类的 `readScore` | `Student.setScore` 集中校验 |

## 程序功能说明

### `Student`：保护一个学生的数据

字段全部是 `private`：

```java
private String id;
private String name;
private int score;
```

外部不能直接写 `student.score = 150`，只能通过公开方法：

- `getId()`、`getName()`、`getScore()`：读取字段。
- `setScore(int score)`：先检查 `0～100`，合法才写入并返回 `true`，否则保持原值并返回 `false`。
- `toString()`：返回 `学号\t姓名\t成绩`，让 `System.out.println(student)` 直接输出可读内容。

构造方法只接收学号和姓名，成绩先保持默认 0，再由 `setScore` 设置。这样“成绩必须合法”的规则只写在 `setScore` 一处，菜单类不需要重复写范围判断。

### `StudentManager`：管理一批学生

内部只有两个字段：

```java
private Student[] students;
private int count;
```

`students.length` 是容量，`count` 是实际人数。所有循环都使用 `i < count`，不会碰到后面那些值为 `null` 的空格子。

主要方法：

| 方法 | 作用 |
| --- | --- |
| `getCount()` | 返回实际人数 |
| `getStudent(int index)` | 按下标取学生，越界返回 `null` |
| `getStudent(String id)` | 按学号取学生，转调 `findById` |
| `getStudents()` | 返回只包含有效学生的新数组（保护性复制） |
| `isEmpty()` / `isFull()` | 判断空表和满表 |
| `findById(String id)` | 线性查找，字符串用 `equals` 比较 |
| `addStudent(Student student)` | 依次检查 `null`、满表、学号重复，再放入数组 |
| `getAverage()` | 用 `double` 累加，避免整数除法丢小数 |
| `getMaxScore()` | 打擂台求最高分，空表返回 -1 |
| `sortByScoreDesc()` | 对 `Student` 引用做冒泡降序排序 |

`getStudent(int)` 和 `getStudent(String)` 是方法重载：名字相同，参数类型不同，编译器根据调用时传入的是 `int` 还是 `String` 选择版本。

`getStudents()` 不直接返回内部数组，而是用 `System.arraycopy` 复制有效部分。这样调用者拿到的是独立数组，不能通过修改它破坏管理器内部数据。

### `StudentManagementSystem`：菜单与输入

`main` 维护 `running` 开关，循环显示菜单、读取编号、用 `switch` 分发：

```text
1 → addStudent      录入
2 → queryStudent    按学号查询
3 → showAll         显示全部
4 → showStatistics  平均分与最高分
5 → sortByScoreDesc 降序排序
0 → 退出
```

输入辅助方法：

- `readInt`：用 `nextLine()` 读整行，再 `Integer.parseInt` 转换；失败时提示并重读。统一用 `nextLine()` 可以避免 `nextInt()` 遗留换行符的问题。
- `readText`：读一整行并去掉首尾空格，空字符串时提示重读。

录入流程有两个“原地重试”循环：

1. 学号重复：提示后回到学号输入，不丢失已输入内容。
2. 成绩越界：`while (!student.setScore(readInt(...)))`，只重输成绩，学号和姓名保留。

统计时先取一次最高分，再遍历所有学生，把所有等于最高分的学生都列出，因此并列最高分不会被漏掉。

排序交换的是 `Student` 引用，不再需要同步交换三个数组：

```java
Student temp = students[j];
students[j] = students[j + 1];
students[j + 1] = temp;
```

## 学习重点

1. 一个类只负责一类事情：`Student` 管数据，`StudentManager` 管集合，`StudentManagementSystem` 管交互。
2. 对象数组保存的是引用，`students[0]` 指向一个 `Student` 对象，不是把对象内容复制进数组。
3. `count` 与 `students.length` 不同：前者是实际人数，后者是容量。
4. `getStudents()` 采用保护性复制，避免外部修改内部数组。
5. 成绩校验集中在 `setScore`，添加、构造和以后任何新入口都不应绕过它。
6. 方法重载按参数类型选择：`getStudent(0)` 和 `getStudent("1001")` 调用不同版本。
7. 排序交换对象引用即可，不需要像 24 号那样同步交换三个数组。
8. 输入重试循环把“提示”和“实际行为”保持一致，不会把后续输入误当成菜单选项。
9. `toString()` 让对象可以直接参与字符串拼接和 `println`。
10. 面向对象不是“把 static 改成实例方法”这么简单，而是重新划分数据和职责。

## 学习难点

### 为什么 `Student` 的字段要私有

如果字段公开，任何代码都能写：

```java
student.score = 150;
```

类没有机会拒绝，成绩范围规则形同虚设。改成 `private` 后，所有修改都必须经过 `setScore`，规则只需维护一处。

### 为什么构造方法不直接接收成绩

本程序先创建 `Student(id, name)`，成绩默认为 0，再循环调用 `setScore`。这样做的好处是：构造对象时不需要处理“成绩还没输入”的中间状态，菜单类可以反复要求用户重输，而对象始终合法。

如果构造方法也接收成绩，就必须在构造方法里再写一次范围检查，或者调用同一个校验方法。两种设计都可以，但要保证所有入口规则一致。

### 为什么 `getStudents()` 要复制

如果直接 `return students;`，外部拿到内部数组后可以：

```java
manager.getStudents()[0] = null;
```

这会破坏管理器内部数据。复制一份有效部分返回，调用者只能看到快照，不能改内部结构。

### 为什么两个 `addStudent` 不冲突

`StudentManagementSystem` 里有一个 `private static void addStudent(Scanner, StudentManager)`，负责和用户交互；`StudentManager` 里有一个 `public boolean addStudent(Student)`，负责真正存数据。它们属于不同的类，名字相同互不影响。调用时看的是“谁的对象/类”：

```java
addStudent(scanner, manager);      // 界面类的方法
manager.addStudent(student);       // 管理器的方法
```

### 为什么平均分用 `double`

如果 `sum` 和 `count` 都是 `int`，`175 / 2` 会得到 `87` 而不是 `87.5`。`sum` 声明为 `double` 后，除法按小数进行，`printf("%.2f")` 再保留两位。

### 排序为什么只交换对象

24 号有三个平行数组，交换时必须同时交换 `ids[j]`、`names[j]`、`scores[j]`，少交换一个就会让学号、姓名、成绩错位。36 号把三条信息放进同一个 `Student` 对象，交换引用就等于整体交换，不会错位。

## 易错点与测试用例

| 场景 | 输入或操作 | 实际结果 | 检查目标 |
| --- | --- | --- | --- |
| 空名单显示 | 菜单 3 | 提示“没有学生信息！” | 空表保护 |
| 空名单统计 | 菜单 4 | 提示“没有学生信息！” | 不除以 0 |
| 空名单排序 | 菜单 5 | 提示“暂无学生数据，请先录入！” | 不进入排序 |
| 正常录入 | 1001 / 张三 / 88 | 添加成功，显示 88 | 基本流程 |
| 重复学号 | 再录入 1001 | 提示后重新输入学号 | 原地重试，不丢内容 |
| 成绩越界 | 输入 -1，再输入 95 | 提示后只重输成绩 | 学号姓名保留 |
| 按学号查询 | 查询 1002 | 显示李四 95 | `equals` 查找 |
| 查询不存在 | 查询 9999 | 提示没有找到 | 返回 `null` |
| 统计 | 88 和 95 | 平均 91.50，最高 95 | `double` 除法、并列最高分 |
| 降序排序 | 菜单 5 | 95 在前，88 在后 | 对象引用交换 |
| 非法菜单 | 输入 9 | 提示重新输入 0~5 | `default` 分支 |
| 满容量 | 录入第 101 人 | 提示人数已满 | `isFull()` |
| 学号为 0 开头 | 如 `007` | 按字符串保存，不丢前导 0 | 学号用 `String` |
| 输入提前结束 | 直接 EOF | 抛出 `NoSuchElementException` | 当前没有 EOF 保护 |

常见错误：

- 把 `count` 当成数组容量，循环写 `i < students.length`，访问到 `null`。
- `findById` 用 `==` 比较学号字符串，而不是 `equals`。
- `setScore` 写成 `void`，调用者无法知道是否设置成功。
- 成绩越界后直接回到主菜单，没有真正重输。
- `getStudents()` 直接返回内部数组。
- 排序时只交换分数，忘记姓名和学号在同一个对象里（本版只需交换引用，反而更安全）。
- 平均分用 `int` 累加，丢掉小数。
- 两个 `addStudent` 混淆，以为它们是同一个方法。

## 当前边界与改进方向

- 没有修改、删除学生功能。
- 数据只保存在内存，退出即丢失。
- 容量固定为 100，不能自动扩容。
- 成绩只支持 `int`，不支持小数。
- 没有处理标准输入提前结束（EOF），直接按 Ctrl+D 会抛 `NoSuchElementException`。
- 没有自动测试，固定输入只能人工核对输出。
- `Student`、`StudentManager` 是包级类，只适合单文件教学；真实项目应拆成独立文件并考虑包名。
- 本文件的 `Student` 与 `Java/05_面向对象/Student.java`、`Java/06_Object方法与对象数组/Student.java` 同名但内容不同。三者不能放进同一个 `javac` 调用或同一个输出目录，否则会出现重复类错误。本文件应单独编译。
- 没有继承、接口、集合、文件持久化或数据库。
