# Java 成绩管理系统简介

## 文件基本信息

- 源码：[GradeManager.java](GradeManager.java)
- 首次整理日期：2026-11-09
- 所属分类：`Java/04_综合项目`

## 分类理由

这不是一道只训练某个语法点的小题，而是完整控制台项目：

1. 有一个持续运行的菜单。
2. 有 5 个业务功能。
3. 使用三个数组共同保存一条学生记录。
4. 包含容量、重复学号、整数、小数和分数范围校验。
5. 同时组合了查找、统计、字符串处理和排序。

仓库维护规则规定“完整菜单程序保留整体”，因此归入 `Java/04_综合项目`，不从程序中拆出多个源码放入其他目录。

## 程序功能说明

可执行代码位于源码第 1～205 行，第 206 行以后是逐行说明注释，编译器会忽略。

程序使用三个长度 50 的数组：

| 数组 | 保存内容 |
| --- | --- |
| `ids` | 学号 |
| `names` | 姓名 |
| `scores` | 成绩 |

下标相同的三个位置属于同一名学生。例如：

```text
ids[0] = "1001"
names[0] = "张三"
scores[0] = 88.5
```

表示第 1 条学生记录。`count` 是实际录入人数，同时也是下一个空位的下标。数组容量是 50，不代表当前已有 50 名学生。

菜单功能如下：

| 选项 | 方法 | 功能 |
| --- | --- | --- |
| 1 | `addStudent` | 检查容量和重复学号，再录入姓名与成绩 |
| 2 | `queryStudent` | 按学号线性查找并显示一条记录 |
| 3 | `showAll` | 输出前 `count` 条有效记录 |
| 4 | `showStats` | 计算平均分、最高分并输出所有并列最高分学生 |
| 5 | `bubbleSortDesc` | 按成绩从高到低排序，并同步交换三个数组 |
| 0 | `main` | 修改 `running`，退出菜单 |

本程序需要 JDK。在仓库根目录执行：

```bash
java_dir=$(mktemp -d /tmp/java-grade.XXXXXX)
javac -encoding UTF-8 -Xlint:all -Werror -d "$java_dir" \
  "Java/04_综合项目/GradeManager.java"
java -cp "$java_dir" GradeManager
```

随后按菜单输入。一个完整测试流程：

```text

1001
张三
88.5
2
1001
3
4
5
0
```

也可以一次送入固定输入：

```bash
printf '1\n1001\n张三\n88.5\n2\n1001\n3\n4\n5\n0\n' |
  java -cp "$java_dir" GradeManager
```

本次在 OpenJDK 21.0.13 下实际通过 `-Xlint:all -Werror` 编译，退出码为 0。

已实际验证的代表性结果：

- 录入张三 88.5 分后，查询能显示 `学号：1001  姓名：张三  成绩：88.5`。
- 统计输出 `平均分：88.50` 和 `最高分：88.5，获得者：张三(1001)`。
- 重复学号 `1001` 会被拒绝。
- 成绩输入 `abc`、`-1`、`101` 会被拒绝，之后输入 `88.5` 能恢复。
- 三名学生 95、95、80 分时，平均分为 `90.00`，最高分同时列出两名 95 分学生。
- 空名单选择 3、4、5、2 时，分别显示对应的“暂无学生数据”提示。
- 第 51 名学生会被拒绝，提示最多 50 人。
- 标准输入提前结束时打印“输入已结束，程序退出”，退出码为 0。

## 学习重点

### 1. 固定容量与有效长度

```java
static final int MAX = 50;
static int count = 0;
```

所有业务循环只访问 `0` 到 `count - 1`。如果把条件写成 `i < MAX`，尚未录入的 `null` 学号和默认成绩 0.0 也会被当成学生。

### 2. 平行数组必须同步

第 `i` 名学生的三项数据来自同一个下标：

```java
ids[i]
names[i]
scores[i]
```

排序时只交换成绩会破坏记录对应关系，因此源码同时交换学号、姓名和成绩三组元素。

### 3. 输入错误与业务错误分开

- `readInt` 负责“下一个输入是不是整数”。
- `readDouble` 负责“下一个输入是不是数字”。
- `readScore` 负责“数字是否在 0～100”。
- `addStudent` 负责“名单是否已满、学号是否重复”。
- `queryStudent` 负责“查询时是否有数据、学号是否存在”。

不同层次负责不同错误，程序才能给出准确提示并继续运行。

### 4. 字符串比较使用 `equals`

```java
if (ids[i].equals(id)) {
```

不能用 `==` 判断两个学号字符串的内容是否相同。`==` 比较的是引用，内容相同的两个不同 `String` 对象可能得到 `false`。

### 5. 统计和排序可以分两步理解

`showStats` 先一次遍历求总分和最高分，再遍历一次找出所有最高分学生。`bubbleSortDesc` 则把之前学过的方法和数组课程组合起来，按成绩降序原地调整三条平行数组。

## 学习难点

### `count` 同时承担两个含义

`count` 既表示“当前有几名学生”，也表示“下一条新记录应该放在哪个下标”。添加成功后执行 `count++`，有效区间从 `[0, count-1]` 扩展到新的 `[0, count-1]`。

### 学号重复检查只能查有效区间

`findIndexById` 的循环条件是 `i < count`，不能查完整 50 格。未录入的位置保存 `null`，直接调用 `ids[i].equals(...)` 会触发 `NullPointerException`。

### 三个数组容易失去同步

录入时三个数组写入同一个 `count`；排序时三个数组交换同一个 `j`。任何一个数组少写一步，某名学生的姓名就可能配到另一名学生的成绩。项目级教程会专门画交换过程。

### 最高分并列

源码先把最高“分数值”保存到 `max`，再第二次遍历。所有 `scores[i] == max` 的学生都会被打印。这里的 `max` 直接来自对应数组元素，没有经过额外浮点计算，所以当前并列比较可以使用 `==`；涉及计算结果的浮点比较仍要谨慎。

### 输入结束采用 `System.exit`

`exitIfNoInput` 发现没有任何输入时直接结束整个 JVM。这个方法对当前单文件菜单程序有效，但大型项目通常应把输入状态返回给调用者，让上层决定如何退出。它也不利于单元测试。

## 已知边界与限制

- 数据只保存在内存中，退出程序后全部丢失。
- 最多 50 人，超过后拒绝继续录入。
- 学号和姓名用 `next()` 读取，不能包含空格。
- 没有删除、修改成绩、文件保存、分页显示或对象封装。
- 学号只检查非空和唯一性，没有规定必须是纯数字或固定长度。
- 菜单编号不是整数会重新输入；整数超出 0～5 时由 `switch` 的 `default` 提示。
- 使用 `System.exit(0)` 响应 EOF，会立即结束进程，不执行普通的返回路径。
- 当前用三个平行数组模拟一条记录，后续更适合改成 `Student` 对象或 `ArrayList`。

这些限制不是编译错误。它们说明程序能完成当前作业目标，但还不是一个具备持久化和面向对象结构的正式系统。

## 拓展练习

1. 增加“按学号修改成绩”，先查找再更新，不改变学号与姓名。
2. 增加“删除学生”，把后面的三条平行数组元素整体前移并减少 `count`。
3. 增加“按学号升序显示”，比较按字符串排序与按数值排序的要求。
4. 把三个平行数组改成一个 `Student` 类对象数组，比较两种设计的可读性和同步风险。
5. 使用 `ArrayList<Student>` 替代固定容量数组。
6. 增加文件保存与启动读取，但要明确文件位置、编码和损坏文件处理。
7. 把 `System.exit(0)` 改为返回状态或抛出受控异常，让输入结束更容易测试。
8. 学会 JUnit 后，把查找、平均分、最高分和排序拆成可单元测试的方法。
