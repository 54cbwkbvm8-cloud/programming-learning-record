# 成绩管理系统面向对象重构零基础教程

本教程配合 [36_2026-11-19_Java成绩管理系统面向对象重构_简介与学习建议.md](36_2026-11-19_Java成绩管理系统面向对象重构_简介与学习建议.md) 和 [StudentManagementSystem.java](StudentManagementSystem.java) 使用。建议先完成 24 号过程式版本，再来对比本教程。

## 一、为什么要重构

24 号用三个平行数组保存学生：

```java
static String[] ids = new String[MAX];
static String[] names = new String[MAX];
static double[] scores = new double[MAX];
static int count = 0;
```

这样做能完成任务，但有几个问题：

1. 一个学生的三条信息分散在三个数组里，靠同一下标关联。
2. 排序时必须同时交换三个数组，少换一个就会错位。
3. 所有方法都是 `static`，数据和操作没有明确的归属。
4. 成绩范围校验写在菜单类里，任何新的修改入口都可能绕过它。

36 号把它改成：

```text
Student          一个学生
StudentManager   一批学生
StudentManagementSystem  菜单和输入
```

每一步只回答一个问题：这条数据应该由谁保存？这个操作应该由谁负责？

## 二、三个类的分工

```text
┌─────────────────────────────────────────────┐
│ StudentManagementSystem                     │
│  - 显示菜单                                 │
│  - 读取键盘输入                             │
│  - 决定调用哪个功能                         │
│  - 显示结果                                 │
└──────────────────┬──────────────────────────┘
                   │ 调用
                   v
┌─────────────────────────────────────────────┐
│ StudentManager                              │
│  - 保存 Student[] 和 count                  │
│  - 查找、添加、统计、排序                   │
│  - 不读键盘，不打印菜单                     │
└──────────────────┬──────────────────────────┘
                   │ 数组元素
                   v
┌─────────────────────────────────────────────┐
│ Student                                     │
│  - id、name、score                          │
│  - 保护成绩范围                             │
│  - 把自己转成文字                           │
└─────────────────────────────────────────────┘
```

这种分工的好处：

- 想改菜单，只动 `StudentManagementSystem`。
- 想改查找或排序，只动 `StudentManager`。
- 想改成绩规则，只动 `Student`。
- 每个类都比较短，容易单独理解和测试。

## 三、`Student`：一个学生的数据

### 1. 字段与构造方法（第 3～11 行）

```java
class Student {
    private String id;
    private String name;
    private int score;

    public Student(String id, String name) {
        this.id = id;
        this.name = name;
    }
```

`private` 表示只有 `Student` 类内部的代码能直接访问这三个字段。类外面不能写 `student.score = 150`。

构造方法只接收学号和姓名：

```java
Student student = new Student("1001", "张三");
```

此时 `score` 没有赋值，`int` 的默认值是 0。成绩稍后由 `setScore` 设置。

`this.id = id;` 中，左边是当前对象的字段，右边是构造参数。如果写成 `id = id;`，两边都是参数，字段仍然是 `null`。

### 2. getter（第 13～23 行）

```java
public String getId() { return this.id; }
public String getName() { return this.name; }
public int getScore() { return this.score; }
```

字段私有后，外部通过这三个方法读取。这里 `this.id` 和 `id` 效果相同，因为没有同名参数遮挡；写 `this.` 更清楚地表示“当前对象的字段”。

### 3. `setScore`：把规则集中到一处（第 25～31 行）

```java
public boolean setScore(int score) {
    if (score < 0 || score > 100) {
        return false;
    }
    this.score = score;
    return true;
}
```

返回值表示“是否设置成功”：

- 合法：写入，返回 `true`。
- 非法：不写入，返回 `false`，成绩保持原样。

菜单类不需要再写 `score < 0 || score > 100`，只需要看返回值。以后如果规则改成 `0～150`，也只改这里一处。

### 4. `toString`（第 33～36 行）

```java
@Override
public String toString() {
    return id + "\t" + name + "\t" + score;
}
```

`System.out.println(student)` 和 `"添加成功！" + student` 都会自动调用 `toString()`。如果不重写，输出会类似 `Student@15db9742`，无法阅读。

`\t` 是制表符，让三列对齐。

## 四、`StudentManager`：一批学生的管理

### 1. 字段与构造方法（第 39～46 行）

```java
class StudentManager {
    private Student[] students;
    private int count;

    public StudentManager(int capacity) {
        this.students = new Student[capacity];
        this.count = 0;
    }
```

`new Student[capacity]` 只创建了 `capacity` 个“格子”，每个格子的初始值是 `null`，还没有任何 `Student` 对象。

```text
students.length = 5
count = 2

下标：   0        1        2      3      4
      [Student] [Student] [null] [null] [null]
```

访问时只能用 `0` 到 `count - 1`，不能遍历到 `students.length`，否则会对 `null` 调用方法。

### 2. 按下标和按学号取学生（第 48～61 行）

```java
public Student getStudent(int index) {
    if (index < 0 || index >= count) {
        return null;
    }
    return students[index];
}

public Student getStudent(String id) {
    return findById(id);
}
```

两个方法同名但参数类型不同，这叫方法重载：

```java
manager.getStudent(0);       // 调 int 版本
manager.getStudent("1001");  // 调 String 版本
```

`getStudent(int)` 先检查下标范围，越界返回 `null`，避免 `ArrayIndexOutOfBoundsException`。

### 3. 保护性复制（第 63～67 行）

```java
public Student[] getStudents() {
    Student[] result = new Student[count];
    System.arraycopy(students, 0, result, 0, count);
    return result;
}
```

为什么不直接 `return students;`？

- 内部数组后面有很多 `null` 空格子。
- 外部拿到内部数组后可以随意修改，破坏管理器数据。

复制一份“有效部分”返回，调用者得到的是快照。注意：复制的是引用，返回数组和内部数组指向同一批 `Student` 对象；但替换数组元素不会影响管理器。

### 4. 空表与满表（第 69～76 行）

```java
public boolean isEmpty() {
    return count == 0;
}

public boolean isFull() {
    return count == students.length;
}
```

`count` 是实际人数，`students.length` 是容量。容量 100、实际 3 人时，既不是空也不是满。

### 5. 按学号查找（第 77～84 行）

```java
public Student findById(String id) {
    for (int i = 0; i < count; i++) {
        if (students[i].getId().equals(id)) {
            return students[i];
        }
    }
    return null;
}
```

两个关键点：

1. 循环条件是 `i < count`，不是 `i < students.length`。
2. 字符串比较用 `equals`，不能用 `==`。`==` 比较的是“是不是同一个对象”，`equals` 比较内容。

找到后立即返回，后面的元素不再检查；走完整个有效范围还没找到才返回 `null`。

### 6. 添加学生（第 86～98 行）

```java
public boolean addStudent(Student student) {
    if (student == null) {
        return false;
    }
    if (isFull()) {
        return false;
    }
    if (findById(student.getId()) != null) {
        return false;
    }
    students[count++] = student;
    return true;
}
```

四个检查按顺序进行：

1. `null`：没有对象可加。
2. 满表：没有空位。
3. 学号重复：不允许。
4. 都通过：放入 `students[count]`，然后 `count` 加 1。

`students[count++] = student;` 等价于：

```java
students[count] = student;
count = count + 1;
```

如果写成 `students[++count]`，会先加 1，跳过一个格子，导致数组下标错位。

### 7. 平均分与最高分（第 100～122 行）

```java
public double getAverage() {
    if (isEmpty()) {
        return 0.0;
    }
    double sum = 0.0;
    for (int i = 0; i < count; i++) {
        sum += students[i].getScore();
    }
    return sum / count;
}
```

`sum` 用 `double`，所以 `175 / 2` 得到 `87.5`。如果 `sum` 是 `int`，整数除法会丢掉小数。

```java
public int getMaxScore() {
    if (isEmpty()) {
        return -1;
    }
    int max = students[0].getScore();
    for (int i = 1; i < count; i++) {
        if (students[i].getScore() > max) {
            max = students[i].getScore();
        }
    }
    return max;
}
```

打擂台：

1. 先假设第一个学生是最高分。
2. 从第二个学生开始依次比较。
3. 遇到更高的就更新 `max`。
4. 空表返回 -1，因为合法成绩最小是 0，-1 可以明确表示“没有最高分”。

### 8. 对对象排序（第 124～134 行）

```java
public void sortByScoreDesc() {
    for (int i = 0; i < count - 1; i++) {
        for (int j = 0; j < count - 1 - i; j++) {
            if (students[j].getScore() < students[j + 1].getScore()) {
                Student temp = students[j];
                students[j] = students[j + 1];
                students[j + 1] = temp;
            }
        }
    }
}
```

冒泡排序的每一轮把当前最小的学生“沉”到右边，最终得到从高到低。

和 24 号最大的区别：这里交换的是 `Student` 引用。学号、姓名、成绩本来就在同一个对象里，交换一次就是整体交换，不会像三个平行数组那样出现“学号换了、成绩没换”的错位。

`<` 而不是 `<=`：分数相同时不交换，相同分数的学生保持原来的先后顺序（稳定）。

## 五、`StudentManagementSystem`：菜单与输入

### 1. 主循环（第 140～172 行）

```java
boolean running = true;
while (running) {
    printMenu();
    int choice = readInt(scanner, "请选择功能编号（0~5）：");
    switch (choice) {
        case 1: addStudent(scanner, manager); break;
        ...
        case 0: running = false; break;
        default:
            System.out.println("无效的选择，请重新输入 0~5 的数字！");
    }
}
```

`running` 是循环开关。选择 0 时改成 `false`，当前这一轮结束，`while` 条件不再成立，程序退出。

每个 `case` 末尾的 `break` 不能漏，否则会“穿透”到下一个功能。

### 2. `readInt`：读一个整数（第 185～195 行）

```java
private static int readInt(Scanner scanner, String prompt) {
    while (true) {
        System.out.print(prompt);
        String line = scanner.nextLine().trim();
        try {
            return Integer.parseInt(line);
        } catch (NumberFormatException e) {
            System.out.println("请输入数字！");
        }
    }
}
```

为什么用 `nextLine()` 再 `parseInt`，而不是直接 `nextInt()`？

`nextInt()` 只读走数字，会把数字后面的回车留在输入里。下一次 `nextLine()` 会先读到这个回车，返回空字符串，用户明明还没输入，程序就跳过去了。统一用 `nextLine()` 读整行，不会遗留换行。

`Integer.parseInt` 遇到 `"abc"`、`"3.5"` 或空字符串会抛 `NumberFormatException`，`catch` 后提示并重读。

### 3. `readText`：读非空文字（第 197～206 行）

```java
private static String readText(Scanner scanner, String prompt) {
    while (true) {
        System.out.print(prompt);
        String text = scanner.nextLine().trim();
        if (!text.isEmpty()) {
            return text;
        }
        System.out.println("输入不能为空！");
    }
}
```

去掉首尾空格后，如果还有内容就返回；否则提示重读。

### 4. 录入学生（第 208～231 行）

```java
if (manager.isFull()) {
    System.out.println("学生人数已满，无法添加！");
    return;
}
```

先检查满表，避免让用户白输一堆内容。

学号重试：

```java
String id;
while (true) {
    id = readText(scanner, "请输入学生学号：");
    if (manager.findById(id) == null) {
        break;
    }
    System.out.println("学号已存在，请重新输入！");
}
```

`findById(id) == null` 表示没有重复，学号可用。重复时提示后回到循环开头，重新输入学号。

姓名只读一次，不参与查重。

成绩重试：

```java
Student student = new Student(id, name);
while (!student.setScore(readInt(scanner, "请输入学生成绩（0-100）："))) {
    System.out.println("成绩必须在 0~100 之间，请重新输入！");
}
```

拆开看：

1. `readInt` 保证读到整数。
2. `student.setScore(...)` 尝试设置，合法返回 `true`，非法返回 `false`。
3. `!` 取反：设置失败时为 `true`。
4. 设置失败就提示，然后回到循环条件，再次读取成绩。

学号和姓名已经在 `student` 对象里，重输成绩不会丢失它们。

最后：

```java
if (manager.addStudent(student)) {
    System.out.println("添加成功！" + student);
} else {
    System.out.println("添加失败！无法保存该学生信息！");
}
```

`"添加成功！" + student` 会自动调用 `toString()`。

### 5. 查询、显示、统计、排序

`queryStudent`（第 233～246 行）：

- 先判断空表。
- 读学号，调用 `findById`。
- 返回 `null` 提示没找到，否则打印表头和学生。

`showAll`（第 248～258 行）：

- 空表提示。
- 打印表头。
- 用增强 `for` 遍历 `manager.getStudents()`。
- 最后显示总人数。

`showStatistics`（第 260～275 行）：

- 空表提示。
- 取一次最高分。
- 打印人数、平均分、最高分。
- 再遍历所有学生，把所有等于最高分的都列出来，处理并列。

`sortByScoreDesc`（第 277～285 行）：

- 空表提示。
- 调用 `manager.sortByScoreDesc()`。
- 显示排序结果。

## 六、用两个学生走一遍

输入：

```text
1001 张三 88
1002 李四 95
```

录入后：

```text
students[0] ──> Student("1001", "张三", 88)
students[1] ──> Student("1002", "李四", 95)
students[2] = null
...
count = 2
```

统计：

```text
sum = 88 + 95 = 183.0
average = 183.0 / 2 = 91.5
max = 95
```

排序时比较 `students[0].getScore()` 和 `students[1].getScore()`：

```text
88 < 95 → 交换引用
```

交换后：

```text
students[0] ──> Student("1002", "李四", 95)
students[1] ──> Student("1001", "张三", 88)
```

对象本身没有移动，只是数组格子里的地址换了。

## 七、常见错误与排查

### 错误 1：循环到 `students.length`

```java
for (int i = 0; i < students.length; i++) {
    sum += students[i].getScore();   // 后面是 null，崩溃
}
```

应使用 `i < count`。

### 错误 2：字符串用 `==`

```java
if (students[i].getId() == id)   // 错
```

应使用 `.equals(id)`。

### 错误 3：忘记更新 `count`

添加后没有 `count++`，下次会覆盖同一个格子，人数也不对。

### 错误 4：成绩越界直接 `return`

如果写成：

```java
if (score < 0 || score > 100) {
    System.out.println("成绩不合法");
    return;   // 错：回到主菜单，学号姓名白输
}
```

应让菜单类循环重输，而不是直接结束录入。

### 错误 5：平均分用整数

```java
int sum = 0;   // 错：183 / 2 = 91，不是 91.5
```

应使用 `double sum = 0.0;`。

### 错误 6：排序只换分数

在 24 号的平行数组版本里，只换 `scores` 会导致学号、姓名和成绩错位。36 号交换整个 `Student` 引用，天然避免这个问题。

### 错误 7：把三个 `Student` 类一起编译

本文件的 `Student`、`Java/05_面向对象/Student.java`、`Java/06_Object方法与对象数组/Student.java` 同名但内容不同。不要这样编译：

```bash
javac Java/04_综合项目/StudentManagementSystem.java \
      Java/05_面向对象/Student.java
```

会出现“重复类”错误。本文件应单独编译到自己的临时目录。

## 九、自测题

1. 为什么 `Student` 的字段要声明为 `private`？
2. `getStudents()` 为什么要复制数组？
3. `getStudent(0)` 和 `getStudent("1001")` 为什么调用不同方法？
4. `students.length` 和 `count` 分别表示什么？
5. 添加学生时四个检查的顺序是什么？为什么 `null` 检查要放在最前面？
6. 为什么平均分要用 `double` 累加？
7. 排序时为什么不需要同步交换学号、姓名和成绩？
8. 学号重复和成绩越界时，为什么用户不会回到主菜单？
9. 如果直接按 Ctrl+D 结束输入，程序会发生什么？
10. 本文件和 24 号相比，哪些代码变简单了？哪些代码变多了？

参考要点：

1. 防止外部绕过 `setScore` 写入非法成绩。
2. 避免外部替换内部数组元素，保护管理器数据。
3. 参数类型不同，触发方法重载。
4. 前者是容量，后者是实际人数。
5. `null`、满表、学号重复、写入；先排除最基础的无效参数。
6. 避免整数除法丢掉小数。
7. 三条信息在同一个对象里，交换引用就是整体交换。
8. 菜单类用 `while` 在原地重试，只重新输入出错的那一项。
9. 抛出 `NoSuchElementException`，当前没有 EOF 保护。
10. 排序和查找变简单；类的数量、对象创建和职责划分变多。

能回答这些问题，并且能独立写出最小版本，才算真正理解这次重构。
