# Java 方法重载简介

## 文件基本信息

- 源码：[MaxOverload.java](MaxOverload.java)
- 首次整理日期：2026-11-08
- 所属分类：`Java/03_方法与数组`
- 程序用途：用三个同名 `max` 方法练习整数两数比较、整数三数比较和小数两数比较。
- 主要问题：Java 为什么允许同名方法；编译器怎样根据参数个数和参数类型选择具体方法。
- 核心知识点：方法重载、参数个数、参数类型、返回类型、实参类型提升、三元表达式、方法复用。

## 程序功能说明

源码有三个同名方法：

```java
max(int a, int b)
max(int a, int b, int c)
max(double a, double b)
```

方法名相同不冲突，因为参数列表不同。`max(int, int, int)` 调用 `max(max(a, b), c)` 复用两数版本，先找出前两个数中的较大值，再与第三个数比较。

`max(3.5, 2)` 中的 3.5 是 `double` 字面量，因此 2 会被提升为 `double`，调用 `max(double, double)`。最终输出 3.5，不会把 3.5 截成 3。

## 学习重点

- 重载的是“方法名相同、参数列表不同”，返回值类型不同本身不足以构成重载。
- 编译器先看实参个数，再看实参类型能否匹配或转换为形参类型。
- 三数版本没有重复写三组比较，而是复用两数版本，体现小方法组合大方法。
- 三元表达式 `a > b ? a : b` 只计算一个表达式并返回较大值。

## 学习难点

### 为什么只改返回类型不能重载

下面两个声明不能同时存在：

```java
static int value(int x)
static double value(int x)
```

调用 `value(3)` 时，编译器还无法从“把结果赋给谁”反推选哪一个版本，因此仅靠返回类型不能区分重载。

### 字面量类型会参与选择

`max(3, 7)` 的两个参数都是 `int`，选择整数版本。`max(3.5, 2)` 的 3.5 是 `double`，因此选择小数版本。若把代码改成 `max(3.5, 2.0)`，仍然是同一个小数版本。

### 三数最大值不能只比较其中两次的偶然结果

三数版本通过两次完整的两数比较得到结果。无论最大值在第一位、第二位还是第三位，最后都会留下正确最大值。测试 4、9、6，9、4、6 和 6、4、9 就是为了排除“只对某个位置正确”的假象。

## 建议学习流程

1. 先按参数列表列出三个重载版本。
2. 对源码中的 12 次调用，先只根据实参类型写出会选哪一个方法。
3. 运行程序核对输出。
4. 手工计算 `max(max(4, 9), 6)` 的调用顺序。
5. 尝试写出 `max(int,int)` 和 `max(double,double)` 的决策表。
6. 关闭源码，自己写 `min` 的二数整数、三数整数和二数小数版本。

## 易错点与测试用例

| 调用 | 预期选择或结果 | 检查目标 |
| --- | --- | --- |
| `max(3, 7)` | `int,int`，返回 7 | 基本整数调用 |
| `max(5, 5)` | 返回 5 | 两数相等 |
| `max(-3, -8)` | 返回 -3 | 全负数不能硬编码 0 |
| `max(4, 9, 6)` | 返回 9 | 最大值在中间 |
| `max(6, 4, 9)` | 返回 9 | 最大值在最后 |
| `max(3.5, 2)` | `double,double`，返回 3.5 | 字面量提升 |

常见错误包括把参数顺序误说成“返回类型重载”、认为 `max(3.5, 2)` 会调用整数版并截断，以及三数比较只写其中两次却漏掉某个位置。当前程序不涉及 `NaN`、无穷大或浮点精度比较，因此小数部分只适合入门演示，不是完整数值比较工具。
