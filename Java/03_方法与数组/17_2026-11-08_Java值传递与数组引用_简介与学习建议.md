## 程序功能说明

`changeInt(int x)` 把形参改成 100。调用后 `num` 仍是 5，因为传入的是 5 的一份副本。

`changeArray(int[] arr)` 执行 `arr[0] = 100`。数组变量里保存的是引用值；形参和实参复制后指向同一个数组对象，所以通过 `arr` 修改元素，调用者的 `data` 能看到变化。

`reassignArray(int[] arr)` 执行 `arr = new int[] {9, 9, 9}`。这里只把形参 `arr` 改成指向一个新数组，调用者的 `data` 仍指向旧数组，因此看不到这次重新赋值。

`swap(int a, int b)` 只交换两个形参的副本，调用者的 `x`、`y` 不变。

## 学习重点

| 操作 | 方法内看到什么 | 调用者最终看到什么 | 原因 |
| --- | --- | --- | --- |
| 修改 `int` 形参 | 100 | 仍为 5 | 复制整数副本 |
| 修改数组元素 | `arr[0]` 变为 100 | 共同数组元素变为 100 | 复制的是相同引用值 |
| 重新给数组形参赋值 | 形参指向新数组 | 旧数组不变 | 只改副本中的引用值 |
| 交换两个整数形参 | 方法内可交换 | 外部不变 | 外部变量没有传入地址 |

Java 只有值传递。容易混淆的地方是：对象和数组变量保存的值本身就是引用，所以“引用的副本”仍指向同一个对象。正确说法不是“数组按引用传递”，而是“引用值按值传递”。

## 学习难点

### 形参变量与它指向的对象要分开

可以把 `data` 和 `arr` 画成两张写着同一地址的纸条。`changeArray` 通过地址找到数组并改元素；`reassignArray` 只是把 `arr` 这张纸条改成另一个地址，没有动 `data` 这张纸条。

### 为什么 Java 没有指针交换

`swap(x, y)` 收到的只是 1 和 2 的副本。方法内部交换 `a`、`b`，不会自动找到 `main` 里的 `x`、`y`。若要交换数组中的两个元素，可以把数组和两个下标传进去，因为方法能通过共同引用修改元素。

## 建议学习流程

1. 画四个变量：`num`、`data`、`x`、`y`，并画出数组对象。
2. 依次执行四次方法调用，每调用完一次写出 `main` 中的变量值。
3. 运行程序验证。
4. 把 `changeInt(num)` 暂时改成 `changeInt(8)`，说明实参不必是变量。
5. 自己写 `resetFirst(int[] arr)`，把第一个元素置 0。
6. 再写 `replaceArray(int[] arr)`，把形参重新指向新数组，确认调用者不变。

## 易错点与测试用例

| 测试或修改 | 预期结果 | 检查目标 |
| --- | --- | --- |
| `changeInt(num)` | `num` 仍为 5 | 基本类型副本 |
| `changeArray(data)` | `data[0]` 为 100 | 共同引用修改元素 |
| `reassignArray(data)` | `data` 仍是旧数组 | 形参重新赋值 |
| `swap(x, y)` | 外部仍为 1、2 | 交换的是副本 |
| 传入 `null` 数组 | 访问元素时抛出 `NullPointerException` | 当前没有空引用检查 |

源码没有对 `arr` 判空。当前只传入真实数组，所以正常路径安全；不能据此认为这些方法可以接受任意输入。
