## 程序功能说明

按题目意图，程序应读取元素个数 `n` 和全部 `n` 个元素，找出与最大值不同的第二档最大值。例如：

```text
5
8 3 8 6 1
```

最大值是 8，重复的 8 不算第二大，答案应是 6。

当前源码存在两个实质逻辑错误，因此实际运行不能得到这个结果。源码按要求原样保留，不擅自修改；完整排查过程见 [零基础教程](22_2026-11-08_Java第二大不同值_零基础教程.md)。

## 当前源码的两个主要问题

### 问题一：没有读取第一个元素

```java
for (int i = 1; i < n; i++) {
    a[i] = sc.nextInt();
}
```

`new int[n]` 的所有元素先被初始化为 0。循环从下标 1 开始，只读取了 `n - 1` 个数，`a[0]` 永远保持 0，同时还少读入一个附件数据。后续最大值从 `a[0]` 开始，就会被这个默认 0 干扰。

最大值的读取循环应从下标 0 开始：

```java
for (int i = 0; i < n; i++) {
    a[i] = sc.nextInt();
}
```

### 问题二：输出判断写反

```java
if (!found) {
    System.out.println(second);
} else {
    System.out.println("NO");
}
```

`found == true` 才表示找到了第二值，因此正确方向应是：

```java
if (found) {
    System.out.println(second);
} else {
    System.out.println("NO");
}
```

## 学习重点

- 数组声明后先有默认值 0，不能把默认值误当成用户输入。
- 取值和比较必须使用同一批完整数据。
- `found` 比用 `second == 0` 判断更可靠，因为 0 可能是真实数据。
- 输出分支是算法的一部分；计算正确但分支写反，最终结果仍然失败。
- 求“第二大不同值”时，重复最大值不能进入第二位置。

## 学习难点

### 为什么 `second = 0` 不能当“没找到”

如果数组是 `[3, 0, -1]`，0 可能是真实的第二大值；如果数组是 `[7, 7, 7]`，又没有第二值。单看 `second` 是否等于 0 无法区分这两种情况，因此需要单独的 `found` 状态。

### 为什么只修输出仍然不够

把输出分支改对以后，输入 5 个数仍只读入 4 个，`a[0]` 仍是 0。计算过程继续错误，所以读取循环和输出分支都要分别修正、分别测试。

### 数组长度为零

源码随后访问 `a[0]`。当 `n = 0` 时会抛出 `ArrayIndexOutOfBoundsException`；当 `n = 1` 时通常没有合法第二值。正式版本应在访问前检查长度。

## 建议学习流程

1. 先用 `5 / 8 3 8 6 1` 手工写出预期答案 6。
2. 运行当前程序，确认得到 `NO`。
3. 用变量表写出数组实际内容 `[0, 8, 3, 8, 6]`，说明最后一个 1 根本没被读取。
4. 单独修正读取循环，再单独讨论输出分支。
5. 阅读 [零基础教程](22_2026-11-08_Java第二大不同值_零基础教程.md)，不要先照抄完整答案。
6. 自己设计正常值、全相等值、全负数和单元素测试。

## 易错点与测试用例

| 输入 | 当前真实输出 | 题目预期 | 暴露的问题 |
| --- | --- | --- | --- |
| `5 / 8 3 8 6 1` | `NO` | `6` | 少读首元素、输出反向 |
| `5 / 2 1 9 9 5` | `NO` | `5` | 重复最大值 |
| `3 / 7 7 7` | `NO` | `NO` | 无第二值，偶然正确 |
| `3 / -1 -2 -3` | `NO` | `-2` | 不能把 0 当有效初值 |
| `1 / 9` | `0` | `NO` 或明确提示 | 没有第二值 |
| `0` | 抛出越界异常，退出码 1 | 应校验输入 | 空数组 |

当前结果由实际运行确认。不要说“程序能编译”或“退出码为 0”就等于逻辑正确；这份源码正好说明二者不是一回事。
