## 程序功能说明

素数定义是大于 1，且只能被 1 和自身整除的整数。`isPrime(int n)` 先处理所有小于 2 的数，再尝试从 2 开始寻找因数。

循环条件：

```java
i <= n / i
```

表示只检查到大约 `sqrt(n)`。如果 `n` 有大于平方根的真因数，另一个对应因数一定小于平方根，因此早就会被找到。这里使用除法而不是 `i * i <= n`，可以避免 `i * i` 在接近 `int` 上限时先溢出。

一旦找到 `n % i == 0` 就返回 `false`；循环结束仍未找到因数，才返回 `true`。

## 学习重点

- 小于 2 的统一前置判断能一次覆盖负数、0 和 1。
- 2 是素数，循环从 2 开始但不会错误排除它。
- `return false` 找到因数后立即结束，不必继续尝试。
- 循环条件和“从 2 到 n-1 全部试除”相比显著减少了次数。
- `boolean` 返回值比打印“是/否”更容易复用和测试。

## 学习难点

### 为什么只检查到平方根

若 `n = 36`，因数成对出现：1 和 36、2 和 18、3 和 12、4 和 9、6 和 6。只要检查到 6，就已经覆盖了所有可能的较小因数。大于 6 的真因数 9、12、18 都有对应的小因数先被发现。

### 为什么不用 `i * i <= n`

当 `n` 接近 `Integer.MAX_VALUE` 时，`i * i` 可能先在 `int` 中溢出，条件失真。`i <= n / i` 用整数除法保持结果在 `int` 范围内，避免这个风险。

### 为什么 1 不是素数

素数要求恰好有两个正因数。1 只有一个正因数 1，因此不是素数。负数也不是素数。

## 易错点与测试用例

| 输入 | 预期结果 | 检查目标 |
| --- | --- | --- |
| `-7` | `false` | 负数 |
| `0` | `false` | 零 |
| `1` | `false` | 最小非素数正整数 |
| `2` | `true` | 最小素数 |
| `4` | `false` | 最小合数 |
| `49` | `false` | 平方数 |
| `97` | `true` | 普通素数 |
| `2147483647` | `true` | 大整数和循环上界 |

常见错误包括从 1 开始试除导致所有数都被判为合数、把循环写成 `i < n / i` 却漏掉平方根边界、用 `i * i` 造成大数溢出，以及把 1 当成素数。当前方法只处理 `int`，没有处理 `long` 或任意大整数。
