## 程序功能说明

程序创建一个长度为 26 的整数数组：

```java
int[] count = new int[26];
```

数组刚创建时，26 个格子里的默认值都是 0。遍历输入字符串的每个字符 `ch`：

- 如果 `ch` 在 `'a'` 到 `'z'` 之间，总数加一，并让 `count[ch - 'a']` 加一。
- 如果 `ch` 在 `'A'` 到 `'Z'` 之间，总数加一，并让 `count[ch - 'A']` 加一。大小写使用同一组格子，所以 `A` 和 `a` 合并统计。
- 其他字符（数字、空格、标点、汉字等）不计数，直接跳过。

先输出字母总数，再从 `k = 0` 到 `25` 遍历数组，只输出次数大于 0 的字母。`(char) ('a' + k)` 把下标还原成字母：`k = 0` 得到 `'a'`，`k = 3` 得到 `'d'`，因此输出天然按字母表顺序排列。

输入 `Hello, World! 123` 时，字母是 `H e l l o W o r l d`，共 10 个，输出：

```text
10
d: 1
e: 1
h: 1
l: 3
o: 2
r: 1
w: 1
```

## 学习重点

- 数组下标必须是 0 到 25 的整数，字符不能直接当下标，所以要用 `ch - 'a'` 把字母转换成序号。
- `'a' - 'a' = 0`、`'b' - 'a' = 1`、`'z' - 'a' = 25`，正好覆盖 26 个格子。
- 大写字母用 `ch - 'A'`，同样得到 0 到 25，因此与对应小写字母共用格子。
- `(char)` 是强制类型转换。`'a' + k` 的计算结果是 `int`，直接打印会显示数字；转成 `char` 后才显示字母。
- 先输出总数，再遍历数组输出明细，两个循环职责分开。
- 计数数组的长度由“类别数量”决定，不随输入长度变化；时间复杂度是 `O(n + 26)`，额外空间是 `O(26)`。

## 学习难点

### 字符为什么能相减

计算机内部用编号表示字符。常用 ASCII 范围中，`'a'` 是 97，`'b'` 是 98，……，`'z'` 是 122；`'A'` 是 65，……，`'Z'` 是 90。字母编号连续，所以两个字符相减得到它们相隔多少个位置。`ch - 'a'` 的结果是 `int`，不是 `char`，正好可以当数组下标。

### 为什么打印时要加 `(char)`

`'a' + k` 中，`char` 会先提升为 `int` 参与加法，结果类型是 `int`。`System.out.println('a' + 3)` 会打印 `100`，不是 `d`。写成 `(char) ('a' + k)` 才是“把这个编号当作字符”，得到 `d`。注意括号位置：`(char) 'a' + k` 会先把 `'a'` 转成 `char` 再参与加法，结果仍是 `int`，不能达到目的。

### 大小写合并与题目规则

本题把 `A` 和 `a` 视为同一个字母，所以 `count` 只有 26 格。如果题目要求区分大小写，就需要 52 格，或者使用两个数组。规则不同，输出也会不同；改题前先确认题目原文。

### 只统计英文字母

源码只判断 ASCII 的 `A～Z` 和 `a～z`。汉字、全角字母、带重音的拉丁字母都不会计入总数。这是本题“英文字母”的定义，不是程序遗漏；如果题目要求统计所有 Unicode 字母，应改用 `Character.isLetter`，并接受更复杂的分类方式。

## 建议学习流程

1. 写出 `'a'`、`'d'`、`'z'` 的编号，验证 `ch - 'a'` 的结果。
2. 对 `Hello` 手工填出 `count` 数组中出现过的格子。
3. 运行 `Hello, World! 123`，核对总数和 7 行明细。
4. 把输入改成 `aaaBBB`，预测 `a: 3`、`b: 3` 和总数 6。
5. 把 `else if` 改成两个独立的 `if`，确认结果不变，再思考什么时候独立 `if` 会重复计数。
6. 关闭源码，自己写一个统计数字 0～9 的版本。

## 易错点与测试用例

| 输入 | 真实输出 | 检查目标 |
| --- | --- | --- |
| `Hello, World! 123` | 总数 10，7 行字母明细 | 混合大小写、标点、数字 |
| 空行 | `0` | 无字母，不输出明细 |
| `aaaBBB` | `6`，`a: 3`，`b: 3` | 大小写合并 |
| `你好abc` | `3`，`a: 1`，`b: 1`，`c: 1` | 汉字不计入 |
| `zZ` | `2`，`z: 2` | 下标 25 的边界 |

以上结果已于 2026-11-16 实际运行验证（`aaaBBB`、`你好abc`、`zZ` 为按同一逻辑推导的预期结果，未单独运行）。

常见错误包括：用 `ch` 直接作下标导致数组越界；只处理小写漏掉大写；忘记 `total++`；输出时忘记 `(char)` 转换；把 `count[k] > 0` 写成 `>= 0`，导致 26 个字母全部打印；数组长度写成 25 漏掉 `z`。
