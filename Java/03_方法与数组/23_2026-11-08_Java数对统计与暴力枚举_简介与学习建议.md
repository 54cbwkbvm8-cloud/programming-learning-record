## 程序功能说明

外层循环固定第一个下标 `i`，内层循环从 `j = i + 1` 开始：

```java
for (int i = 0; i < n; i++) {
    for (int j = i + 1; j < n; j++) {
        if (a[i] + a[j] == target) {
            count++;
        }
    }
}
```

这样只会检查 `(0,1)`、`(0,2)`、`(1,2)` 等不同下标组合，不会把同一对交换顺序后重复计数，也不会使用同一个位置两次。

对 `[1, 2, 3, 4, 5]` 和目标 5，满足的是 `1+4`、`2+3`，所以答案是 2。

## 运行方式

编译：

```bash
java_dir=$(mktemp -d /tmp/java-pairs.XXXXXX)
javac -encoding UTF-8 -Xlint:all -Werror -d "$java_dir" \
  "Java/03_方法与数组/PairCount.java"
```

运行第一组：

```bash
printf '5 5\n1 2 3 4 5\n' | java -cp "$java_dir" PairCount
```

真实输出为 `2`。

测试重复值：

```bash
printf '3 2\n1 1 1\n' | java -cp "$java_dir" PairCount
```

真实输出为 `3`，因为三个同值元素能组成三对不同下标。

## 学习重点

- 同一元素不能和自己配对，所以 `j` 从 `i + 1` 开始。
- 每个无序下标对只访问一次，避免把 `(i,j)` 和 `(j,i)` 重复计数。
- 计数器必须在两层循环之外初始化。
- 两层循环最多比较 `n(n - 1) / 2` 次，时间复杂度是 `O(n²)`。
- 重复值不是重复下标，`[1,1,1]` 的三对都应计数。

## 学习难点

### 为什么不是二重循环都从 0 开始

若内层也从 0 开始，会把同一个元素与自身相加，还会把每对合法组合算两次。`j = i + 1` 同时解决这两个问题。

### 结果是“对数”不是“元素个数”

重复元素参与多对组合时，一个元素可以出现在多个不同下标对中。题目采用“不同下标对”定义，因此 `[1,1,1]` 的答案是 3，而不是 1。

### 输入和加法边界未检查

源码直接读取 `n` 和全部元素。`n <= 0` 时创建空数组并输出 0，看似不崩溃，但没有提示输入无效。若两个很大的正数或负数相加，`int` 加法可能溢出，导致错误匹配；完整题目应说明数值范围或改用 `long` 计算和。

## 建议学习流程

1. 对 `[1,2,3,4,5]` 列出所有下标对和它们的和。
2. 标出符合目标的 `(0,3)` 与 `(1,2)`。
3. 运行程序验证答案 2。
4. 对 `[1,1,1]` 列出三对不同下标。
5. 把目标改成 6，预测后运行。
6. 关闭源码，自己把核心统计逻辑拆成 `countPairs(int[] a, int target)`。

## 易错点与测试用例

| 输入 | 真实输出 | 检查目标 |
| --- | --- | --- |
| `5 5 / 1 2 3 4 5` | `2` | 普通无重复 |
| `3 2 / 1 1 1` | `3` | 重复值、不同下标 |
| `4 0 / -1 1 0 0` | `2` | 只有 `-1+1` 与 `0+0` 两对 |
| `1 4 / 2` | `0` | 单元素不能自配 |
| `0 0` | `0` | 当前无输入错误提示 |
| 两个接近 `Integer.MAX_VALUE` 的数 | 可能溢出 | 未规定大数范围 |

常见错误包括内层从 0 开始、计数器放到外层内部导致重置、把相等元素误判为同一元素，以及把输出“对数”误解成“不同数值的种数”。

## 拓展练习

1. 拆出 `static int countPairs(int[] a, int target)`。
2. 不只统计数量，还打印所有匹配下标对。
3. 使用 `long` 总和避免 `int` 加法溢出。
4. 对比哈希表优化思路：一次遍历记录已经见过的数字，把平均时间降到 `O(n)`。
5. 与 [C 语言两数之和暴力解](../../C/13_算法练习/27_2026-10-18_两数之和_暴力枚举.c) 比较“找到一组就返回”和“统计全部对数”的停止条件。
