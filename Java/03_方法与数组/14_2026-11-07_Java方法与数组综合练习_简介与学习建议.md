## 程序功能说明

源码文件共 788 行，其中第 1 到 216 行是可执行代码，第 217 行以后是大段旧版逐行注释。编译器会忽略这些注释，所以程序只有一个有效类和一组有效方法。

可执行部分按 `main` 的调用顺序分成七块：

1. `demoBasics()` 创建不同类型的数组，观察默认值，并使用下标、`length`、增强 `for` 和普通 `for`。
2. `demoOutOfBounds()` 故意访问 `arr[3]`，再用 `ArrayIndexOutOfBoundsException` 演示异常被捕获后程序仍可继续。
3. `demoCopy()` 比较“两个变量指向同一个数组”和 `Arrays.copyOf()` 创建独立数组的差别。
4. `bubbleSortTrace()` 打印冒泡排序每一轮和每次比较后的数组，便于手工核对。
5. `bubbleSort()` 完成原地排序，用来测试普通数组、逆序数组、已排序数组、重复元素、空数组和单元素数组。
6. `binarySearchTrace()` 打印闭区间 `[low, high]` 的缩小过程。
7. `linearSearch()` 与 `binarySearch()` 用返回下标、找不到返回 `-1` 的统一约定完成查找测试。

`check(String name, boolean passed)` 只负责打印 `[通过]` 或 `[失败]`，它是教学用的简易检查器，不是 JUnit 等正式测试框架。

## 学习重点

| 知识点 | 需要理解什么 | 为什么重要 |
| --- | --- | --- |
| 方法 | `static` 方法怎样定义、传参、返回值和被 `main` 调用 | 把程序拆成可测试的小功能，避免所有逻辑堆在 `main` |
| 数组 | 同类型元素的连续编号集合，下标从 0 开始 | 排序、查找、统计和后续数据结构都依赖数组 |
| `length` | 字段写法是 `arr.length`，没有括号 | 边界和循环条件必须根据实际长度计算 |
| 增强 `for` | 每轮拿到元素值的副本，适合读取，不适合替换数组元素 | 避免误以为 `value = value * 2` 会修改原数组 |
| 引用 | 数组变量保存的是对象引用，不是整组元素的副本 | 方法可以通过引用修改调用者传入的数组 |
| 复制 | `Arrays.copyOf` 创建独立新数组，直接赋值只复制引用 | 区分“同一个数组两个名字”和“真正的新数组” |
| 异常 | 越界访问会抛出异常，`try-catch` 可以处理指定的异常 | 认识运行时错误，并知道异常不是普通返回值 |
| 冒泡排序 | 相邻元素比较交换，每轮把一个当前最大值送到右端 | 练习双层循环、边界和原地修改 |
| 二分查找 | 先要求数组有序，再根据 `arr[mid]` 缩小一半区间 | 建立算法前提、区间和边界意识 |

## 学习难点

### 难点一：数组变量不是整组值的容器复制

```java
int[] original = { 1, 2, 3 };
int[] alias = original;
```

这里 `alias` 和 `original` 指向同一个数组。通过 `alias[0]` 修改元素，`original[0]` 也会看到变化。`Arrays.copyOf(original, 5)` 才创建另一块独立数组。

### 难点二：增强 `for` 只能安全地读取

```java
for (int value : nums) {
    value = value * 2;
}
```

`value` 是当前元素的副本。给 `value` 重新赋值不会写回 `nums`，需要修改元素时必须使用 `nums[i]`。

### 难点三：下标和循环上界差一

数组长度是 `n` 时，合法下标是 `0` 到 `n - 1`。冒泡排序内层循环写 `j < n - 1 - i`，同时保证 `j + 1` 不越界，并跳过已经排好的右端元素。

### 难点四：二分查找的前提和区间

二分查找只适用于有序数组。源码维护闭区间 `[low, high]`：

- `arr[mid] < target` 时，目标只可能在右边，所以 `low = mid + 1`。
- `arr[mid] > target` 时，目标只可能在左边，所以 `high = mid - 1`。
- `low > high` 表示区间为空，查找失败。

`mid = low + (high - low) / 2` 比 `(low + high) / 2` 更不容易发生整数加法溢出。

### 难点五：同一算法可能返回不同的合法下标

数组 `[1, 2, 2, 2, 3]` 中有多个 `2`。普通二分查找只保证找到一个等于目标的下标，不保证一定是第一个或最后一个。如果需要稳定定位第一个重复值，应另外设计“找左边界”的二分查找。

## 边界与已知限制

- 所有接收 `int[] arr` 的方法都没有检查 `arr == null`；当前程序只传入真实数组，不会触发空引用。
- 二分查找没有自动检查数组是否有序，调用者必须先满足有序前提。
- `check()` 打印 `[失败]` 时不会抛出异常，也不会让进程返回非零退出码。当前 18 条都通过；以后若出现失败，必须检查输出，不能只看命令退出码。
- `demoOutOfBounds()` 是故意越界，所以程序里有异常，但异常在展示点被捕获，后续测试继续执行。
- 源码后半段保存了旧版讲解注释。它记录过修复过程，但不是当前执行代码的第二份实现。

## 易错点与测试用例

| 测试数据或修改 | 预期结果 | 检查目标 |
| --- | --- | --- |
| `[]` | 不交换，排序后仍为 `[]` | 空数组边界 |
| `[7]` | 不交换，仍为 `[7]` | 单元素边界 |
| `[1, 2, 3, 4]` | 第一轮没有交换，提前结束 | `swapped` 优化 |
| `[4, 3, 2, 1]` | `[1, 2, 3, 4]` | 最坏的逆序输入 |
| `[3, 1, 3, 2, 1]` | `[1, 1, 2, 3, 3]` | 重复元素 |
| 有序数组中查找第一个元素 | 返回下标 0 | 左边界 |
| 有序数组中查找最后一个元素 | 返回最后一个下标 | 右边界 |
| 有序数组中查找不存在的 `20` | 返回 `-1` | 区间收缩到空 |
| 直接打印数组变量 | 显示类似 `[I@...` 的引用信息 | 必须使用 `Arrays.toString` |

如果自行把数组改成 `null`，当前方法会抛出 `NullPointerException`。这不是现有测试覆盖的输入，不应把“其他 18 条通过”误解为“所有输入都安全”。

1. 写一个 `int sum(int[] arr)`，返回数组元素之和。
2. 写一个 `double average(int[] arr)`，先自己决定空数组应返回什么或怎样报错。

4. 增加 `[2, 1]`、`[1, 2]` 和全相等数组的测试。
5. 为二分查找增加“数组未排序时不做二分”的说明，或设计一个显式检查方法。
6. 实现查找重复值左边界和右边界的两种二分版本。
7. 用 `Arrays.sort()` 对副本排序后查找，并与手写冒泡排序比较代码量和适用场景。
