# Java 方法与数组零基础教程

本教程配合 [ArrayAndBubbleSort.java](ArrayAndBubbleSort.java) 使用。目标不是背下代码，而是能够回答四个问题：

1. 这个方法接收什么材料？
2. 方法里的变量现在是什么值？
3. 数组下标当前指向哪个元素？
4. 循环下一轮或下一次比较会发生在哪里？

源码第 1 到 216 行是可执行部分，第 217 行以后是最初学习时的逐行注释草稿。两段内容不是两个同时运行的版本，本教程只解释可执行代码。

## 一、先看程序的整体分工

`main` 是入口，但它没有把所有操作直接写完，而是调用一组方法：

```text
main
├── demoBasics            数组创建、默认值、遍历
├── demoOutOfBounds       越界异常
├── demoCopy              引用、复制、独立数组
├── bubbleSortTrace       打印排序过程
├── bubbleSort            原地排序
├── linearSearch          从左到右查找
├── binarySearch          在有序数组中减半查找
├── binarySearchTrace     打印二分查找过程
└── check                 打印测试通过或失败
```

这样拆分后，每段代码只有一个主要职责。调试时可以先判断是“数组内容不对”“排序没完成”还是“查找返回了下标不对”。

## 二、方法是什么

看一个最小方法：

```java
static int linearSearch(int[] arr, int target) {
    // 方法体
}
```

各部分可以拆成：

| 部分 | 代码 | 含义 |
| --- | --- | --- |
| 修饰符 | `static` | 这个方法属于类本身，可以被同样是 `static` 的 `main` 直接调用 |
| 返回类型 | `int` | 方法执行结束后交回一个整数 |
| 方法名 | `linearSearch` | 调用时使用的名字 |
| 参数 | `int[] arr` | 接收一个整数数组 |
| 参数 | `int target` | 接收要查找的目标整数 |

方法调用：

```java
int index = linearSearch(sortedArr, 16);
```

执行时，`sortedArr` 交给形参 `arr`，`16` 交给形参 `target`。方法返回 4 后，4 被存进 `index`。

### `void` 与返回值的区别

`demoBasics()`、`bubbleSort()` 的返回类型是 `void`，表示方法只做事，不交回一个值：

```java
bubbleSort(a1);
```

`linearSearch()` 的返回类型是 `int`，所以可以用它的结果：

```java
int index = linearSearch(a1, 3);
```

如果一个方法声明返回 `int`，所有正常结束路径都必须返回整数。源码中的查找方法在找到时返回下标，循环结束后返回 `-1`。

### 为什么这些方法都写 `static`

`main` 本身是 `static`，当前还没有学习对象和实例方法。把这些辅助方法也声明为 `static`，可以直接写方法名调用，不需要先创建对象。现在先把它理解为“本练习中的工具方法”；面向对象阶段会重新区分静态方法和实例方法。

## 三、数组怎样保存一组值

### 创建数组

```java
int[] scores = new int[5];
```

这句话表示：

1. 创建一个能放 5 个整数的数组。
2. 把数组的引用交给变量 `scores`。
3. 每个整数位置先放默认值 `0`。

不同元素类型的默认值：

| 元素类型 | 默认值 |
| --- | --- |
| `int` | `0` |
| `double` | `0.0` |
| `boolean` | `false` |
| 引用类型，例如 `String` | `null` |

`null` 表示“当前没有指向任何字符串对象”，不是空字符串 `""`。

### 初始化时就放入元素

```java
int[] nums = { 5, 3, 8, 1 };
```

Java 根据花括号里的 4 个值创建长度为 4 的数组。

可以把它画成：

```text
下标：   0    1    2    3
元素：   5    3    8    1
```

下标不是从 1 开始。最后一个元素的下标永远是 `length - 1`。

### `length` 是字段，不是方法

```java
nums.length
```

`length` 后面没有括号。若写成 `nums.length()`，编译会报错。

循环应该用长度表达上界：

```java
for (int i = 0; i < nums.length; i++) {
    // i = 0, 1, 2, 3
}
```

不要把条件写成 `i <= nums.length`，否则最后一轮会访问 `nums[4]`，而长度 4 的数组合法下标只到 3。

## 四、普通 `for` 与增强 `for`

### 增强 `for` 适合读取

```java
int sum = 0;
for (int value : nums) {
    sum += value;
}
```

对 `[5, 3, 8, 1]`：

| 轮次 | `value` | 本轮后的 `sum` |
| --- | ---: | ---: |
| 1 | 5 | 5 |
| 2 | 3 | 8 |
| 3 | 8 | 16 |
| 4 | 1 | 17 |

结果是 17。

### 增强 `for` 修改变量不等于修改数组

```java
for (int value : nums) {
    value = value * 2;
}
```

每一轮，`value` 只是当前元素值的副本。即使执行了 `value = value * 2`，`nums` 仍为 `[5, 3, 8, 1]`。

### 普通 `for` 通过下标修改原元素

```java
for (int i = 0; i < nums.length; i++) {
    nums[i] = nums[i] * 2;
}
```

这里直接给 `nums[i]` 赋值，所以数组被改成 `[10, 6, 16, 2]`。

选择规则：

- 只需要看每个元素，用增强 `for`。
- 需要知道下标，或需要修改数组元素，用普通 `for`。

## 五、数组引用、复制与比较

### 直接赋值只复制引用

```java
int[] original = { 1, 2, 3 };
int[] alias = original;
```

内存关系可以画成：

```text
original ─┐
          ├──> [1, 2, 3] 同一个数组对象
alias ────┘
```

所以：

```java
alias[0] = 99;
```

之后 `original` 和 `alias` 打印出来都是 `[99, 2, 3]`。

### `Arrays.copyOf` 创建独立数组

```java
int[] bigger = Arrays.copyOf(original, 5);
int[] smaller = Arrays.copyOf(original, 2);
```

`bigger` 和 `smaller` 是新数组。扩大长度时，新位置补默认值；缩短长度时，只复制前面的部分。

在这个程序里，两处复制发生在 `alias[0] = 99` 之前，所以复制结果保留原来的第一个元素 1：

```text
original = [99, 2, 3]
alias    = [99, 2, 3]
bigger   = [1, 2, 3, 0, 0]
smaller  = [1, 2]
```

### 数组不能用 `==` 比较内容

后续测试使用：

```java
Arrays.equals(a1, new int[] { 1, 3, 5, 8 })
```

它逐个比较元素内容。若写 `a1 == expected`，比较的是两个数组引用是否指向同一个对象，通常不会因为内容相同而返回 `true`。

### 打印数组必须转换

```java
System.out.println(original);
```

直接打印数组引用会得到类似 `[I@1b6d3586` 的文本。`[I` 表示整数数组，`@` 后面是对象标识信息。想看到元素内容应使用：

```java
System.out.println(Arrays.toString(original));
```

## 六、数组传给方法后为什么能修改原数组

调用：

```java
int[] a1 = { 5, 3, 8, 1 };
bubbleSort(a1);
```

Java 参数都是按值传递，但数组参数复制的是“引用值”。因此形参 `arr` 和实参 `a1` 指向同一个数组对象。

关系可以写成：

```text
a1 ──┐
     ├──> [5, 3, 8, 1]
arr ─┘
```

方法里执行 `arr[j] = ...` 修改的是共同指向的数组，所以调用结束后 `a1` 也变成有序数组。方法不需要返回一个新数组。

这并不意味着可以替换调用者变量本身。若方法写 `arr = new int[] { ... }`，只是让形参 `arr` 指向新对象，调用者的 `a1` 仍然指向旧数组。当前源码没有这种重新赋值。

## 七、越界与异常

```java
int[] arr = { 10, 20, 30 };
System.out.println(arr[3]);
```

数组长度为 3，合法下标只有 0、1、2。访问 3 会抛出 `ArrayIndexOutOfBoundsException`。

源码用 `try-catch` 接住它：

```java
try {
    System.out.println(arr[3]);
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("捕获到越界异常：" + e.getMessage());
}
```

执行路径：

1. 进入 `try`，尝试访问 `arr[3]`。
2. Java 发现下标越界，抛出异常。
3. `try` 中后面的语句不再执行。
4. 异常类型与 `catch` 匹配，进入 `catch`。
5. `catch` 完成后，继续执行 `try-catch` 后面的普通语句。

这个演示只接受 `ArrayIndexOutOfBoundsException`。其他异常类型不会因为它被自动处理。

初学者更重要的目标仍是设计正确边界，而不是用 `catch` 掩盖越界。当前程序是故意展示异常；正式代码应先保证下标在 `0 <= i < arr.length` 范围内。

## 八、冒泡排序的思想

冒泡排序反复比较相邻元素。左边大于右边时交换，每完成一轮，当前未排序部分的最大值就移动到右端。

### 手工推演 `[5, 3, 8, 1]`

第 1 轮：

| 比较 | 是否交换 | 本轮后数组 |
| --- | --- | --- |
| 5 与 3 | 是 | `[3, 5, 8, 1]` |
| 5 与 8 | 否 | `[3, 5, 8, 1]` |
| 8 与 1 | 是 | `[3, 5, 1, 8]` |

第 1 轮后，最大值 8 已经就位。

第 2 轮只比较前三个位置：

| 比较 | 是否交换 | 本轮后数组 |
| --- | --- | --- |
| 3 与 5 | 否 | `[3, 5, 1, 8]` |
| 5 与 1 | 是 | `[3, 1, 5, 8]` |

第 2 轮后，5 已经就位。

第 3 轮只比较前两个位置：

| 比较 | 是否交换 | 本轮后数组 |
| --- | --- | --- |
| 3 与 1 | 是 | `[1, 3, 5, 8]` |

最终结果 `[1, 3, 5, 8]`。

### 为什么外层循环到 `n - 1`

`n` 个元素最多需要确定 `n - 1` 个位置。最后一个元素不需要再和谁比较，所以外层循环写：

```java
for (int i = 0; i < n - 1; i++)
```

### 为什么内层循环到 `n - 1 - i`

内层要访问：

```java
arr[j + 1]
```

如果 `j` 能到 `n - 1`，`j + 1` 就是 `n`，会越界。所以只考虑边界时，本来应写 `j < n - 1`。

每轮又会把一个最大值放到右端，已经完成 `i` 轮后，右边有 `i` 个元素不用再比。因此上界继续减 `i`：

```java
j < n - 1 - i
```

### `swapped` 为什么能提前结束

每一轮开始时：

```java
boolean swapped = false;
```

本轮只要发生过一次交换，就改成 `true`。如果整轮没有任何交换，说明每个相邻元素都已经满足“左小右大”，数组已经有序。

```java
if (!swapped) {
    break;
}
```

对 `[1, 2, 3, 4]`：

1. 比较 1 和 2，不交换。
2. 比较 2 和 3，不交换。
3. 比较 3 和 4，不交换。
4. `swapped` 仍为 `false`。
5. 执行 `break`，第一轮后结束。

没有这个优化时，程序仍能得到正确答案，但会继续做后续没有必要的轮次。

### 交换为什么需要临时变量

```java
int temp = arr[j];
arr[j] = arr[j + 1];
arr[j + 1] = temp;
```

如果先执行 `arr[j] = arr[j + 1]`，`arr[j]` 原来的值已经被覆盖。`temp` 先保存旧值，第三句才能把它放回右边。

## 九、线性查找

线性查找从下标 0 开始，逐个比较：

```java
for (int i = 0; i < arr.length; i++) {
    if (arr[i] == target) {
        return i;
    }
}
return -1;
```

找到就立即返回当前下标；遍历结束仍未找到，返回 `-1`。

对 `[1, 2, 2, 2, 3]` 查找 2，会返回下标 1，因为它从左向右遇到第一个 2 就结束。

线性查找不要求数组有序。最坏情况下要看完所有元素。

## 十、二分查找

二分查找要求数组已经从小到大有序。每次查看中间元素，根据大小丢掉一半不可能的区域。

源码使用闭区间 `[low, high]`：

```java
int low = 0;
int high = arr.length - 1;
while (low <= high) {
    int mid = low + (high - low) / 2;
    // 根据 arr[mid] 缩小范围
}
```

### 查找 16

数组：

```text
下标：  0  1  2   3   4   5   6   7
元素：  2  5  8  12  16  23  38  56
```

| 轮次 | `low` | `high` | `mid` | `arr[mid]` | 动作 |
| --- | ---: | ---: | ---: | ---: | --- |
| 1 | 0 | 7 | 3 | 12 | 12 < 16，`low = 4` |
| 2 | 4 | 7 | 5 | 23 | 23 > 16，`high = 4` |
| 3 | 4 | 4 | 4 | 16 | 相等，返回 4 |

### 查找 20

| 轮次 | `low` | `high` | `mid` | `arr[mid]` | 动作 |
| --- | ---: | ---: | ---: | ---: | --- |
| 1 | 0 | 7 | 3 | 12 | 12 < 20，`low = 4` |
| 2 | 4 | 7 | 5 | 23 | 23 > 20，`high = 4` |
| 3 | 4 | 4 | 4 | 16 | 16 < 20，`low = 5` |
| 结束 | 5 | 4 | 不计算 | 无 | `low > high`，返回 `-1` |

`low` 和 `high` 交叉时，闭区间已经为空。

### 为什么用 `low + (high - low) / 2`

直接写 `(low + high) / 2` 在很大的下标上可能先发生整数加法溢出。当前数据量很小，不会触发，但写法 `low + (high - low) / 2` 把差值控制得更小，更适合大数组。

### 为什么必须是有序数组

二分查找会根据 `arr[mid] < target` 推断目标只可能在右边。如果数组没有排序，这个推断不成立，即使目标存在也可能找不到。

### 重复值为什么不能要求固定下标

`[1, 2, 2, 2, 3]` 中有三个 2。二分查找第一次落在哪个中间位置，取决于当前 `low`、`high` 和数组长度。它返回任意一个等于 2 的下标，都满足“找到”的约定。

## 十一、固定测试怎样读

`check` 接收一个测试名称和一个布尔值：

```java
check("空数组 [] 保持不变", Arrays.equals(a5, new int[] {}));
```

先计算第二个参数：

- 内容相同，得到 `true`，打印 `[通过]`。
- 内容不同，得到 `false`，打印 `[失败]`。

当前冒泡排序测试覆盖：

- 普通乱序
- 完全逆序
- 原本有序
- 重复元素
- 空数组
- 单元素

查找测试覆盖：

- 中间位置找到
- 第一个位置找到
- 最后一个位置找到
- 找不到
- 空数组
- 单元素找得到和找不到
- 重复元素的合法下标范围
- 先排序再二分

这种检查器适合学习时快速看结果，但有不严谨之处：`[失败]` 只是打印文字，程序退出码仍然是 0。真正自动化测试应使用 JUnit 或至少在不通过时抛出异常或结束为非零状态。

## 十二、常见错误

### 错误一：把 `length` 写成方法

```java
arr.length()
```

数组中 `length` 是字段，应写 `arr.length`。

### 错误二：最后一个下标写成 `length`

```java
arr[arr.length]
```

这会越界。最后一个合法下标是 `arr.length - 1`。

### 错误三：以为增强 `for` 会修改数组

```java
for (int x : arr) {
    x = 0;
}
```

数组没有被清零，因为 `x` 是副本。需要 `arr[i] = 0`。

### 错误四：把直接赋值当成数组复制

```java
int[] copy = arr;
```

这里只是两个引用指向同一个数组。需要独立内容时使用 `Arrays.copyOf`。

### 错误五：二分查找不先排序

未排序数组不能直接使用当前二分查找。可以先用 `Arrays.sort()` 或自己实现排序，再查找。

### 错误六：更新边界时写成 `low = mid`

当目标在右边时，`arr[mid]` 已经确定小于目标，`mid` 本身可以排除，应写：

```java
low = mid + 1;
```

另一边同理应写：

```java
high = mid - 1;
```

否则某些输入会让区间不缩小，形成死循环。

### 错误七：只看编译通过就认为算法正确

排序和查找需要测试内容、边界和特殊情况。尤其要检查空数组、单元素、已排序、逆序、重复值和找不到。

## 十三、循序练习

### 练习 1：画引用图

不运行程序，画出：

```java
int[] a = { 1, 2 };
int[] b = a;
int[] c = Arrays.copyOf(a, 2);
b[0] = 9;
```

分别写出 `a`、`b`、`c` 的内容。

### 练习 2：手写数组求和

写：

```java
static int sum(int[] arr)
```

先只处理正常非空数组。再加入空数组测试，决定空数组返回 0 还是抛出异常。

### 练习 3：手写冒泡排序

只允许查看 `bubbleSort()` 的三条交换语句。自己完成循环上界、`swapped` 和提前结束。

### 练习 4：改排序方向

把从小到大改成从大到小。只修改比较符号，再解释为什么结果翻转。

### 练习 5：查找重复值左边界

在 `[1, 2, 2, 2, 3]` 中，要求总是返回第一个 2 的下标 1。先写出“找到 2 后不能马上返回，还要继续往左看”的规则。

### 练习 6：加入失败退出

设计一个 `checkOrThrow`，失败时抛出异常，让真正的问题能通过进程状态被发现。先不要直接改原始附件，可另建自己的练习文件。

## 十四、怎样判断自己真的会了

能够完成以下任务，再把自己标为掌握本练习：

1. 不看源码写出一个接收数组的方法。
2. 能解释数组引用赋值和 `Arrays.copyOf` 的区别。
3. 能手工推演 4 个元素的冒泡排序。
4. 能解释 `j < n - 1 - i` 的两个原因。
5. 能手工跟踪二分查找找到和找不到的各一次过程。
6. 能说明二分查找为什么要求有序。
7. 能设计空数组、单元素、重复元素和边界查找测试。
8. 能指出当前 `check()` 不能作为正式自动测试的原因。

真正掌握的标准不是“能运行出 18 个通过”，而是能修改数据后预测变化，并能独立重写核心方法。
