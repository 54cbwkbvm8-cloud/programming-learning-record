# Java 三位水仙花数扫描简介

## 文件基本信息

- 源码：[Narcissistic.java](Narcissistic.java)
- 首次整理日期：2026-11-08
- 所属分类：`Java/03_方法与数组`
- 程序用途：读取范围 `a`、`b`，扫描区间内满足“各位数字立方和等于自身”的整数。
- 主要问题：怎样用除法和取余拆出个位、十位、百位；怎样判断区间内一个结果都没有。
- 核心知识点：`Scanner`、整数拆位、`for`、`%`、`/`、条件判断、`found` 标记、输入边界。
- 前置知识：循环、整数运算、`if`、`Scanner` 基本读取。
- 相关练习：可与 [DigitCount.java](DigitCount.java) 对照，二者都用循环和整数拆位；本练习固定拆三位。

## 程序功能说明

对整数 `num`：

- `num % 10` 得到个位。
- `num / 10 % 10` 先去掉个位，再取当前末位，即十位。
- `num / 100` 得到百位及更高位。
- 三个数字分别立方后相加，与 `num` 比较。

若找到至少一个结果，`found` 变为 `true`。循环结束仍为 `false` 时输出 `NONE`。

重要边界：源码没有先检查 `a`、`b` 是否属于三位数，也没有保证 `a <= b`。在当前实现里，扫描 `1 20` 会输出 `1`，因为 `1³` 等于 1，但 1 并不是通常定义的“三位水仙花数”。因此标准测试应使用 `100 999`。

## 运行方式

在仓库根目录编译：

```bash
java_dir=$(mktemp -d /tmp/java-narcissistic.XXXXXX)
javac -encoding UTF-8 -Xlint:all -Werror -d "$java_dir" \
  "Java/03_方法与数组/Narcissistic.java"
```

标准输入 `100 999`：

```bash
printf '100 999\n' | java -cp "$java_dir" Narcissistic
```

真实输出：

```text
153
370
371
407
```

空范围 `900 100` 的输出为：

```text
NONE
```

## 学习重点

- 整数除法和取余可以逐位提取数字。
- 三位数范围是 100 到 999，位数为三位不是代码自动保证的条件。
- `found` 是“是否至少找到一个答案”的状态标记。
- 输出格式要求一行一个数；范围越界时应先校验，而不是依赖拆位结果碰巧正确。

## 学习难点

### 为什么 `1 20` 会输出 1

当前代码对 1 计算出 `ones=1`、`tens=0`、`hundreds=0`，立方和为 1，于是条件成立。算法并不是“通用位数水仙花数判断”，而是固定按三位拆位；当输入不符合三位边界时，结果不再符合题目定义。

### 为什么 `900 100` 直接输出 NONE

`for (int num = 900; num <= 100; num++)` 第一次条件就为假，循环执行 0 次，`found` 保持 `false`。它没有报错，也没有说明输入顺序错误。

### 为什么必须关闭 Scanner

本程序读完固定两个整数后关闭 `sc`。大型程序若还要继续读取标准输入，关闭时机要结合整体输入来源判断，不能机械套用。

## 建议学习流程

1. 手算 153 的百、十、个位和立方和。
2. 手算 154，确认它不满足条件。
3. 运行范围 `100 999`，核对四个标准答案。
4. 运行 `100 200`，应只看到 153。
5. 运行 `1 20` 和 `900 100`，记录当前边界行为。
6. 在不修改源码的前提下，考虑在哪里加入 `100 <= a && a <= b && b <= 999` 的校验。
7. 关闭源码，自己写出三位水仙花数判断。

## 易错点与测试用例

| 输入 | 当前真实结果 | 预期题目结果 | 说明 |
| --- | --- | --- | --- |
| `100 999` | 153、370、371、407 | 同左 | 标准范围 |
| `100 200` | 153 | 153 | 单个答案 |
| `100 101` | `NONE` | `NONE` | 区间无答案 |
| `1 20` | 1 | 应拒绝非三位范围 | 缺少输入校验 |
| `900 100` | `NONE` | 应提示范围颠倒 | `a > b` |

常见错误包括把十位写成 `num % 10`、把立方写成平方、把三个数字顺序与权重混淆，以及不校验三位数范围。当前代码编译和标准输入运行正常，但存在已记录的输入边界问题。

## 拓展练习

1. 增加 `a`、`b` 的三位数范围校验和 `a <= b` 校验，但另存修正版，不改原始源码。
2. 把固定三位算法改为通用位数版本。
3. 把“打印所有结果”改成“返回数组或列表”。
4. 加入 `Scanner.hasNextInt()`，处理非整数输入。
5. 完成后阅读 [DigitCount.java](DigitCount.java)，比较“判断一个数是否满足条件”和“统计所有数字中出现次数”的拆位方式。
