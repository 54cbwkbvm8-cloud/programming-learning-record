# Java 三位水仙花数扫描简介

## 文件基本信息

- 源码：[Narcissistic.java](Narcissistic.java)
- 首次整理日期：2026-11-08
- 所属分类：`Java/03_方法与数组`
- 程序用途：读取范围 `a`、`b`，扫描区间内满足“各位数字立方和等于自身”的整数。
- 主要问题：怎样用除法和取余拆出个位、十位、百位；怎样判断区间内一个结果都没有。
- 核心知识点：`Scanner`、整数拆位、`for`、`%`、`/`、条件判断、`found` 标记、输入边界。
- 前置知识：循环、整数运算、`if`、`Scanner` 基本读取。
- 相关练习：可与 [DigitCount.java](DigitCount.java) 对照，二者都用循环和整数拆位；本练习固定拆三位。

## 程序功能说明

对整数 `num`：

- `num % 10` 得到个位。
- `num / 10 % 10` 先去掉个位，再取当前末位，即十位。
- `num / 100` 得到百位及更高位。
- 三个数字分别立方后相加，与 `num` 比较。

若找到至少一个结果，`found` 变为 `true`。循环结束仍为 `false` 时输出 `NONE`。

重要边界：源码现在会先把扫描区间夹到三位数范围（`int start = Math.max(a, 100); int end = Math.min(b, 999);`），因此扫描 `1 20` 不再输出 1，而是输出 `NONE`。它仍然不会提示“输入越界”，也没有保证 `a <= b`：区间颠倒时只是循环不执行、输出 `NONE`。标准测试仍建议使用 `100 999`。更早的版本没有这层限制，`1 20` 会输出 1。

## 学习重点

- 整数除法和取余可以逐位提取数字。
- 三位数范围是 100 到 999，位数为三位不是代码自动保证的条件。
- `found` 是“是否至少找到一个答案”的状态标记。
- 输出格式要求一行一个数；范围越界时应先校验，而不是依赖拆位结果碰巧正确。

## 学习难点

### 为什么必须先把区间夹到 `100～999`

算法固定按三位拆位：`ones = num % 10`、`tens = num / 10 % 10`、`hundreds = num / 100`。如果把 1 直接交给它，会得到 `ones=1`、`tens=0`、`hundreds=0`，立方和正好等于 1，于是被误判成水仙花数。当前源码用 `Math.max(a, 100)` 与 `Math.min(b, 999)` 把扫描区间夹在三位数内，`1 20` 因 `start > end` 直接输出 `NONE`，避免了这种误判。需要注意的是，区间被“静默裁剪”而不提示用户，本身仍是这段代码的边界特征。

### 为什么 `900 100` 直接输出 NONE

`for (int num = 900; num <= 100; num++)` 第一次条件就为假，循环执行 0 次，`found` 保持 `false`。它没有报错，也没有说明输入顺序错误。

### 为什么必须关闭 Scanner

本程序读完固定两个整数后关闭 `sc`。大型程序若还要继续读取标准输入，关闭时机要结合整体输入来源判断，不能机械套用。

## 建议学习流程

1. 手算 153 的百、十、个位和立方和。
2. 手算 154，确认它不满足条件。
3. 运行范围 `100 999`，核对四个标准答案。
4. 运行 `100 200`，应只看到 153。
5. 运行 `1 20` 和 `900 100`，记录当前边界行为：前者被夹到三位范围后输出 `NONE`，后者因区间颠倒也输出 `NONE`。
6. 在不修改源码的前提下，考虑怎样把“静默裁剪区间”改成对用户可见的越界提示（例如在扫描前先判断 `a < 100 || b > 999` 并输出提示）。
7. 关闭源码，自己写出三位水仙花数判断。

## 易错点与测试用例

| 输入 | 当前真实结果 | 预期题目结果 | 说明 |
| --- | --- | --- | --- |
| `100 999` | 153、370、371、407 | 同左 | 标准范围 |
| `100 200` | 153 | 153 | 单个答案 |
| `100 101` | `NONE` | `NONE` | 区间无答案 |
| `1 20` | `NONE` | 应拒绝非三位范围 | 区间被夹到 `100～999`，无答案 |
| `900 100` | `NONE` | 应提示范围颠倒 | `a > b` |

常见错误包括把十位写成 `num % 10`、把立方写成平方、把三个数字顺序与权重混淆，以及忘记处理三位数范围。当前代码编译和标准输入运行正常；边界输入不会误判，但越界时只是静默输出 `NONE`，没有提示输入不合法。

## 拓展练习

1. 增加 `a`、`b` 的三位数范围校验和 `a <= b` 校验，但另存修正版，不改原始源码。
2. 把固定三位算法改为通用位数版本。
3. 把“打印所有结果”改成“返回数组或列表”。
4. 加入 `Scanner.hasNextInt()`，处理非整数输入。
5. 完成后阅读 [DigitCount.java](DigitCount.java)，比较“判断一个数是否满足条件”和“统计所有数字中出现次数”的拆位方式。
