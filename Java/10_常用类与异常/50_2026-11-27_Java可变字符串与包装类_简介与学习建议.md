# Java 可变字符串与包装类：简介与学习建议

## 1. 文件基本信息

- **源码**：`BuilderLesson.java`
- **分类**：`Java/10_常用类与异常`
- **程序用途**：演示 `StringBuilder` 的增（append / insert）、删（delete）、改（reverse）与转回 `String`，再演示包装类 `Integer` / `Double` / `Character` 的装箱、拆箱与 `127 / 128` 缓存差异，最后用输入文本做倒序与整数解析。
- **核心知识点**：`StringBuilder` 与 `String` 的分工、`delete(start, end)` 左闭右开、`Integer` 缓存范围 `-128~127`、自动装箱/拆箱、`Integer.parseInt` 与 `NumberFormatException`。
- **前置知识**：`String` 基本 API（49 号）、`try-catch` 的基本写法（35 号输入重试）、`Scanner` 读行。
- **相关练习**：27 号用 `StringBuilder` 做过字符串倒序；本题把它扩展为完整的可变字符串操作，并首次接触包装类。

## 2. 程序功能说明

第一段是 `StringBuilder` 的四个操作：`append("Hello")` → `Hello`；`insert(1, "x")` → `Hxello`（在下标 1 前插入）；`delete(1, 2)` 删掉下标 1（**只删 x，不含下标 2**）→ 回到 `Hello`；`reverse()` 原地反转 → `olleH`，再 `toString()` 得到普通 `String`。

第二段是包装类的核心演示：

```java
Integer a = 127, b = 127;   // 缓存命中：a == b 为 true
Integer c = 128, d = 128;   // 超出缓存：c == d 为 false
```

`Integer` 会把 `-128~127` 的对象缓存复用，这个范围内自动装箱得到同一对象；超出范围每次 `new` 新对象。所以 `==` 比较包装类不可靠，`equals` 才比较数值。`int number = a` 是自动拆箱；`Double.valueOf("3.5")` 从字符串解析；`Character.isLetter('a')` 判断字母。

第三段读一行输入：先整体倒序输出，再尝试 `Integer.parseInt(text.trim())` 转整数——成功输出 `int=`，失败被 `catch` 接住输出 `invalid integer`。

源码后半段保留附件注释教程。

## 3. 编译与运行

在仓库根目录执行：

```bash
java_dir=$(mktemp -d /tmp/java-core.XXXXXX)
javac -encoding UTF-8 -Xlint:all -Werror -d "$java_dir" \
  "Java/10_常用类与异常/BuilderLesson.java"
printf '42\n' | java -cp "$java_dir" BuilderLesson
printf 'abc\n' | java -cp "$java_dir" BuilderLesson
```

已使用 OpenJDK 21.0.13 严格编译并实际运行。输入 `42` 时输出 `append=Hello`、`insert=Hxello`、`delete=Hello`、`reverse=olleH`、`127 == true`、`128 == false`、`128 equals true`、`unbox=127,double=3.5,letter=true`、`inputReverse=24`、`int=42`、`boxed=42`；输入 `abc` 时最后两行为 `inputReverse=cba`、`invalid integer`。

## 4. 学习重点与难点

- **可变与不可变的分工**：`String` 每次拼接都产生新对象；`StringBuilder` 在同一个缓冲区上增删改。循环里大量拼接应使用 `StringBuilder`（27 号的动机）。
- **`delete(1, 2)` 只删一个字符**：参数是**区间**不是"从哪删几个"。写 `delete(1, 3)` 会删掉两个字符。
- **`insert` 的合法范围**：`0 ~ length()`，插入到末尾要写 `length()`；越界抛 `StringIndexOutOfBoundsException`。
- **`reverse()` 原地修改**：返回值还是同一个 builder，不写返回值也能生效；这是与 `String` 方法最大的行为差异。
- **包装类缓存是陷阱源**：`127 == 127` 为 `true`、`128 == 128` 为 `false`。结论不是"记住 128"，而是"包装类一律用 `equals` 比较数值"。
- **拆箱可能 NPE**：`Integer x = null; int y = x;` 会在拆箱时抛 `NullPointerException`；本题的 `a` 非空所以安全。
- **`parseInt` 的边界**：空串、非数字、超出 `int` 范围都抛 `NumberFormatException`；`Double.valueOf` 同理（`Double.parseDouble`）。

## 5. 推荐学习流程

1. 运行两组输入（`42`、`abc`），先看输出再看代码。
2. 手工预测：把 `insert(1, "x")` 改成 `insert(0, "x")` 输出什么；`delete(1, 3)` 又输出什么。
3. 重点理解 `127 / 128` 三行：为什么 `==` 一个真一个假，而 `equals` 都真。
4. 把 `int number = a` 改成 `Integer a = null; int number = a;` 观察 NPE（运行后恢复）。
5. 合上源码重写：输入一个单词，输出倒序 + 是否回文，要求用 `StringBuilder` 与 `charAt` 两种方式各写一遍。
