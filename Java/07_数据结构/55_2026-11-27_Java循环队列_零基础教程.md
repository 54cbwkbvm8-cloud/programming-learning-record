# Java 循环队列：零基础教程

> 配合 [MyQueue.java](MyQueue.java) 与 [55 号简介](55_2026-11-27_Java循环队列_简介与学习建议.md) 使用。建议先运行程序看输出，再按本文顺序理解；队列的空满判断是本文重点。

## 0. 队列是什么

队列是"先进先出"（FIFO, First In First Out）的线性结构：元素只能从**队尾**加入、从**队头**取出。生活中的排队买饭、打印机任务、消息队列都是这个模型。

和 37 号的栈对照：

| 操作 | 栈（Stack） | 队列（Queue） |
| --- | --- | --- |
| 加入 | `push` 压栈（顶部） | `enqueue` 入队（队尾） |
| 取出 | `pop` 弹栈（顶部） | `dequeue` 出队（队头） |
| 顺序 | 后进先出 LIFO | 先进先出 FIFO |
| 数组实现的关注点 | 栈顶下标 `top` | 队头 `head` + 队尾 `tail` |

## 1. 为什么不能"出队后整体前移"

最朴素的做法：出队后把后面所有元素往前挪一格。但每次出队都要移动 n-1 个元素，元素一多就非常慢。

循环队列的做法：**不动元素，只动下标**。`head` 和 `tail` 走到数组末尾后"绕回"开头继续用，前面的空位自然被复用。

## 2. 三个字段的分工

```java
private final int[] data;   // 存元素的固定数组
private int head;           // 下一次出队的位置（队头下标）
private int tail;           // 下一次入队的写入位置（队尾下标）
private int size;           // 当前元素个数
```

关键理解：

- `head` 和 `tail` 都是**下标**，不是元素值。
- 初始时 `head = tail = 0`、`size = 0`（空）。
- `size` 是"唯一可靠的元素计数"，因为 `head == tail` 既可能是空、也可能是满。

## 3. 入队：写在 tail，再往前走一格

```java
public boolean enqueue(int value) {
    if (size == data.length) {   // 满：所有格子都被占用
        return false;            // 返回 false，不覆盖旧数据
    }
    data[tail] = value;                  // ① 写进队尾格子
    tail = (tail + 1) % data.length;     // ② 队尾前进一格，末尾绕回 0
    size++;                              // ③ 计数加一
    return true;
}
```

以容量 5 为例，连续入队 `0 1 2 3 4`：

| 步骤 | 写入位置 | `tail` 之后 | `size` |
| --- | --- | --- | --- |
| 入 0 | `data[0]` | 1 | 1 |
| 入 1 | `data[1]` | 2 | 2 |
| 入 2 | `data[2]` | 3 | 3 |
| 入 3 | `data[3]` | 4 | 4 |
| 入 4 | `data[4]` | `(4+1)%5 = 0` | 5（满） |

## 4. 出队：取 head，再往前走一格

```java
public int dequeue() {
    if (isEmpty()) {
        throw new NoSuchElementException("queue is empty");
    }
    int value = data[head];               // ① 先取出队头值
    head = (head + 1) % data.length;      // ② 队头前进，旧格子作废
    size--;                               // ③ 计数减一
    return value;
}
```

注意出队**不擦除** `data[head]` 的旧值：这个格子已经不属于队列，下次入队会被覆盖。判断"是否为空"只看 `size`，不看格子里有没有旧数据。

## 5. 满与空的判断：为什么要 size

假设没有 `size`，只用 `head == tail`：

- 空队：`head = 0, tail = 0` → 相等 ✅
- 满队：入满 5 个后 `head = 0, tail = 0`（`tail` 绕回 0）→ **也相等** ❌

两种情况无法区分！所以必须有 `size`（或"浪费一个格子"的替代方案）。本题选 `size`：`size == 0` 为空，`size == data.length` 为满。

## 6. 回绕的位置：`snapshot` 与演示

```java
public String snapshot() {
    StringBuilder sb = new StringBuilder("[");
    int index = head;                 // 独立下标，不动真实 head
    for (int i = 0; i < size; i++) {
        if (i > 0) sb.append(", ");
        sb.append(data[index]);
        index = (index + 1) % data.length;   // 同样要取模回绕
    }
    return sb.append(']').toString();
}
```

`main` 的演示验证了回绕：入满 `[0,1,2,3,4]` → 出队 0（`head=1`）→ 入队 6（写到 `data[0]`，`tail` 回绕）→ 此时物理数组是 `[6,1,2,3,4]`，但逻辑顺序是 `[1,2,3,4,6]`。**物理顺序 ≠ 逻辑顺序**，这是循环队列最容易讲不清的地方——必须靠 `head` 起点 + `size` 步数来还原逻辑顺序。

## 7. 常见错误与排查

| 现象 | 原因 | 修复 |
| --- | --- | --- |
| 第 5 次入队后越界 | 忘了取模：`tail = tail + 1` | 改成 `(tail + 1) % data.length` |
| 满队时把旧元素覆盖 | 满判断漏了或写错 | 检查 `size == data.length` |
| 出队顺序错乱 | `head` 与 `tail` 用反 | 入队写 `tail`、出队读 `head` |
| 打印后队列变空 | `snapshot` 直接改 `head` | 用局部 `index` 遍历 |
| 空队 dequeue 返回 0 | 用 0 表示"空" | 抛异常或返回 `Optional`（本仓库用异常） |
| 容量 0 直接崩 | 构造未校验 | `capacity <= 0` 抛 `IllegalArgumentException` |

## 8. 动手练习

1. 画出容量 3 的队列，依次执行：入 1、入 2、出、入 3、入 4、出。写出每步 `head/tail/size` 和逻辑内容。
2. 用"浪费一个格子"方案重写 `enqueue` / `dequeue` / 满判断，去掉 `size` 字段，验证同样通过。
3. 给 `MyQueue` 加 `peek()`（只看队头不出队），空队同样抛异常。
4. 把容量改成 1，测试入队、拒绝、出队的完整流程。
5. 写一个"银行排队"小程序：顾客随机入队，每次服务出队一人，打印队伍变化。

## 9. 自我检查

1. `head` 和 `tail` 分别指向什么？——下一次出队位置、下一次入队写入位置。
2. 为什么 `head == tail` 不能判断空？——满队时也相等（`tail` 绕回）。
3. 出队后旧元素还在数组里吗？——在，但已不属于队列，下次入队覆盖。
4. `snapshot` 为什么不能改 `head`？——打印是只读操作，改了就把队列清空。
5. 队列和栈的核心差别？——FIFO vs LIFO，入出口不同端。

学完后可对照 C 侧 `linked_stack.c`：同一个"栈"概念用链表实现，关注点从"下标回绕"变成"指针与内存释放"。
