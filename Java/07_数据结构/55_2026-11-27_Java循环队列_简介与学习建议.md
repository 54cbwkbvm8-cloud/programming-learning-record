# Java 循环队列（数组实现）：简介与学习建议

## 1. 文件基本信息

- **源码**：`MyQueue.java`
- **分类**：`Java/07_数据结构`
- **程序用途**：用固定长度数组实现循环队列——`enqueue` 入队（满则拒绝）、`dequeue` 出队（空则抛异常）、`isEmpty` / `size` 查询、`snapshot` 按队头到队尾输出内容；`main` 内置边界与回绕演示。
- **核心知识点**：队列"先进先出"、循环数组的 `head` / `tail` 与取模回绕、用 `size` 区分空队与满队、容量校验（`IllegalArgumentException`）、空队异常（`NoSuchElementException`）、遍历时的独立下标。
- **前置知识**：数组下标与长度、`%` 取模、构造方法与私有字段（25/26 号）、`StringBuilder`（27/50 号）、异常抛出与捕获（52 号）。
- **相关练习**：37 号用数组实现了栈（后进先出），本题是同一存储结构的"另一端出口"——队头出、队尾进。两者对照是理解两种线性结构最快的路径。

## 2. 程序功能说明

队列像排队买饭：先来的先走（FIFO），只允许在**队尾进**、**队头出**。数组实现的关键难点是"出队后前面的空位怎么复用"——循环队列让 `tail` 走到末尾后回头从 0 开始：

```java
tail = (tail + 1) % data.length;   // 入队后推进，末尾回到 0
head = (head + 1) % data.length;   // 出队后推进，末尾回到 0
```

只用 `head == tail` 无法区分"空"和"满"（两者都可能相等），所以额外维护 `size`：`size == 0` 为空、`size == data.length` 为满。`snapshot` 用独立的 `index` 从 `head` 起走 `size` 步，避免改动真实队头。

`main` 的演示顺序：空队出队（捕获异常）→ 连续入队 5 个填满 → 满队再入（返回 false）→ 出队 1 个 → 入队 6（复用空位、`tail` 回绕）→ 再入 7（再次拒绝）→ 逐个出队到空。

## 4. 学习重点与难点

- **`head` / `tail` 的含义**：`head` 指向"下一次出队的位置"，`tail` 指向"下一次入队的写入位置"。两者都是下标，不是元素个数（个数是 `size`）。
- **取模回绕是循环队列的灵魂**：`(index + 1) % length`，不加 `%` 就会在数组末尾越界。
- **为什么必须有 `size`**：只靠 `head == tail` 会把"满"误判成"空"。另一种常见做法是"浪费一个格子"（满的条件是 `(tail+1)%len == head`），本题选了更直观的 `size`。
- **入队/出队的返回值约定**：`enqueue` 用 `boolean` 表示成功与否（满不是异常，是正常业务结果）；`dequeue` 用异常表示"没有元素"，因为调用者拿到 0 无法区分"真值 0"和"空队"。这与 37 号栈的约定一致。
- **`snapshot` 不修改状态**：用局部 `index` 遍历，若直接改 `head`，一次打印就会把队列清空。
- **容量校验在构造方法**：`capacity <= 0` 直接抛 `IllegalArgumentException`，把错误挡在对象创建阶段（26 号"构造校验"的复用）。

## 5. 推荐学习流程

1. 先运行程序，对照输出理解每一步的队列状态。
2. 画出 5 格数组，手工跟踪：入队 0~4 后 `head/tail/size` 各是多少；出队一个后 `head` 停在哪。
3. 推演"入队 6"时 `tail` 如何从 4 回绕到 0，`[1, 2, 3, 4, 6]` 为什么不是 `[6, 1, 2, 3, 4]`。
4. 对照 37 号 `StackDemo`：栈的 `top` 与队列的 `head/tail` 有何异同。
5. 合上源码重写：构造、`enqueue`、`dequeue`、`isEmpty`、`size`、`snapshot`，用同样的演示核对。
