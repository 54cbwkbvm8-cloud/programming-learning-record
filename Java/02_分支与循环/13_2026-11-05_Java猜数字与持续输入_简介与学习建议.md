- 程序用途：电脑随机产生 1 到 100 的整数，玩家反复猜测，直到猜中。
- 主要问题：持续读取输入、拒绝非法数据、比较大小、只统计有效猜测次数。

## 程序功能说明

`random.nextInt(100)` 产生 0 到 99，因此加 1 后范围是 1 到 100。程序先检查输入能否按整数读取；不能读取时清理错误内容并重新开始。整数超出 1 到 100 时同样重试，而且不算一次有效猜测。

只有合法猜测才让 `count++`。程序用 `while (true)` 持续询问，猜小时提示后继续，猜大时提示后继续，猜中时输出次数并 `break`。

## 运行方式

```bash
java_dir=$(mktemp -d /tmp/java-guess.XXXXXX)
javac -encoding UTF-8 -Xlint:all -Werror -d "$java_dir" \
  "Java/02_分支与循环/GuessNumber.java"
seq 1 100 | java -cp "$java_dir" GuessNumber
```

`seq 1 100` 依次提供 1 到 100，因此必定包含随机秘密数字，程序一定能在最多 100 次有效猜测内结束。本次实际运行恰好在第 3 次猜中：

```text
我想好了一个1-100之间的整数，你猜是多少？
请输入你的猜测：你猜小了！
请输入你的猜测：你猜小了！
请输入你的猜测：恭喜你，猜对了！你一共猜了3次。
```

由于秘密数字每次随机，重复运行的猜测次数通常不同，不能把 3 固定写成唯一结果。

## 学习重点

1. `nextInt(100)` 的上界 100 不包含在结果里。
2. `while (true)` 需要有明确出口，本题出口是猜中后的 `break`。
3. 输入不是整数和整数超出范围属于两类校验。
4. 非法输入后使用 `continue` 立即回到下一次询问。
5. 只有合法猜测才增加次数，避免把 `abc` 或 0 也算进去。
6. 随机程序的验证重点不是固定输出，而是范围、终止条件和每次提示是否一致。

## 学习难点

- 漏写 `+ 1`，秘密数字范围会变成 0 到 99。
- 输入非整数后没有 `sc.next()`，会反复看到同一段错误内容。
- 在输入校验前就 `count++`，会让无效输入也被统计。
- 猜中时忘记 `break`，程序会继续要求输入。
- 随机结果无法用一次固定输出证明全部正确，需要多次运行或覆盖全部可能值。

## 建议学习流程

1. 先运行小程序，观察随机秘密数字不一定相同。
2. 输入 `abc`，确认提示后还能继续。
3. 输入 `0` 和 `101`，确认范围检查。
4. 用 1 到 100 的顺序输入，保证程序一定终止。
5. 手工记录每次合法猜测和次数变化。
6. 把范围改成 1 到 10，修改上界和提示，并重新测试。
7. 加入“最多猜 7 次”失败退出逻辑作为拓展。

## 易错点与测试用例

| 输入方式 | 预期结果 | 检查目标 |
| --- | --- | --- |
| `abc` 后继续猜 | 提示非整数，不增加次数 | 类型校验 |
| `0` 后继续猜 | 提示超出范围，不增加次数 | 下界 |
| `101` 后继续猜 | 提示超出范围，不增加次数 | 上界 |
| 依次输入 1 到 100 | 必定结束，次数在 1 到 100 之间 | 终止性 |
| 猜中一次 | 输出总次数并结束 | `break` 出口 |

交互式运行时还有一个边界情况：如果标准输入被提前关闭，`hasNextInt()` 为假，随后 `sc.next()` 没有内容可读，可能抛出 `NoSuchElementException`。普通键盘交互不会主动关闭输入；若要做自动化菜单，应额外设计 EOF 或“退出”命令。

## 拓展练习

1. 把范围改成 1 到 1000，并同步修改提示。
2. 限制最多 7 次猜测，超限时公布答案并结束。
3. 增加“比上次更接近/更远”的提示。
4. 支持输入 `q` 主动退出。
5. 让用户先选择难度，再决定数字范围和最大猜测次数。

完成本练习后，应能独立描述程序的完整状态：秘密数字、当前猜测、有效次数和循环出口。
