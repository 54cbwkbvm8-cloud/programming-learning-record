# Java 多态数组与安全类型转换：零基础教程

## 一、题目在解决什么问题

学生和老师都能自我介绍，但介绍内容不同；学生能学习，老师能授课。如果为每种对象分别写一套遍历代码，会越来越重复。

多态让程序用统一的 `Person` 类型保存和遍历对象，同时保留各子类自己的方法实现。

## 二、先分清两个“类型”

```java
Person p1 = new Student("张三", 20);
```

- **声明类型**：`Person`，决定编译器允许通过 `p1` 调用哪些方法。
- **真实对象类型**：`Student`，决定被重写的 `introduce()` 实际执行哪个版本。

这行是**向上转型**：学生也是人，所以不需要强转。`p1.getClass().getName()` 输出 `Student`，证明变量声明没有改变对象真身。

## 三、多态成立的三个条件

1. `Student`、`Teacher` 继承 `Person`。
2. 两个子类都重写 `introduce()`。
3. 使用 `Person` 类型的引用指向子类对象。

缺少重写时，即使引用指向子类，调用的仍是父类实现；缺少继承时，不能直接把对象放进 `Person` 引用。

## 四、构造方法中的 `this(...)` 与 `super(...)`

`Student` 有两个构造方法：

```java
public Student(String name, int age) {
    this(name, age, "计算机科学与技术");
}

public Student(String name, int age, String major) {
    super(name, age);
    this.major = major;
}
```

两参数版本先调用本类三参数版本，三参数版本再调用父类构造方法。这样默认值和初始化逻辑不必重复。

`this(...)` 与 `super(...)` 都必须位于构造方法第一行，不能同时直接写在同一个构造方法里。`Teacher` 使用同样的默认值复用方式。

## 五、多态数组怎样工作

```java
Person[] people = new Person[3];
people[0] = new Student("李四", 21);
people[1] = new Teacher("王五", 35);
people[2] = new Student("赵六", 19);
```

`new Person[3]` 只创建三个保存引用的格子，随后三行才创建对象。遍历时：

| 元素 | 声明类型 | 真实类型 | `introduce()` 的版本 |
| --- | --- | --- | --- |
| `people[0]` | `Person` | `Student` | `Student` |
| `people[1]` | `Person` | `Teacher` | `Teacher` |
| `people[2]` | `Person` | `Student` | `Student` |

循环只写一次 `p.introduce()`，输出却随真实对象变化，这就是运行时方法分派。

## 六、为什么向下转型前需要检查

父类没有 `study()` 和 `teach()`，所以不能直接写 `p.study()`。程序先判断：

```java
if (p instanceof Student) {
    Student s = (Student) p;
    s.study();
} else if (p instanceof Teacher) {
    Teacher t = (Teacher) p;
    t.teach();
}
```

`instanceof` 检查真实对象是否属于目标类型。检查通过后再强转，才能安全使用子类特有方法。当前数组全是学生或老师，所以 `else` 不执行；加入普通 `Person` 后它才有实际输出。

`Student s1 = (Student) p1;` 演示了另一次安全转换。虽然 `s1` 后续未使用，但转换本身合法，因为 `p1` 的真身确实是 `Student`。

## 七、故意失败的反例

`CastErrorDemo` 中：

```java
Person p = new Teacher("Tom", "java");
Student s = (Student) p;
```

编译器知道 `Student` 是 `Person` 的子类，所以这种转换“有可能”合法，能通过编译。运行时真身却是 `Teacher`，因此第 7 行抛出 `ClassCastException`。

实际运行已确认：先打印 `CastErrorDemo$Teacher`，然后异常终止，最后的 `println` 不执行。`$` 表示 `Teacher` 是 `CastErrorDemo` 的静态嵌套类，不是文件损坏。

修复思路不是捕获异常后继续当没事发生，而是在转换前检查类型，或重新设计共同父类方法以减少向下转型。

## 八、常见错误与调试

- **认为向上转型会把对象变成父类**：不会，真实类型不变。
- **通过父类引用直接调用子类特有方法**：编译失败，应使用共同抽象行为或安全转换。
- **看到编译通过就认为强转安全**：错误转换往往到运行时才暴露。
- **对所有元素都强转为某一个子类**：遇到兄弟类型会崩溃。
- **把 `instanceof` 当作业务设计的唯一方案**：大量类型分支可能说明应把差异放进重写方法。

3. 在数组中加入普通 `Shape`（若设计允许实例化），预测 `else` 分支。
4. 故意把 `Rectangle` 强转为 `Circle`，记录编译状态和运行异常。
