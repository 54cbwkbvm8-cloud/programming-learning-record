# Java 多态数组与安全类型转换：简介与学习建议

## 1. 文件基本信息

- **源码**：`PolymorphismDemo.java`、`CastErrorDemo.java`
- **分类**：`Java/08_继承与多态/02_多态与类型转换`
- **程序用途**：演示向上转型、运行时方法分派、多态数组、向下转型、`instanceof`，以及错误转换产生的 `ClassCastException`。
- **核心知识点**：父类引用指向子类对象、重写、`this(...)` 构造方法复用、对象数组、静态内部类、类型检查。
- **前置知识**：38 号的继承、构造方法和方法重写；数组与增强 `for`。
- **版本关系**：两个文件是同一学习单元中的“安全做法”和“故意失败反例”，不是重复程序。

## 2. 程序功能说明

`PolymorphismDemo` 中的 `Student` 和 `Teacher` 都继承 `Person`。`Person` 类型的变量和数组可以保存不同子类对象；调用 `introduce()` 时，真正执行的是对象实际类型重写后的方法。需要调用 `study()` 或 `teach()` 等子类特有方法时，先用 `instanceof` 检查，再向下转型。

`CastErrorDemo` 故意把实际为 `Teacher` 的对象强转为 `Student`。这种转换能通过编译，但运行时抛出 `ClassCastException`，后续语句不会执行。它使用静态内部类，因此可独立编译，不依赖其他文件。

## 3. 编译与运行

```bash
java_dir=$(mktemp -d /tmp/java-polymorphism.XXXXXX)
javac -encoding UTF-8 -Xlint:all -Werror -d "$java_dir" \
  "Java/08_继承与多态/02_多态与类型转换/PolymorphismDemo.java" \
  "Java/08_继承与多态/02_多态与类型转换/CastErrorDemo.java"
java -cp "$java_dir" PolymorphismDemo
java -cp "$java_dir" CastErrorDemo
```

已使用 OpenJDK 21.0.13 严格编译并实际运行：

- `PolymorphismDemo` 正常结束，退出码 0；数组中学生和老师分别执行自己的介绍及特有方法。
- `CastErrorDemo` 先输出 `p 指向的真实对象类型：CastErrorDemo$Teacher`，随后在第 7 行按设计抛出 `ClassCastException`，退出码 1。这是预期教学结果，不是需要掩盖的程序故障。

## 4. 学习重点与难点

- **变量类型与对象类型要分开**：`Person p1 = new Student(...)` 中，左边限制“能调用哪些方法”，右边决定“重写方法实际执行哪个版本”。
- **向上转型自动且安全，向下转型有失败风险**。
- **父类引用不能直接调用子类特有方法**：即使真身是 `Student`，也不能直接写 `p1.study()`。
- **`this(...)` 与 `super(...)`**：本例用 `this(...)` 复用本类另一个构造方法，再由那个构造方法调用 `super(...)`。
- **静态内部类名的 `$`**：异常中的 `CastErrorDemo$Teacher` 表示 `Teacher` 是 `CastErrorDemo` 的嵌套类。

## 5. 推荐学习流程

1. 为 `p1` 和 `people` 的每个元素分别写“声明类型”和“真实对象类型”。
2. 不运行程序，预测三次 `p.introduce()` 的输出。
3. 跟踪 `instanceof` 的每个分支，说明为什么转换安全。
4. 运行 `CastErrorDemo`，找到异常类型、真实对象类型和停止行。
5. 合上源码，写一个 `Shape` 父类及两个子类，用 `Shape[]` 统一调用重写方法。

## 7. 拓展与后续学习

- 把经典 `if + instanceof + 强转` 改为课程允许版本中的模式匹配写法，并比较适用范围。
- 思考怎样用共同父类方法减少向下转型，而不是在所有场景都依赖 `instanceof`。
- 接着学习 40、41 号的多文件继承，再进入接口与集合；当前练习尚未覆盖接口。
