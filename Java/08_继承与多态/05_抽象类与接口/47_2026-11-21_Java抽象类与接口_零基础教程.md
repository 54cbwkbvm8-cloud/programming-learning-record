# Java 抽象类与接口：零基础教程

> 配合 [AbstractAndInterface.java](AbstractAndInterface.java) 和 [47 号简介](47_2026-11-21_Java抽象类与接口_简介与学习建议.md) 使用。先运行程序看输出，再按本文顺序理解；卡在概念上时回来查，不必一次读完。

## 0. 这个程序在做什么

两段演示，回答两个问题：

1. "圆形和矩形都叫图形、都有面积，但算法不同"——怎么用代码表达？答案：**抽象类**。
2. "麻雀、飞机、鸭子是完全不同的东西，但都会飞；鸭子还会游泳"——怎么表达？答案：**接口**。

学完本题，你应能回答：什么时候用抽象类、什么时候用接口、`default` 方法是干嘛的、为什么转换前要 `instanceof`。

## 1. 预备概念：从"继承"到"继承不了的更抽象的东西"

38 号学过：`Student extends Person`，子类自动获得父类的字段和方法。但有两个新问题：

- 有些父类**不该被直接造出来**。世上没有"一个纯粹的图形"，只有具体的圆和矩形。如果允许 `new Shape()`，这个对象算什么呢？
- 有些能力**根本不属于同一家族**。麻雀是鸟、飞机是机器、鸭子是鸟，"会飞"不是它们的共同祖先，而是各自分别具备的能力。

Java 用两个关键字分别解决：`abstract class` 解决前者，`interface` 解决后者。

## 2. 第一组：抽象类 Shape

### 2.1 定义

```java
abstract class Shape {
    private String name;

    public Shape(String name) {
        this.name = name;
    }

    public abstract double area();          // 抽象方法：只有头，没有体

    public void show() {                    // 普通方法：有体，子类直接用
        System.out.println(name + " 的面积 = " + area());
    }
}
```

逐行拆解：

- `abstract class`：标记"这是抽象类，不能 `new`"。但它的**构造方法照常存在**——子类构造时通过 `super("圆形")` 调用它，初始化父类掌握的 `name`。
- `public abstract double area();`：注意结尾是**分号**，没有花括号。它是一份声明："每种图形都必须能算面积，返回 `double`，但算法各写各的。"
- `show()` 是普通方法，子类不写就能用。它内部调用 `area()` 时，Java 会按**对象的真实类型**选择执行谁的版本——这就是 39 号学过的多态在抽象类里继续生效。

### 2.2 子类实现

```java
class Circle extends Shape {
    private double radius;

    public Circle(double radius) {
        super("圆形");
        this.radius = radius;
    }

    @Override
    public double area() {
        return Math.PI * radius * radius;   // 圆周率 × 半径²
    }
}
```

三个要点：

1. 构造第一行 `super("圆形")`——名字交给父类保管（38 号规则）。
2. `@Override public double area()`：把抽象方法**补上方法体**，这叫"实现"。`Rectangle` 同理返回 `width * height`。
3. 若子类不实现 `area()`，编译器直接报错；除非子类自己也声明 `abstract`，把义务继续传给下一级。

### 2.3 为什么 `Shape[]` 合法而 `new Shape()` 非法

```java
Shape[] shapes = new Shape[2];   // 只造了 2 个"空格子"，没造任何图形
shapes[0] = new Circle(2);       // 子类对象放入父类格子：向上转型，自动
```

`new Shape[2]` 造的是**数组**（格子们），不是图形；往格子里放的是具体子类对象。这和 35 号对象数组"格子默认 null、放对象进去"完全一致。而 `new Shape("x")` 是直接造抽象类对象，编译器禁止。

### 2.4 运行时的多态

```java
for (Shape shape : shapes) {
    shape.show();
}
```

两次循环执行同一行 `shape.show()`：

- 第 1 次 `shape` 是 `Circle`：`show()` 里的 `area()` 执行圆的算法 → `圆形 的面积 = 12.566370614359172`
- 第 2 次 `shape` 是 `Rectangle`：同一个 `show()`，`area()` 执行矩形算法 → `矩形 的面积 = 12.0`

**模板方法雏形**：父类写死流程"打印名字和面积"，把变化的部分（怎么算）留给子类。以后写管理系统时，"通用流程 + 可替换步骤"都靠这个思路。

## 3. 第二组：接口 Flyable / Swimmable

### 3.1 定义

```java
interface Flyable {
    void fly();                        // 接口方法默认 public abstract，不用写

    default void land() {
        System.out.println("着陆");     // default：给了现成实现的"默认条款"
    }
}

interface Swimmable {
    void swim();
}
```

把接口理解为**能力合同**：`Flyable` 这份合同只写一条——"想会飞，就必须提供 `fly()`"；至于怎么飞，合同不管。`default` 方法是合同附带的默认条款：签了合同的类如果懒得自己写 `land()`，就用"着陆"这个通用版本。

### 3.2 实现：三个毫无亲缘的类签同一份合同

```java
class Bird implements Flyable {          // 只签 Flyable
    @Override
    public void fly() { ... }
}

class Airplane implements Flyable {      // 签 Flyable，并重写默认条款
    @Override
    public void fly() { ... }
    @Override
    public void land() { ... }           // 自己的着陆方式
}

class Duck implements Flyable, Swimmable {   // 同时签两份合同
    @Override
    public void fly() { ... }
    @Override
    public void swim() { ... }
}
```

关键差别：**`extends` 只能跟一个，`implements` 可以列多个**（逗号隔开）。鸭子既会飞又会游，靠双合同实现——单继承体系表达不了这种交叉能力。

### 3.3 接口数组：把"都会飞的东西"装进同一辆车

```java
Flyable[] flyers = { new Bird("麻雀"), new Airplane("C919"), new Duck("唐老鸭") };
```

三个类没有共同父类，却都签了 `Flyable`，所以都能放进 `Flyable[]`——接口在这里起到了"临时家族"的作用。

```java
for (Flyable f : flyers) {
    f.fly();    // 各自的版本
    f.land();   // 麻雀/鸭子用默认"着陆"，飞机用自己的
}
```

对照实际输出验证 `default` 的行为：

```text
麻雀 在飞翔
着陆              ← Bird 没写 land()，用接口默认
C919 靠发动机推力飞行
C919 在跑道上降落  ← Airplane 重写了 land()
唐老鸭 靠翅膀飞行
着陆              ← Duck 也没写 land()
唐老鸭 在水里游泳
```

### 3.4 `instanceof` + 转型：调用合同之外的能力

`Flyable` 类型的变量 `f`，只能调用 `Flyable` 合同里有的 `fly()`、`land()`。想叫鸭子游泳，必须先确认"它真的签过 `Swimmable`"：

```java
if (f instanceof Swimmable) {
    ((Swimmable) f).swim();
}
```

- `f instanceof Swimmable`：问"这个对象是不是也实现了 Swimmable"。麻雀、飞机答"否"，只有鸭子答"是"。
- `(Swimmable) f`：把变量"当作 Swimmable 来用"，之后才能点出 `swim()`。
- 不检查就强转会抛 `ClassCastException`（39 号 `CastErrorDemo` 演示过）。**先问再转**是铁律。

这和 39 号"父类引用转子类"是同一套规则，只是这次"目的地"是接口而不是类。

## 4. 概念对照表

| 问题 | 抽象类 | 接口 |
| --- | --- | --- |
| 表达什么 | "是什么"（圆是一种图形） | "能做什么"（鸭子会飞） |
| 关键字 | `abstract class` / `extends` | `interface` / `implements` |
| 一个类能有几个 | 只能继承一个 | 可以实现多个 |
| 能有字段和构造方法 | 能（`name`、构造） | 只能有常量 |
| 能有普通方法 | 能（`show()`） | 只能 `default` 或 `static` 方法 |
| 能否 `new` | 不能 | 不能 |
| 能否当数组/变量类型 | 能（`Shape[]`） | 能（`Flyable[]`） |

## 5. 常见错误与排查

| 现象 | 原因 | 排查 |
| --- | --- | --- |
| `Shape is abstract; cannot be instantiated` | 直接 `new Shape(...)` | 改成 `new Circle(...)` 等具体子类 |
| `Circle is not abstract and does not override abstract method area()` | 子类漏实现抽象方法 | 补上 `@Override public double area()`；或子类加 `abstract` |
| `ClassCastException` | 未经 `instanceof` 就强转 | 转型前先 `if (f instanceof Swimmable)` |
| 想调 `swim()` 但变量是 `Flyable` 编译不过 | 接口类型只见合同内的方法 | 先转型成 `Swimmable` 再调用 |
| 输出 `Circle@7852e922` 这类乱码 | 打印对象没重写/没调用合适方法 | 调 `show()` 或重写 `toString()`（附件注释记录的历史问题） |

## 7. 自我检查

能不假思索回答以下问题，才算过关：

1. 抽象方法的方法体在哪里？——在**子类的实现**里，抽象类里只有分号。
2. `new Shape[2]` 与 `new Shape("x")` 哪个合法？为什么？——前者合法（造的是格子），后者非法（造的是抽象类对象）。
3. 鸭子如何做到既会飞又会游？——`implements Flyable, Swimmable` 双合同，单继承做不到。
4. `Bird` 一行都没写 `land()`，为什么麻雀也能执行 `f.land()`？——`Flyable` 接口的 `default` 方法提供了默认实现。
5. 调 `swim()` 前为什么必须 `instanceof`？——`Flyable` 变量看不到 `Swimmable` 的方法；不检查就强转可能 `ClassCastException`。
