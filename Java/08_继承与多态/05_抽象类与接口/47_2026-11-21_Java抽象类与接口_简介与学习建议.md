# Java 抽象类与接口：简介与学习建议

## 1. 文件基本信息

- **源码**：`AbstractAndInterface.java`
- **分类**：`Java/08_继承与多态/05_抽象类与接口`
- **程序用途**：用两组演示理解抽象类与接口——`Shape`/`Circle`/`Rectangle` 演示抽象类与抽象方法；`Flyable`/`Swimmable` 与 `Bird`/`Airplane`/`Duck` 演示接口、`default` 方法、`instanceof` 与向下转型。
- **核心知识点**：`abstract class`、抽象方法、`interface`、`implements`、接口 `default` 方法、多接口实现、`instanceof` 后转型调用、`Math.PI`、`@Override`。
- **前置知识**：继承与 `super`（38 号）、方法重写（38、41 号）、多态与 `instanceof`（39 号）。
- **相关练习**：38→39→40→41 之后学习本题；48 号校园管理系统会把这些概念放进真实项目。

## 2. 程序功能说明

第一组是"图形面积"：`Shape` 是抽象类，规定"每种图形都有面积"（抽象方法 `area()`）并写好通用展示 `show()`；`Circle`、`Rectangle` 各自实现面积算法。`main` 用 `Shape[]` 装两种图形，同一个 `shape.show()` 调用自动执行各自的 `area()`——多态。

第二组是"能力清单"：`Flyable`（会飞）和 `Swimmable`（会游泳）是接口。麻雀、飞机、鸭子互无继承关系，但都实现 `Flyable`，所以能放进同一个 `Flyable[]` 统一处理；只有鸭子同时实现 `Swimmable`，所以循环里先用 `instanceof` 判断再转型调用 `swim()`。`Airplane` 重写了 `default` 版 `land()`，另外两者用接口默认实现"着陆"。

源码后半段保留附件注释教程，其中记录了原始版本的三处问题：打印对象而非调用 `show()`（输出 `Circle@十六进制`）、`Bird` 输出缺空格、标题末尾多余空格——当前源码已是修复后的版本。注释不影响编译执行。

## 4. 学习重点与难点

- **抽象类表达"是什么"**：`Circle` 是一种 `Shape`。它不能 `new`，但可以声明数组类型 `Shape[]`；构造方法仍存在，由子类 `super("圆形")` 调用。
- **抽象方法是"合同条款"**：只有方法头没有方法体；子类必须全部实现，否则子类自己也得声明成抽象的。`Shape.show()` 展示了经典设计——父类写固定流程，变化部分留给子类。
- **接口表达"能做什么"**：`Duck` 会飞也会游泳。一个类只能 `extends` 一个父类，却可以 `implements` 多个接口，这是 Java 组织能力的主要手段。
- **`default` 方法是合同的默认条款**：不重写就用接口里的版本（麻雀、鸭子用"着陆"），想改就重写（飞机跑道降落）。
- **接口数组 + `instanceof` + 转型**：`Flyable` 变量只能调 `fly/land`，想调 `swim` 必须先 `instanceof Swimmable` 确认再 `(Swimmable) f` 转型——39 号安全向下转型规则在接口场景的复用。
- **抽象类 vs 接口怎么选**：有公共字段和构造流程选抽象类（图形），纯粹约定行为选接口（会飞）。

## 5. 推荐学习流程

1. 先运行程序，对照输出找到"麻雀、鸭子用默认着陆、飞机用自己的"那几行。
2. 画出两棵结构图：`Shape ← Circle/Rectangle`（实线继承）和 `Flyable/Swimmable ←- Bird/Airplane/Duck`（虚线实现）。
3. 在 `Circle` 里删掉 `area()` 试试编译（预期报错：必须实现抽象方法），再恢复。
4. 手工预测：给 `Duck` 也重写 `land()` 输出什么；把 `shapes[1]` 换成半径 5 的圆输出什么。
5. 进入 48 号，看抽象概念如何落进带菜单的真实项目。
