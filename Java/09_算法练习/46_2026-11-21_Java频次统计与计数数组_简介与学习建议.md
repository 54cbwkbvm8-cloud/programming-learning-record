# Java 频次统计与计数数组：简介与学习建议（原始版 / 修正版）

## 1. 文件基本信息

- **源码**：`P5_Frequency.java`（原始版，按附件原样保存，**无法编译**）；`P5_FrequencyFixed.java`（修正版，仅修复两处语法错误）
- **分类**：`Java/09_算法练习`
- **程序用途**：评测题——读入 n 个 0~100 的整数，按数值从小到大输出每个出现过的数及其次数。
- **核心知识点**：计数数组（桶）思想——数值本身就是下标；从错误信息定位语法问题；原始版/修正版的阅读顺序。
- **前置知识**：数组默认值为 0、下标即编号、评测题输入格式。
- **相关练习**：29 号字母统计（`ch - 'a'` 映射）是同一思想在字母上的应用；45 号用排序去重，本题用计数数组，正好对照。

## 2. 原始版的两个语法错误（重要学习材料）

`P5_Frequency.java` 保存的是附件原样，它**不能通过编译**，错误本身就是练习材料：

| 位置 | 原始写法 | 问题 | javac 报错 |
| --- | --- | --- | --- |
| 第 14 行 | `for (int i =   i < n; i++)` | 初始化 `int i = 0;` 丢了 `0;`，循环头不完整 | `';' expected` |
| 第 20 行 | `f  (int i = 0; i < 101; i++)` | 关键字 `for` 误写成 `f` | `'.class' expected` 等多条 |

定位方法：读报错的行号和 `^` 指向的位置，先看该行结构（循环头三段：初始化; 条件; 更新），再对照正确模板。第一个错误指向行尾反而要往前找丢失的分号；第二个错误一列就能看出 `f` 不是关键字。**修正版 `P5_FrequencyFixed.java` 只改这两处**（类名按 Java 规则随文件名改为 `P5_FrequencyFixed`），其余逻辑与原始版完全一致。

附件后半段的注释教程记录了原始代码的完整讲解，其正确代码与修正版一致，说明错误很可能产生于誊抄环节——这也提醒：誊抄后必须重新编译验证。

## 3. 程序功能说明（以修正版为准）

准备 101 格计数数组 `cnt`（下标 0~100，默认全 0）。每读到一个数 x 就 `cnt[x]++`——数字本身就是格子的编号。全部读完后从下标 0 扫到 100，凡 `cnt[i] > 0` 就输出 `i` 和次数。因为下标天然从小到大，**不需要排序**就自动按数值升序输出。

这正是"计数数组（桶）"思想：当数值范围小且已知（0~100，如成绩）时，用空间换时间，一遍读入完成统计。45 号的排序去重则不限范围但要多做排序；29 号的 26 格字母统计是同一思想。

## 4. 编译与运行

在仓库根目录执行：

```bash
# 原始版：预期编译失败，报错见上表
javac -encoding UTF-8 -d "$(mktemp -d /tmp/java-p5orig.XXXXXX)" \
  "Java/09_算法练习/P5_Frequency.java"

# 修正版：严格编译并运行
java_dir=$(mktemp -d /tmp/java-algo3.XXXXXX)
javac -encoding UTF-8 -Xlint:all -Werror -d "$java_dir" \
  "Java/09_算法练习/P5_FrequencyFixed.java"
printf '6\n3 1 3 100 0 1\n' | java -cp "$java_dir" P5_FrequencyFixed
```

原始版已实际编译，确认报第 14、20 行语法错误；修正版已使用 OpenJDK 21.0.13 严格编译（`-Werror` 通过）并实际运行，输出：

```text
0 1
1 2
3 2
100 1
```

`printf '0\n'` 时无任何输出（正确：一个数都没有）。

## 5. 学习重点与难点

- **"数字当下标"的映射**：`cnt[x]++` 一行完成"找到 x 的格子并加一"。理解它等价于"数到 3 就让 3 号格加一"，是理解哈希思想（C 语言侧哈希表练习）的前奏。
- **为什么是 101 格**：0~100 共 101 个不同数值；下标从 0 起，格子数 = 最大值 + 1。
- **输出天然有序**：扫描顺序 0→100 就是数值升序，省掉排序。对照 45 号：排序法不限范围，计数法限范围但更快。
- **范围约束是安全边界**：输入 101 或 -1 会让 `cnt[101]`/`cnt[-1]` 越界崩溃。程序信任题目约定（0~100），这是评测题的常态，也是它和"健壮工具类"的差别。
- **读报错先于改代码**：拿到 `';' expected` 这类报错，先定位行、再对照语法模板，比直接翻看正确答案更有训练价值。

## 6. 推荐学习流程

1. 先只看原始版，自己读 javac 报错并尝试定位两处错误（不看修正版）。
2. 打开修正版对照，确认自己的判断；再运行修正版核对输出。
3. 手工跟踪：输入 `6\n3 1 3 100 0 1\n` 时 `cnt[1]`、`cnt[3]`、`cnt[100]` 各是多少。
4. 对照 29 号：把字母统计改写成"数值统计"需要改动哪些地方（数组大小、映射方式）。
5. 合上源码重写一遍，注意输出格式是"数值 空格 次数"每行一组。

## 8. 拓展与后续学习

- 改成"只输出出现次数最多的数"：需要第二遍扫描求最大计数。
- 思考数值范围很大或含负数时怎么办：回到 45 号的排序法，或学哈希表（C 语言侧已有练习可对照）。
- 版本阅读顺序：先原始版练定位，再修正版练逻辑；这与 22 号（逻辑错误复盘）、C 44 号（原始版/修正版）的安排一致。
