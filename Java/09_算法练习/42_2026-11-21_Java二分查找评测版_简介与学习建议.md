# Java 二分查找（评测版）：简介与学习建议

## 1. 文件基本信息

- **源码**：`P1_BinarySearch.java`
- **分类**：`Java/09_算法练习`
- **程序用途**：评测题风格的二分查找——读入 n 个已升序排列的整数和一个待查数 key，输出其下标（找不到输出 -1）。
- **核心知识点**：二分查找的循环不变量（`low`/`high` 圈出"答案还可能在的范围"）、`mid = low + (high - low) / 2` 防溢出写法、评测题输入输出约定。
- **前置知识**：数组下标从 0 开始、`while` 循环、方法参数与返回值、`Scanner` 读整数。
- **相关练习**：14 号 `ArrayAndBubbleSort.java` 的第六、七部分已内置数据演示过同一个算法；本题是它的**独立评测版**——算法相同，输入输出方式完全不同。22 号练习过评测题的读入格式。

## 2. 程序功能说明

程序从键盘读四个部分：`n`（个数）→ `n` 个升序整数 → `key`（要找的数），然后调用 `binarySearch` 输出结果。像猜数字游戏：每次看当前范围正中间的数，太小就把左边界移过去，太大就把右边界移过来，每轮排除一半，所以一百万个数最多约 20 轮就能定位。

与 14 号教学版的三点差异值得注意：

1. 14 号把数据写死在源码里并打印每轮 `low/high/mid`；本题数据来自键盘，什么都不打印，只输出最终答案。
2. 本题没有 14 号的 `swapped` 之类的附加演示，代码只有算法本身，更接近考试和评测系统的提交形态。
3. 评测题不允许"请输入……"之类的提示语，因为评测机逐字比对输出。

源码后半段保留了附件中的大段注释教程，其中包含逐轮跟踪示例。注释不影响编译和执行。

## 3. 编译与运行

在仓库根目录执行：

```bash
java_dir=$(mktemp -d /tmp/java-algo3.XXXXXX)
javac -encoding UTF-8 -Xlint:all -Werror -d "$java_dir" \
  "Java/09_算法练习/P1_BinarySearch.java"
printf '5\n1 3 5 7 9\n5\n' | java -cp "$java_dir" P1_BinarySearch
printf '5\n1 3 5 7 9\n4\n' | java -cp "$java_dir" P1_BinarySearch
```

已使用 OpenJDK 21.0.13 严格编译并实际运行。第一条输出 `2`（5 在下标 2），第二条输出 `-1`。

## 4. 学习重点与难点

- **前提条件是算法的一部分**：数组必须已升序。输入乱序数据程序不会报错，只会返回错误结果——这是"静态正确、动态依赖约定"的典型例子。
- **`mid` 的防溢出写法**：`(low + high) / 2` 在数组超过约 21 亿元素时可能溢出为负数；`low + (high - low) / 2` 数学等价但永不溢出。本仓库 14 号和 30、31 号（`i <= n / i`）反复出现同一主题：把"数学上成立"升级为"机器上也安全"。
- **`while (low <= high)` 用 `<=`**：`low == high` 时范围里还剩 1 个格子，也必须检查；写成 `<` 会漏判。
- **返回 -1 的约定**：合法下标最小是 0，-1 可以无歧义地表示"没找到"。
- **评测题为什么没有提示语**：输出被逐字比对，多一个字就判错。理解这一点才能区分"教学程序"和"提交程序"两种形态。

## 5. 推荐学习流程

1. 先复习 14 号第六部分的 `binarySearchTrace` 输出，回忆每轮范围如何减半。
2. 合上源码，独立写出循环和三分支（等于/小于/大于），再对照本题检查边界。
3. 用纸笔跟踪：在 `1 3 5 7 9` 中找 4（注释教程里有完整三轮过程），预测输出 -1 后运行核对。
4. 修改输入做实验：找第一个元素、最后一个元素、`n = 1`、含负数的数组。
5. 对照 14 号总结：同一个算法的"演示版"和"评测版"各牺牲了什么、换来了什么。

## 6. 易错点与测试用例

| 测试输入 | 预期结果 | 状态 |
| --- | --- | --- |
| `5` / `1 3 5 7 9` / `5` | `2` | 已运行验证 |
| `5` / `1 3 5 7 9` / `4` | `-1` | 已运行验证 |
| `5` / `1 3 5 7 9` / `1` | `0`（找第一个元素） | 预期结果，未运行验证 |
| `5` / `1 3 5 7 9` / `9` | `4`（找最后一个元素） | 预期结果，未运行验证 |
| `1` / `7` / `7` | `0`（单元素命中） | 预期结果，未运行验证 |
| `0` / `5` | `-1`（空数组，`high = -1` 直接跳过循环） | 预期结果，未运行验证 |
| `5` / `1 2 2 2 3` / `2` | `1`、`2`、`3` 之一（重复值返回其中某一个，不保证第一个） | 预期结果，未运行验证 |
| 输入乱序数组如 `5 3 1 9 7` | 程序不报错但结果不可信 | 预期结果，未运行验证 |

两个需要知道的约定（不是错误）：重复元素时返回的下标不一定是第一个；下标从 0 数起，若题目要求从 1 数起需在输出时加 1。

## 7. 拓展与后续学习

- 把本题改成"返回第一个等于 key 的下标"：命中后不立即返回，继续向左收缩 `high`。
- 依次完成 43、44 号（冒泡、插入排序），体会"先排序、再二分"的组合。
- 学有余力时思考：如果数组是降序的，循环里哪两处比较方向需要反过来。
