# Java 冒泡排序（评测版）：简介与学习建议

## 1. 文件基本信息

- **源码**：`P2_BubbleSort.java`
- **分类**：`Java/09_算法练习`
- **程序用途**：评测题风格的冒泡排序——读入 n 个整数，从小到大排序后按"空格分隔、行末无空格"的格式输出。
- **核心知识点**：冒泡排序的双层循环、相邻比较与交换、`temp` 临时变量、评测输出格式控制、数组引用传参（`void` 排序方法为何有效）。
- **前置知识**：嵌套循环、数组下标、方法参数（17 号讲过数组引用）、`print` 与 `println` 的区别。
- **相关练习**：14 号 `ArrayAndBubbleSort.java` 是同一算法的教学版（带 `swapped` 提前结束优化和过程跟踪）；本题是评测版。21 号练过同行空格控制。

## 2. 程序功能说明

读入 `n` 和 n 个数，调用 `bubbleSort(arr)` 排序，再打印结果。冒泡排序每趟从左到右比较相邻两数，左边大就交换，一趟结束后当前最大值"浮"到最右；n 个数最多 n-1 趟完成排序。

与 14 号教学版的两个实质差异：

1. 14 号带 `swapped` 标志，某趟无交换就提前结束；本题没有这个优化，已有序数组也会跑满 n-1 趟。结果仍正确，只是多做无用比较——正好用来对比"正确"与"高效"两个层次。
2. 输出格式是评测题关键：附件注释记录了原版"每个数字后跟空格"导致行末多一个空格的问题，本题已改为"从第二个数字起先打空格再打数字"，行末干净。

源码后半段保留了附件中的注释教程（含 `[5, 2, 9, 1]` 的逐趟演算）。

## 3. 编译与运行

在仓库根目录执行：

```bash
java_dir=$(mktemp -d /tmp/java-algo3.XXXXXX)
javac -encoding UTF-8 -Xlint:all -Werror -d "$java_dir" \
  "Java/09_算法练习/P2_BubbleSort.java"
printf '5\n5 2 9 1 5\n' | java -cp "$java_dir" P2_BubbleSort
```

已使用 OpenJDK 21.0.13 严格编译并实际运行，输出 `1 2 5 5 9`（数字间单个空格，行末无空格）。

## 4. 学习重点与难点

- **内层循环边界 `j < arr.length - i - 1`**：两个条件合成——要访问 `arr[j + 1]` 所以 `j` 最大到 `length - 2`；每完成 i 趟，右边 i 个位置已就位不再参与。
- **为什么 `bubbleSort` 是 `void`**：数组传参传的是引用，方法内改的就是调用者的同一个数组（17 号的核心结论在这里第一次"被用起来"）。
- **`temp` 三步交换**：先存左值、再覆盖、最后回填；直接 `a = b; b = a;` 会丢失 a 的原值。
- **稳定性的雏形**：只在严格大于时交换，相等的数不换位置，冒泡排序因此是稳定排序（39 号之后学多态时可以回头看这句话）。
- **行末空格问题**：肉眼看不出来，但严格比对输出的评测系统会判错。这是"格式也是题意一部分"的第一课。

## 5. 推荐学习流程

1. 用 `[5, 2, 9, 1]` 手工推演三趟（注释教程有完整过程），写出每趟结束时的数组。
2. 运行程序核对 `1 2 5 5 9`，注意输出行末确实没有空格（可用 `| cat -A` 查看）。
3. 对照 14 号：解释 `swapped` 优化省掉了什么，为什么没有它结果仍然正确。
4. 修改输入实验：已有序数组、完全逆序、全部相同、`n = 1`。
5. 合上源码独立重写，重点检查内层循环边界和输出空格逻辑。

## 6. 易错点与测试用例

| 测试输入 | 预期结果 | 状态 |
| --- | --- | --- |
| `5` / `5 2 9 1 5` | `1 2 5 5 9` | 已运行验证 |
| `4` / `1 2 3 4` | `1 2 3 4`（已有序，结果不变） | 预期结果，未运行验证 |
| `4` / `4 3 2 1` | `1 2 3 4`（逆序，最坏情况） | 预期结果，未运行验证 |
| `3` / `7 7 7` | `7 7 7`（全部相同） | 预期结果，未运行验证 |
| `1` / `7` | `7`（单元素） | 预期结果，未运行验证 |
| `0`（仅一个数） | 输出一个空行（与附件注释记录一致） | 预期结果，未运行验证 |
| 把 `if (i > 0)` 改成无条件打印空格 | 行末出现空格，严格评测判错 | 预期结果，未修改源码测试 |

易错提醒：`arr.length` 的 `length` 后面没有括号；`n = 0` 时 `new int[0]` 合法，两层循环都不执行。
